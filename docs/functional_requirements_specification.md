## 기능요구사양 정의 (과제 제출용)

본 절은 과제 계획서의 주요 제공 기능을 기능 설명, 동작 환경, 입력 및 출력 순서로 정의한다. 아래 내용은 개발 목표이며 현재 구현 완료 상태를 나타내지 않는다.

### 1. 그림 카드 탐색 및 선택 기능

- 기능: 사용자는 카테고리별 그림 카드를 조회하고 원하는 카드를 선택한다. 선택한 카드는 문장 구성 영역에 순서대로 표시되며, 개별 삭제, 순서 변경 및 전체 초기화가 가능하다.
- 동작 환경: 웹 브라우저가 설치된 PC, 태블릿 또는 스마트폰과 웹 서버 연결이 필요하다. 터치스크린 또는 마우스·키보드로 조작한다. 카드 이미지와 카테고리 데이터가 서버에 준비되어야 한다.
- 입력: 카테고리 선택, 그림 카드 선택, 카드 이동·삭제 및 초기화 명령을 입력한다.
- 출력: 카드 선택 화면에 카테고리 메뉴, 그림·이름을 포함한 카드 목록, 선택 카드 영역, 삭제·순서 변경·초기화 버튼 및 문장 생성 버튼이 표시된다.

### 2. 사용자별 이용 기록 저장 기능

- 기능: 시스템은 사용자별 카드 선택 내용, 선택 순서, 사용 시각 및 카드 조합을 저장한다. 저장된 기록은 개인 맞춤 추천과 이용 현황 분석에 활용된다.
- 동작 환경: 사용자 구분을 위한 계정 또는 프로필, 백엔드 서버 및 데이터베이스가 필요하다. 기록 저장 시 클라이언트와 서버, 서버와 데이터베이스 사이의 연결이 필요하다.
- 입력: 사용자 식별자, 선택 카드, 선택 순서, 사용 시각 및 의사소통 세션 정보가 입력된다.
- 출력: 데이터베이스에 사용자별 이용 기록이 저장된다. 저장 실패 시 화면에 실패 안내와 재시도 버튼이 표시된다.

### 3. 개인 맞춤형 카드 추천 기능

- 기능: 시스템은 사용자의 카드 사용 빈도, 최근 사용 기록 및 함께 선택한 카드 조합을 분석하여 다음에 사용할 가능성이 높은 카드를 추천한다. 기록이 없는 사용자에게는 기본 추천 카드가 제공된다.
- 동작 환경: 카드 데이터, 사용자별 이용 기록, 추천 알고리즘을 실행하는 서버가 필요하다. 초기에는 빈도·최근성·연관 규칙 기반으로 구현하며 외부 유료 AI 서비스 가입을 필수 조건으로 두지 않는다.
- 입력: 사용자 식별자, 과거 카드 이용 기록 및 현재 선택한 카드 목록이 입력된다.
- 출력: 카드 선택 화면의 추천 영역에 추천 카드의 그림과 이름이 표시된다. 추천 카드를 선택하면 문장 구성 영역에 추가된다.

### 4. 선택 카드 기반 문장 생성 기능

- 기능: 시스템은 선택한 카드의 의미와 순서를 분석하여 자연스러운 한국어 문장을 생성한다. 예를 들어 ‘나 → 물 → 마시다’를 선택하면 ‘저는 물을 마시고 싶어요.’와 같은 문장이 생성된다. 사용자는 생성 결과를 확인하고 재생성을 요청한다.
- 동작 환경: 로컬 Ollama와 `qwen2.5:0.5b` 모델이 필요하다. 모델이 중지되거나 제한 시간을 초과하면 서버의 규칙 기반 문장 생성 모듈이 자동으로 동작한다.
- 입력: 순서가 있는 선택 카드 목록, 카드의 의미 및 문장 생성·재생성 명령을 입력한다.
- 출력: 문장 확인 영역에 생성 문장, 처리 중 상태, 재생성 버튼 및 음성 출력 버튼이 표시된다. 생성 실패 시 오류 안내와 재시도 버튼이 표시된다.

### 5. 문장 음성 출력 기능

- 기능: 시스템은 사용자가 확인한 문장을 TTS로 변환하여 음성으로 출력한다. 사용자는 음성을 재생하거나 중지한다.
- 동작 환경: 한국어를 지원하는 TTS 엔진과 PC·태블릿·스마트폰의 스피커 또는 외부 스피커가 필요하다. 시연 전 음량과 한국어 음성 지원 여부를 확인한다. 외부 TTS API를 사용하는 경우 인터넷 연결과 API 인증 정보가 필요하며 비용 발생 여부는 선정한 서비스에 따라 확정한다.
- 입력: 확인된 문장 텍스트와 재생·중지 명령을 입력한다.
- 출력: 기기 스피커에서 해당 문장의 음성이 출력되며 화면에는 문장 텍스트, 재생 상태 및 재생·중지 버튼이 표시된다.

### 6. 보호자·담당자용 이용 분석 기능

- 기능: 보호자 또는 교사는 연결된 사용자의 카드 사용 횟수, 자주 선택한 카드, 카테고리별 이용 빈도 및 자주 사용한 카드 조합을 확인한다. 선택한 사용자와 기간에 따라 분석 결과가 갱신된다.
- 동작 환경: 권한이 부여된 보호자·담당자 계정, 사용자 연결 정보, 누적 이용 기록, 데이터베이스 및 분석 API가 필요하다. 웹 브라우저가 있는 PC, 태블릿 또는 스마트폰에서 조회한다.
- 입력: 분석 대상 사용자와 조회 시작일·종료일을 입력한다.
- 출력: 대시보드에 사용자 선택 메뉴, 기간 선택 항목, 총 사용 횟수, 자주 사용한 카드 목록, 카테고리별 그래프 및 카드 조합 표가 표시된다. 기록이 없으면 데이터 없음 안내가 표시된다.

### 공통 화면 및 메뉴 구성

| 화면 | UI 구성 및 메뉴 |
|---|---|
| 사용자 진입 화면 | 계정 로그인 또는 사용자 프로필 선택, 카드 사용 화면 진입 |
| 카드 사용 화면 | 카테고리 메뉴, 카드 목록, 추천 카드 영역, 선택 카드 영역, 선택 편집 버튼, 문장 생성 버튼 |
| 문장 확인 영역 | 카드 사용 화면 내 생성 문장, 처리 상태, 재생성 버튼, 음성 재생·중지 버튼 |
| 보호자·담당자 대시보드 | 연결 사용자 선택, 조회 기간 선택, 사용 횟수 요약, 카드 순위, 카테고리 그래프, 카드 조합 표 |

AAC 사용자는 의사소통·학습 홈으로 이동하고, 보호자·담당자는 권한에 따라 연결된 아동의 지원 화면으로 이동한다. 화면 출력은 PC 모니터 또는 스마트폰·태블릿 디스플레이를 사용하고, 조작은 터치 또는 마우스·키보드를 사용한다. 별도 Character Display, 센서, 부저 및 LED는 본 시스템의 필수 장치에 포함하지 않는다.

### 공통 운영 및 시연 환경

- 웹 클라이언트와 백엔드 서버를 실행할 환경 및 카드·이용 기록을 저장할 데이터베이스를 준비한다. 현재 개발 환경은 React/Vite, FastAPI 및 Docker Compose를 사용하며 데이터베이스 제품은 별도 선정한다.
- 원격 서버 또는 외부 AI·TTS API에 접속하는 구성에서는 인터넷 연결이 필요하다. 경진대회 현장에서 네트워크가 제공되지 않는 경우 휴대전화 테더링이나 모바일 핫스폿과 충분한 데이터 용량을 준비한다.
- 노트북에서 서버를 실행하고 스마트폰·태블릿으로 시연하는 경우 두 기기를 같은 네트워크에 연결한다. 현재 로컬 실행 설정의 서버 주소, 포트 공개 범위 및 접근 허용 설정은 다중 기기 시연에 맞게 조정한다.
- 현장 인터넷 없이 시연하려면 카드 데이터, 데이터베이스, 문장 생성 및 한국어 TTS를 모두 로컬에서 실행할 수 있도록 별도 구성해야 한다. 현재 저장소만으로 오프라인 동작이 보장되지는 않는다.
- 시연용 사용자 프로필, 카드 이미지, 예시 이용 기록 및 스피커를 준비하고 카드 선택부터 문장 생성·음성 출력·대시보드 조회까지 사전 점검한다.

## 1. 문서 목적

본 문서는 PESC MATE의 개발, 검수 및 인수 기준이 되는 기능 요구사항을 정의한다. PESC MATE는 실물 PECS 카드가 늘어날수록 발생하는 휴대·분류·관리 부담을 줄이고, 발화장애 아동이 태블릿 한 대에서 익숙한 그림·사진·글자로 자신의 의사를 음성으로 전달하며 어휘와 의사소통을 학습할 수 있도록 지원하는 개인 맞춤형 디지털 AAC 플랫폼이다. 디지털 카드북, 카드 기반 발화, 개인별 학습, 보호자·담당자 지원 및 이용 분석을 하나의 웹 서비스로 제공한다.

본 문서에서 사용하는 요구사항 키워드는 다음과 같다.

- **필수(Must)**: 1차 출시 또는 과제 완료를 위해 반드시 구현해야 한다.
- **권장(Should)**: 사용자 경험과 운영 품질을 위해 구현을 권장한다.
- **향후(Could)**: 초기 범위에는 포함하지 않으며 후속 버전에서 검토한다.

## 2. 시스템 범위

### 2.1 포함 범위

- 사용자 계정 및 역할별 접근 관리
- AAC 그림·사진·글자 카드와 카테고리의 조회 및 관리
- 카드 검색, 탐색, 선택, 순서 변경 및 초기화
- 개인별 카드 이용 이력 저장
- 이용 이력 기반 맞춤 카드 추천
- 선택 카드 기반 자연어 문장 생성 및 편집
- 생성 문장의 TTS 음성 출력
- 카드와 단어의 의미 및 상황별 의사소통을 익히는 학습·연습 기능
- 보호자·담당자용 이용 분석 대시보드
- PC, 태블릿 및 스마트폰을 지원하는 반응형 웹 UI

### 2.2 제외 범위

- 의료적 진단이나 치료 효과 판정
- 응급 상황 자동 신고
- 오프라인 전용 네이티브 앱
- 외부 병원·학교 정보시스템과의 연동
- 초기 버전의 사용자가 직접 학습시키는 AI 모델

### 2.3 현재 구현 기준

현재 저장소에는 React/Vite 기반 웹 클라이언트, FastAPI 기반 API 서버, Docker Compose 실행 환경 및 `/api/health` 상태 확인 기능이 구현되어 있다. 본 문서의 나머지 기능은 목표 요구사항이며 구현 완료를 의미하지 않는다.

## 3. 사용자 및 권한

| 역할 | 설명 | 주요 권한 |
|---|---|---|
| AAC 사용자 | 그림·사진·글자로 의사를 구성하고 음성으로 전달하는 아동 | 카드 조회·선택, 추천 이용, 문장 생성·확인, 음성 출력 |
| 보호자 | 아동의 일상 의사소통과 가정 학습을 지원하는 계정 | 계정별로 부여된 범위에서 연결 아동의 카드판·빠른 표현·음성·접근 설정, 이용 이력 및 학습 성취 조회 |
| 담당자 | 교육·치료·돌봄 현장에서 아동을 지원하며 필요하면 서비스 운영도 맡는 계정 | 아동별로 부여된 카드·학습·기록 권한과 계정별로 부여된 공용 콘텐츠·시스템 운영 권한 |

권한은 최소 권한 원칙을 적용한다. 보호자와 담당자는 명시적으로 연결된 아동에게 계정별로 허용된 기능만 이용할 수 있어야 한다. 같은 역할이라도 `기록 조회`, `메모 작성`, `빠른 표현 관리`, `카드판 관리`, `음성·접근 설정`, `학습 관리` 권한은 서로 다를 수 있다. 공용 카드 승인과 카테고리 관리 같은 전체 운영 기능은 담당자의 아동별 연결 권한과 분리된 계정 권한으로 부여한다. 로그인 후 첫 화면과 메뉴는 계정의 역할과 권한에 따라 다르게 구성한다.

AAC 사용자 홈은 최종 메뉴를 한 번에 확정하지 않는다. 개발 단계에서는 완성된 기능부터 연결하고, 의사소통과 학습 기능이 안정화되면 `말하기`와 `연습하기`를 중심으로 선택지를 단계적으로 구성한다. 보호자와 담당자는 연결 아동 선택 후 자신에게 허용된 관리·조회 메뉴만 본다.

## 4. 주요 이용 흐름

1. 사용자가 로그인하거나 지정된 사용자 프로필을 선택한다.
2. 카테고리, 검색 또는 추천 영역에서 카드를 찾는다.
3. 카드를 선택하면 선택 영역에 선택 순서대로 추가된다.
4. 사용자는 카드의 순서를 변경하거나 일부/전체 선택을 취소한다.
5. 사용자가 문장 생성을 요청하면 시스템이 카드 의미와 순서를 반영한 문장을 제시한다.
6. 사용자가 문장을 확인하거나 허용된 범위에서 수정한다.
7. 사용자가 음성 출력 버튼을 누르면 시스템이 문장을 음성으로 재생한다.
8. 시스템은 카드 선택, 문장 생성 및 음성 출력 이력을 저장한다.
9. 보호자·담당자는 허용된 권한에 따라 연결된 아동의 이용 패턴과 학습 성취를 확인한다.

## 6. 외부 및 내부 인터페이스 요구사항

### 6.1 사용자 인터페이스

- 주요 조작은 이미지와 쉬운 한국어 레이블을 함께 제공한다.
- 카드 선택, 제거, 재생 등 사용 결과를 시각적으로 즉시 피드백한다.
- 핵심 의사소통 흐름은 스마트폰 세로 화면에서도 가로 스크롤 없이 사용할 수 있어야 한다.
- 색상만으로 상태를 구분하지 않고 텍스트, 아이콘 또는 형태를 함께 사용한다.
- 키보드 탐색, 대체 텍스트, 명확한 포커스 표시 등 웹 접근성을 고려한다.

### 6.2 API 공통 규칙

- API 기본 경로는 `/api`를 사용한다.
- 요청·응답 본문은 특별한 사유가 없는 한 JSON을 사용한다.
- 오류 응답은 오류 코드, 사용자에게 표시 가능한 메시지 및 추적 식별자를 포함한다.
- 목록 API는 페이지 정보, 전체 또는 다음 페이지 존재 여부를 제공한다.
- 인증이 필요한 API는 사용자와 역할을 검증하고 객체 단위 접근 권한도 확인한다.
- 카드 이미지와 TTS 오디오 파일은 MIME 형식과 크기를 검증한다.

### 6.3 AI 서비스 인터페이스

- 추천 입력: 사용자 식별자, 현재 선택 카드, 시간 정보 및 사용할 수 있는 카드 집합
- 추천 출력: 순위가 있는 카드 목록, 알고리즘 버전 및 선택적 추천 근거 코드
- 문장 생성 입력: 순서가 보존된 카드 ID와 의미, 언어 및 사용자 표현 설정
- 문장 생성 출력: 생성 문장, 모델/규칙 버전, 안전성 처리 결과 및 처리 상태
- AI 서비스에 불필요한 개인 식별 정보를 전달하지 않는다.

## 10. MVP 범위 및 단계별 출시

### 10.1 1단계 MVP

- 카드·카테고리 조회, 검색 및 이미지 오류 대체 표시
- 문장 보드의 선택, 제거, 순서 변경 및 초기화
- 사용자별 선택 이력 저장
- 빈도·최근성·연관 규칙 기반 추천과 콜드 스타트 기본 추천
- 선택 카드 기반 한국어 문장 생성 및 실패 시 대체 처리
- TTS 재생·중지와 실패 처리
- 기본 역할 및 연결 사용자 접근 통제
- 핵심 분석 지표와 기간별 대시보드
- 운영 권한 담당자용 헬스 체크 및 감사 로그

### 10.2 2단계 개선

- 개인 카드 등록과 고급 카드 관리
- 문장 편집 정책 및 사용자별 표현 설정
- 추천 알고리즘 고도화와 설명 정보
- 분석 데이터 파일 내보내기
- 음성 종류·속도 설정
- 오프라인 또는 설치형 웹 앱 지원 검토

## 13. 미확정 사항

다음 항목은 이해관계자 협의 후 값 또는 정책을 확정해야 한다.

- 로그인 방식과 미성년 사용자 본인 계정 제공 여부
- 보호자·담당자와 AAC 사용자의 연결·권한 승인 절차
- 사용자 전용 카드 등록 주체 및 검수 절차
- 카드 이미지의 허용 파일 형식, 최대 크기와 저장 위치
- 문장 최대 길이, 카드 최대 선택 개수 및 문장 직접 편집 허용 범위
- Ollama 모델의 실행 장비와 TTS 공급자 및 장애 시 대체 방식 (현재 구현: `qwen2.5:0.5b`, 규칙 기반 자동 대체, 브라우저 TTS)
- 이용 이력, AI 요청 로그, 음성 파일 및 감사 로그의 보존 기간
- 개인정보 처리의 출시 국가별 법률·동의 요건
- 지원 브라우저의 구체적인 최소 버전
- 목표 동시 사용자 수, 가용성, 백업 RPO 및 RTO

위 미확정 사항이 결정되면 관련 기능 요구사항, 비기능 수치 및 테스트 케이스를 갱신하고 문서 버전을 올린다.
