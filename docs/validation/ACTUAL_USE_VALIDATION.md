# 실제 사용 환경 검증 기록

## 상태

- 자동 사전 검증: 완료
- 실제 AAC 사용자·보호자·담당자 과업 검증: 참여자와 기기 준비 후 실행 필요
- 실제 태블릿·보조기기·스크린리더 검증: 대상 기기 준비 후 실행 필요

자동 검증 통과만으로 실제 사용성 항목을 완료 처리하지 않는다. 실제 참여자의
성공 여부, 도움 수준, 오터치, 피로와 발화 지연은 현장에서 관찰해야 한다.

## 실제 기기 연결

같은 신뢰된 Wi-Fi에 연결된 PC와 태블릿에서 다음 검수용 구성을 사용한다.

```powershell
docker compose -f compose.yaml -f compose.tablet.yaml up --build
```

태블릿 브라우저에서 `http://<PC의 사설 IPv4>:5173`에 접속한다. 프런트엔드가
같은 출처의 `/api` 요청을 내부 백엔드로 전달하므로 태블릿에서 별도 API 주소를
설정하지 않는다. 외부에는 5173 포트만 열리며 백엔드와 MongoDB 포트는 PC의
loopback 바인딩을 유지한다.

이 방식은 화면 회전, 터치, 기기 TTS와 온라인 역할 과업 검수용이다. LAN HTTP에서는
서비스 워커와 설치·완전 오프라인 동작을 검수하지 않는다. 해당 항목은 HTTPS 배포
주소에서 실행한다. 개발용 비밀번호가 있으므로 공용망에서 실행하지 않고 검수 직후
스택을 종료한다.

## AAC 사용자 현장 통과 기준

- 선호 설정에서 `도와주세요`를 도움 없이 두 번 이하의 조작으로 발화한다.
- 원하는 카드를 찾아 순서대로 문장을 만들고 원래 카드 순서를 확인한다.
- 문장을 확인한 뒤 재생하고 필요하면 일시 정지 또는 중지한다.
- 잘못 선택한 카드를 직접 이동·삭제하거나 전체 문장을 취소한다.
- 과업 중 언제든 긴급·복구 표현을 사용할 수 있다.

서로 다른 특성의 AAC 사용자 최소 2명에게 모든 과업을 실행하고 결과표가 채워진
뒤에만 TODO의 AAC 사용자 실제 과업 테스트를 완료 처리한다.

보호자 과업은 서로 다른 기기에서 연결 사용자를 선택한 뒤 네 과업을 모두 수행하고,
AAC 사용자 계정에서 개인 카드·카드 위치·빠른 표현·학습 설정이 동일하게 반영되는지
확인해야 완료 처리한다.

담당자 과업은 허용된 아동·기능의 성공과 비허용 접근의 실패를 함께 기록한다. 연결
회수 시험은 담당자 화면을 열어 둔 상태, 새로고침, 직접 API 요청, 오프라인 전환 후
재접속을 모두 실행한 뒤에만 완료 처리한다.

## 발견 문제 기록

심각도는 `차단`(핵심 의사소통·개인정보 위험), `높음`(핵심 과업 실패), `보통`
(우회 가능한 불편), `낮음`(표현·시각 개선) 중 하나를 사용한다.

| 문제 ID | 심각도 | 기기·과업 ID | 재현 절차 | 기대 결과 | 실제 결과 | 증빙 위치 | 담당·상태 | 수정 커밋 | 재검증 |
|---|---|---|---|---|---|---|---|---|---|
|  |  |  |  |  |  |  |  |  |  |

`차단` 문제와 개인정보 경계 문제는 해결·재검증 전까지 해당 기기를 지원 대상으로
승인하지 않는다. 현장 기록에는 실명, 발화 원문, 인증 토큰과 개인 이미지 원본을
첨부하지 않는다.
