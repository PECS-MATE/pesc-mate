# 접근성 브라우저 회귀 검증

## 범위

2026-10-18 Windows Chrome·로컬 개발 스택에서 수행한 자동 회귀 검증이다.
실제 사용자 사용성 평가, 스크린리더 낭독, 터치 장치 또는 WCAG 적합성 인증을
대체하지 않는다. 실제 참여자 평가는 [접근성 사용성 평가](ACCESSIBILITY_USABILITY_TEST.md)를 따른다.
이미지 제작·교체·정규화 후속 작업은 이번 범위에서 제외한다.

## 수정한 조작

- 의사소통·추천·카드 목록의 선택과 듣기를 중첩되지 않는 기본 `button`으로 분리했다.
  듣기는 카드 선택이나 상세 카드 변경 없이 실행한다. 두 버튼 사이 간격은 8 CSS px이며
  듣기 버튼도 최소 44×44 CSS px를 확보한다.
- 이동 후에는 이동한 카드의 같은 방향 버튼으로 포커스를 옮긴다. 맨 앞·뒤로 이동해
  해당 방향이 비활성화되면 같은 카드의 첫 활성 버튼으로 이동한다.
- 삭제 후에는 같은 위치의 다음 카드, 없으면 앞 카드의 삭제 버튼으로 이동한다.
  마지막 카드 삭제와 전체 비우기 후에는 문장 제목에 포커스를 두며,
  제목은 일반 Tab 순서에 추가하지 않는다.
- 같은 카드를 여러 번 선택하는 의도적인 표현과 저장 순서는 유지한다.
  카드 추가·데이터 로드 등에서 불필요하게 포커스를 옮기지 않는다.

## 자동 검증과 한계

| 항목 | 검증 내용 | 별도 수동 확인 |
|---|---|---|
| 키보드 경로 | 실제 Tab·Shift+Tab·Enter·Space로 로그인, 본문 바로가기, 출력 방식, 카드 선택·이동·삭제, 발화 요청 | 실제 키보드·스위치, 지원 브라우저별 가시성과 조작 피로 |
| 포커스 | 이동 경계·마지막 삭제·중복 카드에서 포커스 유지, 문장 제목의 외곽선·화면 내 위치 | 확대·가상 키보드·보조공학과 함께 사용하는 상황 |
| 듣기 버튼 | 기본 버튼 역할·이름, 44×44 CSS px와 선택 버튼과의 8px 간격, 선택과 분리된 Space 발화 | 터치 오조작과 반복 탭·길게 누르기 |
| 선택 상태 | 출력 방식과 카드 목록 선택의 `aria-pressed` 갱신 | 실제 스크린리더의 카드명·상태·목적 낭독, 색상 없이 상태 식별 |
| 좁은 화면·글자 확대 | 640×900 뷰포트와 루트 글자 크기 200%에서 문서 가로 넘침 없이 카드 선택·삭제 | 브라우저 자체 200% 확대에서 모든 내용·기능 보존 |

키보드 E2E의 음성은 모의 `speechSynthesis`로 발화 요청 문자열을 확인한다.
스피커로 실제 음성이 들리는지는 [기기 TTS 검수표](DEVICE_TTS_VALIDATION.md)의 별도 항목이다.
CSS 글자 확대나 작은 뷰포트를 브라우저 자체 확대의 통과 증거로 사용하지 않는다.
반복 카드 입력을 일괄 차단하지 않으며, 실제 장치의 반복 탭·길게 누르기 검수는 미실행이다.

근거는 W3C의 [키보드 조작](https://www.w3.org/WAI/WCAG22/Understanding/keyboard.html),
[글자 크기 변경](https://www.w3.org/WAI/WCAG22/Understanding/resize-text.html),
[이름·역할·값](https://www.w3.org/WAI/WCAG22/Understanding/name-role-value.html) 설명을 참고한다.
이 자동 검증만으로 해당 기준 전체를 충족했다고 판정하지 않는다.

## 재현과 기록

로컬 API·프런트엔드·MongoDB가 실행 중인 상태에서 `frontend/`에서 실행한다.

```powershell
npm test
npm run build
npm run test:e2e -- accessibility.spec.js --workers=1
npm run test:e2e -- --workers=1
```

E2E는 전용 신규 AAC 계정을 생성하고 종료 시 해당 계정의 콘텐츠를 삭제한다.
계정과 최소 삭제 영수증은 앱의 기존 정책에 따라 남을 수 있다.
일반 사용자의 카드·이미지·기록은 삭제하거나 변경하지 않는다.

이번 접근성 E2E 3개는 통과했다. 전체 회귀 결과는 아래 실행 기록을 따른다.
수동 검수는 미실행이며 실패·예외를 면제한 것은 아니다. 실제 기기, 브라우저·배율,
보조공학 이름·버전, 수행 과제, 결과, 관찰과 예외 사유를 기록한 뒤 TODO를 완료한다.

### 2026-10-18 실행 결과

- 프런트엔드 단위 91개·React 컴포넌트 27개, 총 118개 통과.
- 프로덕션 빌드 통과. 이미지 자산은 변경하지 않았다.
- 전체 브라우저 E2E 28개 통과(단일 워커, 다른 검증 작업과 동시 실행하지 않음).
- 최초 동시 검증에서는 기존 컴포넌트 2개가 5초 제한을 넘겼고, 카드판 E2E도
  API의 정상 200 응답이 약 6.3초 뒤 도착해 5초 화면 대기를 넘겼다.
  테스트 제한을 늘리거나 항목을 제외하지 않고 단위·컴포넌트 및 전체 브라우저 검사를
  각각 단독 재실행해 통과를 확인했다. 이를 실제 기기의 성능 보장으로 해석하지 않는다.
