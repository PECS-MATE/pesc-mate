# 아동 데이터 경계 자동 검증

## 검증 목적

화면에서 메뉴를 숨기는 것과 별개로, 인증 사용자가 다른 아동의 ID나 객체 ID를 직접
전송해도 서버가 데이터를 반환하지 않는지 확인한다. 자동 검증은
`backend/tests/test_data_boundaries.py`에서 실제 FastAPI 라우트를 호출한다.

## 자동 검증 범위

| 요청 주체 | 직접 요청 대상 | 기대 결과 |
|---|---|---|
| AAC 사용자 A | 사용자 B의 대시보드와 의사소통 기록 | 403 |
| AAC 사용자 A | 사용자 B의 음성·접근성 설정 | 403 |
| AAC 사용자 A | 사용자 B의 보드 구성과 변경 이력 | 403 |
| AAC 사용자 A | 사용자 B의 학습 설정·진행·감사 이력 | 403 |
| AAC 사용자 A | 사용자 B의 개인 카드 목록·이미지 | 403 |
| AAC 사용자 A | 사용자 B 기록에 대한 지원 메모 | 403 |
| AAC 사용자 A | 사용자 B의 프로필 이미지 | 403 |
| 운영 권한 담당자 | 연결되지 않은 아동의 기록·프로필·개인 카드 | 403 또는 존재 비공개 404 |

공용 콘텐츠를 승인하는 `content_manage` 권한은 아동별 연결 권한을 대신하지 않는다.
개인 카드 이미지는 운영 권한만으로 조회할 수 없고, 공용 전환을 요청한 카드만 승인
흐름에 나타나야 한다.

## 의사소통·학습 저장소/API 경계

의사소통은 실제 의도 전달 기록이고 학습은 문제 풀이 기록이다. 일반 저장·조회·
추천·통계에서 한쪽 결과를 다른 쪽 기록으로 취급하지 않는다.

| 기록 | 저장소 | 저장/조회 경로 | 경계 |
|---|---|---|---|
| 의사소통 | `communication_sessions` | `/api/sentences`, `/api/dashboard`, `/api/recommendations` | 학습 점수·정오답·문제별 결과를 넣거나 합산하지 않음 |
| 학습 | `learning_attempts` | `/api/learning/attempts`, `/api/learning/progress` | `record_type=learning_attempt`, 학습 시도만 학습 집계에 포함 |
| 오프라인 발화 | `offline_events` | `/api/offline/events/sync` | UUID로 중복 제거하며 문장이나 학습 결과로 자동 복제하지 않음 |

같은 UUID는 컬렉션별 독립 ID다. 서로 다른 도메인에서 같아도 충돌하지 않으며,
각 도메인 안에서 재전송하면 한 건만 남는다. 같은 도메인에서 다른 아동이 소유한
UUID를 쓰면 409이고, 다른 아동의 조회 ID를 지정하면 403이다.

공통 개인정보 기능은 의도된 예외다. 본인 내보내기는 `communication_sessions`와
`learning_attempts`를 별도 키로 반환하며 본인 삭제는 두 저장소 모두에 적용한다.
이는 통계·추천에서 합산하는 것과 다르다. 다른 아동의 기록은 내보내거나 삭제하지 않는다.

### 권한·객체 경계

- `records_read`만 있는 보호자·담당자는 의사소통 대시보드를 읽지만 학습 설정·성취·감사 이력은 읽지 못한다.
- `learning_manage`만 있는 보호자·담당자는 학습 정보를 읽지만 의사소통 대시보드는 읽지 못한다. 두 지원 역할 모두 아동 대신 문장/학습 결과를 생성하지 못한다.
- 비활성 연결과 연결 없는 `content_manage` 운영 권한은 어느 아동 도메인도 열지 않는다.
- 학습 시도 ID를 문장 재생성이나 의사소통 메모 저장/삭제에 넣어도 404이고, 같은 요청으로 학습 결과를 수정하지 않는다.
- 요청 본문을 다른 도메인 API에 보내면 필수 필드/활동 유형 검사에서 422다. 현재 DTO는 추가 필드를 무시하므로 추가 `user_id`·`record_type`·`score`로 소유자·도메인·서버 계산 점수를 바꿀 수 없는지도 확인한다. 알 수 없는 모든 필드를 거절하는 정책을 도입한 것은 아니다.

### 자동 시험

`backend/tests/test_learning_communication_boundaries.py`의 6개 단위 시험은 허용한
컬렉션만 제공하는 가드 DB를 사용한다. 다른 컬렉션에 **접근하는 순간** 실패하므로
컬렉션 객체 자체의 호출 여부만 검사하는 Mock보다 읽기·쓰기 혼입을 직접 탐지한다.
학습 설정/결과/감사, 의사소통 저장/통계/재생성, 오프라인 발화, 메모 대상 확인을 포함한다.

`backend/integration_tests/test_learning_communication_boundaries.py`의 11개 시험은
실제 MongoDB와 FastAPI 라우트·검증기·응답 모델·Bearer 인증을 사용한다. 합성 계정과
세션만 준비하며 인증/연결 권한 함수를 허용 Mock으로 바꾸지 않는다. 앱의 데모 seed·
시작 인덱스 worker를 실행하지 않는 별도 FastAPI 인스턴스에 실제 라우트를 연결한다.

확인 항목은 다음과 같다.

- 학습 저장 전후 의사소통 통계·추천 전체 응답 불변과 반대 방향 학습 응답 불변
- 동일 UUID의 세 저장소 독립성, 오프라인 학습 재전송과 도메인별 동기화 지표 구분
- 다른 아동의 ID/UUID, 두 지원 역할의 권한 조합, 비활성 연결·운영 권한 우회 차단
- DTO 교차 전달, 소유자/점수/도메인 추가 필드, 문장 재생성·메모 객체 ID 교차 전달
- 동의 미확인 시 두 저장과 발화 동기화 모두 차단
- `created_at`/`completed_at` 기간 필터와 학습 `record_type` 필터
- 학습 저장소 호출 실패 시 문장 저장·대시보드 유지. MongoDB 전체 장애를 견딘다는 뜻은 아님
- 본인 내보내기의 별도 키와 삭제 후 다른 아동의 원본 문서 보존

### 실행과 데이터 안전성

backend 의존성과 테스트용 MongoDB 연결을 준비한 뒤 backend 디렉터리에서 실행한다.

```powershell
python -m unittest discover -s tests -t . -p "test_*.py"
python -m unittest discover -s integration_tests -p "test_*.py" -v
```

단위 시험은 DB 없이 실행한다. 두 번째 명령은 기존 마이그레이션 시험도 포함하며
2026-10-20 원격 CI 제거 후에는 로컬 `npm run verify:full`이 브라우저 시험 전에
동일하게 실행한다. 호스트 백업·복구 통합 시험은 별도이며 이 명령에 포함하지 않는다.

도메인 통합 시험은 매번 `pesc_mate_boundary_test_<UUID>` DB만 만들고 공유 DB 연결을
그곳으로 제한한다. 원래 설정 DB와 다른지, 이름 전체와 UUID 패턴이 맞는지 확인한 뒤
정확히 그 DB만 정리한다. 환경 변수·연결 패치는 각 시험 후 복원한다. 운영 DB를
대상으로 삼거나 볼륨을 삭제하지 않는다.

2026-10-18 로컬 컨테이너에서 전체 단위 테스트 **258개**, 실제 MongoDB 통합 테스트
**16개**(도메인 경계 11개·마이그레이션 5개)를 통과했다. 테스트용 합성 DB만 정리했고
실제 사용자 DB는 변경하지 않았다. 프런트엔드 코드·브라우저 E2E·빌드는 변경/재실행하지
않았고 원격 CI는 실행 결과가 아니라 실행 단계 설정만 추가했다.

## 남은 실제 검증

- 실제 브라우저의 역할별 로그인과 메뉴 우회
- 두 기기에서 연결 회수 직후 열려 있던 화면·직접 URL·재접속 확인
- 프록시나 브라우저 캐시에 민감 응답이 남지 않는지 확인
- 실제 사용 환경의 사용자 A/B 자료로 내보내기·삭제까지 교차 확인(위 합성 DB/API 시험과 구분)
