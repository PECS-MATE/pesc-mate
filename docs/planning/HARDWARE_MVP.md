# 실물 카드 입력 기반 의사소통 MVP

> 후속 USB 우선 요청: 현재 구현·연결 방법·로그·실물 검수는 [USB 연동 안내](../development/RFID_USB_INTEGRATION.md)를 따른다.
> 아래 최초 계획의 체크를 새 USB 펌웨어/실물 성공으로 일괄 변경하지 않는다.

> 2026-10-27 변경: 아래는 최초 단일 리더기 USB 계획의 이력이다. 현재 요구사항은 **RC522 3개 +
> UNO R4 WiFi → HTTP(S) API → 위치별 상태 표시**이며
> [Wi-Fi 연동 구현·설치·실물 검수](../development/RFID_WIFI_INTEGRATION.md)를 우선한다.
> 기존 체크 상태를 Wi-Fi·3개 리더기 검증 완료로 읽지 않는다.

> 계획 확정일: 2026-10-26
> 사용자 확인: Arduino UNO R4 WiFi, Windows PC의 Chrome/Edge에서 먼저 완성.
> RC522는 사용자 추가 스케치에서 확인한 대상이며 실제 배선·동작 검수는 미완료.

## 1. 이번에 완성할 것

실물 그림 카드의 RFID 태그를 하나씩 읽으면 웹의 **선택 문장**에 대응하는 카드가 쌓이고,
사용자가 내용을 확인해 문장을 만들고 PC 스피커로 말할 수 있는 로컬 시연을 완성한다.
리더기가 그림을 인식하는 것이 아니라 **태그 UID와 앱 카드 ID의 연결**로 동작한다.

```text
실물 그림 카드 + RFID 태그
  → RC522 → UNO R4 WiFi → USB 시리얼
  → PC 웹 앱 → 현재 아동의 UID 매핑 → 기존 선택 문장
  → 문장 생성·확인 → 기존 기기 TTS → PC 스피커
```

기본 입력 예시는 ‘나 → 물 → 마시다’다. 한 리더기에 카드를 한 장씩 대며,
놓여 있는 여러 카드의 공간 순서를 한 번에 읽는 카드판은 만들지 않는다.
고정 카드판의 슬롯을 바꾸지 않고 현재 선택한 문장에만 추가한다.

첫 발화 트리거는 **기존 화면 버튼**이다. 마지막 스캔을 추측하거나 일정 시간이 지나면
자동으로 발화하지 않는다. 전용 ‘말하기/한 장 취소/비우기’ 태그는 기본 흐름 완성 후 선택 확장이다.
조합은 현재 한도인 12장까지 유지하며, 초과 시 기존 선택을 보존하고 안내한다.

## 2. 실행 구조와 제외 범위

- 웹은 같은 PC의 `http://127.0.0.1:5173`에서 연다. 시리얼은 Web Serial로 브라우저가 직접
  읽고 Docker의 백엔드가 COM 포트를 열지 않는다. 별도 Python 중계 서버는 이번 범위에서 제외한다.
- Web Serial은 사용자가 버튼으로 포트를 선택해야 하며, 지원 브라우저·안전한 출처를 실행 시
  확인한다. localhost/loopback은 안전한 출처로 취급되지만 일반 LAN HTTP를 같은 조건으로
  가정하지 않는다. [Chrome 안내](https://developer.chrome.com/docs/capabilities/serial),
  [MDN Web Serial](https://developer.mozilla.org/en-US/docs/Web/API/Web_Serial_API),
  [안전한 출처](https://developer.mozilla.org/en-US/docs/Web/Security/Defenses/Secure_Contexts).
- 사용자 확인 환경은 Windows Chrome/Edge지만 실제 지원 판정은 `navigator.serial`·권한·
  포트 열기로 확인한다. 브라우저 이름만으로 실제 기기 동작을 완료 표시하지 않는다.
- Arduino는 카드 읽기와 이벤트 전송만 한다. 문장 생성·음성 출력·로그인은 웹/기존 서버가 담당한다.
- R4의 Wi-Fi/Bluetooth, 태블릿/휴대폰 중계, Arduino 자체 스피커, 카드 데이터 쓰기,
  카메라/OCR, 추가 학습 게임, 클라우드 배포와 유료 TTS는 제외한다.
- Ollama는 필수 경로가 아니다. MVP 검수에서는 기존 `OLLAMA_ENABLED=false` 설정으로 규칙
  경로부터 확인한다. 자연스러운 문장을 임의로 자동 확정하거나 기존 의미 보존 정책을 완화하지 않는다.
- 동의 전·네트워크 실패 때는 기존 **선택 카드 그대로 말하기**로 대체한다. 자연스러운 문장 생성과
  기록 저장을 위해 기존 서버의 동의 검사를 우회하거나 별도 기록 API를 만들지 않는다.
- 새 태그 매핑은 우선 서버에 저장하고 현재 로그인 세션의 메모리에서 사용한다. 서버 연결이
  끊겨도 이미 읽은 매핑과 카드가 있으면 사용할 수 있지만, 오프라인 새 로그인·매핑 미준비 상태의
  실물 입력까지 보장하지 않는다. 이 경우 화면 카드 선택·기본 발화를 유지한다. 새로운 UID 영구
  캐시·원시 스캔 대기열은 이번에 추가하지 않는다.

## 3. 현재 기반과 첫 착수 조건

- [x] 보드·우선 시연 환경 확인: UNO R4 WiFi + Windows Chrome/Edge.
- [x] 기존 선택 문장, 최대 12장, 취소/순서 수정, 문장 생성·확인, 기기 TTS 구현 확인.
- [x] 사용자 작업 트리의 `hardware/arduino/card-reader-test/card_reader_test.ino` 확인:
  `SPI.h`, `MFRC522.h`, SS 10/RST 9, `Serial.begin(115200)`, UID와 3초 상태 출력.
- [ ] 실제 RC522 모듈·태그 종류, 전원/배선, R4 보드 코어·라이브러리 버전 확인.
- [ ] UNO R4 WiFi 대상 컴파일·업로드·UID 읽기 확인. 스케치 존재를 동작 성공으로 취급하지 않는다.

**전기적 연결을 먼저 확인한다.** [UNO R4 WiFi](https://docs.arduino.cc/hardware/uno-r4-wifi/)의
GPIO는 5V이며 [MFRC522 데이터시트](https://www.nxp.com/docs/en/data-sheet/MFRC522.pdf)는
저전압 전원/입출력 조건을 정한다. 모듈의 실제 회로·전압 사양과 SPI 신호의 레벨 변환 필요 여부를
확인하기 전 5V 직결을 가정한 배선이나 업로드를 안내하지 않는다. 핀 번호는 현재 코드 설정일 뿐
실제 배선 확인을 대신하지 않는다. MFRC522 라이브러리의 R4 호환성도 대상 컴파일로 확인한다.

현재 폴더명 `card-reader-test`와 파일명 `card_reader_test.ino`는 서로 다르다.
[Arduino 스케치 규칙](https://docs.arduino.cc/arduino-cli/sketch-specification/)에 맞춰 주 스케치와
폴더 이름을 일치시키는 작업을 MVP-01에 포함한다. 계획 단계에서는 사용자 파일을 이동·수정하지 않는다.

## 4. 기능별 TODO와 구현 순서

### MVP-01 — 카드 읽기와 안정된 이벤트 출력

- [ ] 배선·전압과 R4 호환성 확인 후 스케치 이름을 정리한다.
- [ ] 기존 진단용 문구와 UID 출력에서 웹이 읽을 버전 있는 JSON Lines 이벤트로 정리한다.
- [ ] 초기 준비/연결 오류와 카드 감지를 별도 이벤트로 구분한다. 상태 문구를 카드로 해석하지 않는다.
- [ ] 하나의 물리적 제시마다 한 번 처리하고, 같은 카드를 제거한 뒤 다시 대면 의도된 반복을 허용한다.
  무조건 500ms만 기다리거나 같은 UID를 영구 무시하는 방식으로 완료하지 않는다.
- [ ] 부팅/연결 세션과 증가하는 이벤트 번호를 정의해 재전송과 새 제시를 구분한다.
- [ ] 실제 태그 3장과 같은 태그 유지·제거·재제시·다른 태그 전환 결과를 기록한다.

완료 조건: R4에서 서로 다른 카드의 UID를 읽고 한 제시/한 이벤트와 의도된 재제시를 구분한다.
카드별 실제 UID나 아동 정보는 예제/로그로 Git에 넣지 않는다.

### MVP-02 — 웹에서 리더기 연결·수신

- [ ] 사용자가 ‘리더기 연결’로 포트를 선택하고 준비/연결/해제/오류 상태를 확인한다.
- [ ] 115200bps를 현재 스케치와 맞추되 진단 도구의 포트 점유·취소·열기 실패를 안내한다.
- [ ] 분할 수신·한 번에 여러 줄·CRLF·잘못된 JSON·과도한 길이·알 수 없는 버전을 처리한다.
- [ ] 중복 이벤트 번호와 과거 세션 이벤트는 버리고, 새 세션의 번호 초기화는 정상 처리한다.
- [ ] 연결 직후 준비 핸드셰이크로 제시 상태를 다시 맞춘다. 이미 놓인 카드의 유령 입력을 막는다.
- [ ] 한 페이지에서 한 수신 루프만 유지하고 해제·페이지 이탈·로그아웃 때 reader/port를 정리한다.
- [ ] 다른 탭/앱의 포트 점유를 조용히 재시도하지 않고 안내한다. 권한 취소도 기본 말하기를 막지 않는다.

완료 조건: 사용자가 선택한 리더기의 유효한 이벤트만 받으며 끊김·재연결에 카드가 임의 추가되지 않는다.
이 단계만으로 수신한 UID를 문장에 넣거나 자동 발화하지 않는다.

### MVP-03 — 실물 태그 등록과 문장 카드 입력

- [ ] 보호자/담당자가 `cards_manage` 연결 권한으로 대상 아동을 고르고 태그를 스캔해 앱 카드에 연결한다.
- [ ] UID는 이름/파일명이 아니라 기존 `card_id`에 연결한다. 펌웨어에 카드 뜻·아동별 매핑을 하드코딩하지 않는다.
- [ ] 한 아동 안에서 한 UID는 한 카드에만 연결하고 중복 변경은 명시 확인한다. 여러 태그가 같은 카드를
  가리키는 것은 허용한다. 생성·교체·삭제와 충돌 처리, 변경자·시각 감사를 같은 기능으로 구현한다.
- [ ] 매핑 조회·쓰기에서 현재 역할·아동 연결·카드 사용 가능 상태를 재검사한다. UID로 로그인하거나
  다른 아동의 매핑을 찾지 않는다. 등록 화면의 스캔이 아동의 문장에 들어가지 않도록 모드를 분리한다.
- [ ] 아동의 ‘그림으로 말하기’에서 입력을 직접 활성화한 때만 현재 계정의 등록된 카드를 순서대로 담는다.
- [ ] 미등록·삭제/비활성 카드와 최대 12장 초과는 안내만 하고 기존 문장·고정 위치는 유지한다.
- [ ] 보이지 않는 탭·다른 화면·계정 전환·로그아웃·권한 만료 때 입력을 비활성화하고 남은 이벤트를 버린다.
- [ ] 매핑은 개인정보 범위에 포함해 내보내기·삭제·캐시 정리·보존 정책을 정의한다. 원시 UID를
  일반 접속/CRUD 로그에 추가하지 않고 등록에 필요한 표시만 제한적으로 제공한다.
- [ ] 동의가 없으면 기존 매핑을 현재 로그인에서 조회·사용할 수 있는 범위와 신규 등록/서버 저장 거절을
  분리한다. 기록 없는 스캔 선택을 유지하고 미등록 태그를 몰래 저장하지 않는다.

완료 조건: 같은 PC에서 등록한 실물 카드 3장을 순서대로 대면 해당 아동의 선택 문장에 정확히 담긴다.
UID는 인증 비밀이 아니다. [MFRC522 라이브러리 안내](https://github.com/miguelbalboa/rfid)의
UID 복제 주의에 따라 계정/권한 확인 수단으로 사용하지 않는다.

### MVP-04 — 선택 문장 생성·확인·TTS 완주

- [ ] RFID 입력도 기존 선택 문장 갱신 경로를 사용해 카드 수정·생성 결과 무효화·취소 동작을 통일한다.
- [ ] 문장 생성 중 스캔을 임시 정지하고, 선택이 바뀐 경우 늦은 이전 생성 응답을 적용하지 않는다.
- [ ] 동의·서버 연결이 있을 때 기존 규칙 기반 문장 생성과 내용 확인 후 기기 TTS를 연결한다.
- [ ] 동의 전·생성/서버 실패 시 카드와 텍스트를 보존하고 선택 카드 그대로 발화할 수 있다.
- [ ] 문장 끝은 화면 버튼으로 결정한다. 자동 발화/자동 비우기 없이 완료 뒤 다음 입력을 사용자가 선택한다.
- [ ] 음량 0·한국어 음성 없음·재생 실패에 안내/재시도를 제공하고 긴급·복구 표현을 계속 사용할 수 있다.
- [ ] 실제 의사소통만 기존 동의/저장 정책으로 남긴다. 등록 스캔·상태 조회·학습 결과는 발화 기록과 합치지 않는다.
- [ ] 지원 기기의 Chrome과 Edge에서 직접 재생·중지·재연결까지 검수한다. 스텁 결과를 실제 음성으로 취급하지 않는다.

완료 조건: 실물 입력 → 문장 확인 → 실제 PC 음성 출력이 이어지고, 장애 때도 기본 말하기가 남는다.
Arduino 자체 스피커·Wi-Fi 전송을 구현한 것으로 취급하지 않는다.

## 5. MVP 완료 게이트

- [ ] R4 + RC522 실제 배선·전압·라이브러리·태그 호환성과 컴파일/업로드 증빙.
- [ ] ‘나/물/마시다’, ‘밥/먹다’, ‘화장실/가다’의 실물 입력·화면 확인·기기 음성 출력 시연.
- [ ] 같은 카드 유지 시 중복 없음, 제거 후 재제시와 명시된 반복 카드 처리 확인.
- [ ] 미등록 태그·권한 없는 매핑·다른 아동 ID 요청·카드 삭제·로그아웃 경계 확인.
- [ ] USB 끊김·다시 연결·포트 점유·화면 전환 후 유령 입력 없이 재개.
- [ ] 생성/네트워크/TTS 장애와 동의 없는 사용에서 기존 선택·기본 발화 유지.
- [ ] 파서·매핑 API·입력/TTS 회귀 자동 검사와 실제 하드웨어 결과를 별도 기록.
- [ ] 설치/연결/태그 등록/시연/문제 해결 안내와 발견된 문제 처리.

모든 항목을 확인하면 **Windows PC 실물 카드 의사소통 MVP 완료**로 표시한다.
기존 A0의 실제 AAC 사용자 평가와 A2의 법적/운영 배포 승인을 완료 처리하지 않는다.
새 게임·AI 고도화보다 위 네 기능과 완료 게이트를 먼저 진행한다.

## 6. 커밋과 현재 작업 기록

- MVP-01~04는 **각 기능이 완성될 때 한 커밋**으로 코드·관련 수정·검증·문서를 함께 묶는다.
  파서 파일·버튼·스타일·문서 단위의 중간 커밋은 기본으로 만들지 않는다.
- 검증 생략/실패는 그대로 남기며 커밋을 통과로 표시하지 않는다. 실제 기기가 없으면 자동 검증만으로
  해당 기기 완료 게이트를 닫지 않는다. 원격 푸시와 기존 커밋 재작성은 별도 요청이 있을 때만 한다.
- 이번 요청은 MVP 계획/TODO 정리 작업이다. 앱·펌웨어 구현, 사용자 추가 스케치 편집/이동과
  기존 DB·태그 매핑·사진 변경은 하지 않는다. 확인한 사용자 스케치는 미커밋 상태로 보존한다.
- 현재 코드 경로·사용자 답변·공식 기술 문서를 대조했다. 앱 테스트/빌드·Arduino 컴파일/업로드·
  실제 연결·RC522 전압 측정·브라우저 실물 수신·음성 검수는 이 계획 작업에서 **미실행**이다.
- 문서 7개의 로컬 링크 91개·코드 펜스 짝과 `git diff --check`를 확인해 통과했다.
  이 문서의 미체크 항목은 구현/기기 검증 성공으로 표시하지 않는다.
  기존 A/B 트랙과 사용자 미커밋 스케치를 보존한다.
