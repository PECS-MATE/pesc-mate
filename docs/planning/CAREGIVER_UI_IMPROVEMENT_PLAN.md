# 보호자 UI 가독성과 작업 흐름 개선 개발 계획

작성일: 2026-11-01
상태: 1~4단계 구현·빌드·대표 브라우저 확인 완료, 실기기·보호자 검수 남음

## 목표와 범위

보호자가 아이를 선택하고 카드·연습·기록을 관리할 때 읽고 판단해야 하는 부담을 줄인다.
기존 MVP 이후 개선이며 기능 추가보다 시각적 위계와 다음 행동 안내를 우선한다.
앞선 평가는 코드·스타일·문서 기반 가설이다. 구현 전 실제 화면에서 재확인한다.

대상은 보호자 홈, 개인 카드, 연습 관리, 기록, 아이 설정, 보호자 자신의 설정,
RFID 관리다. `.app.caregiver-ui` 범위와 명시적인 보호자 variant를 사용한다.
아동·담당자·랜딩 화면, 서버 권한·동의, 카드 위치, 발화·학습 엔진은 유지한다.
새 AI 모델·통계·인증 수단·아이 연결 API 개발은 이번 범위에 포함하지 않는다.

참고: [기존 보호자 UI 구현 기록](../development/USER_INTERFACE.md#caregiver-ui-reference),
[MVP 이후 요청서](POST_MVP_DEVELOPMENT.md).
기존 PDF 기반 스타일 중 이번 계획과 충돌하는 큰 패널·균등 카드 배치는 재조정한다.
과거 구현·검증 이력을 덮어쓰지 않고 후속 결과를 별도로 기록한다.

## 1. 시각적 설계 기준

아래 수치는 구현 출발점이며 실제 화면에서 줄바꿈·밀도·접근성을 확인해 조정한다.

| 항목 | 개발 기준 | 완료 확인 |
|---|---|---|
| 글자 | 본문·입력 16px, 보조 설명 14px, 화면 제목 24~28px, 영역 제목 20px | 중요한 안내를 작은 글자로 밀어내지 않음 |
| 행간 | 본문 1.5~1.7, 제목 1.3~1.4 | 긴 이름·오류·안내가 잘리지 않음 |
| 여백 | 8/16/24/32px 중심으로 통일 | 영역 구분을 중첩 카드 대신 여백과 제목으로 표현 |
| 표면 | 페이지 배경 + 주 콘텐츠 표면 중심, 안쪽은 선·목록 사용 | 장식 목적의 색 패널 안에 카드가 반복되지 않음 |
| 모서리·그림자 | 카드 12~16px, 버튼 8~12px, 그림자는 부유 요소에 제한 | 모든 영역이 동일하게 튀어나와 보이지 않음 |
| 색 | 기존 팔레트를 유지하고 배경·선택·행동·상태 역할을 구분 | 색 외에도 텍스트·아이콘·테두리로 상태 식별 |
| 버튼 | 작업 영역별 주 행동 1개, 보조는 테두리, 이동은 텍스트 중심 | 저장·이동·삭제가 동일한 강조로 경쟁하지 않음 |
| 조작 | 주요 터치 대상 최소 44×44px를 제품 목표로 적용 | 글자를 키워도 버튼 겹침·잘림 없음 |

권한·구현 방식 설명은 보조 안내로 옮기되 기록 범위·실패·삭제 영향 같은 필수 정보는
숨기지 않는다. 데이터 표는 14px 이상을 출발점으로 하고 긴 값·모바일은 상세 보기로 보완한다.
새 색상·폰트·아이콘 패키지 도입보다 기존 토큰과 UiIcon을 우선한다.

## 2. 화면별 변경

### 보호자 홈

배치: 아이 선택 → 현재 상태 → 자주 쓰는 작업 → 이번에 해볼 연습 → 기타 관리.

- 선택한 아이 이름을 상단에 유지한다. 보호자 자신의 이름과 구분한다.
- 동일 크기 작업 카드 4~6개 대신 개인 카드·연습 관리·기록 보기의 핵심 동선을
  먼저 배치하고 음성·화면·카드판·RFID 등은 보조 목록으로 정리한다.
- 권한이 없는 기능은 접근 조건을 유지한다. 메뉴 수에 따라 빈 칸이 남지 않게 한다.
- 최근 기록과 준비한 연습은 기존 API가 허용하는 데이터만 표시한다.
  홈에 없는 데이터가 필요하면 우선 링크로 제공하고 신규 집계 API는 별도 제안한다.
- 기록 없음·조회 실패·동의 없음·권한 부족을 구분한다. 없음을 0점/미사용으로 표시하지 않는다.
- 클릭되지 않는 지원 메모 안내 카드는 기록 보기의 보조 설명으로 옮긴다.
- 모바일에서는 큰 작업 카드를 반복하지 않고 제목·설명·이동 표시가 있는 목록을 사용한다.

### 첫 사용과 연결 안내

- ‘연결된 사용자가 없습니다’ 다음에 현재 지원하는 연결 방법과 이동 경로를 설명한다.
- 보호자 계정에서 직접 연결할 API가 없으면 없는 버튼을 만들지 않는다.
  아이 계정에서 연결하는 기존 절차와 준비할 정보를 안내한다.
- 보호자 화면의 ‘지원할 사용자’는 ‘아이 선택’, ‘연결 사용자’는 문맥에 맞게
  ‘연결된 아이’로 바꾼다. 담당자 화면의 용어는 유지한다.

### 개인 카드 관리

- 제목·아이 이름·주 등록 버튼을 상단에 묶고 검색·분류를 다음 줄에 배치한다.
- 개별 등록은 주 행동, 일괄 등록·A4 편집/인쇄는 보조 도구로 구분한다.
- 카드 상태를 사용 중·작성 중·승인 대기 등 명확한 텍스트로 표시한다.
- 등록 완료 후 등록한 카드 보기와 기존 카드판 관리 이동을 제공한다.
  카드판에 자동 배치하거나 기존 위치를 변경하지 않는다.
- 긴 이름·이미지 없음·업로드 중·부분 실패에 같은 레이아웃 원칙을 적용한다.

### 연습 관리와 AI 제안

- 메뉴 ‘학습 기록’은 실제 기능에 맞게 ‘연습 관리’로 바꾸고 설정과 기록을 구분한다.
- 추천은 활동 이름 → 사용 카드/문제 수 → 짧은 근거 → 검토 버튼 순서로 보여준다.
- 표본·기간·모델/규칙 출처는 상세에서 확인하게 하고 개인화 상태는 명확히 표시한다.
- 준비 완료에는 대상 아이와 아이 계정에서 시작하는 위치를 안내한다.
- 보호자 의견은 연습 후 남길 수 있게 위치와 문구를 정리한다. 완료 여부와 별개라는
  기존 의미를 유지하고, 세션 완료와 연결되지 않았는데 ‘사용 후’로 단정하지 않는다.
- 최근 의견의 내부 candidate_id는 활동 이름·날짜로 대체한다.
  기존 응답만으로 이름을 복원할 수 없으면 중립적인 표시를 사용하고 API 확장은 별도 기록한다.

### 의사소통·학습 기록

- 아이·기간·기록 종류를 상단에 묶고 요약 → 추이/카드 → 상세 기록 순서로 배치한다.
- 집계 기준은 짧은 핵심 설명을 먼저, 해석 한계·상세 정의는 펼침으로 제공한다.
- CSV/JSON 내보내기는 보조 조작으로 구분한다. 실제 형식과 권한을 유지한다.
- 차트 색에만 의존하지 않고 항목명·값을 함께 제공한다.

### 설정과 RFID

- ‘내 계정 설정’과 ‘아이 설정’을 제목과 대상 이름으로 명확히 구분한다.
- 설정은 기능별 구획·설명·저장 버튼을 붙여 저장 범위를 분명히 한다.
- 현재 유지되는 폼을 메뉴 이동 때문에 재마운트하지 않는다.
- 저장 결과에 대상·성공/실패를 표시하고 미저장 입력의 이동 동작을 점검한다.
- RFID는 연결 상태·연결 조작·최근 읽은 카드가 먼저 보이게 한다.
  포트·UID·진단 로그는 상세 영역으로 묶되 오류와 재시도는 노출한다.
- 장식 패널을 줄이는 변경으로 USB 연결이 끊기거나 읽기 목록이 초기화되지 않아야 한다.

## 3. 구현 순서와 커밋 단위

| 단계 | 작업 | 우선 확인 파일 | 완료 기준 |
|---|---|---|---|
| 1 | 현재 화면 캡처와 공통 글자·버튼·표면 개선 | assets/caregiverUx.css, UiIcon.jsx | 홈·설정·카드에서 읽기 위계와 보호자 스타일 격리 확인 |
| 2 | 홈·아이 선택·빈 상태·보호자 용어 정리 | App.jsx | 신규/기존/복수 아이·권한별 진입 경로 확인 |
| 3 | 카드와 연습 관리의 다음 행동 정리 | App.jsx, PracticeSuggestionsPanel.jsx | 등록→확인, 제안→준비→시작 안내와 의견 표시 확인 |
| 4 | 기록·설정·RFID 정보 밀도 정리 | MyPage.jsx, SupportRecordTabs.jsx, RfidBoard.jsx | 필터·저장·로그·내보내기 접근과 대상 표시 확인 |

경로는 `frontend/src/` 기준이다. 공통 컴포넌트 수정은 보호자 variant로 제한한다.
App.jsx 분리는 필요한 화면 단위로만 수행하고 전체 구조 개편으로 범위를 넓히지 않는다.
각 단계는 관련 검증·문서를 함께 마친 후 한 커밋으로 묶는다. 중간 파일별 커밋은 만들지 않는다.

## 4. 검증 계획

- 화면 폭 1440/1024/768/390px에서 대표 화면을 캡처하고 전후 비교한다.
- 200% 확대, 긴 이름, 카드/기록 다수, 메뉴 접기, 모바일 세로 배치를 확인한다.
  표처럼 필요한 영역을 제외하고 페이지 전체 가로 넘침이 없어야 한다.
- 키보드 이동·초점 표시·설정 영역 이동·버튼 이름·고대비·동작 줄이기를 확인한다.
- 일반 글자 대비 4.5:1, 큰 글자·주요 비문자 경계 3:1을 내부 검수 목표로 삼아
  기본/선택/오류/초점 상태를 측정한다. 이 검사만으로 접근성 인증을 주장하지 않는다.
- 연결 없음·아이 1명/여러 명·권한 일부·로딩·조회 실패·동의 없음 상태를 확인한다.
- 아이 전환 시 이전 데이터·알림·늦은 응답이 새 아이에게 표시되지 않는지 확인한다.
- 카드 등록/수정/인쇄, 추천 검토/준비/의견, 기간 필터/내보내기,
  설정 저장, USB 연결/로그 기능을 변경 범위에 맞춰 수동 검증한다.
- 프런트엔드 빌드를 실행한다. 제거된 대규모 테스트 도구는 자동 복원하지 않는다.
- 아동·담당자·랜딩 화면의 대표 화면을 확인해 스타일 회귀를 점검한다.
- 실제 보호자에게 카드 등록·최근 기록 찾기·연습 준비 과업을 제시하고
  도움 요청·잘못된 진입·완료 여부를 기록한다. 미수행 시 사용자 검증은 미완료다.

실제 USB·음성·보호자 과업을 대체 데이터 검사와 구분한다.
사용자가 검증을 제한하면 해당 지시를 우선하고 실패·중단·미실행을 명시한다.

## 5. 개발 요청 프롬프트

```text
docs/planning/CAREGIVER_UI_IMPROVEMENT_PLAN.md에 따라 보호자 UI를 개선해줘.
AGENTS.md와 현재 git 상태를 확인하고 관련 없는 기존 카드 이미지 변경은 제외해줘.
먼저 현재 실제 화면과 스타일을 확인하고 1~4단계를 순서대로 구현해줘.
본문·보조 글자, 중첩 패널, 버튼 위계, 모바일 목록을 우선 정리하고
보호자 홈·첫 사용 안내·카드·연습·기록·설정·RFID 동선을 개선해줘.
기존 팔레트와 아이콘을 재사용하고 보호자 범위 밖의 화면 스타일은 유지해줘.
없는 API·가상 수치·자동 카드 재배치·새 인증 수단은 추가하지 말아줘.
각 단계의 코드·검증 결과·문서를 함께 완료해 기능 단위로 커밋해줘.
실제 화면을 실행하지 못하면 그 한계와 미확인 항목을 명시해줘.
마지막에 커밋·작업 트리를 확인하고 원격 푸시는 하지 말아줘.
```

## 이번 문서 작업 검증

- 기존 보호자 UI 기록과 커밋 규칙을 읽고 계획 범위를 대조했다.
- 문서 상대 링크와 변경분 공백 검사를 수행한다.
- 앱 구현·빌드·브라우저·실기기·보호자 관찰은 미실행이다.
  본 문서의 수치와 완료 기준은 향후 개발 기준이며 통과 결과가 아니다.
