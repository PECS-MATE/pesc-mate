# MVP 이후 UX 개선과 AI 연습 제안 개발 요청서

작성일: 2026-10-29

## 상태와 목적

사용자가 기존 MVP 완료를 선언했으며, 이 문서는 이후 개선 개발의 범위다.
과거 문서의 실물·운영 검수 이력은 소급해서 통과로 바꾸지 않는다.
이 문서 작성으로 기능 구현이나 모델 성능 검증이 완료된 것은 아니다.

목표는 아동의 기본 말하기를 단순화하고, 보호자·담당자가 사용 기록에 맞는
연습을 선택하도록 돕는 것이다. 아래 단계는 순서대로 개발하되 각 단계는
코드·문서·관련 검증을 포함한 완결된 기능 단위로 커밋한다.

## 1. 개발 순서

| 단계 | 결과물 | 완료 조건 |
|---|---|---|
| A | 아동 말하기 화면 단순화 | 카드 선택 → 발화가 기본 경로이며 AI 장애와 무관하게 동작 |
| B | 보호자 설정 경계와 시작 방식 | 중요한 설정의 성인 확인, 홈/말하기 시작 선택과 저장 |
| C | 기록 기반 연습 후보와 설정 미리보기 | AI 없이도 허용된 활동을 제안·검토·명시 시작 가능 |
| D | Ollama 연습 제안 | 검증된 후보 중 제안하며 실패 시 규칙 후보로 대체 |
| E | 추천 피드백과 실제 기기 검수 | 피드백 저장·삭제, 권한·전환·발화 회귀와 관찰 결과 기록 |

### A. 말하기와 학습 UX

- 말하기는 카드판, 고른 카드, 말하기, 선택 취소를 중심으로 구성한다.
- 빠른 표현·복구 표현·핵심 카드 위치와 기존 사용자 설정은 유지한다.
- 신규 사용자의 기본 발화는 선택 카드 그대로 말하기로 한다. 기존 사용자의
  발화 방식은 자동 변경하지 않고 보호자가 명시적으로 바꾸도록 한다.
- 출력 방식·기록 상황·AI 생성 정보는 보호자 설정 또는 상세 영역으로 이동한다.
- AI 문장 생성은 선택 기능이며 기존 의미 보존·확인 절차를 유지한다.
- 문장 상단 고정 영역은 작은 화면에서 카드판과 필수 발화 버튼을 가리지 않게 한다.
- 홈의 추상적인 기호는 기존 카드/행동 이미지로 대체한다. 아동 안내는 짧게 쓴다.
- 학습 문제 수·반복·재도전은 보호자가 미리 설정하고 아동은 활동을 시작한다.
- 집중 화면, 키보드·보조 입력, 고대비·동작 줄이기와 오프라인 경로를 보존한다.

### B. 보호자 설정

- 시작 화면을 홈 또는 말하기로 지정할 수 있게 하고 계정별로 저장한다.
- 카드 크기·개수·표시 방식·발화 방식은 미리보기를 제공한다.
- 동의, 데이터 삭제, 지원 연결, 카드 배치 변경은 서버 권한과 기존 재인증을
  확인한다. 화면에 보호자라는 제목만 붙이는 것을 성인 확인으로 취급하지 않는다.
- 아동 계정에서 가능한 성인 확인 수단은 기존 계정/연결 구조를 조사해 설계한다.
  단순 계산 문제를 신원 인증으로 취급하지 않으며 기본 말하기는 잠그지 않는다.

## 2. 우리 아이 연습 제안

### 사용자 흐름

보호자/담당자 홈 → 연결 아동 선택 → 이번에 해볼 연습 → 근거·카드·설정 확인
→ 필요하면 수정 → 이 설정으로 시작 → 기존 학습 활동 → 보호자 피드백.

아동 화면에 분석 보고서를 노출하지 않는다. 제안을 받았다는 이유로 학습을 자동
시작하거나 카드판·난이도·기본 설정을 변경하지 않는다. 나중에와 직접 선택을 제공한다.
한 번에 최대 3개만 제안하고 관심 표현과 학습 수행 근거를 구분해 보여준다.

### 첫 버전의 범위

- 기존 `word_picture_match`, `sound_picture_match`, `sentence_card_order`만 사용한다.
- 문제 수·보기 수·반복·재도전은 현재 엔진의 지원 범위를 먼저 확인한다.
  문서에 예시로 등장한 보기 2개 등을 지원 확인 없이 노출하지 않는다.
- 문장 순서 연습은 기존 예문과 해당 예문의 카드만 사용한다. 임의로 고른 카드
  조합을 예문 엔진에 넘기지 않는다. 지원하지 않는 설정은 후보에서 제외한다.
- 자유 생성 문제, 발음 평가, 능력 진단, 발달 연령 추정, 치료 계획은 범위 밖이다.
- 기존 말하기 카드 추천과 별도 기능·API·정책으로 구현한다.
  `RECOMMENDATION_POLICY.md`의 학습 결과 미사용 원칙은 기존 카드 추천에 유지한다.

### 근거 계산

서버가 최근 14일 기록을 집계한다. 이 기간은 초기 제품 기본값이며 교육적 기준이 아니다.
조회 상한·표본 수·기간을 응답에 명시하고 재전송·재생성 중복을 제거한다.

- 의사소통: 자주 선택한 카드와 사용 상황. 익숙한 소재 후보로만 사용한다.
- 학습: 활동별 참여·완료·재시도, 기록에 실제 존재하는 중단 정보.
- 보호자 피드백: 적절함/어려움/관심 없음. 완료 여부와 별개로 해석한다.
- 실제로 수집하지 않은 응답 시간·중단 원인을 추정하거나 과거 기록에 채우지 않는다.
- 초기 개인화 기준은 중복 제거된 학습 참여 3회 또는 카드 선택 이벤트 10건으로
  제안하되 설정 가능한 규칙으로 둔다. 기준 미달은 개인화 보류와 수동 선택을 제공한다.
- 특정 단어 미사용·재시도·중단을 이해 부족이나 능력 저하로 단정하지 않는다.

## 3. Ollama 모델과 구현 방식

초기 추천 모델: **`qwen3:4b-instruct`**.

공식 태그에서 4.02B, Q4_K_M, 다운로드 약 2.5GB를 확인했다.
짧은 한국어 설명과 제한된 후보 선택을 수행할 시작 후보로 선정한다.
최신·최고 성능이라는 의미가 아니며 한국어 품질·실제 지연은 아직 검증하지 않았다.
파일 용량은 실행 메모리가 아니다. 개발 PC에서 메모리와 CPU/GPU 사용량을 측정한다.

```sh
ollama pull qwen3:4b-instruct
```

위 명령은 향후 개발 환경 준비용이며 이번 문서 작업에서는 실행하지 않았다.

- 기존 문장 생성의 `OLLAMA_MODEL=qwen2.5:0.5b`를 일괄 교체하지 않는다.
- 별도 `OLLAMA_LEARNING_MODEL=qwen3:4b-instruct`와 기능 활성화 설정을 추가한다.
- 서버에서만 로컬 Ollama를 호출한다. Docker의 기존 연결 구성을 재사용한다.
- 초기 요청 제한은 30초, temperature 0, 입력 집계 JSON 8KB 이내,
  출력 512토큰 이내로 제안한다. 실측 후 조정하며 무제한 재시도하지 않는다.
- 서버가 유효한 후보를 만들고 모델은 후보 ID와 근거 ID를 선택한다.
  최종 활동·카드·설정은 서버의 후보에서 복원한다.
- Ollama `format`에 JSON Schema를 전달하고 Pydantic으로 재검증한다.
- 모델 응답은 최대 3개 `{candidate_id, evidence_ids}`로 제한한다.
  사용자에게 보여줄 관찰 수치와 설명은 검증된 근거의 서버 템플릿으로 만든다.
  첫 버전에서는 모델의 자유 서술을 그대로 노출하지 않는다.
- 후보 밖 ID·다른 아동 카드·지원하지 않는 활동·중복·잘못된 JSON은 거절한다.
- 모델 없음·시간 초과·스키마 오류는 규칙 기반 제안으로 대체한다.
  규칙 제안을 AI 제안으로 표시하지 않는다. 기록 부족과 모델 장애를 구분한다.
- 모델/프롬프트/집계/규칙 버전을 저장하고 요청 중복·동시 생성을 제한한다.
- 모델에 이름·사진·원문 문장·보호자 메모를 보내지 않는다. 집계와 내부 후보 ID만
  전달한다. 사용자 카드명 등 텍스트를 전달하게 된다면 지시가 아닌 데이터로 처리한다.

### 권한·데이터 수명

- 기록 조회와 학습 설정/시작 권한은 각각 기존 연결 권한을 확인한다.
- 기존 기록 동의를 기능 확장 동의로 임의 해석하지 않는다. 기존 동의 범위를
  검토하고 보호자에게 개인화 연습 사용을 명시적으로 켤 수 있게 한다.
- 동의 없음·철회·삭제 중에는 개인 기록 분석과 모델 호출을 중지한다.
  일반 활동 선택과 기록 없는 기본 말하기/연습은 유지한다.
- 추천·피드백 저장소는 말하기 및 학습 결과와 분리한다. 추천 열람·수락을
  실제 연습 완료나 의사소통 성공으로 집계하지 않는다.
- 보존 기간·개인 내보내기·삭제·스키마 등록을 함께 구현한다.
- 아동·계정 전환, 권한 변경, 로그아웃 뒤 늦은 응답을 폐기한다.
- 승인/시작 시점에 권한·동의·카드 활성 상태·설정 버전을 재확인한다.
- 오프라인에서는 새 개인화 생성·승인을 제공하지 않고 기존 학습을 이용한다.

### 예상 변경 위치

- `frontend/src/App.jsx`, `HomeDashboard.jsx`, `MyPage.jsx`, `assets/activityUx.css`
- `frontend/src/services/learningGame.js`, `sentenceLearning.js`: 기존 엔진 제약 확인
- 신규 보호자 연습 제안 패널과 API 클라이언트
- `backend/app/services/learning.py`, `support_links.py`, `privacy.py`: 연동 경계 확인
- 신규 집계·후보 계산·Ollama 학습 제안 서비스와 라우트
- `indexes.py`, `schema_versions.py`, 내보내기/삭제 및 환경 설정

파일명은 구현 지시가 아닌 탐색 출발점이다. 기존 코드 구조를 확인하고 결정한다.

## 4. 검증과 완료 기준

- 말하기: 카드 선택·취소·발화, 기존 위치/설정 유지, AI 실패 중 기본 발화 확인.
- 화면: 실제 사용하는 태블릿 우선, 작은 화면·회전·긴 문장·많은 카드 확인.
- 접근성: 키보드/보조 입력, 초점, 고대비, 동작 줄이기, 빠른/복구 표현 접근.
- 후보: 부족한 기록, 중복 기록, 서로 다른 아동 기록, 없는 설정/카드 제외 확인.
- 권한: 연결 없는 대상, 기록 조회만 허용된 대상, 동의 철회, 삭제와 승인 경합 확인.
- 모델: 합성 데이터로 정상 JSON·잘못된 ID·시간 초과·모델 없음·조작 텍스트 확인.
- 한국어 모델 평가는 정상/부족/재시도/중단/카드 비활성 사례를 포함해 최소 20건
  수동 평가한다. 사실 불일치·진단 표현·지원 불가 활동 노출은 0건이 완료 조건이다.
- 성공/실패/규칙 대체와 냉간·재사용 요청 지연을 따로 기록한다.
- 프런트엔드 빌드와 핵심 API 시나리오를 실행하고 결과를 작업 문서에 남긴다.
- 자동 검증 도구는 현재 제거된 상태다. 과거 verify 명령을 실행 가능하다고 가정하거나
  삭제한 대규모 검증 체계를 자동 복원하지 않는다. 현재 가능한 빌드·수동/API 검증을
  사용하고 새 로직의 핵심 경계를 검증할 최소 테스트가 필요하면 범위를 명시한다.
- 실제 아동·보호자 과업 관찰은 별도 수행한다. 미수행이면 현장 사용성 확인으로 표시하지 않는다.

## 5. 복사해서 사용할 개발 요청 프롬프트

```text
현재 PESC MATE의 기존 MVP는 완료되었고 후속 개선을 개발한다.
docs/planning/POST_MVP_DEVELOPMENT.md를 요구사항으로 읽고 구현해줘.

먼저 AGENTS.md, 현재 코드와 git 상태, 관련 정책을 확인해줘.
A 말하기 단순화 → B 보호자 설정 → C 규칙 기반 연습 제안
→ D Ollama 연동 → E 피드백/검수 순서로 진행해줘.
계획만 제출하고 멈추지 말고 각 단계를 완결된 기능으로 구현해줘.
실제 구조와 문서의 예상 경로가 다르면 실제 구조에 맞춰 반영해줘.

Ollama 연습 제안 모델은 qwen3:4b-instruct를 별도 설정으로 사용해줘.
기존 문장 생성 모델은 일괄 변경하지 말고 기존 학습 3종만 제안해줘.
서버가 허용된 후보와 근거를 계산하고 AI는 그 안에서 선택하도록 해줘.
JSON 스키마/ID/권한/동의 검증과 규칙 기반 대체를 구현해줘.
보호자가 검토하고 명시적으로 시작하며 자동 학습/카드 재배치는 금지해줘.

말하기 카드 추천과 연습 제안을 분리하고 기존 카드 위치, 빠른/복구 표현,
오프라인 기본 발화, 기존 사용자 설정을 유지해줘.
```
