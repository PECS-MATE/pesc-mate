## 카드 세로 스크롤과 반복 문구 정리

2026-11-05: 아동 카드 보기의 `○○을(를) 표현하는 PECS 카드예요.`라는 반복 설명을 제거했다.
카드 이름·그림·분류와 단어 듣기·문장에 사용하기는 유지한다.
`나의 카드` 제목과 빈 등록 안내도 제거하며, 제출 카드가 없으면 해당 영역 자체를 만들지 않는다.
실제 등록한 카드가 있을 때는 초안·반려 카드의 수정과 승인 요청 등 기존 작업을 유지한다.

카드 보기와 그림으로 말하기의 이전/다음·페이지 번호를 없애고, 카드 목록 안에서
위아래 스크롤하도록 변경했다. 카드 선택 버튼은 그대로이며 페이지 이동 버튼만 제거했다.
카드 목록은 이름이 있는 포커스 가능 영역으로 제공해 터치·마우스 휠·키보드로 탐색한다.
보호자 공유 카드판의 페이지 이동과 학습 문제의 다음 버튼은 이번 변경 대상이 아니다.

`useCardScroll`을 공통으로 사용하며 처음에는 일부 카드만 렌더링한다.
아래쪽에 도달하면 다음 묶음을 추가해 큰 PNG를 처음부터 전부 로딩하지 않는다.
검색·분류·폴더가 바뀌면 스크롤과 로딩 범위를 초기화하고, 화면이 넓거나 글자 전용 모드라
목록이 짧으면 스크롤할 수 있을 때까지 필요한 묶음을 더 표시한다.
기존 `cards_per_page` 저장 필드는 유지하되 설정 문구를 `한 번에 불러올 카드 수`로 바꾸고
초기·추가 로딩 묶음 크기로 사용한다. 카드 순서·ID·문장·음성·권한과 저장 동작은 변경하지 않는다.

### 검증 기록

- `npm run build`, `git diff --check` 통과. 기존 500KB 초과 묶음 경고는 남아 있다.
- 모의 API를 사용하는 전체 앱 브라우저 검사 19개 통과:
  빈 등록 영역과 반복 문구 제거, 기존 상세 동작과 등록 초안 수정 버튼,
  카드 보기·말하기에서 113종 끝까지 로딩, 검색·폴더 변경 시 초기화,
  선택 카드 유지, 키보드 PageDown, 390px 모바일 터치 스크롤·가로 넘침 방지를 확인했다.
- 짧은 행을 사용하는 공통 훅 브라우저 검사 8개 통과:
  빈 화면 자동 채우기, 화면 크기 변경, 유휴 렌더 반복 없음,
  추가 로딩·문맥 초기화·빈 결과와 결과 복귀를 확인했다.
- 최초 등록 초안 검사는 고정 1초 대기 안에 화면이 준비되지 않아 실패했다.
  화면 조건을 기다리도록 일회성 검사 스크립트를 바꾸고 전체 19개를 다시 수행해 통과했다.
- 검사 중 실제 API 쓰기 요청은 없었다. 실제 계정·DB·TTS·RFID·실기기 터치와
  스위치/자동 스캔 전체 흐름은 미검수이며 사용자 추가 PNG 파일은 변경·커밋하지 않는다.

## 프론트엔드 구조 정리

2026-11-04: 화면과 기능은 유지하면서 `App.jsx`에 함께 있던 아래 책임을 분리했다.

| 파일 | 역할 |
| --- | --- |
| `frontend/src/config/appDefaults.js` | 카드 기본 메타정보, 음성·접근성·개인정보 기본값과 설정 정규화 |
| `frontend/src/services/cardMedia.js` | 카드 이미지 조회, 오프라인 이미지 목록, Blob 복원과 학습 카드 캐시 변환 |
| `frontend/src/components/CardVisuals.jsx` | 카드 그림·대체 표시·빠른 표현의 공통 표시 컴포넌트 |
| `frontend/src/hooks/useSidebar.js` | 반응형 메뉴 상태, 포커스 이동·순환, Escape와 스크롤 잠금 해제 |
| `frontend/src/pages/AdminContentPage.jsx` | 공용 카드 등록·승인과 카테고리 관리 화면 |

권한에 따른 화면 노출, API 호출, 계정 전환 시 응답 폐기와 Object URL 해제는
기존 흐름을 유지한다. 관리자 화면은 입력 콜백을 전달받으며 자체적으로 권한을 부여하지 않는다.
렌더 콜백을 받는 기존 화면에는 얇은 어댑터를 유지해 DOM 클래스, 접근성 이름과 카드 키를 보존했다.
새 의존성이나 상시 실행 테스트 파일은 추가하지 않았다. 사용자 추가 이미지 9개는 변경·커밋하지 않는다.

이번 작업은 첫 구조 정리이며 `App.jsx`의 인증·문장 생성·학습·보호자 데이터 흐름까지
모두 분리한 상태는 아니다. CSS와 화면 배치는 변경하지 않는다.

### 검증 기록

- `npm run build`: 통과. 기존 500KB 초과 JavaScript 묶음 경고는 남아 있다.
- 별도 Chrome에서 이미지·설정·캐시 일회성 검사 16개 통과:
  기본값, 공백 파일명 매핑, 사용자 이미지 우선, 대체 이미지, 임시 URL 제외,

- 표시 컴포넌트·사이드바·관리자 입력 일회성 검사 14개 통과:
  기존 DOM 의미, Tab·Shift+Tab 순환, Escape 후 포커스 복원, 세션 종료 시
  스크롤 잠금 해제, 카테고리·승인·반려 콜백과 검토 메모 입력을 확인했다.
- 모의 API를 사용하는 전체 앱 화면 5종 통과:
  비로그인, 아동 홈·말하기, 보호자, 일반 담당자, 콘텐츠 관리자.
  관리자 권한이 없는 화면에서는 관리자 페이지가 노출되지 않았고 런타임 오류는 없었다.
  이는 클라이언트 표시 검사이며 서버 권한 검증을 대신하지 않는다.
- 최초 이미지 검사에서는 브라우저에 남은 이전 모듈의 새 export를 찾지 못해 실패했다.
  페이지를 새로 로드한 후 위 16개를 재실행해 통과했으며, 최종 코드로 14개도 재확인했다.
- 실사용 계정·DB 쓰기, 실물 RFID, iPad 음성, 실제 오프라인 재접속 통합 검수는 미실행이다.

<a id="activity-ux--화면과-동선"></a>
#### 화면과 동선

- 홈에서 **말하기·연습하기·내 카드**를 먼저 선택한다. 기존 선택 카드가 있으면 이어서 말하기를 제공한다.
- 주제별 카드는 실제 사용 가능한 카드·카테고리로 구성하고 개수를 집계한다. 선택하면 해당 주제의
  카드 목록으로 이동한다. 카드 추가·말하기는 기존 기능을 사용하며 탐색 자체로 발화하지 않는다.
- 홈과 말하기 화면에서 **카드 리더기 열기**로 입력 영역을 펼친다. USB 연결 상태와 읽은 개수는
  실제 연결 상태를 사용하고, 읽은 카드는 그림·단어·위치 또는 입력 순서를 구분한다.
- 읽은 카드의 명시 추가·적용 뒤 말하기 화면에서 기존 문장 생성·확인·TTS로 이어간다.
  다른 활동·마이페이지에서는 문장 적용을 막는다. 칩 인식만으로 발화하거나 기존 문장을 바꾸지 않는다.
- 같은 로그인 계정에서는 홈·말하기·연습·카드 탐색 사이를 이동하거나 영역을 접어도 USB 연결과
  읽기 목록을 유지한다. 로그아웃·계정/세션 전환·앱 이탈의 기존 연결 해제 처리를 유지한다.
  Wi-Fi 상태 조회는 다른 활동·마이페이지에서 중지하고 돌아왔을 때 새 상태를 조회한다.
- 장치의 포트·속도·진단 스케치 설명과 로그는 아동 화면에서 펼쳐 확인한다. 관리자·보호자 등록
  화면은 기존 상세 표시를 유지한다. 로그에 UID·인증 자료를 추가하지 않는다.
- 말하기에서는 고정 카드판과 현재 문장을 먼저 표시하고 추천을 아래에 둔다. 추천의 순서·동의·
  노출 집계 정책과 고정 카드 배치는 유지한다.
- 빠른 표현·복구 표현은 모든 아동 활동에서 계속 접근할 수 있다. 오프라인 음성 준비의 자세한
  상태는 펼쳐 확인한다. 준비 실패·재시도는 숨기지 않는다.
- 프로필 설정 진입점은 사이드바의 이름·사진으로 유지한다. 실제 학습 설정을 선택하는 화면의
  종류·범위·시작 조작을 묶고, 임의의 레벨·목표·포인트를 표시하지 않는다.

<a id="activity-ux--유지한-경계"></a>
#### 유지한 경계

동의 없는 기본 말하기, 기존 지원 권한, 관리자 공용 칩 등록과 개인 매핑 우선 규칙은 유지한다.
DB·API·펌웨어·음성 공급자를 변경하지 않는다. 입력 방식에 따라 1개 리더기의 순서 누적과
2·3개 리더기의 위치 배열을 구분한다. 카드 ID·카드 위치·표현을 임의로 교체하지 않는다.

핵심 웹 기능의 구현·자동 검증 이력은 존재하지만, 실물 칩 등록→문장→발화와 RC522 3개 통합,
제거 판정·배선·전압·RF 간섭·실제 기기 음성 품질의 검수는 여전히 남아 있다.
이 UI 변경이나 자동 검사로 하드웨어 MVP·현장 사용·배포 완료를 표시하지 않는다.

### 새 참고 화면의 활동 UX 반영

2026-10-28 사용자 요청: 새 이미지를 참고해 UX만 수정하고 검사는 사용자가 직접 수행한다.

<a id="reference-ux--적용-범위"></a>
#### 적용 범위

| 참고 화면 | 기존 기능에 반영한 UX |
|---|---|
| 랜딩·홈 | 앞선 랜딩·활동 홈 구현을 유지한다. |
| 단어 연습 | 문제 그림·소리 듣기와 답 선택을 중앙에 크게 배치하고 진행·피드백·다음 조작을 구분한다. |

| 리포트 | 기존 실제 집계·카테고리 사용과 자주 사용한 카드를 카드형 패널과 순위 목록으로 정리한다. |

말하기·연습하기의 `집중 화면`은 사이드 메뉴를 접는 화면 배치 전환이다. 같은 위치의
`메뉴와 함께 보기`로 복귀한다. 활동이나 계정이 바뀌면 집중 상태를 해제한다.
브라우저 전체화면 API·장치 권한·추가 서버 호출을 사용하지 않는다.

말하기의 카드 선택·이동·삭제와 생성·확인·TTS 핸들러는 그대로 사용한다. 생성 정보와 원래 선택
순서는 접어 확인하며, 만들어진 문장이나 진행 중인 음성이 없을 때 불필요한 발화 조작을 줄인다.
빠른 표현과 복구 표현은 유지한다. 칩의 UID 고정·명시 저장·매 작업 재인증과 공용/개인 적용 규칙도
기존 로직을 사용한다. 리포트는 기존 API의 기록만 표시하며 예시 점수·별·증감률은 추가하지 않는다.
새 녹음·발음 평가·인쇄 기능이나 새 학습·장치 API를 추가하지 않는다.

스타일은 `frontend/src/assets/activityUx.css`의 `.app` 범위에 두어 랜딩과 구분한다.
작은 화면의 단일 패널 배치, 선택 목록 스크롤과 고대비 설정을 고려했으나 실행 검수는 남아 있다.
기존 이미지와 카드 매핑을 재사용하며 참고 PDF·마스코트 변경·Arduino 진단 스케치를 커밋에 넣지 않는다.

#### A. 아동 말하기 화면 단순화

- 카드 선택 후 고른 카드 말하기를 기본 버튼으로 둔다. 모델 요청 중이거나 오프라인이어도 이 버튼을 사용할 수 있다.
- 신규 가입 계정의 기본 출력 방식을 `selection`으로 저장한다. 기존 계정의 누락된 값은 `natural`로 해석해 기존 동작을 보존한다.
- 문장 생성은 기존 계정에서 선택 기능으로 남기고 생성 결과 확인 절차를 유지한다.
- 출력 방식과 기록 상황은 상세 영역으로 옮긴다. 빠른 표현, 복구 표현, 카드 배치는 변경하지 않는다.
- 홈 활동의 추상 기호를 현재 카드 그림으로 바꾸고 작은 화면에서는 문장 영역의 고정을 해제한다.
- 검증: 사용자 요청에 따라 자동 테스트·빌드·브라우저·실기기 검증 미실행. 코드 변경과 공백 차이만 확인했다.

<a id="post-mvp-implementation--b-보호자-설정과-시작-화면"></a>
#### B. 보호자 설정과 시작 화면

- 계정별 접근 설정에 `start_screen`과 `output_mode`를 저장한다. 홈과 그림으로 말하기 중 시작 화면을 고른다.
- 기존 계정은 저장값이 없으면 홈·기존 자연스러운 문장 설정을 유지한다. 새 계정은 고른 카드 말하기를 사용한다.
- 카드 표시·크기·개수와 발화 방식의 샘플 미리보기를 보호자 설정에 제공한다.
- 연결된 보호자·담당자의 `voice_access_manage` 권한으로 중요 설정을 저장한다. 아동 계정은 글자 크기,
  고대비, 동작 줄이기만 직접 바꿀 수 있다. 서버가 중요 필드 변경을 거절하고 아동의 저장에서 해당
  필드를 쓰지 않아 보호자와 동시에 저장해도 덮어쓰지 않는다.
- 개인정보 동의·데이터 삭제·지원 연결의 기존 API는 아동 본인 계정에서도 실행 가능하다. 현재 구조는
  별도 보호자 본인 확인 수단이 없으므로 이 설정들을 성인 확인 완료로 표시하지 않는다. 카드 배치는
  기존 연결별 `board_manage` 권한을 사용한다. 단순 계산 문제로 보호자 확인을 대체하지 않는다.
- 검증: 사용자 요청에 따라 자동 테스트·빌드·브라우저·실기기 검증 미실행. 코드 변경과 공백 차이만 확인했다.

<a id="post-mvp-implementation--c-규칙-기반-연습-제안"></a>
#### C. 규칙 기반 연습 제안

- 기존 그림카드 추천과 별도의 `/api/practice-suggestions` 경로를 둔다. 연결별 `records_read`와
  `learning_manage` 권한이 모두 있어야 보호자·담당자가 후보를 볼 수 있다.
- 개인화는 기본 꺼짐이며 보호자가 명시적으로 켠다. 기존 기록 동의가 없거나 삭제 중이면 분석하지 않는다.
- 최근 14일의 중복 ID가 없는 카드 선택 이벤트 최대 500건과 완료된 학습 최대 100건만 조회한다.
  응답에는 기간·표본·상한·최소 기준을 표시한다. 선택 이벤트 10건 또는 완료 3회 미만이면
  개인화 후보를 내지 않고 수동 학습 선택을 제공한다. 기준은 환경 변수로 조정 가능하다.
- 기존 학습 3종과 현재 학습 설정·제공 중인 카드로 후보를 만든다. 문장 순서 후보는 작성된 예문
  ID와 그 카드만 사용한다. 예문 목록은 프런트엔드의 기존 작성 예문과 일치시킨다.
- 보호자는 근거·카드·문제 수·보기 수·반복·재도전을 확인하고 명시적으로 준비한다. 아동은
  연습 화면에서 다시 명시적으로 시작한다. 후보 열람이나 준비는 학습 완료로 기록하지 않는다.
- 아동에게는 분석 근거를 반환하지 않는다. 시작할 때 현재 동의·설정·카드 상태를 다시 확인한다.
- 검증: 사용자 요청에 따라 자동 테스트·빌드·브라우저·실기기 검증 미실행. 코드 변경과 공백 차이만 확인했다.

  Ollama `/api/chat`에 보낸다. 입력은 8KB 이하이며 응답 제한은 512토큰, 요청 제한은 30초다.
- 공식 [구조화 출력 설명](https://docs.ollama.com/capabilities/structured-outputs)에 따라
  Pydantic JSON Schema를 `format`에 전달하고 응답도 Pydantic과 허용 ID 집합으로 검사한다.
  모델은 최대 3개 후보 ID와 해당 후보의 근거 ID만 선택한다. 화면 수치와 설명은 서버가 만든다.
- 모델 비활성·없음·시간 초과·형식 오류·후보 밖 ID는 규칙 후보로 대체하고 AI 제안으로 표시하지 않는다.
  기록 부족은 모델 장애와 별도 상태다. 한 번에 한 요청만 모델을 사용한다.
- 요청 UUID별 생성 결과는 제안 묶음에 저장한다. 모델·프롬프트·규칙·집계 기간 버전을 기록하고
  같은 UUID의 중복 조회는 같은 후보 순서를 반환한다.
- 실제 모델 다운로드·추론·한국어 품질·냉간 지연 검증은 미실행이다. 자동 테스트·빌드·브라우저
  검증도 사용자 요청에 따라 실행하지 않았다. 코드 변경과 공백 차이만 확인했다.

<a id="post-mvp-implementation--e-보호자-피드백과-데이터-수명"></a>
#### E. 보호자 피드백과 데이터 수명

- 연결별 `records_read`와 `learning_manage` 권한이 있는 보호자·담당자만 준비한 연습에
  `적절함`·`어려움`·`관심 없음` 의견을 저장·수정·삭제할 수 있다. 수정과 삭제는 revision을
  확인한다. 피드백은 학습 완료 여부와 별개이며 능력·발달·진단 판단으로 사용하지 않는다.
- 최근 14일의 보호자 의견을 서버 템플릿 근거로만 후보에 덧붙인다. 모델에는 의견 문장이나
  사용자 정보 대신 허용된 근거 ID만 보낸다.
- 기존 개인정보 보존 기간을 적용할 때 제안 묶음·준비한 연습·피드백도 정리한다.
  개인정보 내보내기와 개인 데이터 삭제에도 개인화 설정과 이 세 저장소를 포함한다.
  동의 철회 시 개인화 설정을 끄고 저장된 제안·준비한 연습·피드백을 삭제한다.
- 제안 생성 중 동의가 철회되면 저장 전에 동의·설정·후보의 카드와 학습 설정을 재확인해
  오래된 결과를 폐기한다. 준비 요청도 권한·동의·후보를 재확인한다. 화면은 계정 전환·
  로그아웃 뒤 이전 요청의 응답을 적용하지 않는다.
- 자동 테스트·빌드·브라우저·실기기·실제 모델 추론은 사용자 요청에 따라 미실행이다.
  한국어 모델 20건 수동 평가와 실제 아동·보호자 과업 관찰도 미실행이며 완료 게이트로
  남는다. 코드 변경과 공백 차이만 확인했다.

<a id="post-mvp-implementation--연습-화면-ui-정리"></a>
#### 연습 화면 UI 정리

- [Bootstrap 5.3.8](https://getbootstrap.com/docs/5.3/getting-started/download/)의 그리드와
  배치 유틸리티를 npm 의존성으로 추가했다. 전역 카드·버튼 스타일과의 충돌을 줄이기 위해
  컴포넌트 전체 스타일과 JavaScript 플러그인은 가져오지 않는다.
- 아동 연습 화면을 `연습 종류 → 카드 범위 → 시작` 순서로 정리했다. 연습 종류는 설명이 있는
  선택 카드, 범위는 누르기 쉬운 버튼으로 표시하고 현재 선택을 `aria-pressed`로 알린다.
- 보호자가 준비한 연습과 최근 30일 기록을 같은 화면 흐름에 맞췄다. 화면 폭에 따라
  선택 카드와 요약 배치를 바꾸고 고대비·동작 줄이기 설정을 반영한다.
- 문장 순서 연습에서는 실제로 가능한 예문이 있는 범위만 보여준다. 설정에서 허용하지
  않은 카테고리의 카드가 직접 선택으로 들어오지 않도록 범위 계산을 보강했다.
- 검증: 코드·패키지 경로와 `git diff --check` 확인. 사용자 요청에 따라 빌드·브라우저·
  실기기 검증은 미실행이다.

<a id="post-mvp-implementation--docker-프런트엔드-의존성-갱신"></a>
#### Docker 프런트엔드 의존성 갱신

- Compose의 `/app/node_modules` 영구 볼륨이 새 이미지의 의존성을 가리는 경우를 막기 위해
  컨테이너 시작 시 `package-lock.json` 해시를 확인한다. 변경된 경우에만 `npm ci`로
  볼륨을 갱신하고 완료 해시를 기록한다.
- 기존 볼륨은 해시 파일이 없으므로 첫 시작에서 갱신된다. 설치 실패 시 해시를 기록하지
  않아 다음 시작에서 다시 시도한다.
- 검증: `docker compose up -d --no-deps --build frontend`로 컨테이너를 재시작했다.
  컨테이너 안에 두 Bootstrap CSS 파일이 존재하며 Vite 준비 로그를 확인했다.
  `git diff --check`도 통과했다. 실제 브라우저 화면 확인은 사용자 검증에 남긴다.

<a id="post-mvp-implementation--usb-연결-위치-조정"></a>
#### USB 연결 위치 조정

- 아동 화면의 왼쪽 하단 연결 버튼을 오른쪽 상단 서비스 상태 메뉴로 옮겼다.

  리더기 세션은 유지되고, 집중 화면에서도 같은 상단 메뉴를 사용한다.
- 검증: 포털 대상과 화면 상태 조건, `git diff --check` 확인. 사용자 요청에 따라
  빌드·브라우저·실기기 검증은 미실행이다.

  좁은 화면에서는 메뉴를 두 열로 배치하고, 선택 상태와 고대비 표시를 유지한다.

- 설정별 내용 길이에 따라 팝업이 늘거나 줄지 않도록 화면 크기 안에서 일정한 높이를

- 설정 항목을 바꿀 때 이전 항목의 스크롤 위치가 남지 않도록 내용 영역을 맨 위로 돌린다.
  작은 화면에서는 메뉴 높이를 제한해 내용 영역을 확보한다. 팝업 드래그는 넣지 않았다.
- 검증: 코드 변경과 `git diff --check` 확인. 사용자 요청에 따라 자동 테스트·빌드·
  브라우저·실기기 검증은 미실행이다.

#### KRDS 기준 UI·UX 마무리 점검과 수정

2026-10-29 코드 기준으로 주요 화면을 점검했다. 앞선 마이페이지 팝업은 이 작업에서
설정 전용 화면으로 전환했다. KRDS 적합성 인증이나 실사용 검수 완료를 의미하지 않는다.

| 점검 영역 | 반영 내용 |
| --- | --- |
| 카드 등록 | 두 등록창을 공통 네이티브 대화상자로 통합했다. 입력란으로 초점을 옮기고 Tab 순환·Esc 닫기·초점 복귀를 처리한다. 저장 중 중복 제출과 닫기를 막고, 스크롤과 별개로 하단 액션을 유지한다. |
| 등록 행동 예측 | 공개 범위에 따라 `카드 저장`과 `공개 승인 요청`을 구분하고 이미지 조건을 입력란과 연결했다. |
| 마이페이지 | 사진·접근·음성·보호자 설정을 전용 화면에서 제공한다. 이전 화면 복귀와 설정 탭의 방향키·Home·End 탐색을 지원한다. 기존 카드·연습·USB 세션은 마운트 상태로 유지한다. |
| 탐색 상태 | 주 메뉴와 프로필에 현재 화면 상태를 제공하고, 설정을 연 동안 이전 메뉴를 선택 상태로 표시하지 않는다. |
| 글자와 액션 | 프로필·랜딩·공통 보조 글자와 주요 버튼 대비를 보강하고 공통 색상 변수를 사용한다. 연습 범위 선택에는 체크 표시도 제공한다. |

| 말하기 | 문장 생성 대기 중에도 선택 카드 그대로 말할 수 있음을 안내한다. 생성 실패 시 문장 생성 재시도를 명시한다. 모델 추론 속도를 변경한 작업은 아니다. |

검증 상태:

- 변경 소스의 참조·폼 필드·메뉴 조건과 `git diff --check`를 확인했다.
- 기존 `App.jsx` 포맷 변경을 제외한 커밋용 파일과 작업 파일을 공백 제외 비교하고,
  Rolldown 변환 결과가 같은지 확인했다.
- 초기 구문 검사 시도는 서비스 중지·Compose 옵션 미지원·`esbuild` 미설치로 실패했다.
  기존 이미지의 네트워크 없는 읽기 전용 임시 컨테이너에서 현재 Vite에 포함된
  Rolldown·Lightning CSS로 검사 경로를 바꾸어 JSX 6개·CSS 3개 구문 검사를 통과했다.
- 색상 값 계산에서 흰 배경 대비는 보조 글자 `#526474` 6.12:1, 주요 버튼 `#b4235d`
  6.29:1이다. 실제 화면의 모든 배경·상태 조합을 검사한 결과는 아니다.
- 자동 테스트·빌드·브라우저·실기기 검증은 사용자 요청에 따라 미실행이다.

남은 수동 확인:

1. 등록창에서 Tab·Shift+Tab·Esc, 취소 후 초점 복귀, 저장 중 버튼 상태 확인.
2. 개인 카드·공개 요청·임시 저장·기존 카드 수정의 저장 결과 확인.
3. 마이페이지 열기·항목 전환·이전 화면 복귀 후 카드 선택과 연습 상태 유지 확인.
4. USB 연결 전·후·분리·응답 중단 상태와 실제 태그 → 문장 추가 → TTS 확인.
5. 연습 종류·범위의 키보드 선택, 기본 설정으로 시작, 보호자가 준비한 연습 시작 확인.
6. 태블릿·좁은 화면·확대 화면에서 잘림·스크롤·초점 표시와 고대비 모드 확인.

<a id="post-mvp-implementation--아동-핵심-화면-단순화"></a>
#### 아동 핵심 화면 단순화

- 홈의 큰 활동 선택을 `말하기`·`연습하기` 두 개로 줄였다. 이어서 말하기는 같은
  말하기 버튼에서 제공하고, 내 카드와 주제별 탐색은 보조 진입점으로 정리했다.
- 저장된 빠른 표현은 모든 화면에서 유지하며 홈·연습에서는 작게 표시한다. 표현 수정은
  말하기 화면에 두고, 이전 문장·다시 듣기 도구는 필요할 때 펼치도록 했다.
- 문장 다듬기와 추천 카드는 기본으로 접는다. 생성 중·결과·실패 시 문장 영역을 펼치며
  기본 카드 발화는 바로 사용할 수 있다. 아동 화면의 추천 알고리즘 버전 표시는 제거했다.
- 리더기 영역은 상단 메뉴에서 열거나 태그가 추가됐을 때 말하기 화면에 표시한다.
  USB 세션은 유지하고 오프라인 음성 준비 안내·재시도는 연결 메뉴로 모았다.
- 연습 종류·범위 변경과 최근 기록은 기본으로 접고, 현재 선택과 시작 버튼을 먼저
  제공한다. 연습 불가 범위에서는 변경 영역을 펼친다. 펼친 채로 종류·범위를 바꿀 수 있다.
- 카드 순서·사용자 설정·학습 상태·발화 동작은 변경하지 않았다.
- 검증: JSX 5개·CSS 3개 구문 검사와 `git diff --check` 통과. 커밋용 `App.jsx`와
  작업 파일의 Rolldown 변환 결과 일치를 확인해 기존 포맷 변경을 제외했다.
- 자동 테스트·빌드·브라우저·실기기 검증은 사용자 요청에 따라 미실행이다. 홈 진입,
  접기·펼치기와 연습 변경, 생성 결과 표시, USB 태그 후 영역 자동 열기는 수동 확인이 남는다.

<a id="post-mvp-implementation--연결-메뉴-정렬과-인터페이스-아이콘-통일"></a>
#### 연결 메뉴 정렬과 인터페이스 아이콘 통일

- 리더기 연결 메뉴를 `상태 점 / 문구 / 화살표`의 고정 열로 배치했다. 글자 화살표를
  SVG로 바꾸고 중앙 정렬했으며, 열림 상태에서는 같은 자리에서 회전한다.
- 공통 `UiIcon`으로 메뉴·마이페이지·홈·랜딩·연습·등록·순서 편집·발화 조작의
  아이콘을 통일했다. 같은 viewBox·선 굵기·선 끝 모양과 기본 크기를 사용한다.
- 일반 펼침 메뉴의 브라우저 기본 삼각형도 같은 SVG 경로의 화살표로 통일했다.
  그림카드의 이미지와 표현 기호는 유지한다. 아이콘만 있는 조작의 기존 접근성 이름은
  유지하고 SVG는 보조기술에서 중복 낭독하지 않도록 처리했다.
- 검증: JSX 11개·CSS 2개 구문 검사, 정적 아이콘 이름·설정 매핑 검사와
  `git diff --check` 통과. 커밋용 `App.jsx`와 작업 파일의 변환 결과 일치를 확인했다.
- 자동 테스트·빌드·브라우저·실기기 검증은 사용자 요청에 따라 미실행이다.
  연결 상태별 정렬·열림 화살표 방향, 좁은 화면의 메뉴와 고대비·동작 줄이기 표시,
  아이콘 단독 버튼의 초점·접근성 이름은 실제 브라우저에서 확인이 남는다.

<a id="post-mvp-implementation--자동-문장-생성과-그림-중심-문장띠-2026-11-01"></a>
#### 자동 문장 생성과 그림 중심 문장띠 (2026-11-01)

- 문장 다듬기 접기 메뉴와 수동 생성 버튼을 제거했다. 로그인한 AAC 사용자가
  자연스러운 문장 모드에서 카드를 선택·제거·재배치한 뒤 700ms 동안
  선택을 바꾸지 않으면 기존 문장 API로 자동 생성한다.
- 온라인·카드 로딩 완료·기존 보호자 동의가 확인된 말하기 화면에서만
  자동 요청한다. 동의를 자동 처리하지 않는다. 오프라인·동의 없음·단어
  즉시 발화 모드에서는 기존 기본 말하기를 유지한다.
- 자동 생성에도 기존 API의 문장 세션 저장 정책이 적용된다. 연속 선택은
  대기 시간으로 묶되, 쉬었다가 추가 선택하면 별도 세션이 생길 수 있다.
  모델을 병렬 호출하지 않으며 생성 중에도 카드 선택·삭제·이동을 허용한다.
- 요청 중 선택·순서·화면·계정·동의·연결 상태가 달라지면 늦은 응답을
  현재 문장에 적용하지 않는다. 진행 중인 서버 처리를 취소하는 것은 아니다.
  기존 요청이 끝난 뒤 최신 선택으로 다시 대기·생성한다.
- 생성 실패는 무한 자동 재시도하지 않는다. 직접 다시 시도할 수 있고
  고른 카드 그대로 말하기는 생성 성공 여부와 관계없이 유지한다.
- 자동 음성 재생은 하지 않는다. 생성 결과를 화면에서 확인한 뒤
  `이 문장 말하기` 한 번으로 발화한다. 별도 확인 버튼은 제거했다.
- 나의 문장은 카드 이미지와 이름을 표시한다. 이미지가 없으면 카드 이름으로
  대체한다. 중복 어휘 카드도 위치별로 구분한다. 화살표 버튼 대신 마우스·터치
  Pointer Events로 끌어 이동하며, 놓을 때만 순서와 생성 대기를 갱신한다.
- 끄는 카드 미리보기·놓을 위치 테두리·가장자리 가로 자동 스크롤을 제공한다.
  세로 터치 스크롤 및 포인터 취소 시 순서를 유지한다. 드래그 대안으로
  옮길 카드와 목적지 카드를 차례로 누를 수 있다. 키보드 좌우·Home·End로
  순서 이동, Escape로 선택 취소, 별도 빼기 버튼으로 삭제할 수 있다.
  이동 알림과 포커스 복원, 44px 삭제 조작 영역을 제공한다.
- 새 PNG 이미지는 수정하거나 커밋에 포함하지 않는다.

검증 상태:

- 읽기 전용·네트워크 없는 기존 로컬 Docker 이미지로 JSX 2개와 CSS 1개의
  구문 검사 및 변경분 공백 검사를 통과했다. 자동 테스트·전체 빌드는 미실행이다.
- 실제 모델·API·브라우저·터치 검증은 미실행이며 동작 검증 완료가 아니다.
  사용자 확인 항목: 연속 카드 선택 후 최종 문장 생성, 생성 중 재배치·삭제,
  늦은 응답 무시, 빈 문장·중복 카드·12장, 오프라인·동의 없음·단어 모드,
  실패 후 수동 재시도, 화면 이동·계정 전환 중 요청, 임의 음성 자동 재생 없음,
  마우스·터치 드래그 및 가장자리 스크롤·취소, 두 번 누르기·키보드 이동,
  작은 화면·고대비에서 그림과 포커스 표시를 확인해야 한다.

<a id="post-mvp-implementation--카드-듣기-제어와-주-메뉴-접기-정리-2026-11-01"></a>
#### 카드 듣기 제어와 주 메뉴 접기 정리 (2026-11-01)

- 원인: 카드 듣기와 문장 읽기는 공통 음성 재생 상태를 사용하지만,
  문장 다듬기에서도 그 상태로 재생 제어를 표시했다. 문장이 없어도
  카드 음성이 재생되면 문장 다듬기에 일시 정지·중지 버튼이 나타났다.
- 음성 일시 정지·재개·중지는 기존 상단 재생 패널 한곳에 유지한다.
  문장 다듬기에는 생성된 문장 확인·읽기·다시 만들기만 남긴다.
  다른 음성이 재생 중일 때 문장 읽기·재생성 비활성화는 유지한다.
- 이전 집중 화면 버튼과 전용 화면 축소 규칙을 제거했다.
  모든 로그인 역할에서 본문 왼쪽 상단의 삼선 버튼으로 주 메뉴를
  접고 펼친다. 버튼은 메뉴 바깥에 두어 접힌 상태·마이페이지에서도
  유지한다. 페이지 이동 시 접기 상태를 유지하고 계정 변경 시 초기화한다.
- 접힌 메뉴는 `hidden`으로 키보드·접근성 탐색에서도 제외한다.
  버튼에는 동작 이름, `aria-controls`, `aria-expanded`를 제공하며
  44px 조작 크기와 기존 포커스·고대비 색상 체계를 유지한다.
  메뉴 접기 외에 빠른 표현 설명·간격 등을 바꾸던 집중 화면 효과는 없다.
- 새로 추가된 카드 PNG는 수정하거나 커밋에 포함하지 않는다.

검증 상태:

- 읽기 전용·네트워크 없는 기존 로컬 Docker 이미지에서
  Rolldown으로 JSX 2개, Lightning CSS로 CSS 1개 구문 검사를 통과했다.
- `git diff --check`를 통과했고 이전 집중 화면 코드 참조가 없음을 확인했다.
- 자동 테스트·전체 빌드·실제 브라우저 음성 및 반응형 검증은 미실행이다.
  실제 동작 검증 완료로 표시하지 않는다. 사용자가 확인할 항목:
  카드 듣기 중 문장 다듬기에 재생 제어가 생기지 않는지,
  상단 음성 일시 정지·재개·중지와 문장 확인 후 읽기가 동작하는지,
  데스크톱·모바일·고대비에서 삼선 버튼을 키보드로 반복 조작할 수 있는지,
  메뉴를 접은 채 화면 이동·마이페이지 진입 후에도 펼칠 수 있는지.

#### 민트·크림 공통 색상 체계

- `styles.css` 최상단에 역할별 색상 토큰 23개를 정의했다. 실제 HEX 값은
  반투명 장식·그림자·오버레이·고대비 검정을 포함한 22종이다.
  `--color-on-action`은 흰색 표면 토큰의 별칭이다.
- 기존 CSS 4개의 직접 색상 선언을 토큰 참조로 통합했다. 같은 HEX라도
  본문·액션·경고·오류·선택 등 적용 역할을 구분했다. 기존 `--ui-*`와
  `--landing-*`는 공통 토큰의 별칭으로 연결했다.
- 홈·말하기·연습·카드 목록·리더기·마이페이지·보호자 관리·랜딩에 적용했다.
  레이아웃·카드 순서·카드 이미지·발화·권한·개인화 로직은 변경하지 않았다.
- 카드 순번별 배경색과 추천 카드 제목의 서로 다른 색상 띠를 제거했다.
  그림카드는 흰색, 선택 영역은 연한 민트와 진한 테두리로 구분한다.
  카테고리 선택에는 하단 선, 카드 상세 선택에는 안쪽 테두리를 추가했다.
  기존 연습 종류·범위의 체크 표시와 라디오 입력은 유지했다.
- 오류·성공·경고는 별도 전경·배경 토큰을 사용한다. 상태 문구와 아이콘은
  유지하며, 리더기 연결 점에는 성공 전경색을 사용한다.
- 키보드 포커스 파랑과 흑백 고대비 모드를 유지했다. 고대비 모드에서

- HTML 테마와 웹 앱 매니페스트도 민트·크림으로 변경했다. 그림·로고 파일,

  효과 입증이나 AAC 사용성 검증 완료로 해석하지 않는다.

### PDF 시안 기반 보호자 UI

<a id="caregiver-ui-reference--기준과-범위"></a>
#### 기준과 범위

- 사용자 제공 `uxpilot-export-11-01-26 (1).pdf` 13쪽을 로컬에서 렌더링하고
  텍스트와 화면을 확인했다. 보호자용 9~13쪽을 직접적인 구현 기준으로 삼았다.
- 크림 배경·흰 사이드바·민트색 선택 상태·큰 라운드 콘텐츠 카드·일관된 아이콘과
  여백을 기존 디자인 토큰으로 적용한다. 새 색상 팔레트·아이콘 패키지는 추가하지 않는다.
- `.app.caregiver-ui`로 스타일을 제한한다. 지원 담당자·아동·랜딩의 테마는
  바꾸지 않는다. 공통 컴포넌트의 기능·서버 API·권한·동의 조건도 유지한다.
- 원본 PDF나 시안의 인물 사진은 저장소에 복사하지 않는다. 기존 마스코트와
  실제 계정 프로필을 사용한다. 사용자가 추가한 카드 PNG도 커밋하지 않는다.

<a id="caregiver-ui-reference--화면별-반영"></a>
#### 화면별 반영

| 시안 | 적용 화면 | 반영 내용 |
| --- | --- | --- |
| 9쪽 | 보호자 지원 홈 | 민트색 개요 패널, 4열 작업 카드, 사용자 선택, 별도 추천 연습 영역 |
| 10쪽 | 설정·마이페이지 | 왼쪽 고정 폭 영역 메뉴, 오른쪽 세로 설정 카드, 아이콘 헤더 |
| 11쪽 | 개인 카드 관리 | 제목·등록·사용자 도구 모음, A4·일괄 등록 접기 패널, 빈 목록 안내 |
| 12쪽 | 의사소통 기록 | 넓은 기록 탭, 집계 범위 안내, 사용자·기간 필터, 지표·차트·기록 카드 |
| 13쪽 | RFID 카드판 | 민트색 바깥 패널, 흰 USB 리더기 카드, 일관된 연결 조작 영역 |

- 설정 페이지의 세로 메뉴는 실제 영역으로 이동하고 해당 제목에 포커스를 준다.
  설정 카드를 모두 유지해 메뉴 이동 시 폼을 새로 마운트하지 않는다.
- 마이페이지 프로필은 로그인한 보호자 자신의 프로필이다. 아이 프로필처럼
  이름을 바꿔 표시하지 않는다. 연결된 아이의 음성·접근 설정은 기존 권한 기반
  관리 경로를 유지하며 그 화면도 동일한 카드형 스타일로 정리한다.
- 시안의 학습 단계, 화면 이탈 잠금, 4자리 보호자 잠금, 가상의 연결 전문가,
  캐릭터 음성, 보상 점수·사용 시간·증가율 등 미구현 기능·예시 수치는 추가하지 않는다.
- 의사소통 기록과 학습 기록은 기존처럼 별도 권한·집계로 유지한다.
  현재 지원하는 CSV·JSON 내보내기를 존재하지 않는 PDF 내보내기로 바꾸지 않는다.
- 실제 USB 연결 버튼·상태·로그, 사진 등록·A4 인쇄·추천 승인·설정 저장과
  권한이 없는 메뉴의 노출 조건을 그대로 유지한다.
- 이전 요청의 삼선 메뉴 접기·펼치기와 본문 바로가기, 포커스 표시도 유지한다.

<a id="caregiver-ui-reference--반응형접근성"></a>
#### 반응형·접근성

- 넓은 화면의 작업 카드는 4열, 1000px 이하에서 2열, 아주 좁은 화면에서 1열이다.
  모바일의 가로 메뉴, 설정 영역 줄바꿈과 카드 한 열 배치를 제공한다.
- 기본 버튼 크기·명시적인 라벨·상태 문구·테두리와 키보드 포커스를 유지한다.
  고대비에서는 무테 작업 카드에도 명확한 경계를 제공한다.
- 장식 효과를 위한 새 애니메이션은 넣지 않고 보호자 버튼의 이동 호버 효과를 제거한다.

<a id="caregiver-ui-reference--검증-상태"></a>
#### 검증 상태

- PDF의 기본 권한 렌더링은 임시 모듈 파일 접근 제한으로 실패했다.
  승인된 로컬 읽기·렌더링으로 13쪽 전체를 확인했다. PDF는 외부에 전송하지 않았다.
  임시 PDF 도구만 사용했으며 프로젝트 의존성은 변경하지 않았다.
- 읽기 전용·네트워크 없는 기존 로컬 Docker 이미지에서 JSX 2개와 CSS 1개의
  정적 구문 검사 및 변경분 공백 검사를 통과했다.
- 전체 빌드·자동 테스트·실제 브라우저 렌더링·픽셀 비교·기기 반응형 검증은
  미실행이다. 시안과 실제 화면의 시각적 일치 검증 완료로 표시하지 않는다.
- 사용자 확인 항목: 지원 홈 4열·2열과 설명 줄바꿈, 메뉴 접고 펼치기,
  사용자 변경 시 권한·데이터 전환, 개인 카드 등록·A4 편집 패널 열기,
  기록 탭·기간 필터·CSV/JSON, USB 연결·로그, 설정 영역 이동과 입력 유지,
  모바일·고대비·키보드 포커스 및 아동·지원 담당자 화면 회귀 여부.

## 보호자 UI 개선 진행 기록

<details>
<summary>상세 구현·설정·검증 기록</summary>

<a id="caregiver-ui-improvement-progress--보호자-ui-개선-진행-기록"></a>
### 보호자 UI 개선 진행 기록

기준: `docs/development/USER_INTERFACE.md#caregiver-ui-plan-history`. 과거 PDF 구현 기록은 유지한다.
코드 구현·브라우저 확인·실제 보호자/기기 검수를 구분한다.

<a id="caregiver-ui-improvement-progress--1단계--공통-가독성과-표면"></a>
#### 1단계 — 공통 가독성과 표면

- 실제 로컬 앱을 분리된 임시 Chrome 프로필로 열고 기존 보호자 계정으로 확인했다.
  변경 전 홈·카드·설정을 1440/1024/768/390px에서 임시 캡처했다.
  기본 권한의 브라우저 경로 조회는 제한됐지만 승인된 로컬 실행으로 확인했다.
- 본문·입력 16px, 보조 14px, 제목 24~28px와 영역 제목 20px을 출발점으로 적용했다.
  작은 프로필 설명·권한 안내·필터 글자를 키웠다.
- 민트색 바깥 홈 패널과 반복 그림자·큰 모서리를 줄이고 선·여백으로 구분한다.
  모바일 작업 카드를 목록형으로 바꾸고 보호자 전용 범위를 유지했다.
- 검증: 변경 전 3개 화면·4개 폭 캡처에서 페이지 가로 넘침 없음.
  변경 후 홈 1440/390px에서 설명 14px·버튼 글자 16px와 넘침 없음을 확인했다.
  JSX 6개·CSS 정적 구문과 공백 검사를 통과했다. 전체 빌드는 4단계에서 수행한다.
- 실제 보호자 과업·실물 USB·음성 검증은 미실행이며 전체 완료로 표시하지 않는다.

<a id="caregiver-ui-improvement-progress--2단계--홈과-아이-선택"></a>
#### 2단계 — 홈과 아이 선택

- 보호자 전용 홈을 분리해 아이 선택 → 현재 관리 대상/연결 상태 → 주요 작업
  3개 → 연습 제안 → 보조 관리 목록으로 정리했다. 권한별로 항목을 필터링한다.
- 지원 메모 안내 카드는 제거하고 기록 보기 설명에 포함했다. 홈에 없는 통계를
  임의로 0이나 점수로 표시하지 않는다. 추천의 동의·기록 없음·오류 상태는 유지한다.
- 연결 없음에는 아이 계정의 프로필/보호자 설정에서 연결하는 실제 절차와
  보호자 아이디를 안내한다. 새 연결 API나 권한 자동 부여는 추가하지 않는다.
- 실제 계정 홈을 1440/1024/768/390px에서 캡처했고 주요 작업 3개·보조 3개,
  페이지 가로 넘침 없음을 확인했다. JSX 7개·CSS 구문과 공백 검사 통과.
- 실제 복수 아이·무권한·연결 없는 계정 검수와 실기기·보호자 과업은 미실행이다.
  해당 분기의 코드와 기존 권한 조건을 대조했으며 실제 검수 완료로 간주하지 않는다.

<a id="caregiver-ui-improvement-progress--3단계--카드와-연습-관리"></a>
#### 3단계 — 카드와 연습 관리

- 개인 카드 검색·분류, 로딩/검색 결과 없음/카드 없음 구분을 제공한다.
  등록·일괄 등록 성공 안내에 대상 아이와 카드명을 표시하고 등록 항목 보기와
  카드판 관리 이동을 제공한다. 카드판 위치는 자동 변경하지 않는다.
- 카드 등록 응답은 계정·토큰·아이 대상이 그대로일 때만 화면에 적용한다.
  아이 변경 시 검색과 등록 안내를 초기화한다.
- 보호자 메뉴를 연습 관리로 바꾸고 제안에 활동·카드·문제 수·짧은 근거와
  검토 동작을 먼저 표시한다. 표본·출처는 상세로 옮기고 개인화 상태는 남긴다.
- 준비한 연습과 의견은 실제 완료를 뜻하지 않음을 명시한다. 과거 의견의
  내부 후보 ID 대신 활동명·날짜 또는 중립적인 ‘이전에 준비한 연습’을 표시한다.
  기존 API만 사용하며 과거 후보명을 얻기 위한 API 확장은 추가하지 않았다.
- 실제 계정에서 제안 3개와 출처 기본 접힘·검토 열기, 카드 검색 UI,
  카드 화면 1440/390px 캡처와 가로 넘침 없음을 확인했다.
  JSX·CSS 정적 구문과 공백 검사를 통과했다.
- 실제 카드 생성·수정·인쇄와 연습 준비·의견 저장은 실제 데이터를 바꾸므로
  이번 화면 확인에서는 수행하지 않았다. 부분 실패·복수 아이 전환도 미검수다.

<a id="caregiver-ui-improvement-progress--4단계--기록설정rfid"></a>
#### 4단계 — 기록·설정·RFID

- 보호자 기록에서 짧은 집계 설명을 먼저 표시하고 해석 한계는 펼침으로 제공한다.
  CSV/JSON 내보내기도 보조 펼침 영역으로 옮겼으며 다운로드 전 개인정보 안내를 유지한다.
- 내 계정 설정과 아이 설정을 제목·대상으로 구분한다. 목소리·화면·연습의
  저장 결과는 대상 아이와 범위를 표시하고 실패 메시지도 대상을 포함한다.
- 아이 음성/화면과 연습의 미저장 변경에는 안내와 화면 이동 확인을 제공한다.
  내 계정 설정 영역 이동은 기존 폼을 유지한다. 아이 변경 및 늦은 설정 응답·
  오류·로딩 종료에 계정·토큰·대상·요청 순서 검사를 추가했다.
- RFID는 실제 USB 상태와 연결 조작·읽은 카드를 유지하고 포트·UID·로그는
  기본 접힌 상세로 옮겼다. 오류는 계속 노출한다. 리더기 생성/파괴나 읽기
  목록 초기화 로직은 변경하지 않았다. 실제 USB 연결 유지 검수는 별도다.
- 실제 화면에서 입력 선택 상자가 44px보다 작은 것을 발견해 최소 높이 44px로
  보완했다. 보호자 사이드바는 글자를 키운 상태에 맞춰 기본 폭 240px로 조정했다.

<a id="caregiver-ui-improvement-progress--수행한-검증"></a>
##### 수행한 검증

- 홈·카드·기록·아이 설정·연습 관리·RFID·내 계정 설정, 7개 화면을
  1440/1024/768/390px에서 실제 캡처했다. 모든 해당 화면에서 페이지 전체의
  가로 넘침이 없었다. 캡처는 임시 폴더에만 두고 개인정보 이미지를 커밋하지 않았다.
- 변경 전후 홈을 시각적으로 대조했고 실제 설명 14px·조작 글자 16px,
  아이 설정 선택 상자 44px을 확인했다.
- 실제 기간 필터를 최근 7일로 변경해 조회를 확인했다. 내보내기·집계 상세와
  RFID 진단 상세의 초기 접힘, 미저장 안내·이동 확인 취소, 메뉴 접기·펼치기를 확인했다.
- 임시 DOM의 긴 아이 이름에서도 모바일 가로 넘침이 없었다. 키보드 이동 후
  초점 5px 표시와 임시 고대비/동작 줄이기 클래스에서 넘침 없음·전환 0초를 확인했다.
  실제 계정에 고대비·동작 줄이기 설정을 저장하는 검증은 수행하지 않았다.
- 1440px 화면의 200% 확대에 상당하는 720 CSS px 리플로에서 넘침 없음을 확인했다.
  브라우저 자체 확대 200%의 전체 동작을 대체하지 않으며 원래 확대 검수는 남는다.
- 사용 중 토큰의 지정 색상 쌍 대비: 본문/크림 8.95:1, 보조/크림 5.84:1,
  액션/흰색 5.30:1, 조작 경계/흰색 3.63:1, 포커스/흰색 5.98:1.
  모든 상태의 전수 검사나 접근성 인증 결과가 아니다.
- 기존 아동·담당자 계정의 대표 실제 화면과 로그아웃 화면에서 보호자 테마가
  적용되지 않고 1440px 가로 넘침이 없음을 확인했다. 이 검수의 임시 로그인
  세션은 각 계정에서 로그아웃했으며 기존 사용자 브라우저 세션은 사용하지 않았다.

2026-10-24 사용자 요청: 아동의 개인정보 화면 강제 이동을 없애고 보호자 설정으로 분리한다.
동의가 없어도 카드 탐색·선택 카드 발화·긴급/복구 표현을 사용할 수 있다. 동의는 자동으로
체크하거나 서버에 대신 저장하지 않는다.

<a id="guardian-consent-flow--반복-화면의-코드상-원인"></a>
#### 반복 화면의 코드상 원인

기존 온라인·오프라인 로딩은 `guardian_consent`가 false/없는 경우 항상 개인정보 탭으로
이동했다. 이미 저장된 true 동의를 매 로그인 초기화하는 코드는 아니다. 화면에서 체크만
하고 **동의 및 기간 저장**을 누르지 않은 경우도 서버 값은 false다. 특정 사용자 DB의 실제
반복 원인은 조회하지 않았으며 테스트를 사용자 DB에서 실행하지 않는다.

<a id="guardian-consent-flow--변경한-흐름"></a>
#### 변경한 흐름

- 아동 주 메뉴에서 개인정보 버튼을 빼고 보호자 설정으로 옮긴다.
  2026-10-28부터 **이름·프로필 사진 → 마이페이지 → 보호자 설정**에서 관리한다.
  자세한 화면 구성은 [마이페이지 안내](USER_INTERFACE.md#my-page-settings)를 따른다.
  기본 말하기는 동의 화면으로 강제 이동하지 않는다. 저장된 동의는 이후 로그인에도 유지한다.
- 이 영역은 화면상의 관리 구분이다. 새 보호자 인증/PIN·법정대리인 신원 확인이나 연결된
  보호자 계정의 새로운 개인정보 쓰기 권한을 구현한 것으로 취급하지 않는다. 기존 계정
  소유자의 API 권한은 유지한다.
- 동의 편집 초안과 서버에서 확인된 동의를 분리한다. 체크만 바꿔도 수집이 켜지던 로컬
  상태 혼동을 막고, 서버 저장에 성공한 뒤에만 확정 값을 사용한다. 오프라인 저장은 막는다.
- 동의가 없으면 새 선택·발화 이력, 추천 노출/선택, AI 문장 생성/저장, 선택 카드의
  localStorage 초안, 학습 진행/완료 결과와 새 오프라인 기록을 저장·전송하지 않는다.
  문장 조합은 선택 카드 그대로 기기 음성으로 말한다. 연습 결과는 현재 화면에서만 본다.
- 동의가 없을 때 새로 읽는 카드/설정 스냅샷에도 false 상태를 유지하므로 캐시 복원 뒤
  동의 화면으로 보내거나 기록 수집을 켜지 않는다. 기존 동의 때 만든 대기 이력은 임의로
  삭제하지 않고, 동의가 없을 때 자동 동기화하지 않는다. 기기 TTS의 온라인/오프라인
  지원 한계는 기존 음성 정책과 같다.

이는 모든 계정 데이터·프로필·기존 서버 이력을 없애는 익명 모드가 아니다. 로그인 세션,
기존 사용자별 카드/설정 캐시와 기본 음성은 기존 범위로 남는다. 서버 이력/사진 삭제는
별도 명시적 개인정보 삭제를 사용한다. 서버의 동의 없는 문장·발화·학습·이미지 쓰기
거절은 제거하지 않았다. 실제 동의 고지·신원/정책 버전·법적 승인은 별도다.

### 흰색 페이지 배경과 원형 프로필 정리

<a id="white-surface-profile-refinement--원인과-변경"></a>
#### 원인과 변경

- 랜딩의 `section`은 경계·그림자·모서리만 초기화하고 배경은 초기화하지 않아
  공통 `section`의 민트색을 상속받았다. 고정 콘텐츠 폭의 첫 영역만 사각형으로
  칠해져 양옆 크림색 페이지와 분리돼 보였다.
- 랜딩 section의 배경을 명시적으로 투명화하고, 전체 페이지 배경 토큰은 흰색
  표면 토큰의 별칭으로 변경했다. 헤더·첫 영역·소개 영역이 동일한 흰 배경으로
  이어지며 제목·간격·구분선으로 영역을 나눈다.
- 공통 section 기본값과 문장판·로그인 화면의 장식용 배경도 흰색으로 정리했다.
  랜딩 예시 배지·문장·보호자 안내는 흰색과 구분선을 사용한다.
  실제 선택·주요 행동·오류·성공·경고·키보드 포커스 색상 토큰은 유지한다.
- 프로필 아바타는 흰 바탕·원형 윤곽선으로 표시하고 그림자를 제거한다.
  열린 내 계정 상태는 원형 선을 강조하며 사이드바의 프로필 버튼 전체를
  민트색 사각형으로 채우지 않는다.
- 프로필 선택에서는 사각 라벨의 색 배경·테두리를 제거하고 이미지의 원형 선으로
  선택을 표현한다. 선택한 이미지는 3px 선, 기본은 1px 선을 사용한다.
  라디오 입력·이름·키보드 초점과 기존 저장 동작을 유지한다.
- 원본 카드·프로필·사용자 사진은 수정하지 않는다. 사진 자체에 포함된 색이나
  장식은 CSS로 제거하거나 이미지 보정을 하지 않는다.

- CSS 3개 정적 구문 검사와 변경분 공백 검사, 프런트엔드 빌드를 통과했다.

### 메뉴 펼침·접기 아이콘 위치 정리

#### 변경

- 메뉴 아이콘의 상시 테두리·색 배경·그림자·둥근 박스를 제거했다.

  순환한다. 닫거나 큰 화면으로 전환하면 잠금을 해제한다.
- 보호자 테마의 일반 버튼 흰 배경 규칙보다 아이콘의 투명 배경이 우선하도록 했다.

- 최종 프런트엔드 빌드와 변경분 공백 검사 통과.

  발견해 수정했다. 로드 전 DOM 접근으로 중단된 검수도 앱 준비 대기로 수정 후 재실행했다.
- 실제 분리 Chrome에서 아동·보호자 각각 320·390·1000·1280px 확인:
  메뉴가 왼쪽에서 열리고, 아이콘은 브랜드 행 오른쪽 끝이며 border 0px·
  투명 배경이고 페이지 가로 넘침이 없었다.
- 1000px 이하에서 열릴 때 접기 버튼 초점, 본문 inert, Escape 닫기와
  펼치기 버튼으로의 초점 복귀를 확인했다. 390px에서 마지막 버튼 다음 Tab이
  접기 버튼으로 순환하는 것도 두 계정에서 확인했다.
- 1280px에서는 일반 사이드바를 유지하고 접기 및 초점 복귀를 확인했다.
  처음부터 펼쳐진 데스크톱 화면에 강제로 초점을 이동시키지는 않는다.
- 검수용 로그인은 로그아웃하고 분리 브라우저를 종료했다. 카드·설정은 저장하지 않았다.
- 바깥 클릭·메뉴 선택 자동 닫힘·실제 실기기 터치·Shift+Tab·스크린리더·
  모든 역할과 화면·USB·TTS 전수 검수는 미실행이다.
- 사용자 카드 PNG와 수정 중인 제작 체크리스트는 변경·커밋하지 않는다.

- 빠른 표현·복구 표현은 가능한 열 수로 자동 배치하고 긴 문구는 줄바꿈한다.
- 카드 목록은 화면 폭과 사용자 카드 크기 설정을 함께 반영한다.
- 보호자 테마의 기존 반응형 스타일과 우선순위 충돌을 정리했다.
  구현은 `responsiveUx.css`에서 기존 테마 뒤에 로드한다.

<a id="compact-responsive-layout--확인-결과"></a>
#### 확인 결과

- 최종 프런트엔드 빌드와 변경분 공백 검사 통과.
  기존 500kB 초과 청크 경고는 남아 있다.
- 분리 실행한 실제 Chrome에서 아동 말하기 화면을 320·390·640·768·1000·
  1280px로 확인했다. 메뉴 열림/닫힘 모두 페이지 가로 넘침이 없었다.
  1000px 최초 확인에서 문장판 로드가 끝나지 않아 다시 기다려 확인했다.
- 390×700px 화면에 12장 구조를 임시 DOM으로 주입하여 레이아웃만 확인했다.
  페이지 가로 넘침 없이 카드 줄 내부가 스크롤되고, 페이지를 내리면 문장판의
  상단 좌표는 0px·높이는 250px였다. 실제 12장 선택·저장 검수는 아니다.
- 최종 보호자 화면은 320·390·768·1000px에서 메뉴 열림/닫힘과 두 열 grid,
  가로 넘침 없음을 확인했다. 다른 보호자 하위 화면 전수 검수는 미실행이다.
- 390px 빈 문장판·임시 12장 스크롤 화면을 캡처해 확인했다. 캡처는 커밋하지 않는다.
- 검수 로그인은 로그아웃했고 분리 실행한 브라우저만 종료했다.
  카드·설정·동의·프로필·연습 데이터의 저장은 수행하지 않았다.

  및 접근성 상태 전수 검수는 미실행이다. 현장 승인으로 간주하지 않는다.
- 사용자가 수정한 제작 체크리스트와 추가 카드 PNG는 변경하거나 커밋하지 않는다.

### 반짝이 버튼으로 문장 생성 후 바로 발화

- 카드·화면·계정·동의가 바뀐 요청은 기존 컨텍스트 확인으로 버린다.
  요청 이후 다른 음성이 시작되거나 중지했다면 뒤늦은 결과를 자동 발화하지 않는다.
- 새 결과의 세션 ID를 발화 기록에 직접 전달해 React 상태 반영 전에도
  직전 세션과 혼동하지 않도록 했다. 화면 전용 출처·횟수·확인 상태를 정리했다.

<a id="speaking-card-folders--말하기-카드-탭과-폴더"></a>
### 말하기 카드 탭과 폴더

> 후속 변경: [대표 그림과 통합 격자](USER_INTERFACE.md#symbol-folder-covers)를 적용했다.
> 카드의 별·개별 듣기는 `카드 도구`를 펼쳐 사용하며, 홈 카드와 폴더를 같은 격자로 표시한다.

<a id="speaking-card-folders--화면-구성"></a>
#### 화면 구성

- `무엇을 말하고 싶나요?` 대신 홈·즐겨찾기·긴급어·감정·시간/일정 분류를 표시한다.
- 홈의 기본 카드는 좋아요·싫어요·도와주세요 순서다. 실제 사용 가능한 카드만 표시한다.
- 나머지는 기존 카드 분류와 보호자가 저장한 상황 카드판을 그림 미리보기가 있는
  폴더로 표시한다. 기본 카드판·모든 카드·다시 말하기 폴더도 제공한다.
- 폴더를 열면 관련 카드가 표시되고 목록으로 돌아올 때 해당 폴더로 초점을 복귀한다.
  기본·상황 카드판 폴더에서는 저장된 슬롯 순서를 따른다.
- 현재 카드판 표시·말하기 상세설정·기존 카테고리 버튼 열을 제거했다.
  말하기 화면의 중복 빠른 표현 목록은 홈 카드와 긴급어로, 복구 표현은
  다시 말하기 폴더로 접근한다. 다른 화면의 빠른 표현은 유지한다.
- 이전 문장·다시 듣기와 추천은 유지하며 카드 목록 뒤에 배치한다.

<a id="speaking-card-folders--데이터와-동작"></a>
#### 데이터와 동작

- 긴급어는 `safety_relevant`, 감정은 기존 감정 분류와 semantic_group을 사용한다.
  시간/일정은 시간·일정·날짜 분류 또는 관련 semantic_group을 사용한다.
  해당 카드가 없으면 빈 상태이며 새 단어·가짜 그림을 생성하거나 DB에 등록하지 않는다.
- 검색은 홈에서 사용 가능한 전체 카드, 나머지 탭·폴더에서는 해당 범위에 적용한다.
  사용자별 카드 수/페이지 설정과 카드 크기 설정을 유지한다.
- 선택 카드는 기존 발화 모드에 따라 문장 담기 또는 단어 발화를 한다.
  복구 표현은 기존대로 직접 발화하며 문장 생성에 잘못된 카드 ID를 넣지 않는다.
- 카드 ID·원본 사진·권한·카드판 설정·잠금 데이터는 수정하지 않는다.
  새 탭·폴더는 탐색용이며 기존 단일 카드판 화면의 고정 위치를 그대로 보여 주는
  모드는 아니다. 카드판 폴더 내부만 저장된 순서를 따른다.
- 기록 상황 상세 선택 UI를 제거했으며 폴더 이동을 기록 상황으로 추정하지 않는다.

<a id="speaking-card-folders--즐겨찾기"></a>
#### 즐겨찾기

<a id="landing-page--구성과-동선"></a>
#### 구성과 동선

- 첫 화면: 프로젝트 소개, 카드 3장으로 문장을 표현하는 정적 사용 예시와 시작하기.

- FAQ: 리더기 선택 사용, PC·태블릿과 USB 브라우저 조건, 오프라인 준비, 개인정보·기록 관리.

첫 진입 때 하단 폼으로 자동 초점을 주지 않으므로 소개가 먼저 보인다. 가입 전환 시 개인정보 동의는
체크하지 않은 상태로 시작하며 기존 필수 동의와 명시 제출을 유지한다. 보기만 해서는 인증·기록 API를
호출하지 않으며 예시가 실제 문장 생성·리더기 연결·음성 재생을 실행하지 않는다.

로그인·프로필 설정 뒤 앱 화면의 처음으로 이동하고, 유효한 기존 세션은 소개를 거치지 않고 앱으로
복원한다. 로그아웃하면 소개 처음으로 돌아가며 가입 초안·동의 체크와 비밀번호를 초기화한다.
인증 오류는 기존 폼에서 표시하고 해당 위치로 이동한다. 별도 라우터·새 인증 API·외부 서비스를
추가하지 않았다. 기존 프로필·동의·지원 권한·오프라인 세션 정책을 유지한다.

#### 사용자 요청 반영

- 소개 영상 버튼·영상 플레이어·외부 임베드는 넣지 않는다.

- 장치·센서·언어모델 모델명은 랜딩에 노출하지 않는다. 실물 카드 태그가
  가능하다는 기능 설명만 사용하고, 화면 터치만으로도 사용할 수 있음을 안내한다.
- 카드 태그 연결과 화면 카드 사용의 브라우저 지원 범위를 구분한다.
  모든 태블릿·모든 브라우저에서 장치 연결이 된다고 표현하지 않는다.
- 영상·후기·카드 상점·고객센터·팀 소개처럼 실제 제공되지 않는 경로를 만들지 않는다.
  PDF의 학습 효과 극대화·오류 없는 조작·발화 향상 보장 등의 문구도 사용하지 않는다.
- 실제 기존 로그인·가입 핸들러와 필드·동의 상태를 유지한다.
  예전 랜딩의 카드 미리보기 전달과 불필요해진 스타일은 정리했다.
- 고정 헤더가 로그인 폼과 앵커 제목을 가리지 않도록 스크롤 여백을 둔다.

<a id="landing-pdf-redesign--검증"></a>
#### 검증

- 최종 프런트엔드 빌드와 변경분 공백 검사 통과.
  기존 500kB 초과 JS 청크 경고는 남아 있다.
- 실제 분리 Chrome에서 320·390·768·1024·1440px의 페이지 가로 넘침 없음을 확인했다.

## 목표와 범위

보호자가 아이를 선택하고 카드·연습·기록을 관리할 때 읽고 판단해야 하는 부담을 줄인다.
기존 MVP 이후 개선이며 기능 추가보다 시각적 위계와 다음 행동 안내를 우선한다.
앞선 평가는 코드·스타일·문서 기반 가설이다. 구현 전 실제 화면에서 재확인한다.

대상은 보호자 홈, 개인 카드, 연습 관리, 기록, 아이 설정, 보호자 자신의 설정,
RFID 관리다. `.app.caregiver-ui` 범위와 명시적인 보호자 variant를 사용한다.
아동·담당자·랜딩 화면, 서버 권한·동의, 카드 위치, 발화·학습 엔진은 유지한다.
새 AI 모델·통계·인증 수단·아이 연결 API 개발은 이번 범위에 포함하지 않는다.

참고: [기존 보호자 UI 구현 기록](USER_INTERFACE.md#caregiver-ui-reference),
[MVP 이후 요청서](USER_INTERFACE.md#post-mvp-plan-history).
기존 PDF 기반 스타일 중 이번 계획과 충돌하는 큰 패널·균등 카드 배치는 재조정한다.
과거 구현·검증 이력을 덮어쓰지 않고 후속 결과를 별도로 기록한다.

## 1. 시각적 설계 기준

아래 수치는 구현 출발점이며 실제 화면에서 줄바꿈·밀도·접근성을 확인해 조정한다.

| 항목 | 개발 기준 | 완료 확인 |
|---|---|---|
| 글자 | 본문·입력 16px, 보조 설명 14px, 화면 제목 24~28px, 영역 제목 20px | 중요한 안내를 작은 글자로 밀어내지 않음 |
| 행간 | 본문 1.5~1.7, 제목 1.3~1.4 | 긴 이름·오류·안내가 잘리지 않음 |
| 여백 | 8/16/24/32px 중심으로 통일 | 영역 구분을 중첩 카드 대신 여백과 제목으로 표현 |
| 표면 | 페이지 배경 + 주 콘텐츠 표면 중심, 안쪽은 선·목록 사용 | 장식 목적의 색 패널 안에 카드가 반복되지 않음 |
| 모서리·그림자 | 카드 12~16px, 버튼 8~12px, 그림자는 부유 요소에 제한 | 모든 영역이 동일하게 튀어나와 보이지 않음 |
| 색 | 기존 팔레트를 유지하고 배경·선택·행동·상태 역할을 구분 | 색 외에도 텍스트·아이콘·테두리로 상태 식별 |
| 버튼 | 작업 영역별 주 행동 1개, 보조는 테두리, 이동은 텍스트 중심 | 저장·이동·삭제가 동일한 강조로 경쟁하지 않음 |
| 조작 | 주요 터치 대상 최소 44×44px를 제품 목표로 적용 | 글자를 키워도 버튼 겹침·잘림 없음 |

권한·구현 방식 설명은 보조 안내로 옮기되 기록 범위·실패·삭제 영향 같은 필수 정보는
숨기지 않는다. 데이터 표는 14px 이상을 출발점으로 하고 긴 값·모바일은 상세 보기로 보완한다.
새 색상·폰트·아이콘 패키지 도입보다 기존 토큰과 UiIcon을 우선한다.

## 2. 화면별 변경

### 보호자 홈

배치: 아이 선택 → 현재 상태 → 자주 쓰는 작업 → 이번에 해볼 연습 → 기타 관리.

- 선택한 아이 이름을 상단에 유지한다. 보호자 자신의 이름과 구분한다.
- 동일 크기 작업 카드 4~6개 대신 개인 카드·연습 관리·기록 보기의 핵심 동선을
  먼저 배치하고 음성·화면·카드판·RFID 등은 보조 목록으로 정리한다.
- 권한이 없는 기능은 접근 조건을 유지한다. 메뉴 수에 따라 빈 칸이 남지 않게 한다.
- 최근 기록과 준비한 연습은 기존 API가 허용하는 데이터만 표시한다.
  홈에 없는 데이터가 필요하면 우선 링크로 제공하고 신규 집계 API는 별도 제안한다.
- 기록 없음·조회 실패·동의 없음·권한 부족을 구분한다. 없음을 0점/미사용으로 표시하지 않는다.
- 클릭되지 않는 지원 메모 안내 카드는 기록 보기의 보조 설명으로 옮긴다.
- 모바일에서는 큰 작업 카드를 반복하지 않고 제목·설명·이동 표시가 있는 목록을 사용한다.

### 첫 사용과 연결 안내

- ‘연결된 사용자가 없습니다’ 다음에 현재 지원하는 연결 방법과 이동 경로를 설명한다.
- 보호자 계정에서 직접 연결할 API가 없으면 없는 버튼을 만들지 않는다.
  아이 계정에서 연결하는 기존 절차와 준비할 정보를 안내한다.
- 보호자 화면의 ‘지원할 사용자’는 ‘아이 선택’, ‘연결 사용자’는 문맥에 맞게
  ‘연결된 아이’로 바꾼다. 담당자 화면의 용어는 유지한다.

### 개인 카드 관리

- 제목·아이 이름·주 등록 버튼을 상단에 묶고 검색·분류를 다음 줄에 배치한다.
- 개별 등록은 주 행동, 일괄 등록·A4 편집/인쇄는 보조 도구로 구분한다.
- 카드 상태를 사용 중·작성 중·승인 대기 등 명확한 텍스트로 표시한다.
- 등록 완료 후 등록한 카드 보기와 기존 카드판 관리 이동을 제공한다.
  카드판에 자동 배치하거나 기존 위치를 변경하지 않는다.
- 긴 이름·이미지 없음·업로드 중·부분 실패에 같은 레이아웃 원칙을 적용한다.

### 연습 관리와 AI 제안

- 메뉴 ‘학습 기록’은 실제 기능에 맞게 ‘연습 관리’로 바꾸고 설정과 기록을 구분한다.
- 추천은 활동 이름 → 사용 카드/문제 수 → 짧은 근거 → 검토 버튼 순서로 보여준다.
- 표본·기간·모델/규칙 출처는 상세에서 확인하게 하고 개인화 상태는 명확히 표시한다.
- 준비 완료에는 대상 아이와 아이 계정에서 시작하는 위치를 안내한다.
- 보호자 의견은 연습 후 남길 수 있게 위치와 문구를 정리한다. 완료 여부와 별개라는
  기존 의미를 유지하고, 세션 완료와 연결되지 않았는데 ‘사용 후’로 단정하지 않는다.
- 최근 의견의 내부 candidate_id는 활동 이름·날짜로 대체한다.
  기존 응답만으로 이름을 복원할 수 없으면 중립적인 표시를 사용하고 API 확장은 별도 기록한다.

### 의사소통·학습 기록

- 아이·기간·기록 종류를 상단에 묶고 요약 → 추이/카드 → 상세 기록 순서로 배치한다.
- 집계 기준은 짧은 핵심 설명을 먼저, 해석 한계·상세 정의는 펼침으로 제공한다.
- CSV/JSON 내보내기는 보조 조작으로 구분한다. 실제 형식과 권한을 유지한다.
- 차트 색에만 의존하지 않고 항목명·값을 함께 제공한다.

### 설정과 RFID

- ‘내 계정 설정’과 ‘아이 설정’을 제목과 대상 이름으로 명확히 구분한다.
- 설정은 기능별 구획·설명·저장 버튼을 붙여 저장 범위를 분명히 한다.
- 현재 유지되는 폼을 메뉴 이동 때문에 재마운트하지 않는다.
- 저장 결과에 대상·성공/실패를 표시하고 미저장 입력의 이동 동작을 점검한다.
- RFID는 연결 상태·연결 조작·최근 읽은 카드가 먼저 보이게 한다.
  포트·UID·진단 로그는 상세 영역으로 묶되 오류와 재시도는 노출한다.
- 장식 패널을 줄이는 변경으로 USB 연결이 끊기거나 읽기 목록이 초기화되지 않아야 한다.

# MVP 이후 UX 개선과 AI 연습 제안 개발 요청서

작성일: 2026-10-29

## 상태와 목적

사용자가 기존 MVP 완료를 선언했으며, 이 문서는 이후 개선 개발의 범위다.
과거 문서의 실물·운영 검수 이력은 소급해서 통과로 바꾸지 않는다.
이 문서 작성으로 기능 구현이나 모델 성능 검증이 완료된 것은 아니다.

목표는 아동의 기본 말하기를 단순화하고, 보호자·담당자가 사용 기록에 맞는
연습을 선택하도록 돕는 것이다. 아래 단계는 순서대로 개발하되 각 단계는
코드·문서·관련 검증을 포함한 완결된 기능 단위로 커밋한다.

## 1. 개발 순서

| 단계 | 결과물 | 완료 조건 |
|---|---|---|
| A | 아동 말하기 화면 단순화 | 카드 선택 → 발화가 기본 경로이며 AI 장애와 무관하게 동작 |
| B | 보호자 설정 경계와 시작 방식 | 중요한 설정의 성인 확인, 홈/말하기 시작 선택과 저장 |
| C | 기록 기반 연습 후보와 설정 미리보기 | AI 없이도 허용된 활동을 제안·검토·명시 시작 가능 |
| D | Ollama 연습 제안 | 검증된 후보 중 제안하며 실패 시 규칙 후보로 대체 |
| E | 추천 피드백과 실제 기기 검수 | 피드백 저장·삭제, 권한·전환·발화 회귀와 관찰 결과 기록 |

### A. 말하기와 학습 UX

- 말하기는 카드판, 고른 카드, 말하기, 선택 취소를 중심으로 구성한다.
- 빠른 표현·복구 표현·핵심 카드 위치와 기존 사용자 설정은 유지한다.
- 신규 사용자의 기본 발화는 선택 카드 그대로 말하기로 한다. 기존 사용자의
  발화 방식은 자동 변경하지 않고 보호자가 명시적으로 바꾸도록 한다.
- 출력 방식·기록 상황·AI 생성 정보는 보호자 설정 또는 상세 영역으로 이동한다.
- AI 문장 생성은 선택 기능이며 기존 의미 보존·확인 절차를 유지한다.
- 문장 상단 고정 영역은 작은 화면에서 카드판과 필수 발화 버튼을 가리지 않게 한다.
- 홈의 추상적인 기호는 기존 카드/행동 이미지로 대체한다. 아동 안내는 짧게 쓴다.
- 학습 문제 수·반복·재도전은 보호자가 미리 설정하고 아동은 활동을 시작한다.
- 집중 화면, 키보드·보조 입력, 고대비·동작 줄이기와 오프라인 경로를 보존한다.

### B. 보호자 설정

- 시작 화면을 홈 또는 말하기로 지정할 수 있게 하고 계정별로 저장한다.
- 카드 크기·개수·표시 방식·발화 방식은 미리보기를 제공한다.
- 동의, 데이터 삭제, 지원 연결, 카드 배치 변경은 서버 권한과 기존 재인증을
  확인한다. 화면에 보호자라는 제목만 붙이는 것을 성인 확인으로 취급하지 않는다.
- 아동 계정에서 가능한 성인 확인 수단은 기존 계정/연결 구조를 조사해 설계한다.
  단순 계산 문제를 신원 인증으로 취급하지 않으며 기본 말하기는 잠그지 않는다.

## 2. 우리 아이 연습 제안

### 사용자 흐름

보호자/담당자 홈 → 연결 아동 선택 → 이번에 해볼 연습 → 근거·카드·설정 확인
→ 필요하면 수정 → 이 설정으로 시작 → 기존 학습 활동 → 보호자 피드백.

아동 화면에 분석 보고서를 노출하지 않는다. 제안을 받았다는 이유로 학습을 자동
시작하거나 카드판·난이도·기본 설정을 변경하지 않는다. 나중에와 직접 선택을 제공한다.
한 번에 최대 3개만 제안하고 관심 표현과 학습 수행 근거를 구분해 보여준다.

### 첫 버전의 범위

- 기존 `word_picture_match`, `sound_picture_match`, `sentence_card_order`만 사용한다.
- 문제 수·보기 수·반복·재도전은 현재 엔진의 지원 범위를 먼저 확인한다.
  문서에 예시로 등장한 보기 2개 등을 지원 확인 없이 노출하지 않는다.
- 문장 순서 연습은 기존 예문과 해당 예문의 카드만 사용한다. 임의로 고른 카드
  조합을 예문 엔진에 넘기지 않는다. 지원하지 않는 설정은 후보에서 제외한다.
- 자유 생성 문제, 발음 평가, 능력 진단, 발달 연령 추정, 치료 계획은 범위 밖이다.
- 기존 말하기 카드 추천과 별도 기능·API·정책으로 구현한다.
  `RECOMMENDATION_POLICY.md`의 학습 결과 미사용 원칙은 기존 카드 추천에 유지한다.

### 근거 계산

서버가 최근 14일 기록을 집계한다. 이 기간은 초기 제품 기본값이며 교육적 기준이 아니다.
조회 상한·표본 수·기간을 응답에 명시하고 재전송·재생성 중복을 제거한다.

- 의사소통: 자주 선택한 카드와 사용 상황. 익숙한 소재 후보로만 사용한다.
- 학습: 활동별 참여·완료·재시도, 기록에 실제 존재하는 중단 정보.
- 보호자 피드백: 적절함/어려움/관심 없음. 완료 여부와 별개로 해석한다.
- 실제로 수집하지 않은 응답 시간·중단 원인을 추정하거나 과거 기록에 채우지 않는다.
- 초기 개인화 기준은 중복 제거된 학습 참여 3회 또는 카드 선택 이벤트 10건으로
  제안하되 설정 가능한 규칙으로 둔다. 기준 미달은 개인화 보류와 수동 선택을 제공한다.
- 특정 단어 미사용·재시도·중단을 이해 부족이나 능력 저하로 단정하지 않는다.

## 3. Ollama 모델과 구현 방식

초기 추천 모델: **`qwen3:4b-instruct`**.

공식 태그에서 4.02B, Q4_K_M, 다운로드 약 2.5GB를 확인했다.
짧은 한국어 설명과 제한된 후보 선택을 수행할 시작 후보로 선정한다.
최신·최고 성능이라는 의미가 아니며 한국어 품질·실제 지연은 아직 검증하지 않았다.
파일 용량은 실행 메모리가 아니다. 개발 PC에서 메모리와 CPU/GPU 사용량을 측정한다.

```sh
ollama pull qwen3:4b-instruct
```

위 명령은 향후 개발 환경 준비용이며 이번 문서 작업에서는 실행하지 않았다.

- 기존 문장 생성의 `OLLAMA_MODEL=qwen2.5:0.5b`를 일괄 교체하지 않는다.
- 별도 `OLLAMA_LEARNING_MODEL=qwen3:4b-instruct`와 기능 활성화 설정을 추가한다.
- 서버에서만 로컬 Ollama를 호출한다. Docker의 기존 연결 구성을 재사용한다.
- 초기 요청 제한은 30초, temperature 0, 입력 집계 JSON 8KB 이내,
  출력 512토큰 이내로 제안한다. 실측 후 조정하며 무제한 재시도하지 않는다.
- 서버가 유효한 후보를 만들고 모델은 후보 ID와 근거 ID를 선택한다.
  최종 활동·카드·설정은 서버의 후보에서 복원한다.
- Ollama `format`에 JSON Schema를 전달하고 Pydantic으로 재검증한다.
- 모델 응답은 최대 3개 `{candidate_id, evidence_ids}`로 제한한다.
  사용자에게 보여줄 관찰 수치와 설명은 검증된 근거의 서버 템플릿으로 만든다.
  첫 버전에서는 모델의 자유 서술을 그대로 노출하지 않는다.
- 후보 밖 ID·다른 아동 카드·지원하지 않는 활동·중복·잘못된 JSON은 거절한다.
- 모델 없음·시간 초과·스키마 오류는 규칙 기반 제안으로 대체한다.
  규칙 제안을 AI 제안으로 표시하지 않는다. 기록 부족과 모델 장애를 구분한다.
- 모델/프롬프트/집계/규칙 버전을 저장하고 요청 중복·동시 생성을 제한한다.
- 모델에 이름·사진·원문 문장·보호자 메모를 보내지 않는다. 집계와 내부 후보 ID만
  전달한다. 사용자 카드명 등 텍스트를 전달하게 된다면 지시가 아닌 데이터로 처리한다.

### 권한·데이터 수명

- 기록 조회와 학습 설정/시작 권한은 각각 기존 연결 권한을 확인한다.
- 기존 기록 동의를 기능 확장 동의로 임의 해석하지 않는다. 기존 동의 범위를
  검토하고 보호자에게 개인화 연습 사용을 명시적으로 켤 수 있게 한다.
- 동의 없음·철회·삭제 중에는 개인 기록 분석과 모델 호출을 중지한다.
  일반 활동 선택과 기록 없는 기본 말하기/연습은 유지한다.
- 추천·피드백 저장소는 말하기 및 학습 결과와 분리한다. 추천 열람·수락을
  실제 연습 완료나 의사소통 성공으로 집계하지 않는다.
- 보존 기간·개인 내보내기·삭제·스키마 등록을 함께 구현한다.
- 아동·계정 전환, 권한 변경, 로그아웃 뒤 늦은 응답을 폐기한다.
- 승인/시작 시점에 권한·동의·카드 활성 상태·설정 버전을 재확인한다.
- 오프라인에서는 새 개인화 생성·승인을 제공하지 않고 기존 학습을 이용한다.

## 4. 검증과 완료 기준

- 말하기: 카드 선택·취소·발화, 기존 위치/설정 유지, AI 실패 중 기본 발화 확인.
- 화면: 실제 사용하는 태블릿 우선, 작은 화면·회전·긴 문장·많은 카드 확인.
- 접근성: 키보드/보조 입력, 초점, 고대비, 동작 줄이기, 빠른/복구 표현 접근.
- 후보: 부족한 기록, 중복 기록, 서로 다른 아동 기록, 없는 설정/카드 제외 확인.
- 권한: 연결 없는 대상, 기록 조회만 허용된 대상, 동의 철회, 삭제와 승인 경합 확인.
- 모델: 합성 데이터로 정상 JSON·잘못된 ID·시간 초과·모델 없음·조작 텍스트 확인.
- 한국어 모델 평가는 정상/부족/재시도/중단/카드 비활성 사례를 포함해 최소 20건
  수동 평가한다. 사실 불일치·진단 표현·지원 불가 활동 노출은 0건이 완료 조건이다.
- 성공/실패/규칙 대체와 냉간·재사용 요청 지연을 따로 기록한다.
- 프런트엔드 빌드와 핵심 API 시나리오를 실행하고 결과를 작업 문서에 남긴다.
- 자동 검증 도구는 현재 제거된 상태다. 과거 verify 명령을 실행 가능하다고 가정하거나
  삭제한 대규모 검증 체계를 자동 복원하지 않는다. 현재 가능한 빌드·수동/API 검증을
  사용하고 새 로직의 핵심 경계를 검증할 최소 테스트가 필요하면 범위를 명시한다.
- 실제 아동·보호자 과업 관찰은 별도 수행한다. 미수행이면 현장 사용성 확인으로 표시하지 않는다.
