# 활동 중심 홈과 말하기 UX

2026-10-28 사용자 제공 `uxpilot-export-10-28-26.pdf`의 두 번째 대시보드에서 정보 배치와
활동 동선을 참고했다. 당시 작업은 기존 캐릭터·카드·색상 체계를 사용한 앱 화면 개선에 한정했다.
후속 사용자 요청으로 추가한 비로그인 소개 화면은 [랜딩페이지 기록](LANDING_PAGE.md)을 따른다.

## 화면과 동선

- 홈에서 **말하기·연습하기·내 카드**를 먼저 선택한다. 기존 선택 카드가 있으면 이어서 말하기를 제공한다.
- 주제별 카드는 실제 사용 가능한 카드·카테고리로 구성하고 개수를 집계한다. 선택하면 해당 주제의
  카드 목록으로 이동한다. 카드 추가·말하기는 기존 기능을 사용하며 탐색 자체로 발화하지 않는다.
- 홈과 말하기 화면에서 **카드 리더기 열기**로 입력 영역을 펼친다. USB 연결 상태와 읽은 개수는
  실제 연결 상태를 사용하고, 읽은 카드는 그림·단어·위치 또는 입력 순서를 구분한다.
- 읽은 카드의 명시 추가·적용 뒤 말하기 화면에서 기존 문장 생성·확인·TTS로 이어간다.
  다른 활동·마이페이지에서는 문장 적용을 막는다. 칩 인식만으로 발화하거나 기존 문장을 바꾸지 않는다.
- 같은 로그인 계정에서는 홈·말하기·연습·카드 탐색 사이를 이동하거나 영역을 접어도 USB 연결과
  읽기 목록을 유지한다. 로그아웃·계정/세션 전환·앱 이탈의 기존 연결 해제 처리를 유지한다.
  Wi-Fi 상태 조회는 다른 활동·마이페이지에서 중지하고 돌아왔을 때 새 상태를 조회한다.
- 장치의 포트·속도·진단 스케치 설명과 로그는 아동 화면에서 펼쳐 확인한다. 관리자·보호자 등록
  화면은 기존 상세 표시를 유지한다. 로그에 UID·인증 자료를 추가하지 않는다.
- 말하기에서는 고정 카드판과 현재 문장을 먼저 표시하고 추천을 아래에 둔다. 추천의 순서·동의·
  노출 집계 정책과 고정 카드 배치는 유지한다.
- 빠른 표현·복구 표현은 모든 아동 활동에서 계속 접근할 수 있다. 오프라인 음성 준비의 자세한
  상태는 펼쳐 확인한다. 준비 실패·재시도는 숨기지 않는다.
- 프로필 설정 진입점은 사이드바의 이름·사진으로 유지한다. 실제 학습 설정을 선택하는 화면의
  종류·범위·시작 조작을 묶고, 임의의 레벨·목표·포인트를 표시하지 않는다.

## 유지한 경계

동의 없는 기본 말하기, 기존 지원 권한, 관리자 공용 칩 등록과 개인 매핑 우선 규칙은 유지한다.
DB·API·펌웨어·음성 공급자를 변경하지 않는다. 입력 방식에 따라 1개 리더기의 순서 누적과
2·3개 리더기의 위치 배열을 구분한다. 카드 ID·카드 위치·표현을 임의로 교체하지 않는다.

핵심 웹 기능의 구현·자동 검증 이력은 존재하지만, 실물 칩 등록→문장→발화와 RC522 3개 통합,
제거 판정·배선·전압·RF 간섭·실제 기기 음성 품질의 검수는 여전히 남아 있다.
이 UI 변경이나 자동 검사로 하드웨어 MVP·현장 사용·배포 완료를 표시하지 않는다.

## 검증 상태

`npm run verify:frontend` 격리 Docker 검증은 통과했다. Node 110개·React 205개, 총 315개와
프런트엔드 빌드·임시 환경 정리가 통과했으며 runner 정책 검사 28개도 통과했다.
프로젝트는 `pesc-verify-b3b3d3ae019e45f0bdff60cf24575a17`, 실행 시간은 174.4초다.
결과는 `.local-validation/2026-10-28T06-30-03.016Z-b3b3d3ae019e45f0bdff60cf24575a17/summary.json`에 있다.

첫 Windows 직접 React 실행은 202개 통과·3개 실패였다.
새 주제 탐색 버튼의 이름 선택자와 위치별 카드의 분리된 마크업 선택자를 수정했다.
기존 카드 12장 한도 검사 1개는 5초 시간 초과였다. 동시 실행 수를 1로 줄인 후속 Windows 실행에서도
기존 카드 한도·중복 카드 초점 검사 2개의 5초 시간 초과가 발생해 해당 직접 실행을 중단했다.
이 중단 실행을 전체 통과로 집계하지 않는다. 같은 제한·파일 격리를 유지한 Docker 재검증에서는
205개 모두 통과했다. 제한 시간을 늘리거나 검사 개수·파일 격리를 줄이지 않았다.

개발 앱의 Chromium 9개 실행은 6개 통과·3개 실패였다. 키보드 조작 3개, 동의 유지, 새 홈 탐색,
복구 발화가 통과했다. 실패는 프로필 저장 완료 표시 대기, Wi-Fi 장치 세션의 HTTP 차단 403,
USB 입력 이후 문장 생성 요청의 클라이언트 시간 초과였다. 개발 설정을 검사용으로 바꾸지 않았다.

기존 `compose.verify.yaml`의 임시 DB·내부망·외부 모델 비활성 환경에서 4개를 재검증했다.
홈 탐색·Wi-Fi·USB 3개가 통과했고 마이페이지는 추천 카드와 고정 카드판의 같은 단어 버튼이
동시에 발견되는 검사 선택자 문제로 실패했다. 임시 스택·DB 정리는 통과했다. 이 실행 전체를
