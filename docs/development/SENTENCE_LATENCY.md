# AI 문장 생성·자동 발화 지연 — 2026-11-13

## 변경

- 동시 RFID 묶음은 온라인·동의 상태에서 문장판 반영 후 `/sentences`를 호출한다.
  생성된 문장과 세션 번호를 받아 표시·발화한다. 단일 태그는 계속 화면만 갱신한다.
- 진행 중인 생성보다 새 입력이 우선이다. 오래된 결과는 발화하지 않으며,
  새 묶음의 대기 생성은 앞 요청이 종료된 뒤 최신 문장판으로 시작한다.
- 미동의 기본 말하기와 요청 실패 시 카드명 읽기 대체 경로를 유지한다.
  백엔드의 AI 실패·의미 누락·안전성 실패 시 규칙 문장 대체도 유지한다.
- 모델 준비는 빈 사용자 카드와 동일 시스템/공통 요청 프롬프트를 미리 처리한다.
  1토큰만 생성하며 서버 시작을 막지 않는다. 실제 사용자 카드·기록을 보내지 않는다.
- 같은 계정의 최근 5분 기록 중 최대 최근 32건에서 같은 순서의 카드를 찾는다.
  모델·정책 버전·개인 카드 메타데이터가 같고 형식·의미·안전성 재검사를 통과한
  AI 문장만 재사용한다. 기존 계정별 최근 기록 인덱스를 이용하며 서버 측 쿼리 실행 시간은 100ms로 제한한다.
- 기록이 삭제되면 재사용 데이터도 사라진다. 별도 캐시 컬렉션·프로세스 사용자 캐시는 없다.
  재사용해도 새 요청 기록을 저장하고 최종 동의/삭제 revision·멱등성 검사를 유지한다.
- 다른 사용자·다른 카드 순서·변경된 카드·정책·모델·명시적 재생성에는 재사용하지 않는다.
- 나/저 카드의 의미 누락을 줄이도록 주어 보존 요청을 명확히 하고 프롬프트 버전을 v4로 올렸다.
  기존 출력·안전 정책을 완화하거나 무조건 모델 결과를 수락하지 않는다.
- 모델·프레임워크·타임아웃 기본값은 변경하지 않았다. 유료 API·모델 다운로드는 하지 않았다.

## 실제 측정

Windows Python 3.13.5, 로컬 Ollama `qwen2.5:0.5b` Q4_K_M, context 2048.
Ollama 적재 상태에서 `size_vram=0`으로 보고되었다. 합성 `나 / 물 / 마시다`만 사용했다.

| 조건 | 결과 | 범위 |
| --- | --- | --- |
| 변경 전 첫 직접 모델 호출 | 10,032.3ms 후 TimeoutError·규칙 대체 | 사전 적재 여부를 확인하기 전 첫 지연 관측. 서버 10초 설정 유지 |
| 변경 전 준비된 직접 호출 | 1,104.0ms·AI 응답 | DB·HTTP·TTS 제외. 이 값도 보존하여 새 조합 전체가 빨라졌다고 주장하지 않음 |
| 공통 프롬프트 준비(v4) | 1,128.5ms·준비 성공 | 사용자 요청 전에 수행하는 준비 단계 |
| 새 조합 최초 서비스 요청(v4) | 2,083.5ms·AI 응답 | 모델 내부 2,062.4ms, 검증·실제 격리 DB 저장 포함 |
| 같은 계정·조합 다음 서비스 요청(v4) | 5.0ms·AI 문장 재사용 | 재사용 조회/검증 0.8ms, 실제 격리 DB 저장 포함. 새 모델 호출 없음 |

각 수치는 해당 합성 입력의 단일 관측이며 평균·p95·실사용 지연 보장이 아니다.
반복 조합의 추론 생략 효과를 확인했으며, 새 조합이 항상 1초 이내라는 근거는 없다.
150ms 태그 묶음·UID 매핑·HTTP 인증·TTS·브라우저 첫 소리 시간은 위 서비스 측정에서 제외했다.
실제 다중 리더기·음성 서버·절전 복귀·사용자 체감 지연은 미검수다.

첫 중간 측정에서는 기존 프롬프트가 나 카드를 누락하여 첫 1,082.7ms·다음 703.1ms 응답이
모두 규칙 문장으로 대체되었다. 이 결과를 AI 재사용 성공으로 계산하지 않았다.
주어 보존 프롬프트 보완 후 v4 측정을 새 합성 DB에서 실행한 결과가 위 표다.

## 재현 도구

```powershell
backend/.venv/Scripts/python.exe -u backend/tools/benchmark_sentence_latency.py --uri mongodb://127.0.0.1:27017 --warmup
```

도구는 새 `pesc_mate_test_ai_latency_*` DB를 만들고 합성 동의·문장 두 건만 저장한 뒤
자신이 만든 DB만 제거한다. 기존 DB를 덮어쓰지 않는다. 이 명시적 측정 프로세스에서만
로컬 모델을 활성화하며 앱의 환경 설정은 바꾸지 않는다. 모델은 설치되어 있어야 한다.
재현 환경·부하에 따라 수치와 AI 검증 통과 여부가 달라질 수 있다.

## 자동 검증

- 백엔드 문장 재사용·준비·기존 생성·OpenAPI/HTTP 계약 관련 30개 통과.
- 프론트 자동 AI 생성·지연 응답·기본 발화 대체·RFID 큐·App·음성 플레이어 관련
  30개 통과. 최신 대기 문장판 처리 검사를 추가한 뒤 해당 파일의 12개를 재실행해 통과했다.
- 재사용 첫 테스트는 기존 BSON 밀리초/최초 응답 마이크로초 차이 때문에 실패했다.
  운영 동작은 바꾸지 않고 기존 회귀 기준과 동일하게 해당 시각만 1ms 미만 차이를 허용한 뒤 통과했다.
- 기본 백엔드 실행에서 기존 Starlette HTTPX TestClient 중단 예정 경고 1건이 유지되었다.
- `git diff --check` 통과.
- 빌드·전체 백엔드·전체 MongoDB 경합·브라우저/실기기 첫 소리 검사는 미실행이다.
- 서버 재시작으로 중간 직접 호출 1회의 결과를 회수하지 못했다. 이를 통과/실측에 포함하지 않았다.
