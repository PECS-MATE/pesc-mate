# API 오류율과 응답 시간 지표

`GET /api/admin/metrics`는 현재 API 프로세스의 요청 수, 오류율과 처리 시간 분포를 반환한다.
기존 `content_manage` 운영 권한 검사를 적용한다. AAC 사용자·보호자·일반 담당자는 403,
비로그인 요청은 401이며 모든 지표 응답은 `Cache-Control: no-store`를 사용한다.

## 수집 범위

- 단위: 요청 전체와 HTTP 메서드·등록된 경로 템플릿별 집계
- 보관: 현재 1분과 직전 14분, 총 15개의 1분 버킷
- 내용: 요청 수, 4xx·5xx·응답 시작 후 전송 오류, 처리 시간의 합계·평균·최댓값·분포
- 시간: 요청 진입부터 ASGI 처리 완료까지의 시간. 스트리밍과 후처리 시간을 포함하며 화면 로딩 시간이나 TTS 소리 시작 시간이 아니다.
- 개인정보: 사용자 ID가 들어간 실제 URL, 쿼리, 본문, 토큰, 이름, 이미지 경로, 요청 ID, IP를 보관하지 않는다.
- 경로: 예를 들어 사용자별 요청도 `/profile/{user_id}/image` 같은 하나의 템플릿으로 집계한다. 매칭되지 않은 URL은 `unmatched`로 묶는다.
- 크기 제한: 메서드·경로 조합 128개와 초과분 `OTHER / other` 하나로 제한한다. 개별 요청이나 원시 지연 샘플은 보관하지 않는다.

집계는 메모리에만 저장하고 MongoDB에 추가로 쓰지 않는다. 계정 인증의 기존 DB 조회는 유지한다.
집계 실패가 정상 API 응답을 실패로 바꾸지 않으며 예외 원문도 로그에 출력하지 않는다.

## 조회

운영 권한 계정으로 로그인한 세션 토큰을 사용한다. 실제 토큰은 문서·공유 로그에 기록하지 않는다.

```http
GET /api/admin/metrics
Authorization: Bearer {access_token}
```

응답에는 다음 필드가 있다. `totals`와 각 `routes[]`는 같은 집계 필드를 사용한다.

| 필드 | 의미 |
|---|---|
| `scope` | `process`: 요청을 처리한 프로세스 하나의 집계 |
| `reset_on_restart` | `true`: 재시작·개발 리로드 시 초기화 |
| `window_seconds`, `bucket_seconds` | 최대 보관 범위 900초, 버킷 60초 |
| `uptime_seconds` | 해당 집계기 생성 후 경과 시간 |
| `totals.requests` | 현재 버킷 범위의 전체 요청 수 |
| `client_errors`, `server_errors` | 4xx, 5xx 응답 수 |
| `transfer_errors` | 성공 응답 헤더를 보낸 뒤 전송에 실패한 요청 수 |
| `errors`, `error_rate` | 4xx + 5xx + 전송 오류와 전체 요청 대비 비율 |
| `server_error_rate` | 5xx + 전송 오류의 전체 요청 대비 비율 |
| `duration_ms.sum`, `mean`, `max` | 처리 시간 합계·평균·최댓값, 단위 ms |
| `duration_ms.p50_upper_bound`, `p95_upper_bound` | 해당 백분위가 속하는 시간 버킷의 상한 |
| `duration_ms.buckets[]` | `le_ms` 이하인 요청의 누적 개수 |
| `routes[]` | 메서드·경로 템플릿별 집계 |

비율은 0~1이다. 예를 들어 `0.02`는 2%다. 전송 오류는 성공 헤더를 보낸 경우에만
별도로 세므로 5xx와 중복 합산하지 않는다. 401·403·404도 클라이언트 오류에 포함되므로
서버 장애 판단은 `server_error_rate`와 해당 경로를 함께 확인한다.

시간 버킷 상한은 10·25·50·100·250·500·1000·2500·5000·10000ms와 무한대다.
무한대는 `le_ms: null`이며 마지막 버킷 개수는 전체 요청 수와 같다. 백분위 상한은
정확한 백분위 시간이 아니다. 예를 들어 `p95_upper_bound: 500`은 95번째 백분위가
500ms 이하인 버킷에 있다는 뜻이다. 10초 초과 버킷에 속하거나 표본이 없으면 null이다.
표본이 없을 때 평균·최댓값도 null이며 요청 수와 오류율은 0이다.

버킷 경계에서 만료하므로 정확한 직전 900초 이동 구간과 최대 1분 차이가 날 수 있다.
헬스 체크·지표 조회·CORS preflight도 포함한다. 현재 지표 조회 요청 자체는 응답 집계에
아직 들어가지 않고 다음 조회부터 반영된다.

## 운영 한계와 다음 단계

현재 로컬 단일 프로세스 개발 환경을 위한 지표다. 재시작 이전 이력은 유지하지 않고,
여러 worker·서버의 값을 자동으로 합치지 않는다. 장기 추세·외부 알림·다중 프로세스 집계가
필요하면 별도 수집기로 전달하는 단계가 필요하다. 이 API의 집계를 전체 운영 서버의
누적 성공률이나 실제 기기 TTS 성공률로 해석하지 않는다.

현재 프로세스의 반복 실패를 운영자 화면에 표시하는 기능은
[운영 알림](OPERATIONAL_ALERTS.md)에서 별도로 제공한다.
