# B1-04 추천 통제·탐색 보조

## 구현 범위

추천은 그림으로 말하기의 별도 후보 영역에만 표시한다. 고정 슬롯·빠른 표현·복구 표현을
재배치하지 않으며 카드 선택·의도·필요·능력을 대신 판단하지 않는다. 학습 결과나 보호자 메모로
추천하지 않는다. 이미지 작업과 B2 학습 확장은 이번 범위에 포함하지 않는다.

보호자·담당자는 연결별 `board_manage` 권한으로 빠른 표현·카드판 화면에서 다음을 설정한다.

- 추천 사용 여부, 자동 후보 또는 승인 목록 전용 방식.
- 추천 승인·추천 숨김 카드 목록(각 100개 이하, 중복·동시 지정 금지).
- 추천에 반영할 상황, 기기의 현재 시간대 사용 여부.

숨김은 추천 후보에서만 제외하는 설정이다. 전체 카드 목록이나 긴급·복구 발화의 접근 제한이
아니다. 승인 전용 목록이 비면 후보를 표시하지 않고 전체 카드 탐색 경로를 유지한다.
현재 제공되는 카드와 기존 정책에 남은 카드 ID만 저장할 수 있다. 비활성 개인 카드는 후보에서 제외한다.
AAC 사용자는 자기 설정을 읽을 수 있으나 보호자 정책을 직접 변경할 수 없다.

사용 기록의 반복 노출 점검은 별도의 `records_read` 연결 권한을 매 요청 확인한다.
보드 관리, 학습 관리 또는 공용 콘텐츠 운영 권한만으로 아동의 추천 사용 기록을 볼 수 없다.
빠른 표현 관리 권한만 있는 지원자에게는 공용 감사 저장소의 추천 정책 변경 이력도 반환하지 않는다.
지원 대상·계정이 바뀌면 이전 요청의 늦은 응답을 표시하지 않는다.

## 후보 계산: `aac-candidates-v1`

사용자의 현재 이용 가능 카드에서 숨김 카드와 이미 선택한 카드를 제외한다. 승인 전용 모드는
승인 목록과 교집합만 사용한다. 아래 정수 근거를 합산하고 동점이면 원래 카드 목록 순서를 따른다.
사용 기록이 부족하면 같은 허용 범위 안에서 기본 카드 순서로 제안한다.

| 근거 | 계산 | 상한 |
|---|---|---|
| 빈도 | 원본 저장 문장에 포함된 횟수 × 2 | 20 |
| 최근 시각 | 마지막 포함 시각이 1일/7일/30일 이내면 12/8/3 | 12 |
| 앞선 카드 조합 | 현재 선택 카드와 함께 원본 문장에 포함된 횟수 × 4 | 20 |
| 시간대 | 기기 현지 시각의 같은 6시간 구간에 저장한 횟수 × 2 | 10 |
| 지정 상황 | 보호자가 지정한 상황의 카드 선택 관찰 횟수 × 3 | 15 |
| 반복 완화 | 최근 실제 표시 묶음에 노출된 횟수 × -2 | -20 |

한 원본 문장의 중복 카드는 한 번만 세며 재생성 기록은 중복 학습 근거로 쓰지 않는다.
상황 근거도 한 관찰 이벤트의 중복 카드를 한 번만 센다. 발화 결과·복구 발화는 상황별 카드 선택으로
세지 않는다. 점수는 제한된 관찰 근거이며 사용자 능력 점수나 예측 확률이 아니다.

- 원본 문장 조회: 최근 90일, 최신 최대 200개(재생성 제외는 이 표본 안에서 적용).
- 지정 상황 선택 관찰: 최근 90일, 최대 500개.
- 반복 완화: 최근 90일의 실제 노출된 묶음 최신 최대 20개.
- 시간 변환: 브라우저 `getTimezoneOffset()` 분을 과거 UTC 시각에서 빼서 현지 시각을 구한다.
  현재 기기 오프셋 기준이므로 과거 여행·서머타임 이력까지 복원하지 않는다.
- 상황을 지정하지 않으면 상황 근거는 0이다. 아동 화면의 **기록 상황** 선택과 보호자의
  **추천에 반영할 상황**은 별도이며 기록 선택만으로 추천 설정을 바꾸지 않는다.

한 카테고리는 최대 2개, 전체 최대 6개다. 최근 3개 노출 묶음에 모두 나타난 후보는
허용 범위 안에 대체 카드가 있을 때 다음 갱신에서 잠시 제외한다. 승인 목록의 유일한 후보를
지우거나 숨김·승인 정책을 풀어 빈자리를 채우지 않는다. 따라서 6개보다 적을 수 있다.
반복 완화는 피드 갱신 기준이며 실제 경과 시간이나 모든 의사소통 기회를 뜻하지 않는다.

## 근거·노출·선택 기록

`POST /recommendations/feed`는 요청 UUID, 현재 선택 카드 ID(최대 12개), 현지 시각,
UTC 오프셋만 받는다. 응답은 후보별 관찰 근거·정수 기여도와 알고리즘 버전,
적용한 설정 버전, 사용한 표본 수를 포함한다. 후보 UI에는 근거와 버전을 표시한다.

동의가 유효하고 후보가 있으면 `recommendation_batches`에 계산 시점의 후보·근거·버전·맥락을
보관한다. 같은 요청 UUID와 맥락을 재시도하면 같은 스냅샷을 반환한다. 다른 사용자·맥락의 ID 재사용,
정책 버전 변경, 제공 카드 비활성화 이후의 이전 응답 재생은 409로 거절한다.

조회 완료는 노출이 아니다. 문서가 보이고 관찰자가 후보의 10% 이상 교차를 확인한 카드만
노출 API로 전송한다. 관찰자를 지원하지 않으면 수동으로 조회만 한 후보를 노출로 가정하지 않는다.
후보 본체를 클릭하면 노출 확인 후 선택을 전송하되 실제 카드 추가·말하기는 기다리지 않는다.
스피커 미리 듣기 자체는 문장에 담은 선택으로 세지 않는다.

서버는 요청한 카드가 그 묶음에서 제공되었는지 확인하며 선택은 노출된 카드만 허용한다.
노출·선택은 **묶음당 카드별 여부**이고 여러 번 누른 횟수나 성공 발화 횟수가 아니다.
중복 전송은 `$addToSet`으로 한 번만 반영한다. 노출 확인이 실패하면 선택 기록을 보내지 않는다.
정책 변경 후 이전 묶음의 추가 기록은 409이며, 계정·오프라인·세션 전환 이후 늦은 확인으로
선택을 이어서 전송하지 않는다. 단순 선택 변경으로 후보가 갱신되어도 방금 클릭한 기록은 보존한다.

반복 점검은 최근 90일 내 실제 노출된 최신 최대 50개 묶음의 카테고리 분포,
카드별 노출·선택 여부 합계, 최근 3묶음 공통 카드, 사용한 알고리즘 버전을 보여 준다.
미선택을 거절·관심 없음·지원 불필요로 해석하지 않고 자동 위험 판정도 하지 않는다.

## 장애·동시 편집·오프라인

추천은 로그인·기본 카드 로딩의 필수 요청에서 분리했다. 별도 패널에서 실패 안내와 재시도를 제공한다.
전체 카드에서 고르기는 고정 슬롯 목록이 아니라 전체 카드 카탈로그로 이동하며 검색·카테고리를
초기화한다. 여기서 문장에 사용할 수 있고 이전에 선택한 카드도 유지한다.

추천 조회는 선택 변경 후 150ms 지연, 문장 저장, 화면 복귀·포커스, 보이는 화면에서 30초마다
갱신한다. 서버 푸시가 아니므로 보호자가 바꾼 정책은 다음 갱신까지 이전 후보로 보일 수 있다.
이때 노출·선택 기록 요청은 서버의 최신 정책 버전을 재확인한다. 이미 전송 중인 요청과 정책 저장을
하나의 트랜잭션으로 묶지는 않는다. 숨김은 카드 접근 금지가 아니며 고정 카드판에는 영향이 없다.

오프라인에서는 개인화 후보를 캐시에서 복원하지 않는다. 저장된 전체 카드·고정 카드판·긴급·복구
발화를 사용한다. 추천 조회·노출·선택 실패는 실제 카드 추가나 말하기를 막지 않는다.
보호자 설정은 `expected_revision`으로 비교 저장한다. 409일 때 초안을 유지하고 사용자가
확인해 최신 설정을 불러온 경우에만 교체한다. 변경자·시각·전후 정책과 버전을 감사 기록에 남긴다.

## 데이터 수명·배포

- `recommendation_settings`: 사용자 `_id`, 독립 revision, 기존 고정 보드 revision은 유지.
- `recommendation_batches`: 사용자·생성 시각 인덱스, 스키마 버전 1. 개별 묶음 최대 6개 후보.
- 두 컬렉션을 스키마 레지스트리와 개인 내보내기·삭제에 포함했다. 기존 기록을 소급 생성하지 않는다.
- 개인정보 설정의 보존 기간 적용 시 해당 사용자의 오래된 묶음을 삭제한다. 설정 자체는 최신 상태를 유지한다.
- 개인정보 삭제는 두 컬렉션과 기존 카드판 감사 이력을 지우고 영수증에 각각의 건수를 남긴다.
  다른 사용자와 로그인 계정은 유지한다. 내려받은 파일·별도 백업은 자동 삭제 범위가 아니다.
- 동의가 없거나 삭제 진행·실패·완료 상태이면 개인 기록으로 순위를 계산하거나 묶음을 새로 저장하지
  않는다. 현재 정책을 적용한 기본 후보만 제공하고 batch_id는 null이다. 기존 기록의 조회 권한과
  삭제 기능은 기존 개인정보 정책을 따른다.
- 전체 DB 백업·복원·지문 확인은 동적 컬렉션 열거를 사용하므로 신규 컬렉션도 포함한다.
  기존 운영 데이터 삭제나 개발 DB 초기화는 하지 않는다.
- API는 동작 데이터를 반환할 뿐 일반 DB 조회·접속 콘솔 로그를 추가하지 않는다.
