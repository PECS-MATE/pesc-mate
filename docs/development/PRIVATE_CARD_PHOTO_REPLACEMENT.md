# 개인 카드 사진 교체

2026-10-23 B1-01 개발 단위. 연결 아동의 `cards_manage` 권한을 가진 보호자·담당자가
개인 카드 관리에서 카드별 **사진 교체**를 선택한다. 아동의 직접 수정·공유 카드·기본 카드
수정은 허용하지 않는다. 잠긴 핵심 카드의 교체는 409로 거절한다.
[핵심 잠금](../policies/CORE_CARD_LOCK_POLICY.md)의 설정 화면과 API를 후속 단위에서
연결했으며 기존 데이터에 자동 잠금을 지정하지 않는다.

## 변경 범위와 보관

카드 ID·카드명·뜻·분류·소유자·공개 범위·승인 상태·생성 시각을 유지한다. 원본·화면용
WebP·썸네일·안전성 결과만 교체하고 사진 버전을 증가시킨다. 보드 슬롯·빠른/복구 표현·
음성 설정·사용 기록은 수정하지 않는다. 새 썸네일 주소와 ETag로 이전 사진을 갱신한다.
지원 화면에서 이전 목록의 Blob URL도 해제한다. 다른 기기의 화면 강제 갱신은 아니다.

현재 DB 문서의 이전 사진은 덮어쓰며 사진 변경 이력을 별도 보관하지 않는다. 새 원본은
로컬 MongoDB에 실제 바이트 그대로 보관한다. 원본 촬영 정보는 API·안전성 전송·JSON
내보내기에 노출하지 않지만 DB·별도 백업에는 남을 수 있다. 기존 백업은
[로컬 이미지 저장 정책](LOCAL_IMAGE_STORAGE.md)의 30일 보존·명시적 정리 대상이다.
교체가 백업 삭제를 대신하지 않는다. 개인정보 삭제의 백업 무효화 규칙은 유지한다.

## API와 충돌

`PUT /api/cards/submissions/{id}/image` — 인증 multipart:

- `user_id`: 연결된 아동 ID(필수)
- `expected_revision`: 조회한 `image_revision`(필수, 0 이상)
- `image`: JPG·PNG·WebP 원본(필수, 기존 5MiB/해상도 제한)
- `image_edits`: 선택 JSON. 신규 등록과 같은 엄격한 보정 규격

응답은 기존 카드 등록 응답과 `image_revision`이다. 구버전 카드의 사진 버전은 0으로 읽는다.
현재 교체 화면은 보정을 지정하지 않으며 이전 사진의 자르기·회전 설정은 제거한다.
새 사진의 형식·동의·전체/선택 보정 프레임 안전성·원본/파생 저장량을 재검사한다.
같은 전역 이미지 쓰기 잠금 안에서 삭제 경쟁·연결 권한·핵심 잠금·사진 버전을 다시 확인하고
버전 조건부 갱신한다. 성공 감사에는 담당자와 이전/이후 버전만 남기며 사진 바이트나 원래
파일명은 넣지 않는다.

403 권한·공유 카드, 404 대상 없음, 409 버전/잠금/삭제 경쟁, 413 용량, 422 잘못된
이미지·차단, 503 DB 오류를 구분한다. DB 쓰기 후 감사 실패처럼 결과가 불명확할 수 있으므로
409·권한·네트워크·서버 오류 뒤에는 최신 목록을 확인해야 한다. 자동 재전송하지 않는다.
명확한 형식 거절 뒤에는 파일을 다시 선택할 수 있다. 사진 저장 성공 후 목록 갱신 실패도
업로드 재시도 대상으로 바꾸지 않는다. 세션·아동 전환 뒤 늦은 응답은 폐기한다.

## 검증

Node 96·React 153개, 총 249개와 프런트엔드 빌드 통과. Linux 백엔드 379개와 격리
MongoDB 이미지 HTTP 통합 검사 21개 통과(제외 없음). 실제 원본 교체·문구/보드/음성 유지·
권한·잠금·MIME·안전성·용량·연결 회수·레거시 버전·경쟁 갱신·ETag를 확인했다.

첫 React 실행의 파일 선택 후 제출 실패는 jsdom의 합성 FileList/required 검사 문제였다.
컴포넌트 검사는 폼 핸들러를 직접 실행하고 실제 파일 제출은 Chromium에서 확인한다.
App 검사의 중복 카드명은 등록 카드 목록으로 범위를 한정했다. 실제 구현의 required 검사나
서버 검증은 제거하지 않았다. 수정 후 위 전체 프런트엔드 검사와 빌드가 통과했다.

첫 Chromium 실행은 기존 3개 통과·교체 1개 실패였다. 생성 응답의 마이크로초와 MongoDB
저장 후 밀리초 정밀도를 직접 비교한 검사 문제로, 교체 전후의 저장된 카드끼리 비교하도록
수정했다. 다음 실행에서도 보드 저장 응답의 같은 정밀도 차이를 확인해 보드 역시 저장된
조회값끼리 비교했다. 최종 Chromium 일괄 등록·보정·순서·사진 교체 4개가 모두 통과했다.
보고서: `.local-validation/b1-progress-20261023/browser-photo-final/report/`.
임시 스택 `pesc-verify-e1f89336d0bd4597bcf272a97116f16f`는 정리했다.

전체 `npm run verify:full`·실제 태블릿·스크린리더·현장 검수는 미실행이다.
사용자 사진·기존 DB·운영 볼륨은 변경하지 않는다. B1 전체 완료나 배포 승인이 아니다.
