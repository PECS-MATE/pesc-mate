# 관리자 공용 RFID 칩 등록

현재 PC는 USB 연결을 사용한다. 기존 아동별 RFID 설정과 별도로 운영 권한 담당자가
**칩을 하나씩 읽어 공용 그림카드에 미리 연결하는 페이지**를 추가했다.
사용자 선택에 따라 공용 칩은 모든 아동에게 적용하고 개인 사진 카드는 기존 아동별 매핑을 유지한다.

## 사용하는 순서

1. 공용 콘텐츠 운영 권한(`support_staff` + `content_manage`)이 있는 계정으로 로그인한다.
   기본 로컬 시연 환경의 `admin`이 해당 계정이다. 새 역할을 만들거나 일반 담당자에게 자동 부여하지 않는다.
2. 왼쪽 **RFID 칩 등록** 메뉴를 연다. 아동을 먼저 연결/선택하거나 Wi-Fi 장치를 등록할 필요가 없다.
3. Arduino IDE의 시리얼 모니터를 닫고 **USB 장치 연결**에서 Arduino 포트를 선택한다.
   브라우저 권한·안전한 출처·115200bps와 기존 `UID:`/USB JSON 지원은 [USB 연동 안내](RFID_USB_INTEGRATION.md)를 따른다.
4. 칩을 하나만 대면 **인식한 칩 UID**에 값이 고정된다. 다른 칩을 대더라도 확인 중인 UID는 바뀌지 않는다.
5. 카드명/분류를 검색해 공용 그림카드를 고르고 그림과 `UID → 카드명`을 확인한다.
   이미 등록된 UID는 현재 연결을 표시한다. 같은 연결의 중복 저장은 하지 않는다.
6. **칩 등록 저장** 또는 **칩 연결 변경**을 누른다. 기존 공용 콘텐츠 작업과 동일하게 본인 비밀번호로
   매 작업을 확인한다. 확인 창에는 UID·기존/새 카드·전체 사용자 적용 범위를 표시한다.
7. 저장 완료 후 칩을 떼고 **다음 칩 인식**을 누른다. 선택 카드와 UID를 비운 뒤 다음 칩을 읽는다.
8. 목록에서 UID/카드명으로 검색해 수정·해제할 수 있다. 최근 50개를 우선 표시하고 전체 등록 수도 보여 준다.

기존 기본 카드 또는 승인된 공용 카드 중에서 선택한다. 개인 카드·승인 대기·반려·비활성 카드는
공용 후보에 포함하지 않는다. 미리보기 로딩/오류를 구분하고 카드명과 선택 내용도 표시한다.

## 등록과 실제 말하기의 분리

USB 등록 모드는 UID만 전달한다. 아동 태그 조회·문장 대기열·문장 생성·발화·학습 기록을 만들지 않는다.
여러 위치의 칩이 동시에 읽히면 한 칩씩 올리라는 안내를 표시한다. 장치 상태 로그는 관리자 권한의
경로로 전송하며 일반 로그에 UID/비밀번호를 넣지 않는다.

저장한 공용 매핑은 USB와 기존 Wi-Fi 조회 모두에서 사용한다. 우선순위는 **아동별 개인 매핑 →
관리자 공용 매핑 → 미등록 안내**다. 개인 연결을 해제하면 공용 연결이 다시 적용된다.
공용 카드가 비활성화되거나 개인 카드로 바뀌면 공용 조회는 사용 불가가 된다. 원래 소유 아동도
이 경로로 개인 카드를 우회 사용하지 못하며, 별도 개인 매핑은 기존 정책대로 처리한다.

## API·권한·저장

모든 경로 앞에 `/api`가 붙고 기존 Bearer 세션을 사용한다.

| 메서드/경로 | 동작 |
|---|---|
| GET /rfid/admin/catalog | 운영 권한으로 공용 카드와 UID 등록 목록 조회, no-store |
| PUT /rfid/admin/bindings | 운영 권한 + 매 요청 본인 비밀번호. uid·card_id·expected_revision·password |
| POST /rfid/admin/usb/events | 운영 권한으로 허용된 USB 상태 action만 로그에 남기고 204 |

`card_id=null`은 해제다. 신규는 `expected_revision=null`, 기존은 조회한 revision을 보낸다.
등록/변경/해제는 공유 쓰기 잠금 안에서 계정 상태·운영 권한·비밀번호·공용 카드 범위·버전을 확인한다.
삭제 후 재등록도 새 revision을 만들며 충돌은 409다. 오류 뒤에는 현재 칩과 선택 카드를 보존하고
목록 새로고침으로 실제 등록 상태를 확인하게 한다. 자동 쓰기 재시도는 없다.

공용 칩은 5000개 한도다. `rfid_shared_bindings`의 `_id`는 정규화 UID이며 card_id·revision·updated_at·
schema_version을 저장한다. 카드명/사진은 복제하지 않는다. 최신순 색인과 문서 스키마 기준선에 포함한다.
기존 로컬 BSON 백업 범위에 포함되지만 새 운영 백업 복원 훈련을 완료한 것으로 취급하지 않는다.

공용 칩은 플랫폼 자산이므로 아동 개인정보 내보내기/삭제로 전체 매핑을 내보내거나 지우지 않는다.
아동의 개인 매핑은 기존 삭제 정책을 따른다. 감사는 기존 privacy_audit_logs에 운영자 범위의
rfid_shared_saved/removed와 UID 해시를 기록하고 원시 UID/비밀번호는 넣지 않는다.

아동·보호자·운영 권한 없는 담당자는 메뉴와 공용 관리 API를 사용할 수 없다. 공용 칩 사용이
개인 카드 열람·아동 기록 조회·운영 권한 관리 책임자 권한을 부여하지 않는다.

## 검증 기록

- 호스트 RFID·색인·스키마 단위 33개 통과.
- 단일 칩 고정·비밀번호 확인·취소·충돌 보존, USB 등록 모드의 문장 입력 방지를 포함한 컴포넌트 10개 통과.
- UUID 전용 합성 MongoDB에서 RFID 통합 12개 통과. 실제 앱 DB는 사용하지 않고 만든 테스트 DB만 정리했다.
  공용 권한/비밀번호, 전체 아동/Wi-Fi 적용, 개인 우선, 비공개 카드 차단, 버전 충돌, 개인 삭제 경계를 확인했다.
- no-store와 미리보기 대체 표시까지 포함한 전체 `npm run verify:full`은 890개·빌드·임시 스택/볼륨 정리를 통과했다.
  정책 28개, 백엔드 396개, Node 110개·React 200개, MongoDB 통합 99개, Chromium 57개다.
  소요 874.3초이며 결과는 다음 로컬 보고서에 있다.
  `.local-validation/2026-10-27T15-54-07.732Z-3b533565391d45a5b48a3d0c97ff1b02/summary.json`.
  브라우저에서 칩 두 개를 공용 등록한 뒤 아동이 개인 매핑 없이 사용하는 흐름을 확인했다.
- 브라우저 검사는 합성 USB·UID를 사용한다. 실제 칩을 읽어 저장하는 관리자 검수는 미실행이다.
- 실행 중인 앱의 첫 확인에서는 화면 소스는 200이었지만 새 관리자 API 경로가 빠져 있었다.
  연결된 소스에는 경로가 있어 백엔드만 재시작했고 이후 catalog/bindings/usb/events 세 경로와
  API health=ok를 확인했다. 현재 앱 반영은 확인했으나 자동 재시작 문제가 해결됐다고 표시하지 않는다.
- 기존 사용자 진단 스케치와 로컬 비밀 설정은 수정·커밋 대상에서 제외한다. 실제 UID를 하드코딩하지 않는다.

구현·자동 검사·커밋을 실제 하드웨어 등록 완료나 현장/운영 배포 승인으로 표시하지 않는다.
