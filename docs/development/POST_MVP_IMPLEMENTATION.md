# MVP 이후 개발 진행 기록

요구사항: [개발 요청서](../planning/POST_MVP_DEVELOPMENT.md). 기능 구현 상태와 검증 상태를 구분한다.

## A. 아동 말하기 화면 단순화

- 카드 선택 후 고른 카드 말하기를 기본 버튼으로 둔다. 모델 요청 중이거나 오프라인이어도 이 버튼을 사용할 수 있다.
- 신규 가입 계정의 기본 출력 방식을 `selection`으로 저장한다. 기존 계정의 누락된 값은 `natural`로 해석해 기존 동작을 보존한다.
- 문장 생성은 기존 계정에서 선택 기능으로 남기고 생성 결과 확인 절차를 유지한다.
- 출력 방식과 기록 상황은 상세 영역으로 옮긴다. 빠른 표현, 복구 표현, 카드 배치는 변경하지 않는다.
- 홈 활동의 추상 기호를 현재 카드 그림으로 바꾸고 작은 화면에서는 문장 영역의 고정을 해제한다.
- 검증: 사용자 요청에 따라 자동 테스트·빌드·브라우저·실기기 검증 미실행. 코드 변경과 공백 차이만 확인했다.

## B. 보호자 설정과 시작 화면

- 계정별 접근 설정에 `start_screen`과 `output_mode`를 저장한다. 홈과 그림으로 말하기 중 시작 화면을 고른다.
- 기존 계정은 저장값이 없으면 홈·기존 자연스러운 문장 설정을 유지한다. 새 계정은 고른 카드 말하기를 사용한다.
- 카드 표시·크기·개수와 발화 방식의 샘플 미리보기를 보호자 설정에 제공한다.
- 연결된 보호자·담당자의 `voice_access_manage` 권한으로 중요 설정을 저장한다. 아동 계정은 글자 크기,
  고대비, 동작 줄이기만 직접 바꿀 수 있다. 서버가 중요 필드 변경을 거절하고 아동의 저장에서 해당
  필드를 쓰지 않아 보호자와 동시에 저장해도 덮어쓰지 않는다.
- 개인정보 동의·데이터 삭제·지원 연결의 기존 API는 아동 본인 계정에서도 실행 가능하다. 현재 구조는
  별도 보호자 본인 확인 수단이 없으므로 이 설정들을 성인 확인 완료로 표시하지 않는다. 카드 배치는
  기존 연결별 `board_manage` 권한을 사용한다. 단순 계산 문제로 보호자 확인을 대체하지 않는다.
- 검증: 사용자 요청에 따라 자동 테스트·빌드·브라우저·실기기 검증 미실행. 코드 변경과 공백 차이만 확인했다.

## C. 규칙 기반 연습 제안

- 기존 그림카드 추천과 별도의 `/api/practice-suggestions` 경로를 둔다. 연결별 `records_read`와
  `learning_manage` 권한이 모두 있어야 보호자·담당자가 후보를 볼 수 있다.
- 개인화는 기본 꺼짐이며 보호자가 명시적으로 켠다. 기존 기록 동의가 없거나 삭제 중이면 분석하지 않는다.
- 최근 14일의 중복 ID가 없는 카드 선택 이벤트 최대 500건과 완료된 학습 최대 100건만 조회한다.
  응답에는 기간·표본·상한·최소 기준을 표시한다. 선택 이벤트 10건 또는 완료 3회 미만이면
  개인화 후보를 내지 않고 수동 학습 선택을 제공한다. 기준은 환경 변수로 조정 가능하다.
- 기존 학습 3종과 현재 학습 설정·제공 중인 카드로 후보를 만든다. 문장 순서 후보는 작성된 예문
  ID와 그 카드만 사용한다. 예문 목록은 프런트엔드의 기존 작성 예문과 일치시킨다.
- 보호자는 근거·카드·문제 수·보기 수·반복·재도전을 확인하고 명시적으로 준비한다. 아동은
  연습 화면에서 다시 명시적으로 시작한다. 후보 열람이나 준비는 학습 완료로 기록하지 않는다.
- 아동에게는 분석 근거를 반환하지 않는다. 시작할 때 현재 동의·설정·카드 상태를 다시 확인한다.
- 검증: 사용자 요청에 따라 자동 테스트·빌드·브라우저·실기기 검증 미실행. 코드 변경과 공백 차이만 확인했다.

## D. 제한된 Ollama 연습 제안

- 문장 생성 모델 `qwen2.5:0.5b`은 그대로 두고, 연습 제안은 별도의
  `OLLAMA_LEARNING_ENABLED`(기본 `false`)와 `OLLAMA_LEARNING_MODEL`(기본 `qwen3:4b-instruct`)을 사용한다.
- 서버가 C단계의 후보와 근거 ID를 만든 뒤 이름·사진·문장·메모 없이 ID와 집계 건수만 로컬
  Ollama `/api/chat`에 보낸다. 입력은 8KB 이하이며 응답 제한은 512토큰, 요청 제한은 30초다.
- 공식 [구조화 출력 설명](https://docs.ollama.com/capabilities/structured-outputs)에 따라
  Pydantic JSON Schema를 `format`에 전달하고 응답도 Pydantic과 허용 ID 집합으로 검사한다.
  모델은 최대 3개 후보 ID와 해당 후보의 근거 ID만 선택한다. 화면 수치와 설명은 서버가 만든다.
- 모델 비활성·없음·시간 초과·형식 오류·후보 밖 ID는 규칙 후보로 대체하고 AI 제안으로 표시하지 않는다.
  기록 부족은 모델 장애와 별도 상태다. 한 번에 한 요청만 모델을 사용한다.
- 요청 UUID별 생성 결과는 제안 묶음에 저장한다. 모델·프롬프트·규칙·집계 기간 버전을 기록하고
  같은 UUID의 중복 조회는 같은 후보 순서를 반환한다.
- 실제 모델 다운로드·추론·한국어 품질·냉간 지연 검증은 미실행이다. 자동 테스트·빌드·브라우저
  검증도 사용자 요청에 따라 실행하지 않았다. 코드 변경과 공백 차이만 확인했다.

## E. 보호자 피드백과 데이터 수명

- 연결별 `records_read`와 `learning_manage` 권한이 있는 보호자·담당자만 준비한 연습에
  `적절함`·`어려움`·`관심 없음` 의견을 저장·수정·삭제할 수 있다. 수정과 삭제는 revision을
  확인한다. 피드백은 학습 완료 여부와 별개이며 능력·발달·진단 판단으로 사용하지 않는다.
- 최근 14일의 보호자 의견을 서버 템플릿 근거로만 후보에 덧붙인다. 모델에는 의견 문장이나
  사용자 정보 대신 허용된 근거 ID만 보낸다.
- 기존 개인정보 보존 기간을 적용할 때 제안 묶음·준비한 연습·피드백도 정리한다.
  개인정보 내보내기와 개인 데이터 삭제에도 개인화 설정과 이 세 저장소를 포함한다.
  동의 철회 시 개인화 설정을 끄고 저장된 제안·준비한 연습·피드백을 삭제한다.
- 제안 생성 중 동의가 철회되면 저장 전에 동의·설정·후보의 카드와 학습 설정을 재확인해
  오래된 결과를 폐기한다. 준비 요청도 권한·동의·후보를 재확인한다. 화면은 계정 전환·
  로그아웃 뒤 이전 요청의 응답을 적용하지 않는다.
- 자동 테스트·빌드·브라우저·실기기·실제 모델 추론은 사용자 요청에 따라 미실행이다.
  한국어 모델 20건 수동 평가와 실제 아동·보호자 과업 관찰도 미실행이며 완료 게이트로
  남는다. 코드 변경과 공백 차이만 확인했다.

## 연습 화면 UI 정리

- [Bootstrap 5.3.8](https://getbootstrap.com/docs/5.3/getting-started/download/)의 그리드와
  배치 유틸리티를 npm 의존성으로 추가했다. 전역 카드·버튼 스타일과의 충돌을 줄이기 위해
  컴포넌트 전체 스타일과 JavaScript 플러그인은 가져오지 않는다.
- 아동 연습 화면을 `연습 종류 → 카드 범위 → 시작` 순서로 정리했다. 연습 종류는 설명이 있는
  선택 카드, 범위는 누르기 쉬운 버튼으로 표시하고 현재 선택을 `aria-pressed`로 알린다.
- 보호자가 준비한 연습과 최근 30일 기록을 같은 화면 흐름에 맞췄다. 화면 폭에 따라
  선택 카드와 요약 배치를 바꾸고 고대비·동작 줄이기 설정을 반영한다.
- 문장 순서 연습에서는 실제로 가능한 예문이 있는 범위만 보여준다. 설정에서 허용하지
  않은 카테고리의 카드가 직접 선택으로 들어오지 않도록 범위 계산을 보강했다.
- 검증: 코드·패키지 경로와 `git diff --check` 확인. 사용자 요청에 따라 빌드·브라우저·
  실기기 검증은 미실행이다.

- 검증: 파일 경로와 참조 위치, `git diff --check` 확인. 사용자 요청에 따라 빌드·
  브라우저 검증은 미실행이다.

## Docker 프런트엔드 의존성 갱신

- Compose의 `/app/node_modules` 영구 볼륨이 새 이미지의 의존성을 가리는 경우를 막기 위해
  컨테이너 시작 시 `package-lock.json` 해시를 확인한다. 변경된 경우에만 `npm ci`로
  볼륨을 갱신하고 완료 해시를 기록한다.
- 기존 볼륨은 해시 파일이 없으므로 첫 시작에서 갱신된다. 설치 실패 시 해시를 기록하지
  않아 다음 시작에서 다시 시도한다.
- 검증: `docker compose up -d --no-deps --build frontend`로 컨테이너를 재시작했다.
  컨테이너 안에 두 Bootstrap CSS 파일이 존재하며 Vite 준비 로그를 확인했다.
  `git diff --check`도 통과했다. 실제 브라우저 화면 확인은 사용자 검증에 남긴다.

## USB 연결 위치 조정

- 아동 화면의 왼쪽 하단 연결 버튼을 오른쪽 상단 서비스 상태 메뉴로 옮겼다.
  메뉴에서 USB 포트를 연결·해제하고 카드 읽기 영역으로 이동할 수 있다.
- 카드 인식·문장 적용·장치 로그는 기존 리더기 영역에 유지한다. 메뉴가 닫혀도
  리더기 세션은 유지되고, 집중 화면에서도 같은 상단 메뉴를 사용한다.
- 검증: 포털 대상과 화면 상태 조건, `git diff --check` 확인. 사용자 요청에 따라
  빌드·브라우저·실기기 검증은 미실행이다.

## 마이페이지 설정 메뉴 정리

- 프로필 진입 버튼의 화살표를 톱니바퀴로 표시해 이름과 사진을 누르면 설정이
  열린다는 점을 드러냈다. 기존 진입 동작과 설정 저장 동작은 유지한다.
- 마이페이지의 가로 나열 버튼을 설명이 있는 설정 메뉴와 내용 영역으로 정리했다.
  좁은 화면에서는 메뉴를 두 열로 배치하고, 선택 상태와 고대비 표시를 유지한다.
- 검증: 코드 변경과 `git diff --check` 확인. 사용자 요청에 따라 자동 테스트·빌드·
  브라우저·실기기 검증은 미실행이다.

## 마이페이지 팝업 크기 고정

- 설정별 내용 길이에 따라 팝업이 늘거나 줄지 않도록 화면 크기 안에서 일정한 높이를
  사용한다. 제목과 메뉴는 제자리에 두고 설정 내용만 내부에서 스크롤한다.
- 설정 항목을 바꿀 때 이전 항목의 스크롤 위치가 남지 않도록 내용 영역을 맨 위로 돌린다.
  작은 화면에서는 메뉴 높이를 제한해 내용 영역을 확보한다. 팝업 드래그는 넣지 않았다.
- 검증: 코드 변경과 `git diff --check` 확인. 사용자 요청에 따라 자동 테스트·빌드·
  브라우저·실기기 검증은 미실행이다.

## KRDS 기준 UI·UX 마무리 점검과 수정

2026-10-29 코드 기준으로 주요 화면을 점검했다. 앞선 마이페이지 팝업은 이 작업에서
설정 전용 화면으로 전환했다. KRDS 적합성 인증이나 실사용 검수 완료를 의미하지 않는다.

| 점검 영역 | 반영 내용 |

## 아동 핵심 화면 단순화

- 홈의 큰 활동 선택을 `말하기`·`연습하기` 두 개로 줄였다. 이어서 말하기는 같은
  말하기 버튼에서 제공하고, 내 카드와 주제별 탐색은 보조 진입점으로 정리했다.
- 저장된 빠른 표현은 모든 화면에서 유지하며 홈·연습에서는 작게 표시한다. 표현 수정은
  말하기 화면에 두고, 이전 문장·다시 듣기 도구는 필요할 때 펼치도록 했다.
- 문장 다듬기와 추천 카드는 기본으로 접는다. 생성 중·결과·실패 시 문장 영역을 펼치며
  기본 카드 발화는 바로 사용할 수 있다. 아동 화면의 추천 알고리즘 버전 표시는 제거했다.
- 리더기 영역은 상단 메뉴에서 열거나 태그가 추가됐을 때 말하기 화면에 표시한다.
  USB 세션은 유지하고 오프라인 음성 준비 안내·재시도는 연결 메뉴로 모았다.
- 연습 종류·범위 변경과 최근 기록은 기본으로 접고, 현재 선택과 시작 버튼을 먼저
  제공한다. 연습 불가 범위에서는 변경 영역을 펼친다. 펼친 채로 종류·범위를 바꿀 수 있다.
- 카드 순서·사용자 설정·학습 상태·발화 동작은 변경하지 않았다.
- 검증: JSX 5개·CSS 3개 구문 검사와 `git diff --check` 통과. 커밋용 `App.jsx`와
  작업 파일의 Rolldown 변환 결과 일치를 확인해 기존 포맷 변경을 제외했다.
- 자동 테스트·빌드·브라우저·실기기 검증은 사용자 요청에 따라 미실행이다. 홈 진입,
  접기·펼치기와 연습 변경, 생성 결과 표시, USB 태그 후 영역 자동 열기는 수동 확인이 남는다.

## 연결 메뉴 정렬과 인터페이스 아이콘 통일

- 리더기 연결 메뉴를 `상태 점 / 문구 / 화살표`의 고정 열로 배치했다. 글자 화살표를
  SVG로 바꾸고 중앙 정렬했으며, 열림 상태에서는 같은 자리에서 회전한다.
- 공통 `UiIcon`으로 메뉴·마이페이지·홈·랜딩·연습·등록·순서 편집·발화 조작의
  아이콘을 통일했다. 같은 viewBox·선 굵기·선 끝 모양과 기본 크기를 사용한다.
- 일반 펼침 메뉴의 브라우저 기본 삼각형도 같은 SVG 경로의 화살표로 통일했다.
  그림카드의 이미지와 표현 기호는 유지한다. 아이콘만 있는 조작의 기존 접근성 이름은
  유지하고 SVG는 보조기술에서 중복 낭독하지 않도록 처리했다.
- 검증: JSX 11개·CSS 2개 구문 검사, 정적 아이콘 이름·설정 매핑 검사와
  `git diff --check` 통과. 커밋용 `App.jsx`와 작업 파일의 변환 결과 일치를 확인했다.
- 자동 테스트·빌드·브라우저·실기기 검증은 사용자 요청에 따라 미실행이다.
  연결 상태별 정렬·열림 화살표 방향, 좁은 화면의 메뉴와 고대비·동작 줄이기 표시,
  아이콘 단독 버튼의 초점·접근성 이름은 실제 브라우저에서 확인이 남는다.

## 민트·크림 공통 색상 체계

- `styles.css` 최상단에 역할별 색상 토큰 23개를 정의했다. 실제 HEX 값은
  반투명 장식·그림자·오버레이·고대비 검정을 포함한 22종이다.
  `--color-on-action`은 흰색 표면 토큰의 별칭이다.
- 기존 CSS 4개의 직접 색상 선언을 토큰 참조로 통합했다. 같은 HEX라도
  본문·액션·경고·오류·선택 등 적용 역할을 구분했다. 기존 `--ui-*`와
  `--landing-*`는 공통 토큰의 별칭으로 연결했다.
- 홈·말하기·연습·카드 목록·리더기·마이페이지·보호자 관리·랜딩에 적용했다.
  레이아웃·카드 순서·카드 이미지·발화·권한·개인화 로직은 변경하지 않았다.
- 카드 순번별 배경색과 추천 카드 제목의 서로 다른 색상 띠를 제거했다.
  그림카드는 흰색, 선택 영역은 연한 민트와 진한 테두리로 구분한다.
  카테고리 선택에는 하단 선, 카드 상세 선택에는 안쪽 테두리를 추가했다.
  기존 연습 종류·범위의 체크 표시와 라디오 입력은 유지했다.
- 오류·성공·경고는 별도 전경·배경 토큰을 사용한다. 상태 문구와 아이콘은
  유지하며, 리더기 연결 점에는 성공 전경색을 사용한다.
- 키보드 포커스 파랑과 흑백 고대비 모드를 유지했다. 고대비 모드에서
  공통 토큰과 기존 `--ui-*` 별칭을 함께 재정의해 일반 테마색 유입을 줄였다.
- HTML 테마와 웹 앱 매니페스트도 민트·크림으로 변경했다. 그림·로고 파일,
  Bootstrap 패키지 내부 색상과 서비스 워커의 캐시 정책은 변경하지 않았다.
  기존 설치 앱의 매니페스트·테마 갱신 여부는 별도 확인이 필요하다.
