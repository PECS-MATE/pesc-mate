# MVP 이후 개발 진행 기록

요구사항: [개발 요청서](../planning/POST_MVP_DEVELOPMENT.md). 기능 구현 상태와 검증 상태를 구분한다.

## A. 아동 말하기 화면 단순화

- 카드 선택 후 고른 카드 말하기를 기본 버튼으로 둔다. 모델 요청 중이거나 오프라인이어도 이 버튼을 사용할 수 있다.
- 신규 가입 계정의 기본 출력 방식을 `selection`으로 저장한다. 기존 계정의 누락된 값은 `natural`로 해석해 기존 동작을 보존한다.
- 문장 생성은 기존 계정에서 선택 기능으로 남기고 생성 결과 확인 절차를 유지한다.
- 출력 방식과 기록 상황은 상세 영역으로 옮긴다. 빠른 표현, 복구 표현, 카드 배치는 변경하지 않는다.
- 홈 활동의 추상 기호를 현재 카드 그림으로 바꾸고 작은 화면에서는 문장 영역의 고정을 해제한다.
- 검증: 사용자 요청에 따라 자동 테스트·빌드·브라우저·실기기 검증 미실행. 코드 변경과 공백 차이만 확인했다.

## B. 보호자 설정과 시작 화면

- 계정별 접근 설정에 `start_screen`과 `output_mode`를 저장한다. 홈과 그림으로 말하기 중 시작 화면을 고른다.
- 기존 계정은 저장값이 없으면 홈·기존 자연스러운 문장 설정을 유지한다. 새 계정은 고른 카드 말하기를 사용한다.
- 카드 표시·크기·개수와 발화 방식의 샘플 미리보기를 보호자 설정에 제공한다.
- 연결된 보호자·담당자의 `voice_access_manage` 권한으로 중요 설정을 저장한다. 아동 계정은 글자 크기,
  고대비, 동작 줄이기만 직접 바꿀 수 있다. 서버가 중요 필드 변경을 거절하고 아동의 저장에서 해당
  필드를 쓰지 않아 보호자와 동시에 저장해도 덮어쓰지 않는다.
- 개인정보 동의·데이터 삭제·지원 연결의 기존 API는 아동 본인 계정에서도 실행 가능하다. 현재 구조는
  별도 보호자 본인 확인 수단이 없으므로 이 설정들을 성인 확인 완료로 표시하지 않는다. 카드 배치는
  기존 연결별 `board_manage` 권한을 사용한다. 단순 계산 문제로 보호자 확인을 대체하지 않는다.
- 검증: 사용자 요청에 따라 자동 테스트·빌드·브라우저·실기기 검증 미실행. 코드 변경과 공백 차이만 확인했다.

## C~E

구현 및 검증 상태는 각 단계 완료 시 기록한다. 이전 단계의 미실행 검증을 통과로 표시하지 않는다.
