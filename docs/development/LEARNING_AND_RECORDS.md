# 학습 활동과 의사소통 기록

> 통합일: 2026-11-04 · 현재 사용 안내와 과거 구현 기록을 구분합니다.

현재 학습은 단어·그림 맞추기, 소리 듣고 카드 찾기, 카드 순서로 문장 만들기, 상황에 맞는 카드 고르기 4종입니다. 문장 순서 활동은 정해진 예문을 따라 구성하며 자유 문장 채점이나 진단은 하지 않습니다. 학습 결과와 의사소통 기록은 저장소·동의·집계에서 구분합니다. 보호자·담당자의 기록 접근은 연결 권한에 따릅니다. 합성 사용 기록 도구는 실제 계정의 통계·추천에 영향을 주므로 별도 확인 없이 실행하지 않습니다.

## 맞춤 세트와 일일 코스 (2026-11-06)

- 식사·학교·외출 상황 연습을 추가했습니다. 상황은 정해진 문구로 제시하며 정답은 해당 상황에 허용된 카드입니다. 임상 평가나 자유 대화 채점이 아닙니다.
- 아이 관리 → 연습 관리에서 이름·종류·카드를 골라 최대 20개 세트를 저장합니다. 상황 세트는 해당 상황의 정답 카드를 포함해야 합니다.
- 세트를 코스 순서에 넣고 시작 날짜·복습 간격을 저장합니다. 순서는 30일 동안 반복되며 아이가 날짜별 코스와 준비된 세트를 직접 시작합니다. 자동 실행·알림 전송은 없습니다.
- 복습은 세트별 마지막 완료 기록을 기준으로 제안합니다. 상황 연습은 단어 숙련도 집계에서 제외합니다.
- `GET/PUT /learning/program?user_id=...`: 학습·카드 관리 권한과 보호자 동의를 모두 확인합니다. PUT은 보호자·담당자 전용이며 revision 충돌은 409로 거부합니다.
- 기존 `learning_settings` 안에 프로그램을 저장하고 `learning_attempts.program_set_id`로 완료를 연결하므로 기존 개인정보 내보내기·삭제 범위를 유지합니다.
- 코스 관리는 온라인 전용입니다. 기본 말하기와 기존 오프라인 연습은 유지합니다.
- 검증: 프론트 빌드(큰 번들 경고 유지), 백엔드 라우터 import, 스키마·권한·동의·카드 필터링 점검, 상황 보기·일일/복습 계산 점검 통과. 첫 일정 검사에서 반환값을 undefined로 잘못 기대해 실패했으며 null 기대값으로 바로잡아 재검사 통과했습니다. 실제 브라우저·보호자/아동 기기 검수·실 DB 권한 회수 경쟁 조건 검증은 미실행이며 운영 승인으로 간주하지 않습니다.

과거 날짜의 검사 통과는 현재 버전 전체의 검수나 운영 배포 승인이 아닙니다. 상세 기록에는 이전 화면·제거된 기능 설명도 있으므로 현재 사용 경로는 위 안내를 우선하고, 남은 실제 기기·권한·음성 검수는 TODO와 각 절의 미실행 기록을 확인하세요.

<a id="learning-data-model--학습-기록-데이터-모델"></a>
### 학습 기록 데이터 모델

의사소통은 사용자가 실제 의도를 전달한 기록이고, 학습은 문제 풀이 결과이므로
서로 다른 컬렉션과 API에서 관리한다. 학습 점수나 오답은 카드 추천 및
의사소통 통계에 포함하지 않는다.

<a id="learning-data-model--컬렉션"></a>
#### 컬렉션

- `communication_sessions`: 실제 카드 선택과 생성 문장 기록
- `learning_settings`: 사용자별 학습 카테고리, 문제 수, 보기 수, 카드 반복 빈도,
  제한 시간, 재도전 설정
- `learning_attempts`: 활동 유형, 카테고리, 문제·정답·오답 수, 문제별 카드 ID·표시명·
  첫 시도 성공 여부, 서버 계산 점수, 소요 시간 및 완료 시각
- `learning_audit_logs`: 설정 변경 대상, 변경자, 변경 전·후 값 및 변경 시각

학습 시도에는 `record_type=learning_attempt`를 저장한다. 동일한 요청 ID를 다시
전송해도 한 건만 저장하며, 보존 기간과 개인정보 다운로드·삭제는 기존 사용자
정책을 동일하게 적용한다.

신규 학습 설정·시도·감사 문서에는 `schema_version=1`을 저장한다. 기존 누락 문서는
일반 조회·수정 중 자동 변환하지 않으며 별도 명시적 기준선 도구를 사용한다.
학습 요청 UUID와 보드 편집 revision은 저장 형식 버전과 구분한다.
대상·적용 전제는 [데이터 버전·마이그레이션](DATA_SCHEMA_MIGRATIONS.md)을 따른다.

최근 학습 진행은 총점보다 참여 횟수와 단어별 경험을 먼저 보여 준다. 조회 기간
안에서 두 번 이상 모두 첫 시도에 찾은 카드는 `familiar_words`, 한 번이라도
어려움이 있었던 카드는 `repeat_words`, 한 번 편안하게 찾은 카드는
`practicing_words`로 집계한다. 과거 문제별 결과가 없는 기록도 세션 참여 집계에는
포함되며 단어 집계에서만 제외한다.

클라이언트는 진행 중인 문제 순서·현재 위치·문제별 결과와 학습 설정을 사용자별
IndexedDB에 저장한다. 오프라인에서 완료한 결과는 원래 `request_id`를 유지한 채
대기열에 넣고 재연결 시 `POST /api/learning/attempts`로 전송한다. 서버의 기존
요청 ID 멱등 처리를 사용하므로 재시도나 연결 이벤트가 반복되어도 한 건만 남는다.

<a id="learning-data-model--역할별-api"></a>
#### 역할별 API

| API | AAC 사용자 | `learning_manage` 연결 계정 |
|---|---:|---:|
| `GET /api/learning/settings` | 본인 조회 | 연결 사용자 조회 |
| `PUT /api/learning/settings?user_id=...` | 차단 | 설정 변경 |
| `POST /api/learning/attempts` | 본인 결과 저장 | 차단 |
| `GET /api/learning/progress` | 본인 조회 | 연결 사용자 성취 조회 |
| `GET /api/learning/audit` | 본인 조회 | 연결 사용자 설정 이력 조회 |

설정 변경과 성취 조회는 역할명만으로 허용하지 않고 활성 연결과
`learning_manage` 권한을 모두 확인한다. 최초 지원 활동은
`word_picture_match`이며, 보호자·권한 있는 담당자는 연결 사용자의 학습 범위와
문제 수, 보기 수, 반복 빈도, 권장 시간, 재도전 여부를 편집할 수 있다. 후속
활동은 별도 유형으로 추가한다. 2026-10-24 [소리 듣고 카드 찾기](LEARNING_AND_RECORDS.md#sound-card-learning)를
`sound_picture_match`로 추가했다. 신규 결과의 `content_version`은 활동별 v1과 일치해야
하며 과거 누락 문서는 null로 읽는다. 문제 음성은 의사소통/발화 이력에 넣지 않는다.
동의 없는 연습은 새 진행/결과/대기열을 저장하지 않는다.

같은 날짜에 [카드 순서로 문장 만들기](LEARNING_AND_RECORDS.md#sentence-order-learning)를 `sentence_card_order`와
`sentence-order-v1`로 추가한다. 문제별 `content_id`·`card_ids`에 예문과 구성 순서를 남기고,
이 활동의 결과는 참여 합계에만 포함하며 단어별 경험 집계에서는 제외한다.

<a id="learning-data-model--경계-확인-상태"></a>
#### 경계 확인 상태

의사소통 통계·추천과 학습 성취의 상호 불변, 독립 UUID·권한, 객체 ID 교차 사용,
오프라인 재전송, 본인 내보내기·삭제의 분리 범위는
과거에는 자동 시험으로 확인했으나 2026-10-28 해당 시험과 실행기를 제거했다.
현재 버전은 실제 인증·임시 MongoDB API 통합 확인을 수행하지 않았다.

<a id="sound-card-learning--소리-듣고-카드-찾기"></a>
### 소리 듣고 카드 찾기

2026-10-24 학습 콘텐츠 확장의 첫 활동. **연습하기 → 연습 종류 → 소리 듣고 카드 찾기**에서
시작한다. 기존 단어·그림 맞추기도 유지한다. 실제 의사소통·청력·언어 능력을 평가하거나
진단하는 검사가 아니다.

<a id="sound-card-learning--출제와-재생"></a>
#### 출제와 재생

기존 보호자 학습 설정의 카테고리·문제 수·보기 수·반복·재도전을 사용한다. 선택 범위에서
그림이 있는 카드만 후보로 사용하며 문제당 정답 1개와 중복 없는 보기를 만든다.
새 문제를 자동 재생하지 않는다. **문제 소리 듣기**를 누르고 재생 시작 콜백이 와야
답 카드를 고를 수 있다. 문제의 정답 그림은 미리 보여 주지 않고 보기에 그림·단어를 함께
표시한다. 재생 시작은 실제 청취 확인이 아니다. 시간 제한 때문에 자동 실패 처리하지 않는다.

기기 TTS를 기존 사용자 음량·속도·목소리 설정으로 재생한다. 온라인 음성 공급자의 전송
특성은 기존 음성 정책과 같으며 별도 서버 TTS 공급자나 음성 업로드는 도입하지 않는다.
오프라인 문제 재생은 `localService=true`인 한국어 음성이 있어야 한다. 없거나 재생이
실패하면 안내·재시도를 제공하고, 연습 목록에서 그림·단어 연습을 고를 수 있다.
같은 문제의 재생 중지 후 다시 듣기도 가능하다.

문제 음성은 공용 재생기를 사용하지만 의사소통 발화/선택 이력·마지막 말·문장에는 넣지
않는다. 상단에는 정답 대신 **학습 문제 음성**으로 표시한다. 긴급·복구·기본 말하기는
문제 음성을 대체할 수 있다. 문제 화면을 나갈 때는 자신이 시작한 재생만 정리하므로
그 뒤 시작된 긴급 발화를 중단하지 않는다. 학습 때문에 말하기를 잠그지 않는다.

<a id="sound-card-learning--결과재개동기화"></a>
#### 결과·재개·동기화

`activity_type=sound_picture_match`, `content_version=sound-picture-v1`을 학습 결과에
기록한다. 기존 활동은 `word_picture_match`, `word-picture-v1`이다. 종류와 버전이 맞지
않으면 422로 거절한다. 과거 저장 문서의 없는 버전은 null로 읽으며 임의로 채우지 않는다.
버전 없는 구형 요청은 해당 활동의 현재 v1으로 저장해 기존 클라이언트를 유지한다.

문제 순서·결과·종류·버전·요청 ID를 기존 아동별 학습 캐시에 보관한다. 새로고침해도
같은 활동/문제로 재개하고, 아직 답하지 않은 소리 문제는 다시 듣게 한다. 지원하지 않는
활동/버전은 강제로 복원하지 않고 새 연습 선택을 안내한다. 오프라인 완료는 같은 활동·
버전·UUID를 기존 학습 대기열로 전송하므로 재연결/재시도에도 한 번 저장된다.

서버는 기존 합계/문제별 결과 일치·동의·역할·소유자 검사를 유지한다. 단어별 집계에는
두 활동의 관찰 결과가 함께 포함되며 자동 능력 판정이나 난이도 추천을 추가하지 않는다.
학습 진행/개인정보 JSON에 버전을 포함하고 학습 기록 CSV/JSON에도 `content_version`을
추가한다. 의사소통 기록과 합치지 않으며 기존 개인정보 삭제/보존 범위를 따른다.
동의가 없으면 앞선 [기록 없는 연습](USER_INTERFACE.md#guardian-consent-flow)에 따라 결과·진행·대기열을
저장하지 않고 현재 화면에서만 사용한다.

<a id="sound-card-learning--검증과-남은-범위"></a>
#### 검증과 남은 범위

Node 96·React 179개, 총 275개와 빌드 통과. 새 컴포넌트 5개는 기존 활동 유지·자동 재생
없음·시작 전 선택 차단·오류/재시도·이전 문제 콜백 폐기·정리·완료/저장 상태를 검사한다.
Windows 백엔드 386개 실행은 통과했으나 환경 의존 심볼릭 링크 2개를 제외했다.
후속 Linux 백엔드 386개·격리 MongoDB 전체 통합 86개 통과(제외 없음).
첫 통합 실행에서 최초 저장 응답과 재전송 응답의 완료 시각 표기가 달라 1개가 실패했다.
BSON 밀리초 정밀도·UTC 표기를 응답에서 통일해 기존 DB를 고치지 않고 재전송 응답을
일치시켰다. 같은 전체 단위·통합 검사를 재실행해 모두 통과했다.

Chromium 10개 통과: 소리 학습의 명시 재생·새로고침 재개·학습에만 저장·오프라인 완료와
한 번 동기화·긴급 발화 우선 및 화면 이탈 정리, 기존 학습/오프라인/개인 카드/보호자 동의/
복구 흐름을 실제 API·임시 MongoDB에서 확인했다. 보고서:
`.local-validation/learning-guardian-20261024/browser-sound-final/report/`.

추가 Chromium 1개도 통과했다. 동의 없는 소리 학습 10문제를 실제 화면에서 완료하고,
서버 학습/발화/의사소통 결과·기기 진행·대기열·관련 POST/PATCH가 없는지 확인했다.
보고서: `.local-validation/learning-guardian-20261024/browser-recordless-learning/report/`.
각 임시 스택은 정리했다. 사용자 사진·DB·운영 볼륨과 원격 저장소는 변경하지 않았다.

실제 기기 음질·아동 과업·스크린리더 검수와 전체 `verify:full`은 미실행이다.
문장 순서 만들기·상황 연습·보호자 지정 문제 세트·적응 난이도·일일 코스 등 나머지
B2-01 항목은 별도 후속 범위다. 콘텐츠 버전은 추가했지만 전체 출제 근거/콘텐츠 이력
체계까지 완료한 것은 아니다.

후속 검증: 같은 날짜의 [문장 순서 학습](LEARNING_AND_RECORDS.md#sentence-order-learning) 개발 후 전체

이 후속 전체 실행은 소리 학습과 동의 없는 연습 회귀도 포함한다. 실제 기기 검수는 계속 별도다.

<a id="sentence-order-learning--카드-순서로-문장-만들기"></a>
### 카드 순서로 문장 만들기

2026-10-24 B2-01의 두 번째 콘텐츠다. **연습하기 → 연습 종류 → 카드 순서로 문장 만들기**에서
시작한다. 실제 아동의 의도·발화·문장 능력을 추론하거나 진단하지 않는 예문 따라 만들기다.

<a id="sentence-order-learning--출제와-조작"></a>
#### 출제와 조작

`frontend/src/services/sentenceLearning.js`에 2~3장으로 이루어진 고정 예문 10개를 둔다.
물 마시기·밥/사과/간식 먹기·화장실 가기·쉬기와 일부 ‘나’ 포함 예문이다. 기존 내장 개념 ID를
참조하며 파일명·이름이 같은 개인 사진을 임의로 문제에 넣지 않는다. 이미지나 AI를 생성하지 않는다.
이 목록은 개발용 첫 콘텐츠이며 실제 AAC 사용자에게 적합한 문장·순서 검수는 별도다.

현재 아동에게 제공된 그림 카드 중 학습 설정·선택 카테고리 안에 예문 카드가 모두 있어야
출제한다. 일부 구성 카드가 없으면 그 예문을 제외하며 전혀 없으면 시작을 막고 전체 범위나
다른 활동을 안내한다. 카테고리 밖의 행동/사람 카드를 몰래 추가하지 않는다.
문제 수·반복·재도전 설정은 유지한다. 보기 수 설정은 적용하지 않고 예문마다 정해진 2~3장을
모두 사용한다고 표시한다. 권장 시간이 지나도 자동 실패나 말하기 잠금을 만들지 않는다.

예문 문장과 모범 그림 순서를 보여 주고, 섞인 보기의 카드를 눌러 순서대로 담는다.
고른 카드를 누르면 뺄 수 있어 드래그 없이 순서를 수정한다. 모두 담은 뒤 **순서 확인**으로
제출한다. 중복·누락·외부 카드 ID는 정답으로 처리하지 않는다. 같은 오답의 중복 제출을 막고
재도전을 허용할 때만 고쳐 제출할 수 있다. 재도전 정답은 첫 시도 성공으로 올려 세지 않는다.
재도전이 꺼져 있으면 예문 순서를 안내하고 다음 문제로 이동한다. 확정·저장 중 입력을 막는다.

예문은 자동 재생·실제 발화·마지막 말·선택 문장에 넣지 않는다. 기본·긴급·복구 말하기와
카드판 위치는 바꾸지 않으며 **말하기로 이동**을 계속 제공한다. 추가 서버 TTS도 사용하지 않는다.

<a id="sentence-order-learning--버전재개결과"></a>
#### 버전·재개·결과

- 활동: `sentence_card_order`, 콘텐츠 버전: `sentence-order-v1`.
- 기존 단어/소리 활동의 문제별 필드는 유지한다. 새 활동은 문제별 `content_id`와 정답 순서의
  `card_ids` 2~3개를 추가한다. 기존 `card_id`·`label`은 마지막 행동 카드다. 전체 문장을
  행동 카드 하나의 성공으로 해석하지 않는다. 모든 시도 순서나 음성을 저장하는 기능은 아니다.
- 서버는 버전·문제별 합계·유일한 카드 ID·마지막 카드 일치와 기존 동의·역할·소유자 검사를
  적용한다. 문장 활동에는 문제별 결과가 필수다. 다른 활동의 문장 전용 필드를 거절한다.
  결과는 클라이언트의 연습 관찰 기록이며 서버가 언어 능력이나 의미를 독립 채점하지 않는다.
- 참여·문제 합계에는 포함하되 단어별 반복/익숙함 집계에서 문장 활동을 제외한다.
- 학습 JSON·CSV의 문제별 항목 및 개인정보 JSON에 콘텐츠 ID·카드 순서를 포함한다.
  의사소통 기록·추천 학습 데이터로 합치지 않는다. 기존 보존·내보내기·삭제 정책을 적용한다.

동의가 있으면 문제·예문·보기 순서·고른 카드·재도전 상태·요청 UUID를 아동별 IndexedDB에
보관한다. 새로고침 때 같은 문제와 선택을 복원하며, 지원하지 않는 버전·예문·선택 카드
구성은 강제 재개하지 않는다. 임시 Blob URL은 저장하지 않고 기존 그림 캐시에서 복원한다.
오프라인 완료와 응답 유실은 기존 학습 대기열에 같은 UUID로 저장해 한 번만 동기화한다.
서버의 새 데이터 삭제가 오프라인 기기에 즉시 전파되는 것은 아니다.

동의가 없으면 결과는 현재 화면에서만 보며 새 진행·완료·오프라인 대기 기록을 만들지 않는다.
기존 계정·카드 캐시는 남으므로 익명 모드가 아니다. 자세한 범위는
[보호자 동의 흐름](USER_INTERFACE.md#guardian-consent-flow)을 따른다.

<a id="support-record-dashboard--의사소통학습-기록-화면-분리"></a>
### 의사소통·학습 기록 화면 분리

B1-03의 구현 범위다. 첫 단위인 탭 분리를 확장해 보호자·담당자의 기존 연결 권한과 별도
저장소를 유지하면서 기록의 목적, 조회 범위, 관찰 지표와 삭제 결과를 화면에서도 구분한다.

<a id="support-record-dashboard--조회-범위"></a>
#### 조회 범위

| 영역 | 연결 권한 | API | 지표 기준 |
|---|---|---|---|
| 의사소통 기록 | `records_read` | `/dashboard?user_id=…` | 저장한 문장과 그 문장에 포함된 카드 |
| 학습 기록 | `learning_manage` | `/learning/settings?user_id=…`, `/learning/progress?user_id=…&days=30` | 최근 30일 완료한 연습과 단어별 연습 결과 |

- 학습 참여는 의사소통의 문장·카드 집계에 합산하지 않는다. 의사소통 지표는 실제 음성
  재생 성공 횟수도 아니다. 학습 결과를 의사소통 능력 평가나 진단으로 해석하지 않는다.
- 기존 `학습 성취` 메뉴를 `학습 기록`으로 바꾸고 학습 권한이 조회·설정 관리를 포함함을
  알린다. 권한 자체를 새로 부여하거나 세분화한 것은 아니다.
- 한 영역의 권한만 있으면 다른 탭은 `조회 권한 없음`으로 비활성화한다. 해당 API를
  미리 조회하지 않으며 서버도 별도 권한으로 차단한다. 공용 콘텐츠 운영 권한은 우회 수단이 아니다.
- 탭의 좌우 방향키·Home·End로 허용된 영역만 전환한다. 활성 탭과 패널을 접근성 속성으로 연결한다.

<a id="support-record-dashboard--비동기-응답과-실패"></a>
#### 비동기 응답과 실패

- 영역·대상 사용자·조회 기간 변경 시 이전 지표를 비우고 해당 영역만 다시 읽는다.
- 최신 조회 번호, 로그인 세션, 현재 계정과 대상 사용자, 연결 권한, 온라인 상태를 확인한
  결과만 반영한다. 이전 조회의 늦은 성공·오류는 현재 기록을 덮어쓰지 않는다.
- 권한 변경·오프라인 전환 시 지원 사용자 데이터를 닫고 진행 중 조회를 무효화한다.
  보호자·담당자의 기록을 오프라인 캐시에 저장하지 않는다.
- 조회 실패를 참여 0회로 표시하지 않는다. 오류를 알리고 다른 허용된 기록 영역으로 이동할 수 있다.

<a id="support-record-dashboard--변경하지-않는-범위"></a>
#### 변경하지 않는 범위

고정 카드 위치, 말하기·긴급·복구 표현, AAC 사용자의 오프라인 학습은 유지한다.
새 컬렉션이나 별도 조회 콘솔 로그는 추가하지 않는다. 추가 필드는 기존 컬렉션에 선택적으로
저장하며 과거 기록을 자동으로 보충하지 않는다. 기존 보관 기간·권한·개인정보 삭제 범위를 유지한다.

<a id="support-record-dashboard--카드-조합타임라인다운로드--2026-10-21"></a>
#### 카드 조합·타임라인·다운로드 — 2026-10-21

- `top_combinations`는 조회 기간에 처음 저장한 문장에 함께 포함된 서로 다른 두 카드의 조합
  상위 10개다. 순서와 같은 카드 반복을 무시하고 재생성 행은 제외한다. 기간 밖의 원본을
  기간 안 재생성으로 다시 세지 않는다. 동률은 카드 ID 순으로 정렬한다. 추천이나 고정 보드에 반영하지 않는다.
- 기존 문장·카드 지표는 재생성 행을 포함한 저장 행 기준으로 유지한다. 조합의 집계 기준과
  다름을 화면에 안내한다. 비교·진단·위험 판단을 추가하지 않는다.
- 최근 10개 타임라인은 카드 순서, 개인 카드 스냅샷, 수집된 선택 시각, 생성 방식,
  재생성 회차·원본 기록 번호를 표시한다. 해당 문장과 명시적으로 연결한 재생 결과를 최근 최대
  10개씩 표시한다. 과거·복원 카드의 없는 시각은 `기록 없음`, 연결 결과가 없으면 그 사실을 알린다.
  저장 시각이나 전체 TTS 횟수를 발화 성공으로 바꾸지 않는다.
- `GET /api/records/export?domain=communication|learning|activity&format=json|csv&days=7&user_id=…`는
  영역별 기존 권한(`records_read` / `learning_manage`)을 매 요청 확인한다. AAC 사용자는 본인만
  가능하고, 운영 권한은 다른 아동을 내보낼 권한을 주지 않는다. 메모 권한의 확대도 없다.
- UI는 의사소통의 현재 7일·30일·전체, 학습의 현재 최근 30일을 사용한다. API는 `days=1~365`와
  생략 시 전체를 지원하며, 요청 시각까지의 저장/완료 기록만 읽는다. 학습은 `learning_attempt`
  유형과 완료 시각으로 제한한다. 다른 영역·다른 사용자·지원 메모·계정/이미지/토큰은 제외한다.
- 화면의 10/20개 미리보기 한도와 달리 전체 기간 기록을 다운로드한다. 서버는 최대 10,001개를
  읽고 10,000개 초과 시 413으로 기간 축소를 안내한다. 잘린 파일을 정상 응답으로 보내지 않는다.
  JSON은 영역·대상·기간·포함 경계 시각·행 수·해석 안내와 `records`를 담는다.
- CSV는 헤더와 한 기록당 한 행, 배열·단어별 결과는 JSON 셀로 제공한다. 한글용 UTF-8 BOM,
  쉼표/따옴표/줄바꿈 이스케이프와 공백 뒤 `=`, `+`, `-`, `@` 및 제어문자 시작 셀의
  작은따옴표 접두사로 스프레드시트 수식 실행을 방어한다. JSON 원문은 변형하지 않는다.
- 다운로드 응답은 `no-store`, `nosniff`, 고정된 첨부 파일명으로 반환한다. 화면·대상·기간 변경,
  권한 해제·오프라인·세션 교체 후의 늦은 응답은 파일로 만들지 않는다. 자동 다운로드나
  IndexedDB 보관은 하지 않는다. 사용자가 저장한 파일은 서버 삭제 시 자동 회수할 수 없다.

<a id="support-record-dashboard--선택상황복구-표현의-관찰-기록"></a>
#### 선택·상황·복구 표현의 관찰 기록

- AAC 사용자가 카드판에 추가할 때 각 카드의 기기 선택 시각을 보관하고 문장 저장 시 배열로
  전달한다. 순서를 바꿔도 처음 선택한 시각과 중복 카드를 유지한다. 복원 카드의 시각은 추정하지 않는다.
- `offline_events`에 `card_selection`, `speech_result`, `recovery_speech`를 추가한다. 카드 선택·순서
  변경·비우기의 결과, 카드 ID 배열, 기기 시각, 페이지 흐름 UUID와 증가 순서만 수집한다.
  음성 본문·녹음·IP·기기 지문은 수집하지 않는다. 기존 최소 요청 형식도 계속 읽고 결과 미확인으로 분리한다.
- 상황은 `상황 미지정/집/학교/치료실/외출/식사/병원` 중 직접 선택한다. 페이지·계정 전환 시
  미지정으로 초기화한다. 카드판·추천·학습 범위를 변경하는 상황 보드(B1-02)는 아니다.
- 음성의 종료·오류·중지 콜백에서 결과를 한 번 기록한다. 재생 전에 네트워크를 기다리지 않고,
  기록 전송 실패는 말하기를 중단하지 않는다. 실패한 전송은 AAC 사용자 자신의 기존 오프라인
  대기열에서 동일 ID로 재전송한다. 4xx 거절은 새 대기열에 저장하지 않는다.
- 기기 재생 완료는 브라우저·오디오 엔진 완료일 뿐 실제 청취나 의사 전달 성공이 아니다.
  생성 문장과 연결한 `session_id`는 서버가 동일 사용자 소유인지 검증한다. 다른 계정·동의 철회 뒤
  오래된 음성 콜백은 기록하지 않는다. 서버의 동의 검사·보관 기간·전체 삭제 범위를 그대로 따른다.
- `/records/activity`는 `records_read` 권한으로 조회한다. 실제 조회 기간·사용자 조건의 최대
  10,001개를 읽고 한도 초과 시 413을 반환한다. 상황별 집계, UTC 날짜별 추이, 최근 100개 활동,
  최근 20개 복구 흐름을 반환한다. 다른 영역의 집계에 합산하지 않는다.
- 복구 흐름은 동일 페이지 흐름에서 앞뒤 순서의 인접 기록만, 기기 시각 차이 5분 이내에 연결한다.
  기간 밖·다른 기기·누락된 인접 기록은 빈칸으로 알린다. 원인·의도·회복·지원 필요성을 추론하지 않는다.
- 활동 CSV/JSON은 `domain=activity`로 별도 다운로드한다. 문장 CSV의 `speech_status=unknown`은
  활동 기록을 조인하지 않은 값이며, 실제 결과는 활동 파일의 명시적 `session_id`로 구분한다.

<a id="support-record-dashboard--지원-메모-작성수정삭제"></a>
#### 지원 메모 작성·수정·삭제

- `notes_write`와 현재 연결을 매 요청 검사하며 작성자 자신의 메모·수정 이력만 열람한다.
  다른 보호자의 메모나 단순 `records_read` 권한으로 내용을 확장하지 않는다.
- 메모는 작성자 ID·수정 시각·증가 `revision`을 저장하고 동일 문서 안에 본문 이력을 유지한다.
  최초 작성의 고유 ID 충돌, 수정·삭제의 예상 버전 충돌은 409다. 화면은 초안을 유지한다.
  이전 클라이언트가 버전을 생략해도 서버의 읽기-쓰기 사이 동시 변경을 덮어쓰지 않는다.
- 이력은 버튼을 눌러 별도 조회하고 최근 20개부터 추가 표시한다. 1,000개 도달 시 새 본문 수정을
  거절해 문서 크기를 제한하며 기존 이력을 몰래 자르지 않는다. 삭제는 한도에서도 가능하다.
- 메모 삭제는 현재·이전 모든 버전의 본문을 제거한다. 작성자·버전·행위·처리 시각만 남겨 결과를
  확인한다. 개인정보 전체 삭제와 기존 보관 기간 적용 시 이 메타데이터까지 함께 제거한다.
- 사용자·영역·세션 변경 후 늦은 조회·저장 결과를 다른 사용자 화면에 반영하지 않는다.

<a id="support-record-dashboard--개인정보-삭제-확인"></a>
#### 개인정보 삭제 확인

- 삭제 시작 전에 동의를 해제하고 `in_progress` 영수증을 저장한다. 완료는 각 컬렉션 삭제,
  프로필 제거와 삭제 감사 기록 생성이 모두 성공한 뒤에만 표시한다. 다중 컬렉션 작업이므로
  중간 실패 시 원상 복구를 약속하지 않고 `failed`와 확인된 부분 삭제 건수를 보관한다.
- `deletion_receipt`에는 요청 번호·요청/완료 시각·이번 요청의 컬렉션별 삭제 건수·프로필 처리·
  유지 항목(계정·확인 기록)·자동 삭제되지 않는 파일/별도 백업의 한계를 담는다. 재시도는 이미
  삭제한 항목을 중복 집계하지 않는다. 새 동의를 저장해도 이전 영수증은 역사적 요청 결과로 유지한다.
- 개인정보 화면에서 영수증과 이 기기의 임시 기록 삭제 여부를 분리해 표시한다. 기기 저장소를
  지우지 못하면 서버 성공만으로 전체 완료를 안내하지 않는다. 삭제 후 동의가 없는 계정의
  온라인 로딩에서도 기기 임시 기록을 다시 정리해 오래된 대기열의 재전송을 막는다.
- MongoDB가 timezone 없는 UTC 날짜를 돌려주는 경우에도 메모 수정·이력과 삭제 영수증의 시각에
  UTC 정보를 복원해 응답한다. 브라우저·태블릿의 현지 시각으로 변환할 때 이중 시차가 생기지 않게 한다.
- 삭제하면 지원 연결도 제거된다. 이전 보호자는 삭제 영수증을 계속 조회할 수 없으며 AAC
  계정의 개인정보 화면에서만 확인한다. 연결 해제 뒤 404를 삭제 실패로 해석하지 않는다.

뿐 실제 이해나 의사소통 능력을 의미하지 않음을 안내한다. 기술적 재생·조회 오류와 사용자 평가를

### 한 달 사용 합성 데이터

<a id="synthetic-usage-month--목적과-주의"></a>
#### 목적과 주의

- 사용자 요청으로 현재 아이 계정에 사용 테스트용 가상 기록을 추가한다.
  실제 아동 사용·관찰·임상 평가·실제 음성 재생이나 모델 실행 결과가 아니다.
- 문장은 `[테스트]` 접두사로 표시한다. DB에는 `synthetic: true`,
  `synthetic_kind: usage-month-v1`, `synthetic_batch_id`를 함께 저장한다.
- 해당 계정의 통계·추천·활동 및 전체 TTS 집계에 합성 데이터가 포함된다.
  음성 시작 지연 값 역시 합성값이므로 실제 성능 측정에 사용하지 않는다.
- 학습 정답률·아동 능력·의료 증상은 생성하지 않는다. 기존 계정·동의·연결·사진·
  카드판·보호자 메모·학습 기록·추천 설정도 변경하지 않는다.
- 웹 API나 앱 시작 시 자동 실행되는 코드를 추가하지 않는다.
  `backend/tools/seed_usage_month.py`는 로컬 운영자가 명시적으로 실행하는 도구다.

<a id="synthetic-usage-month--생성-방식"></a>
#### 생성 방식

- 지정한 한국 날짜까지 최근 30일, 하루 8~14개 문장을 만든다.
  미래 시각은 제외하므로 당일 실행 시각에 따라 마지막 날의 건수는 줄어들 수 있다.
- 식사·간식, 놀이, 이동, 휴식, 도움 요청, 긍정·거절 등 기본 카드 조합을 사용한다.
  문장은 기존 규칙 생성기를 사용하며 실제 모델을 호출하지 않는다.
- 카드 선택 → 발화 성공·취소·실패와 일부 재시도·복구 흐름을 연결한다.
  `communication_sessions`, `offline_events`, `tts_events`만 대상으로 한다.
- 삽입은 기존 보호자 동의가 있고 삭제 처리 상태가 아닌 아동 계정에서만 가능하다.
  도구가 동의를 대신 부여하거나 기록 삭제 상태를 해제하지 않는다.
- 계정·배치·날짜·항목을 이용한 UUID와 `$setOnInsert`로 동일 인자의 재실행을
  중복 없이 처리한다. 날짜 범위를 바꿀 때는 새 배치 ID를 사용한다.
- 기본 실행은 읽기 전용 미리보기다. 쓰기는 `--apply` 및 동일한
  `--user-id`/`--confirm-user-id`를 명시해야 한다. 중간 실패는 같은 인자로 재실행한다.

<a id="synthetic-usage-month--powershell-실행-예"></a>
#### PowerShell 실행 예

저장소 루트에서 실행한다. 비밀번호나 세션 토큰을 읽거나 출력하지 않는다.
백엔드 컨테이너의 기존 DB 연결 설정을 사용한다. `demo`는 대상 ID로 바꾼다.

```powershell
# 추가 미리보기
Get-Content backend/tools/seed_usage_month.py -Raw -Encoding utf8 |
  docker compose exec -T backend python -B - --user-id demo --batch-id usage-month-20261101-demo --end-date 2026-11-01

# 명시적 추가
Get-Content backend/tools/seed_usage_month.py -Raw -Encoding utf8 |
  docker compose exec -T backend python -B - --user-id demo --confirm-user-id demo --batch-id usage-month-20261101-demo --end-date 2026-11-01 --apply

# 이 합성 배치만 삭제할 경우 먼저 대상 건수 확인
Get-Content backend/tools/seed_usage_month.py -Raw -Encoding utf8 |
  docker compose exec -T backend python -B - --user-id demo --batch-id usage-month-20261101-demo --delete

# 확인 후 위 삭제 명령에 --apply --confirm-user-id demo를 추가한다.
```

삭제는 계정 ID·합성 표시·합성 종류·배치 ID를 모두 만족하는 3개 컬렉션의
문서만 대상으로 한다. 실제 기록은 지우지 않는다. 삭제 후 합성 데이터는 이
도구로 재생성할 수 있다. 합성 기록을 본 뒤 별도로 만든 추천 노출 기록·카드판은
이 삭제 대상이 아니므로 자동으로 되돌리지 않는다. 이번 작업에서는 삭제하지 않았다.

<a id="synthetic-usage-month--검증-상태"></a>
#### 검증 상태

- 실제 로컬 MongoDB 삽입·건수 확인, 30일 분포, 미래 문장 0건,
  문장 연결 누락 0건, 합성 문장 전체 및 대시보드 응답 스키마 확인을 통과했다.
- 통계·활동 보고서·카드 추천의 읽기를 확인했고 활동별 카드판 추천에서
  식사·간식, 이동·외출, 놀이, 자주 쓰는 표현 4개 후보가 나왔다.
- 첫 일회성 확인 코드가 추천 반환값을 객체로 잘못 취급해 실패했다.
  실제 반환 타입인 리스트로 수정한 뒤 재확인을 통과했다. DB 쓰기 실패는 아니다.
- 같은 배치 재실행 시 새 삽입 0건을 확인했다. Python 정적 구문 및
  변경분 공백 검사를 통과했다.
- 전체 자동 테스트·전체 빌드·브라우저 화면 검증·실제 삭제 검증은 미실행이다.
  브라우저에서 새로고침 후 의사소통 기록·활동·추천 화면을 확인해야 한다.
