# 음성 합성과 문장 생성

> 통합일: 2026-11-04 · 현재 사용 안내와 과거 구현 기록을 구분합니다.

온라인 음성은 로컬 서버를 사용합니다. 기본 Compose는 MeloTTS, 선택형 Qwen overlay는 여자아이·남자아이 합성 음색을 제공합니다. 기기 음성·핵심 표현 녹음·오프라인 캐시는 별도 대체 경로입니다. 문장 생성은 선택형 Ollama와 규칙 기반 대체를 사용합니다. 모델 준비·생성·음성 합성·재생 시작 지연을 구분해 측정하며 캐시 성공을 실제 기기 음성 성공으로 취급하지 않습니다. 음성·문장 정책은 docs/policies의 해당 정책을 우선 확인합니다.

과거 날짜의 검사 통과는 현재 버전 전체의 검수나 운영 배포 승인이 아닙니다. 상세 기록에는 이전 화면·제거된 기능 설명도 있으므로 현재 사용 경로는 위 안내를 우선하고, 남은 실제 기기·권한·음성 검수는 TODO와 각 절의 미실행 기록을 확인하세요.

## 현재 실행과 캐시

기본 `compose.yaml`은 MeloTTS입니다. Qwen으로 실행하려면 여자아이·남자아이 합성 참조 두 개와
`compose.qwen.yaml`이 필요합니다. 두 음색은 기본 0.90배이며 일반 설정에서는 목소리·속도·볼륨만 고릅니다.
기존 개인 속도는 강제로 덮어쓰지 않습니다. 기기별 음색 목록과 수동 음높이 선택은 일반 UI에서 제거했습니다.

### 최초 Qwen 준비

생성 WAV는 Git에 포함하지 않으므로 새로 clone한 PC에는 없습니다. VoiceDesign 시안을 만든 뒤
직접 들어보고 선택합니다. 이미지 생성 API 키는 필요하지 않지만 공개 모델의 최초 다운로드는 필요합니다.
CPU BF16 경로이며 사전 점검은 Docker 총 8GiB·가용 6GiB 이상을 요구합니다. 실제 PC의 여유 메모리도 확인하세요.
시안 생성 중 Melo/Qwen 합성 서버를 함께 실행하지 않습니다(실행 중이면 잠시 음성이 중단됩니다).

```powershell
docker compose -f compose.voice-design.yaml run --rm --build voice-design --text "물 주세요. 도와주세요. 잠깐만요."
docker compose -f compose.voice-design.yaml run --rm voice-design --description-file /app/voice-description-boy.txt --text "물 주세요. 도와주세요. 잠깐만요."
```

각 명령이 출력한 `.local-voice-design/audition-...` 폴더의 `sample.wav`를 듣고 실제 폴더를 아래에 넣습니다.
형식 검사나 파형 생성만으로 발음·음색·표현 누락이 검증된 것은 아닙니다. 실존 아동의 녹음 업로드 기능이 아닙니다.

### Qwen 실행·태블릿 접속

```powershell
$env:QWEN_REFERENCE_DIR = './.local-voice-design/audition-여자아이ID'
$env:QWEN_BOY_REFERENCE_DIR = './.local-voice-design/audition-남자아이ID'
$env:QWEN_CACHE_VERSION = 'qwen-선택한두음색-v1'
docker compose -f compose.yaml -f compose.qwen.yaml -f compose.tablet.yaml up -d --build
```

위 ID는 예시이며 실제 생성 폴더로 바꿉니다. 이후 터미널에서도 같은 값을 지정하거나 로컬 `.env`에 보관합니다.
참조를 교체하면 캐시 버전도 바꾸고 브라우저를 새로고침합니다. 기존 `.env`를 예제로 덮어쓰지 마세요.
Qwen을 쓰던 중 기본/태블릿 Compose만 실행하면 Melo 설정으로 돌아갈 수 있으므로 같은 파일 조합을 유지합니다.
반대 음성 서버가 이미 실행 중이면 해당 서버를 중지해 메모리를 확보합니다. DB/캐시 볼륨은 삭제하지 않습니다.
태블릿은 [PC 모바일 핫스팟 안내](LOCAL_DEVELOPMENT.md#pc-모바일-핫스팟으로-ipad-연결)를 따릅니다.

### 캐시와 검사 범위

| 범위 | 보관 | 재시작 후 |
| --- | --- | --- |
| 브라우저 | 세션 메모리, 30분·128개/64MiB | 새로고침·세션 변경 시 소멸 |
| backend 개인 음성 | 계정별 메모리 키, 30분·전체 256개/64MiB | 프로세스 재시작 시 소멸 |
| 기본 카드 label 음성 | Qwen Docker 볼륨, 생성 후 7일·512개/128MiB | 볼륨을 유지하면 재사용 |

음색·속도·공급자·참조 버전을 구분합니다. 개인 카드/생성 문장을 디스크에 추가 보관하지 않습니다.
만료 파일은 조회/저장 때 정리하며 주기 삭제 작업이 아닙니다. 자세한 보관 경계는 [TTS 정책](../policies/TTS_POLICY.md)을 따릅니다.
캐시 미스의 첫 CPU 합성 지연은 남습니다. Qwen 요청 제한은 backend 75초·브라우저 90초이며 성능 보장은 아닙니다.
`/api/health`의 Qwen ready와 실제 기기 소리 출력은 별도입니다. 실측은 아래 날짜별 기록,
최신 검사·미검증 항목은 [안정화 결과](LOCAL_DEVELOPMENT.md#안정화-회귀-점검--2026-11-12)를 참고합니다.

### 두 음색 선택 및 기본 카드 영속 캐시 (2026-11-11)

일반 음성 설정은 여자아이·남자아이 두 목소리만 선택하며, 기기별 음성 목록과 수동 음높이,
여러 진단 버튼을 제거했습니다. 속도/볼륨과 서버 미리 듣기는 유지합니다.
오프라인의 자동 기기 음성 대체는 유지하며, 같은 여자아이·남자아이 음색을 보장하지 않습니다.
이전 child/woman/man 설정은 읽기/저장 시 두 값으로 정규화하고 기존 개인 속도는 유지합니다.

기존 메모리 캐시 위에 `PublicSpeechCache`를 추가했습니다. 기본 제공 `CARDS`의 정확한
label만 디스크 저장 대상이며, 개인 카드/생성 문장은 별도 디스크에 남기지 않습니다.
개인 문구가 기본 카드 label과 같으면 동일한 공개 고정 음성으로 취급합니다.
Qwen overlay가 `pesc-mate_public_speech_cache` 볼륨을 자동 연결합니다.
최대 512개/128MiB, 생성 시각 기준 7일, 파일당 최대 12MiB PCM WAV입니다.
파일명은 공급자·주소·버전·음색·문구·속도의 SHA-256 해시이며 계정 ID·원문 메타데이터는 저장하지 않습니다.
원자적 파일 교체, 손상/만료 캐시 미스 처리, 저장 시 오래된 파일 정리와 쓰기 실패 대체를 적용합니다.
주기적 삭제 작업은 아니며 조회/저장 때 정리합니다. 실패 응답은 저장하지 않습니다.
개인 문장은 기존 계정별 메모리 캐시(재시작 시 소멸), 브라우저는 세션 메모리 캐시를 유지합니다.

검증:

- Python 70개 AST, 프론트 빌드 통과(기존 큰 번들 경고), Compose 설정·실행 적용 통과.
- 임시 디렉터리 검사: 캐시 인스턴스 재생성 후 읽기, 두 음색 분리, TTL/개수/바이트 제한,
  손상 WAV 삭제와 복구 경로, 개인 문장 디스크 미저장, upstream 실패 중 공개 캐시 재사용 통과.
- Node 검사: 선택지 정확히 girl/boy 두 개, 0.90배 기본값, 이전 프리셋 정규화 통과.
- backend 이전 설정 정규화/개인 속도 유지, 버전·속도별 디스크 키 분리,
  디스크 쓰기 실패가 합성을 막지 않는 대체 경로 검사 통과.
- 실제 기본 표현 ‘도와주세요’ girl/0.90배 첫 합성 56.04초·1.42초 WAV/68310바이트.
  backend 컨테이너 재시작 후 새 진단 프로세스에서 upstream 호출을 실패시키고도
  동일 WAV를 1.019초(콜드 import 포함)에 읽었습니다. 모델 재합성 호출 0건 확인.
  진단은 합성 키만 사용하고 사용자 DB 이력·계정은 만들지 않았습니다.
- 새 캐시 볼륨을 연결하고 backend/frontend를 재시작했습니다. Qwen 모델·DB는 재시작하지 않았습니다.
  WAV는 Docker 볼륨에만 저장하며 Git에 추가하지 않습니다. 자동 테스트 파일도 추가하지 않았습니다.

남은 한계: 한 번도 합성하지 않은 카드는 여전히 CPU 추론이 필요합니다. 전체 어휘 사전 생성,
실제 iPad 재생/오프라인과 장시간 동시 부하는 미검증입니다. 캐시는 음질 검수의 대체가 아닙니다.

### 속도 확정 및 음성 경로 안정화 점검 (2026-11-11)

사용자가 0.90배 재생 속도를 확정했습니다. 여자아이·남자아이 프리셋과 저장 설정의 기본값을
유지하며, 속도가 생략된 API/worker 요청도 1.0배가 아닌 0.90배로 통일했습니다.
이미 저장된 개인 속도는 일괄 변경하지 않습니다. 음성 설정에서 프리셋을 선택하면 0.90배가 됩니다.

이번 점검 범위는 음성 설정·합성 요청·캐시·재생 수명주기입니다. 플랫폼 전체의 오류 없음이나
실제 iPad 재생까지 검증한 것으로 해석하지 않습니다. 자동 테스트 파일은 추가하지 않았습니다.

- 격리 worker HTTP 점검: 속도 생략 시 0.90배, 두 음색 전달, 빈 입력/알 수 없는 음색/
  bool·NaN 속도 거부(422), 사용 중 429, 강제 합성 실패 503 이후 잠금 반환·정상 재요청 통과.
  이 중 `QWEN | FAILED | RuntimeError`는 의도한 장애 주입 결과이며 실제 모델 장애가 아닙니다.
- 격리 backend 점검: 두 프리셋 설정 저장/조회 0.90배 유지, API 기본값/범위 검사,
  타 계정 설정 권한 거부 시 저장 호출 없음 확인. DB 모의 객체만 사용해 사용자 데이터 미변경.
- 브라우저 큐 점검: 연속 요청 중 마지막 대기만 유지, 캐시 재사용, 실패 후 재시도,
  로그인 세션 변경 시 캐시 분리 통과.
- 재생 점검: 서버에서 속도 조절한 WAV는 브라우저 1.0배로 재생하여 이중 감속 방지,
  중단 시 object URL 해제·타이머 정리 통과. 브라우저 모의 객체 검사이며 실제 청음은 별도입니다.
- Python 69개 파일 AST와 프론트 빌드 통과. 기존 500kB 초과 번들 경고는 남아 있습니다.
- 시작 시 Qwen만 실행 중이어서 웹 health가 연결 거부였습니다. 데이터 볼륨을 유지하고
  동일 참조의 Qwen/DB/backend/frontend 전체 구성을 다시 빌드·실행했습니다.
- 재시작 후 worker girl/boy 준비와 웹 Qwen ready, 실제 비로그인 음성 API 401 확인.
  속도를 생략한 실제 라우트 함수 진단(합성 키, DB 기록 없음)은 girl/0.90배,
  첫 합성 32.92초·1.42초 PCM WAV/peak 20020, 동일 응답 캐시 0.0001초로 확인했습니다.
  인증 검증은 별도 HTTP 401 검사로 확인했으며 합성 진단 자체는 로그인 요청이 아닙니다.

남은 제한: 최초 CPU 합성 지연, 긴 문장의 누락/잘림, 실제 iPad 음량·재생 권한,
장시간·여러 사용자 동시 부하는 별도 검수 대상입니다. 제한 시간 연장은 성능 개선이 아닙니다.

### 여자아이·남자아이 선택과 속도 조절 (2026-11-11)

Qwen 모드의 음성 설정에서 **여자아이 / 남자아이**를 선택합니다. 두 프리셋의 속도는
원본의 0.90배입니다(재생 길이 약 11% 증가). 음높이를 바꾸는 대신 시간 신축을 사용합니다.
이미 저장한 개별 속도는 덮어쓰지 않으며, 프리셋을 다시 선택하면 0.90배로 맞춰집니다.
기기 pitch 설정은 서버 음색에 영향을 주지 않고, 오프라인 기기 음성은 별도 경로입니다.

단일 Base 모델에 두 VoiceDesign 참조 프롬프트를 올리고 요청의 `voice: girl | boy`로 구분합니다.
브라우저·backend 캐시 모두 음색과 속도를 키에 포함하여 목소리 변경 시 이전 캐시가 섞이지 않습니다.
기존 child/woman 설정은 Qwen 화면에서 girl, man은 boy로 표시하며 저장 API는 이전 값도 허용합니다.
Melo 구성은 기존 단일 화자를 유지합니다. 두 합성 음색은 Qwen overlay에서만 사용할 수 있습니다.

로컬 참조(생성 WAV는 Git 제외):

- 여자아이: `audition-80fd55b8b675` — 사용자가 음색을 청음 후 긍정 평가했습니다.
- 남자아이: `audition-96b8310c56ca` — 새 합성 시안, 아직 사용자 청음 승인은 없습니다.
  BF16 로드 19.90초 / 합성 147.77초, 원본 3.92초·24kHz·peak 0.6836입니다.
  실제 아동 녹음을 복제한 것이 아니며 프롬프트만으로 나이·성별 표현을 보장하지 않습니다.

현재 두 음색 구성 실행(해당 로컬 파일이 있는 PC):

```powershell
$env:QWEN_REFERENCE_DIR = './.local-voice-design/audition-80fd55b8b675'
$env:QWEN_BOY_REFERENCE_DIR = './.local-voice-design/audition-96b8310c56ca'
$env:QWEN_CACHE_VERSION = 'qwen-girl-boy-20261111'
docker compose -f compose.yaml -f compose.qwen.yaml -f compose.tablet.yaml up -d --build
```

다음 시작에도 같은 환경변수를 지정하거나 로컬 `.env`에 보관합니다(실제 `.env`는 커밋하지 않습니다).

현재 서비스 기본 음성은 **MeloTTS 그대로**입니다. Qwen 샘플 제작은 독립된
`compose.voice-design.yaml`의 일회성 CPU 작업이며, 기본 Compose와 합치지 않습니다.
`Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign`을 사용하고, 0.6B 한국어 화자 모델이나
기존 기기 음성의 음높이 조절로 대체하지 않습니다. 실제 사람의 참고 녹음은 사용하지 않습니다.

음색 설명은 `services/qwen-voice-design/voice-description.txt`에서 수정합니다.
어린이 느낌·성별이 두드러지지 않는 음색은 생성 지시일 뿐 결과 보장이 아니므로 청음이 필요합니다.

```powershell
docker compose -f compose.voice-design.yaml run --rm --build voice-design --check
docker compose -f compose.voice-design.yaml run --rm voice-design
# 문장은 최대 100자. 처음에는 짧게 청음합니다.
docker compose -f compose.voice-design.yaml run --rm voice-design --text "물 주세요. 싫어요."
```

첫 명령도 Python 패키지와 CPU PyTorch 이미지 빌드는 필요하지만, `--check`는
모델 가중치를 다운로드하거나 합성하지 않습니다. 모델 다운로드는 실제 제작 명령에서만 실행합니다.
Docker 총 메모리 8GiB·가용 6GiB를 프로젝트의 보수적인 사전 기준으로 적용합니다.
이는 제조사 최소 사양이나 실행 성공 보장이 아닙니다. 기존 서비스 메모리도 별도로 필요합니다.
컨테이너는 CPU 2개·메모리 최대 10GiB이며 CUDA/FlashAttention을 요구하지 않습니다.
다운로드·로드·합성을 합쳐 기본 900초의 작업 제한을 두지만 CPU 연산/네트워크 내부의
중단 반응은 지연될 수 있습니다. `Ctrl+C` 또는 해당 일회성 컨테이너 중단으로 종료할 수 있습니다.
표본에는 512토큰 상한이 있어 긴 문장은 잘릴 수 있으며, 파일 생성만으로 완료로 판정하지 않습니다.

출력은 `.local-voice-design/audition-*/sample.wav`와 `metadata.json`입니다.
메타데이터에 설명·문장·모델 스냅샷 리비전·로드/합성 시간·길이를 남기고, 기존 시안은 덮어쓰지 않습니다.
입력 문장이 로컬 파일에 저장되므로 개인정보 없는 시험 문장만 사용하세요.
이 디렉터리는 Git에서 제외하며 외부 API로 문장을 전송하지 않습니다.
가중치는 별도 `qwen_voice_models` Docker 볼륨에 보관합니다.
기본 모델 리비전은 main이므로 재현 시 기록된 리비전을 `QWEN_MODEL_REVISION`으로 지정하세요.

샘플을 듣고 음색·발음·누락·문장 끝을 확인한 뒤에만 서비스 연결을 진행합니다.
매 문장을 VoiceDesign으로 다시 만들면 화자 일관성이 달라질 수 있습니다. 선택한 음색을
유지할 기준 음성/Base 연결, 기본 카드 사전 합성, 음색별 영구 캐싱은 **후속 작업**입니다.
현재 짧은 브라우저 메모리 캐시를 영구 캐시로 변경하지 않았고 여성 핵심 녹음도 교체하지 않았습니다.

## 연속 카드 터치와 음성 대기 충돌 수정 (2026-11-07)

브라우저는 합성 1건을 유지하고 서로 다른 표현은 마지막 요청 1건만 대기합니다.
취소된 표현은 뒤늦게 재생하지 않지만 완료된 WAV는 같은 로그인 세션의 메모리 캐시에 남깁니다.
같은 표현·속도는 합성을 공유하고 최대 32건/16MiB, 5분 재사용으로 제한합니다.
로그아웃/토큰 변경 시 대기·캐시를 초기화하며, 오류는 자동 반복 요청하지 않습니다.
캐시는 디스크·DB에 저장하지 않고 첫 합성의 CPU 지연까지 없애지는 않습니다.

백엔드도 단일 합성을 유지하되 활성/대기 합계 최대 4건, 최대 10초 대기를 허용합니다.
상위 로컬 TTS 응답 타임아웃은 35초입니다. 진짜 과부하·장애까지 숨기거나 무제한 대기하지 않습니다.
문장 카드가 12장이어도 단어 소리는 재생하며, 한도는 문장 추가에만 적용합니다.

검증:

- 첫 캐시 만료 검사에서 이미 완료된 작업에 구독하여 대기하는 버그를 발견했고 완료 플래그 수정 후 재검사 통과.

## 로컬 한국어 MeloTTS

<a id="melo-tts--로컬-한국어-melotts"></a>
### 로컬 한국어 MeloTTS

<a id="melo-tts--구조와-실행"></a>
#### 구조와 실행

Ollama는 문장을 만들고 별도 `melotts` 컨테이너는 한국어 WAV를 합성한다.
브라우저의 말하기·카드 듣기·학습 소리는 서버 연결 시 WAV를 기본 사용한다.
내장 음성은 오프라인/진단용이며 iPad 유나 음성의 무음 문제 해결로 간주하지 않는다.

```powershell
docker compose -f compose.yaml -f compose.tablet.yaml up -d --build
docker compose logs --tail 40 melotts
```

`TTS | READY | 한국어 로컬 음성 준비 완료` 후 마이페이지 → 음성 설정 →
`서버 음성 테스트`로 확인한다. 처음에는 이미지 설치·모델 다운로드가 오래 걸릴 수 있다.
현재 PC Docker 메모리는 약 4GiB이며 실제 응답 속도·메모리 여유는 현장 확인이 필요하다.
모델은 시작 시 한 번 로드하고 고정 안내 문장으로 워밍업한다. 요청마다 다시 로드하지 않는다.
모델 캐시는 `melotts_models` 볼륨에 남긴다. 일반 재시작은 다운로드를 재사용한다.
최초 설치는 외부 패키지·공개 모델 서버에 접속하며 사용자 문장을 외부 합성 API에 보내지는 않는다.

<a id="melo-tts--설정과-제약"></a>
#### 설정과 제약

- CPU 전용 PyTorch, 한국어 KR 화자 1개를 사용한다. 별도 API 사용료는 없지만
  PC 전력·메모리·다운로드·유지보수 비용은 발생한다. GPU는 이번 구성에 포함하지 않는다.
- MeloTTS upstream은 `209145371cff8fc3bd60d7be902ea69cbdb7965a`로 고정한다.
  원저작권·MIT 조건은 이미지 내부 `/opt/MeloTTS/LICENSE`를 유지한다.
  [공식 설치법](https://github.com/myshell-ai/MeloTTS/blob/main/docs/install.md),
  [한국어 모델](https://huggingface.co/myshell-ai/MeloTTS-Korean)을 참고한다.
- 속도는 서버 합성 시 적용하고 파일 재생에서 다시 배속하지 않는다. 볼륨은 브라우저에서 적용한다.
  기존 느낌 프리셋이 속도도 변경하므로 서버 속도에 간접 반영되지만 선택 음성/음높이 합성은 지원하지 않는다.
- 브라우저는 최대 128개/64MiB의 WAV를 메모리에서 재사용한다. 캐시 유효시간은 30분이며
  로그아웃·세션 변경 시 비운다. IndexedDB·디스크에 새 문장 음성을 영구 저장하지 않는다.
- 기존 핵심/긴급 표현 녹음은 서버 합성 대기 없이 즉시 우선 사용한다.
  서버 요청 실패 시 해당 표현의 기본 녹음이 있으면 대체한다. 없는 표현은 오류와
  다시 재생을 보여 주며 조용한 기기 합성을 성공으로 대신 보고하지 않는다.
- 오프라인/서버 미연결에서는 새 문장 MeloTTS 합성이 불가능하다. iPad 내장 음성도
  무음이면 준비된 기본 녹음 이외의 임의 문장은 읽을 수 없다.
- iPad 자동 재생 제한은 남는다. 같은 Audio 요소를 탭에서 준비하고 다시 재생 버튼을
  제공하지만 실제 기기 성공은 직접 확인해야 한다. 데이터/계정·일반 서비스 로그는 추가하지 않는다.

<a id="melo-tts--검증-기록"></a>
#### 검증 기록

- 프런트엔드 빌드 및 Compose 설정 검사 통과. 기존 큰 JS 청크 경고 유지.
- 일회성 Node 검사로 합성 WAV 경로·배속 중복 없음·기기 합성 대체 없음·요청 중단·
  오래된 응답 무시·Blob URL 해제·기본 녹음 대체·권한 오류 시 대체 금지를 확인했다.
- 백엔드 직접 호출/대역 검사로 PCM WAV 검사, 잘못된 응답·사용 중·시간 초과·락 해제,
  입력 글자 수·유한 속도 범위를 확인했다. 실제 계정·DB는 사용하지 않았다.
- 최초 Docker 빌드 시도들은 PyTorch 전용 저장소의 typing_extensions 메타데이터/빌드
  의존성 조회 오류로 실패했다. 일반 의존성 저장소와 CPU 패키지 명시로 수정 후 빌드 통과.
  최초 실행에서 자동 설치되던 한국어 MeCab을 이미지에 포함하고 NLTK 자원은 모델 볼륨에
  유지하도록 최종 이미지를 다시 빌드했다. 경고(Python 3.10 관련 의존성 지원 종료 안내,
  Hugging Face/PyTorch API 사용 중단 예고)는 남아 있어 운영 배포 시 의존성 갱신이 필요하다.
- 한국어 모델 로드·고정 문장 워밍업 성공과 worker/backend healthy를 확인했다.
  실제 한국어 두 문장을 격리 FastAPI 앱의 인증 의존성 대역을 통해 요청했다.
  실제 MeloTTS HTTP 합성·PCM WAV·no-store·비무음 파형을 확인했고, 익명 요청은 401이었다.
  실제 사용자 세션/로그인 DB는 사용하지 않았다.
- 현재 CPU 2스레드·Docker 약 4GiB에서 `물 주세요.`는 5.15초(음성 길이 2.05초),
  `엄마와 학교에 가고 싶어요.`는 8.54초(음성 길이 3.13초)였다. 샘플레이트는 44100Hz,
  워커 메모리는 약 1.8GiB였다. 두 문장 측정일 뿐 평균/백분위나 실시간 성능 보장이 아니다.
  처음 읽는 문장의 합성 지연은 남으며 반복 표현은 브라우저 메모리 캐시를 사용한다.
- 격리 Chrome에서 모의 서버 WAV 요청부터 실제 Audio playing/ended까지 확인했다.
  클라이언트 요청 도구는 같은 세션 캐시 재사용·세션 교체 격리·잘못된 WAV·이전 세션의
  늦은 결과 차단도 검사했다. 실제 계정 로그인부터 전체 사용자 흐름과 실제 iPad 청취,
  오프라인 전체 회귀는 미실행이다. 영구 테스트 도구는 추가하지 않는다.

## 문장 생성의 첫 요청·유휴 후 지연 개선

<details>
<summary>상세 구현·설정·검증 기록</summary>

<a id="sentence-generation-performance--문장-생성의-첫-요청유휴-후-지연-개선"></a>
### 문장 생성의 첫 요청·유휴 후 지연 개선

> 작업일: 2026-11-01
> 범위: 로컬 Ollama 문장 생성 경로. 카드 사진은 수정·스테이징·커밋하지 않음.

<a id="sentence-generation-performance--확인한-현상과-원인-후보"></a>
#### 확인한 현상과 원인 후보

사용자는 연속 생성보다 처음 요청하거나 오래 쉬었다가 요청할 때 느리다고 답했다.
기존 구현은 모델 유지 시간을 요청마다 `10m`으로 지정하고 시작 시 사전 로딩을 하지 않았다.
또한 시스템 규칙과 중복되는 긴 지시문·예시를 매 요청에 포함하고,
완료된 동일 요청의 DB 기록도 모델 호출 후에 확인했다.

따라서 유휴 후 모델 재로딩이 유력한 원인 후보지만 실제 장비의 GPU 사용 여부와
로드 시간을 측정한 결론은 아니다. 작업 환경에서 `127.0.0.1:11434/api/ps`와
`/api/tags` 조회는 모두 연결에 실패했다. 모델 설치·실행 상태를 변경하거나
새 모델을 내려받는 작업은 하지 않았다.

<a id="sentence-generation-performance--변경-사항"></a>
#### 변경 사항

1. API 시작 시 백그라운드 스레드에서 빈 프롬프트로 문장 모델을 미리 로딩한다.
   카드·사용자 정보·발화 내용을 보내지 않으며 API 시작을 모델 준비가 끝날 때까지 막지 않는다.
2. 기본 메모리 유지 시간을 10분에서 30분으로 늘리고 환경 변수로 조절한다.
   유지 시간이 지나거나 메모리 부족·다른 모델 실행 등으로 내려가면 다시 로딩될 수 있다.
3. 중복 지시·고정 예시를 줄인 짧은 요청문을 사용한다. 기존 시스템의 의미·부정·
   안전성 규칙과 카드 의미 검증은 유지하고 프롬프트 템플릿 버전을 기록한다.
4. 기본 문맥 길이는 2048, 출력 상한은 기존과 같은 60토큰으로 두고 개행에서 생성을 멈춘다.
   출력 상한 때문에 잘린 응답은 완성 문장으로 채택하지 않는다. 조사·부정·의미 보존과
   생성 품질은 실제 모델을 통한 추가 확인이 필요하다.
5. 백엔드 프로세스마다 모델 요청을 하나로 제한한다. 준비 중·다른 생성 중인 요청은
   Ollama 대기열에 쌓지 않고 기존 규칙 기반 문장으로 응답한다. 이 경우 모델 생성 성공으로
   표시하지 않는다. 모델 사용을 강제로 보장하는 방식이 아니며 여러 사용자 동시 사용 시
   기본 문장 사용이 늘어날 수 있다. 학습 추천용 모델의 별도 요청까지 통합 제한하지는 않는다.
6. 이미 저장된 같은 사용자·요청 ID·카드 구성은 모델 호출 전에 반환한다.
   카드나 재생성 대상이 다른 동일 요청 ID는 기존과 같이 409로 거절한다.
   새 요청 ID의 같은 카드 구성까지 공유 캐시로 재사용하거나 사용자 간 문장을 공유하지 않는다.
7. 생성 응답의 `generation.performance`에 시간·토큰 수만 추가한다.
   새 카드 원문 로그·DB 조회 로그·별도 성능 로그 파일은 추가하지 않는다.

<a id="sentence-generation-performance--설정과-적용"></a>
#### 설정과 적용

| 백엔드 환경 변수 | 기본값 | 의미 |
| --- | --- | --- |
| `OLLAMA_KEEP_ALIVE` | `30m` | 모델 응답 후 유지 시간. 숫자 문자열은 JSON 숫자로 전달 |
| `OLLAMA_WARMUP_ENABLED` | `true` | 백엔드 시작 시 모델 사전 준비 |
| `OLLAMA_WARMUP_TIMEOUT_SECONDS` | `30` | 사전 준비 HTTP 요청의 소켓 타임아웃 |
| `OLLAMA_NUM_CTX` | `2048` | 문맥 길이. 코드 허용 범위 1024~8192 |
| `OLLAMA_NUM_PREDICT` | `60` | 출력 토큰 상한. 코드 허용 범위 32~128 |
| `OLLAMA_TIMEOUT_SECONDS` | 기존 `10` 유지 | 실제 생성 HTTP 요청의 소켓 타임아웃 |

환경 변수의 숫자 형식이 잘못되면 기본값을 사용한다. 소켓 타임아웃은 DB·검증·
전송 전체를 합친 엄격한 종단 간 시간 상한이 아니다. 브라우저의 기존 요청 타임아웃도 유지한다.
Compose에서 전달하는 `OLLAMA_KEEP_ALIVE`는 백엔드가 API 본문에 넣는 값이며,
호스트 Ollama 프로세스의 전역 환경 변수를 수정한 것은 아니다.

변경된 Compose 환경 변수는 컨테이너 재생성 후 적용된다. 사용자가 실행한다.

```powershell
docker compose up -d --no-deps --force-recreate backend
```

로컬 Ollama가 먼저 실행되어 있고 `qwen2.5:0.5b`가 설치돼 있어야 한다.
사전 준비 실패는 API 시작을 실패시키지 않으며 기본 문장 경로를 유지한다.
준비 중 생성 요청 역시 `generation_source: rule`이며, 준비 이후 새 요청이나 재생성에서
모델을 사용할 수 있다. 이미 저장한 기본 문장을 같은 요청 ID 재전송으로 자동 교체하지 않는다.

충분한 메모리가 있고 계속 상주시켜도 되는 PC라면, 다음과 같이 무기한 유지를 선택할 수 있다.
RAM/VRAM을 계속 점유하므로 기본값으로 강제하지 않는다.

```powershell
$env:OLLAMA_KEEP_ALIVE = '-1'
docker compose up -d --no-deps --force-recreate backend
```

세션 환경 변수는 해당 PowerShell 세션에 적용된다. 기본 유지 시간으로 돌아가려면
이 변수를 제거하고 컨테이너를 다시 생성한다. 모델 종류 변경·GPU 설정 변경·호스트 서비스
재시작·컨테이너 재생성은 이번 작업에서 실행하지 않았다.

<a id="sentence-generation-performance--지연-확인-방법"></a>
#### 지연 확인 방법

브라우저 개발자 도구에서 `POST /api/sentences` 응답의 아래 항목을 비교한다.
인증 토큰·개인 카드명·원문이 포함된 응답 전체를 공개 로그로 공유하지 않는다.

| 항목 | 해석 |
| --- | --- |
| `generation_source` | `ollama`면 모델 응답 채택, `rule`이면 기본 문장 |
| `generation.performance.status` | `generated`, `warming_up`, `busy`, `disabled`, `unavailable`, `invalid_response` |
| `elapsed_ms` | 모델 호출 함수 안의 경과 시간. DB·전체 HTTP 요청 시간과 다름 |
| `load_ms` | Ollama가 반환한 모델 로딩 시간 |
| `prompt_ms` | Ollama가 반환한 입력 처리 시간 |
| `decode_ms` | Ollama가 반환한 출력 생성 시간 |
| `model_total_ms` | Ollama가 반환한 전체 처리 시간 |
| `input_tokens` / `output_tokens` | Ollama가 반환한 토큰 수 |

모델이 해당 지표를 반환했을 때만 필드를 기록한다. 과거 기록에는 성능 필드가 없을 수 있다.
`performance.status: generated`는 모델 응답을 받았다는 의미이며, 이후 의미·안전 검증에서
기본 문장으로 바뀔 수 있으므로 최종 `generation_source`와 `generation.validation`도 확인한다.
장치 처리량은 새 성능 필드로 먼저 구분하고 단순히 모델 크기를 올리는 방식으로 해결하지 않는다.

남은 사용자 확인:

- [ ] 서버 재생성 후 준비가 끝났을 때 첫 생성과 연속 생성의 실제 시간을 비교한다.
- [ ] 10분 이상 유휴 후에도 30분 유지 설정에서 `load_ms`가 낮게 유지되는지 확인한다.
- [ ] 유지 시간을 넘긴 뒤 다시 로딩될 수 있음을 확인하고 필요하면 유지 시간을 조절한다.
- [ ] `나·물·마시다`, `물`, 거절·통증·복수 행동·개인 카드 조합의 의미와 한국어 품질을 확인한다.
- [ ] 준비 중·동시 요청·Ollama 중지·응답 잘림에서 기본 문장 표시와 원문 발화를 확인한다.
- [ ] 같은 완료 요청 ID를 재전송했을 때 기존 기록을 반환하고 새 생성 기록을 만들지 않는지 확인한다.

<a id="sentence-generation-performance--검증-상태"></a>
#### 검증 상태

- Python 4개 파일은 실행·가져오기 없이 AST 구문 분석을 통과했다.
  첫 시도는 PowerShell→Python 표준 입력 인코딩 오류로 실패했으며 UTF-8 모드로 재확인해 통과했다.
- `docker compose config --quiet`와 `git diff --check`를 확인했다.
- Ollama의 로컬 상태 조회는 연결 실패로 완료하지 못했다. 실제 생성·시간 비교·GPU/CPU 확인은 미실행이다.
- 자동 테스트·빌드·브라우저·DB 통합·실기기 검증은 사용자 요청에 따라 미실행이다.
  구문 검사와 커밋을 성능 향상 측정·문장 품질 검증 완료로 취급하지 않는다.
- 사용자가 추가한 카드 사진은 전부 미추적 상태로 보존하며 이번 커밋에서 제외한다.
