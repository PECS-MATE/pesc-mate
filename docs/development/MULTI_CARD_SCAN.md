# 한 번 촬영한 여러 실물 카드 가져오기

## 사용 방법

- 보호자·담당자: 아이 관리 → 개인 카드 관리 → 실물 카드 한 번에 가져오기.
- 운영자: 공용 콘텐츠 운영 → 실물 카드 한 번에 가져오기.
- 카드들을 겹치지 않게 간격을 두고 펼쳐 한 번 촬영하거나 사진을 선택한다.
  흰 카드와 대비되는 바탕에서 카드 전체와 이름이 보이도록 촬영한다.
- 카드 영역 찾기 → 영역 확인·수정 → 분리하고 이름 읽기 → 그림·이름·뜻·분류 확인
  → 등록할 카드 선택 → 확인 체크 → 선택 카드 저장.
- 자동 영역은 추정이다. 못 찾은 카드는 영역 추가, 잘못 찾은 영역은 삭제하고,
  네 꼭짓점을 끌거나 좌표 입력으로 수정한다. 모서리는 왼쪽 위부터 시계 방향이다.
- 한 장도 같은 방식으로 처리한다. 경계를 찾지 못하면 영역을 직접 지정한다.
- 기본 범위는 한 사진당 최대 20장이다. 20개보다 많이 검출되면 잘림 안내를 표시한다.
  작거나 흐린 글자는 여러 장으로 나눠 더 크게 촬영하는 편이 낫다.
- 한 장씩 OCR 요청을 보내며 이름 인식은 자동 저장이 아닌 제안이다.
  OCR 도구가 없거나 실패해도 분리된 그림은 유지하고 이름·뜻을 직접 입력할 수 있다.
- 새 이미지 생성, 카드 안 그림만의 누끼, 배경의 의미 제거는 하지 않는다.
  기존 카드의 그림과 인쇄된 이름을 포함한 카드 전체를 유지한다.

## 저장과 오류 처리

- 보호자는 선택한 아동의 개인 카드로 저장한다. 운영자는 공용 공개 권한을 확인한 후
  모두에게 공개한다. 일반 보호자의 사진을 공용으로 자동 이전하지 않는다.
- 공통 분류와 개별 분류를 지정할 수 있다. 이름·뜻·분류를 검토해야 저장할 수 있다.
- 기본 카드와 현재 등록 목록·선택 목록의 중복 이름을 표시한다.
  최종 중복·형식·권한·동의·이미지 검사는 기존 등록 API에서도 다시 수행한다.
- 기존 카드 등록 API를 한 장씩 호출한다. 전체 트랜잭션은 아니며 결과를 카드별로 표시한다.
- 성공한 카드는 다시 전송하지 않는다. 명확한 검증 실패만 수정 후 다시 저장할 수 있다.
- 통신·서버 오류로 저장 여부가 불분명하면 해당 카드를 잠그고 등록 목록 확인을 안내한다.
  등록 목록 갱신이 같은 카드의 저장 완료를 자동 확정하거나 재전송하지는 않는다.
- 영역 찾기·OCR은 중단할 수 있고 늦은 응답은 무시한다. 저장 중에는 중단 버튼을 숨긴다.
  화면을 떠나 이미 전송된 저장까지 취소할 수 있다고 가정하지 않는다.
- 저장 전 사진 교체나 영역 재편집은 확인 창을 거친다. 이미 저장된 카드를 삭제하지 않는다.
- 카드판 위치·기존 카드·RFID 연결은 자동 변경하지 않는다. 아이는 목록 새로고침 후
  새 카드를 사용할 수 있으며 RFID 연결은 별도 작업이다.

## 구현과 API

`POST /api/cards/scan` multipart:

- `image`: 기존 업로드 규칙의 JPG·PNG·WebP, 5MiB 이하, 각 변 128~4096px.
- `scope`: `private`(기본) 또는 `shared`.
- `user_id`: 개인 카드 대상 아동. 보호자·담당자의 `cards_manage`와 보호자 동의를 확인한다.
- 공용은 `content_manage`를 확인하며 아동 ID나 아동 동의를 사용하지 않는다.
- `regions` 없음: `{regions: [{corners: [[x,y], ...4개]}], width, height, truncated}` 반환.
- `regions` 있음: 위 영역 배열을 JSON 문자열로 전달. `{cards: [{image: 'data:image/jpeg;base64,...'}]}` 반환.
- 좌표는 0~1 범위이며 최대 20개다. 볼록성·순서·최소 크기·너비높이비를 검사한다.
  잘못된 영역은 422, 도구 없음은 503, 다른 분리 요청 처리 중이면 429다.
- OpenCV의 윤곽선·사각형 근사로 후보를 찾고 중복 경계·큰 바깥 프레임 후보를 줄인다.
  원근 변환으로 카드 영역을 펴서 자른다. 검출은 글자·상징 의미를 이해하는 AI가 아니다.
- 정상화된 사진은 긴 변 2048px 이하, 분리 JPEG는 긴 변 1024px 이하·짧은 변 128px 이상이다.
  작은 영역을 확대하더라도 원본에 없는 글자 세부 정보가 복구되는 것은 아니다.
- OCR은 기존 로컬 한국어 Tesseract API를 카드별로 재사용한다. 외부 API 키가 필요 없다.
- 스캔 API는 사진·이미지·OCR·카드를 DB에 저장하지 않고 `Cache-Control: no-store`를 반환한다.
  브라우저 메모리의 사진·분리본은 해당 화면을 벗어나면 유지되지 않는다.
- 저장할 때만 분리 JPEG를 기존 카드 이미지 보관 정책으로 저장한다. 촬영한 전체 사진을
  서버에 원본으로 별도 보관하지 않는다. 원근 보정 이전으로의 서버 복원 기능은 없다.
- Apple 피사체 분리 API나 새 이미지 생성 API는 사용하지 않는다.

새 OpenCV 의존성을 추가했으므로 Docker에서는 백엔드를 다시 빌드한다.

```powershell
docker compose up -d --build backend
```

구현 참고: [OpenCV 원근 변환](https://docs.opencv.org/4.13.0/da/d54/group__imgproc__transform.html).

## 검증 기록 — 2026-11-04

- 로컬 가상환경에 OpenCV headless·NumPy를 설치해 실제 검출·원근 변환을 실행했다.
- 합성 사진의 카드 4개 검출·4개 JPEG 자르기, 기울어진 단일 카드 검출과 원근 보정,
  빈 사진 0개, 24개 후보를 20개로 제한하고 잘림 표시를 확인했다.
- 잘못된 영역 수, 교차·너무 작은 영역, 범위 밖/무한 좌표·잘못된 자료형 거부를 확인했다.
- TestClient와 모의 서비스로 운영 권한·개인 대상 권한/동의·다른 대상 거부·no-store를 확인했다.
- Chrome 모의 API로 4개 영역 표시·추가·삭제, 분리·순차 OCR·중복 이름 표시,
  공용 저장의 성공/명확한 실패/저장 불명확 상태, 실패 항목만 재시도를 확인했다.
- 보호자 한 장 등록의 좌표 입력 수정·개인 대상 ID 전달, OCR 503 시 수동 입력과
  개인 등록 요청을 확인했다. 390px 화면 가로 넘침이 없음을 확인했다.
- Chrome 터치 에뮬레이션의 꼭짓점 끌기, OCR 중단 후 늦은 이름 응답 폐기와
  다음 카드 OCR 요청 중지를 확인했다. 실제 iPad 터치 검수와는 구분한다.
- 로컬 프로덕션 빌드와 Python 구문·FastAPI 앱 import, 공백 검사 통과.
- 기존 번들 크기 경고와 개발 서버 public 음성 manifest import 경고는 남아 있다.
- 실제 카드 사진·조명·라미네이팅 반사·여러 줄 한글 인식률, iPad 카메라·터치,
  Docker 재빌드, 실제 MongoDB 저장·아동 화면·TTS·RFID 통합은 미실행이다.
  실제 사용자 계정·DB·사진은 변경하지 않았고 영구 자동 테스트 파일을 추가하지 않았다.
- 합성 검출·모의 OCR 통과는 실물 카드의 검출률이나 한국어 인식률 보장이 아니다.
- 작업 중 사용자가 추가한 카드 PNG는 이번 기능 변경에 포함하거나 커밋하지 않는다.
