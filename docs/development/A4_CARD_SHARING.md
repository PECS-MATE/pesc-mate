# 보호자 A4 카드판 공유

## 사용 흐름

- 보호자 홈의 `함께 만드는 그림 카드판`: 둘러보기·내 보관함·새 카드판 만들기를 제공한다.
  아이 연결 전에도 이용할 수 있고 기존 아이 관리 기능은 유지한다.
- A4 편집기의 `편집본 저장·공유` 아이콘에서 모든 쪽의 미리보기와 제목·주제·설명을 확인한다.
  프린트 설정 창의 같은 아이콘은 현재 미리보기의 방향·행열·이름 표시·양면 구성을 그대로 사용한다.
  기본은 비공개 새 편집본 저장이다. 아이 계정 사용 체크박스와 전체 공유는 별개다.
- 공개에는 공유 승인 요청, 이미지 권리 확인, 개인정보 확인을 명시적으로 선택해야 한다.
  다른 보호자의 복사·수정·재공유·인쇄와 이미 만든 사본의 회수 불가를 안내한다.
- 기존 콘텐츠 운영 담당자의 카드 승인 화면 상단에서 공유 요청·신고를 검토한다.
  승인 전에는 작성자와 운영 담당자만 볼 수 있다. 자기 승인은 금지하며 반려·중단·신고 처리에는 사유가 필요하다.
- 다른 보호자는 상세 A4 미리보기를 보고 독립 비공개 사본을 복사해 편집·인쇄한다.
  아이의 디지털 카드로 자동 등록하지 않으며 원본을 수정하지 않는다.
- 편집 중인 변경은 새 편집본으로 저장해야 서버에 남는다. 덮어쓰기·자동 저장·댓글·채팅은 MVP에서 제외한다.
- 본인 공유는 중단할 수 있고 비공개/반려/중단 편집본은 삭제할 수 있다. 공개·대기 자료는 먼저 중단한다.
  삭제는 되돌릴 수 없으며 다른 보호자의 사본은 남는다.

## 데이터와 경계

- 실제 배치된 카드·보이는 인쇄 문구·용지·칸 설정만 저장한다. 배치하지 않은 사진, 원본 보관함 이름,
  숨긴 문구, 아이 ID, 개인 카드 내부 ID, 뜻·분류·원본 파일명은 전송하지 않는다.
  단 양면 인쇄의 뒷면에 표시되는 이름은 보이는 문구이므로 포함한다.
  서버 스키마도 추가 필드를 거부한다.
- JPG/PNG/WebP의 서명·크기·해상도·디코딩을 검사하고 최대 768px WebP 사본으로 정규화한다.
  EXIF 등을 제거하지만 사진 픽셀 안의 얼굴·이름·민감성은 자동 보증하지 않는다. 보호자 확인과 수동 승인이 필요하다.
  기존 개인 카드 원본 보관 정책은 바꾸지 않는다.
- 상세는 기존 브라우저 A4 렌더러로 모든 쪽을 보여 준다. 목록은 첫 쪽의 작은 참고 썸네일이며
  글꼴·줄바꿈은 실제 인쇄와 다를 수 있다. 인쇄 설정은 기존 프린트 창에서 한다.
- 로그인한 보호자 또는 기존 콘텐츠 운영 권한 담당자 전용이다. 아동·일반 지원 담당자·비로그인은 이용할 수 없다.
  공개 작성자의 실명·계정 ID·아이 연결 정보는 목록/상세에 제공하지 않는다.
- 계정당 활성 편집본 100개, 요청 12MiB, 처리 후 프로젝트 8MiB, 카드 원본 60개·A4 최대 5쪽이다.
  양면은 최대 10면이며 기존 이미지 사용자/전체 저장 한도에도 포함한다.
  저장·복사는 요청 UUID로 중복 생성을 막고 상태 변경은 버전을 확인한다.
- 보관함 삭제 시 사진·제목·설명·출처를 제거하고 최소 요청 식별/중복 방지 표식만 남긴다.
  전체 이용 데이터 삭제 시 이 표식도 삭제한다. 지연된 동일 저장 요청으로 사진이 되살아나지 않는다.
- 개인정보 내보내기에 본인 카드판 메타데이터·신고를, 전체 이용 데이터 삭제에 본인 카드판·신고를 포함한다.
  이미지 저장 잠금·삭제 경합 검사에 참여한다. 다른 보호자의 독립 사본, 이미 시작한 복사·다운로드,
  이미 열린 화면·파일은 회수할 수 없다.
- 공개 목록은 최신순·제목 검색·주제 필터·12개 페이지다. 신고는 계정/카드판별 한 번 접수한다.
- 소프트웨어가 적법한 공개·재이용 권한을 대신 확인하지 않는다. 공개 운영 전 이용 정책·이미지 권리·
  개인정보 처리 절차는 별도 검토가 필요하다.

## API

| 메서드 | 경로 | 범위 |
|---|---|---|
| GET | `/api/a4/projects?scope=discover/mine/review&topic=&q=&offset=0` | 공개/본인/운영 검토 목록 |
| POST | `/api/a4/projects` | 비공개 저장 또는 명시적 승인 요청 |
| GET | `/api/a4/projects/{id}` | 권한 확인 후 편집 가능한 사본 |
| POST | `/api/a4/projects/{id}/copy` | 승인 자료를 본인 보관함에 독립 복사 |
| POST | `/api/a4/projects/{id}/withdraw` | 본인 공유 중단 |
| POST | `/api/a4/projects/{id}/review` | 운영 승인·반려·중단·신고 검토 완료 |
| POST | `/api/a4/projects/{id}/report` | 다른 보호자의 공개 자료 신고 |
| DELETE | `/api/a4/projects/{id}` | 본인 비공개/반려/중단 자료 삭제 |

응답은 `no-store`이며 상세의 사본 이미지는 인증 JSON에 포함한다. 별도 공개 이미지 URL은 만들지 않는다.
내부 컬렉션은 `a4_projects`, `a4_reports`다. 기존 카드 승인·아동 연결 권한은 변경하지 않는다.

## 검증 기록

### 보호자 홈과 아이 관리 분리

- 사이드바 후속 수정: 상위 두 메뉴의 너비와 행 높이를 통일하고 시작 위치를 고정했다.
  사이드바 전체 대신 상세 메뉴만 스크롤하며 프로필·로그아웃은 하단에 유지한다.
  보호자 이름과 설정 아이콘은 한 줄로 배치하고 긴 이름은 말줄임 처리한다.
  데스크톱 너비는 256px로 조정하고 작은 화면은 기존 서랍 너비를 유지한다.
- 고정 배치 검증: 빌드와 `git diff --check` 통과. 격리 Chrome/모의 전체 권한 계정으로
  1440×700·390×700·320×568에서 홈/관리 전환 전후 상위 메뉴·프로필 좌표 동일,
  이름 줄바꿈 없음, 사이드바 전체 넘침 없음, 상세 스크롤 시 상위 메뉴 유지 확인.
  기존 큰 JS 청크 경고 유지. 실제 iPad 터치·스크린리더 검수는 미실행이다.

- 후속 UX 수정: 아이 관리로 들어가면 주 메뉴 아래 여섯 상세 항목을 권한 범위에 맞게
  펼친다. 상세 화면에서도 유지하여 관리 첫 화면으로 돌아가지 않고 바로 이동할 수 있다.
  선택한 항목은 현재 페이지로 표시하며, 홈에서는 하위 목록을 숨긴다.
  작은 화면에서는 아이 관리 클릭 직후 메뉴를 닫지 않아 상세 항목을 바로 고를 수 있다.
- 후속 검증: 프런트엔드 빌드와 `git diff --check` 통과. 격리 Chrome/모의 API로
  단일 권한 및 전체 여섯 항목, 상세 직접 이동·선택 표시·홈 복귀,
  390px에서 펼침 후 메뉴 유지 확인. 전체 권한 첫 검사는 연습 제안의 모의 403이
  권한 회수 처리를 유발해 실패했고, 권한 오류가 아닌 모의 503으로 수정 후 재검사 통과했다.
  실제 iPad·스크린리더·실계정 왕복은 미실행이다.

- 보호자 홈에는 공유 갤러리와 카드판 만들기·보관함만 표시한다. 아이 선택·연결 안내,
  개인 카드·연습·기록·음성·카드판·기기 관리는 별도 ‘아이 관리’ 화면에 모았다.
- 보호자 주 메뉴는 홈과 아이 관리로 단순화한다. 담당자 메뉴는 변경하지 않으며,
  관리 기능의 기존 아이별 권한 확인과 저장하지 않은 설정의 이동 확인을 유지한다.
- 프런트엔드 빌드와 `git diff --check` 통과. 기존 큰 JS 청크 경고 유지.
- 격리 Chrome/모의 API로 홈에는 공유만 표시, 관리 화면 이동, 권한별 메뉴,
  아이 변경, 무권한 상태, 홈 복귀, 미연결 계정의 연결 안내 분리를 확인했다.
  첫 검사는 합성 계정의 프로필 누락으로 초기 프로필 화면에 머물러 실패했으며,
  검수 응답을 보완한 후 통과했다. 실제 사용자 데이터는 변경하지 않았다.
- 실제 계정 서버 왕복·iPad 터치·스크린리더 검수는 이번 변경에서 미실행이다.

### 미리보기 중심 갤러리 정리

- 가운데 제목과 짧은 소개, 큰 미리보기, 제목·주제·쪽수·카드 수·등록일 순서로 정리했다.
  작성자 이름이나 계정 식별값은 공개하지 않는다. 등록일은 서버가 제공한 날짜를 표시한다.
- 데스크톱 3열, 태블릿 2열, 작은 화면 1열로 배치한다. 미리보기 영역은 4:3으로 통일하되
  세로형 A4와 카드 이미지 자체는 자르거나 늘리지 않는다. 보관함·검토 상태는 별도 표시한다.
- 격리 Chrome/모의 API로 1440·768·320px 열 수, 긴 제목의 동일 높이,
  가로 넘침 없음, 이미지 비율 보존, 등록일 표시와 상세 → 복사 → 편집 → 공유 흐름을 확인했다.
  첫 비율 검사는 이미지 고유 크기로 영역이 늘어나 실패했으며, 이미지 배치 수정 후 재검사 통과했다.
- 프런트엔드 빌드와 `git diff --check` 통과. 기존 큰 JS 청크 경고는 유지된다.
  실제 iPad 터치·스크린리더·프린터와 실제 계정 전체 왕복은 이번 UI 작업에서 미실행이다.

### 공유 기능 구현

- 프런트엔드와 한글 썸네일용 Nanum 글꼴을 포함한 백엔드 이미지 빌드 통과. 기존 JS 청크 경고 유지.
- 격리 임시 MongoDB에서 비공개 격리·아동 접근 거부·공개 확인 필수·저장/복사 중복 방지,
  운영 권한·자기 승인 금지·버전 충돌·승인 후 목록·신고 중복·신고 처리·중단·사본 유지,
  용량 집계·아이 식별값/잘못된 칸 거부·전체 이용 데이터 삭제를 확인했다.
  임시 검수 DB만 삭제했으며 실제 사용자 계정·데이터는 사용하지 않았다.
- 격리 Chrome/합성 그림/모의 API로 둘러보기 → 미리보기 → 복사 → 독립 편집 →
  명시적 확인 → 승인 요청과 320px 문서 가로 넘침 없음을 확인했다.
  첫 검사는 검수 호스트의 `.app` 범위 누락으로 실패했고 실제 앱 범위 적용 후 통과했다.
- 최종 추가 검사: 격리 ASGI API에서 익명 401·아동 403·초과 본문 413·추가 필드 422,
  공개/비공개 저장·승인·복사를 확인했다. 개별 삭제 후 용량 반환·사진/제목 제거·동일 요청 부활 금지,
  숨긴 이름 제외도 확인했다. 브라우저에서는 미배치 사진 제외, 가로 5cm 양면 설정 전달,
  보이는 뒷면 이름 유지, 중첩 저장창 Escape가 프린트 설정을 닫지 않음을 확인했다.
- 실제 보호자/운영 계정의 브라우저 전체 왕복, 개인 사진의 권리·개인정보 판정,
  iPad 터치·스크린리더·프린터와 운영 배포 승인은 미실행이다. 영구 테스트 도구는 추가하지 않았다.
