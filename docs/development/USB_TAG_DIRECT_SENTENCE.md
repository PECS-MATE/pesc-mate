# USB 태그를 나의 문장에 바로 추가

## 변경

- 아동의 USB 흐름에서 별도의 `실물 카드로 말하기`·태그 목록·적용 버튼을
  제거했다. 태그를 등록 카드로 조회한 뒤 나의 문장 뒤에 직접 추가한다.
- 홈에서 태그하면 기존 문장을 유지한 채 말하기 화면으로 이동한다.
  연결·해제 버튼은 상단 연결 메뉴 안에 유지한다.
- 사용자 연결 표시는 `기기 연결`·`기기 연결됨`으로 간소화했다.
  연결 중·응답 대기와 실제 실패 안내는 유지하되 서비스 모드·장치 로그·
  음성 준비 상태는 사용자 연결 메뉴에서 제거했다. 보호자 등록 로그는 유지한다.
  오프라인 대체 음성의 백그라운드 준비와 재생 실패 안내는 유지한다.
- 기존 보호자/관리자의 리더기·칩 등록·수동 적용 흐름은 변경하지 않는다.
  이번 자동 추가는 브라우저 USB 입력에 적용하며 서버/API를 삭제하지 않는다.
- 정상 단일 리더기 펌웨어는 계속 올려둔 카드의 반복 상태를 무시한다.
  떼었다가 다시 대면 새 태그로 취급하므로 같은 단어를 다시 추가할 수 있다.
- 진단용 UID 출력은 기존 800ms 중복 억제를 사용한다. 카드 유지/제거가 없는
  진단 출력으로 물리적 재태깅 여부를 완벽하게 판단할 수 있다고 보장하지 않는다.
- 여러 위치 입력도 문장을 교체하지 않고 새로 인식된 카드만 추가한다.
  카드 제거가 이미 담은 문장을 지우지는 않는다.
- 조회 중 새 태그는 순서를 유지해 모으고 최신 배치로 조회한다. 정상 카드만
  추가하고 미등록/사용 불가·문장 12장 초과는 오류 안내한다.
- 계정·화면·문장·동의/연결 상태가 달라진 조회 응답은 뒤늦게 반영하지 않는다.
  메뉴/설정·연습 등 비활성 화면과 발화 중·숨긴 탭·오프라인에서는 추가하지 않는다.
- 리더기 오류·잘못된 프레임·연결 해제는 진행 중인 추가를 무효화한다.
- 빠른 연속 조회가 React 반영보다 앞서도 이전 문장을 덮어쓰지 않도록 현재
  문장 참조를 동기 갱신한다. 태그 자체가 문장 생성이나 TTS를 자동 실행하지는 않는다.

## 검증

- 최종 프런트엔드 빌드와 변경분 공백 검사 통과.
  기존 500kB 초과 청크 경고는 남아 있다.
- 중간 빌드는 작업 중 마스코트 이미지 부재로 실패했다. 이미지가 다시 존재하는
  상태에서 최종 빌드를 재실행해 통과했다. 이미지 파일은 이번 변경에 포함하지 않는다.
- 연결 메뉴 간소화 후 JSX 구문 검사와 빌드는 통과했다.
  아래 가상 USB 브라우저 검수는 연결 메뉴 간소화 전 실행한 결과이며,
  최종 연결 메뉴의 실제 기기·브라우저 조작 검수는 미실행이다.
- 실제 Chrome 안에서 가상 Web Serial 스트림과 태그 조회 응답을 사용했다.
  카드·발화 이용 기록 및 USB 이벤트 저장 요청은 가상 응답으로 차단했다.
- 최초 검수는 메뉴가 열린 비활성 상태여서 추가가 차단됐다. 상태를 확인하고
  메뉴를 닫은 정상 사용 흐름으로 재실행했다.
- 홈에서 물 태그 → 나의 문장 1장, 계속 유지 → 1장, 떼었다 재태깅 → 2장,
  다른 태그 → 물/물/마시다 순서, 미등록 태그 → 추가 없음 확인.
- 별도 실물 카드 영역 없음, 조회 도중 비우기 후 늦은 추가 없음,
  빠른 12회 태깅의 12장 유지와 추가 태그의 한도 차단,
  연결 해제 후 늦은 응답 추가 없음을 확인했다.
- 임시 브라우저의 문장 저장 키를 검수 전 값으로 복구했고 로그아웃·종료했다.
  실제 매핑·카드·동의·설정 데이터는 수정하지 않았다.
- 실제 USB 보드·리더기·실물 카드·발화·다중 리더기·관리자 등록·오프라인·
  네트워크 오류·브라우저 권한·모든 접근성 상태의 회귀 검수는 미실행이다.
- 사용자 카드 PNG·PDF·수정 중인 제작 체크리스트와 자동 테스트 파일은 커밋하지 않는다.
