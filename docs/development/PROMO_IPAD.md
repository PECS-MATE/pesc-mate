# 아이패드 프레임 시연 화면

PECS MATE의 기능을 아이패드 형태의 가로 프레임 안에서 자동 소개하는 촬영용 페이지다.
앱 서버를 평소처럼 실행한 뒤 같은 주소의 `/promo-ipad.html`을 연다.
예: 개발 서버가 `http://localhost:5173`이면 `http://localhost:5173/promo-ipad.html`.

1. 페이지를 열면 홈 → 카드 선택 → 문장 완성 → 연습 → 마무리 순서로 자동 재생한다.
2. 민트 또는 흰 배경을 고르고 전체 화면으로 전환한다.
3. 촬영 모드를 누르면 설정 버튼이 사라진다. 화면 녹화는 별도 녹화 도구로 실행한다.
4. Esc로 설정 버튼을 복원한다. 키보드 Tab으로 왼쪽 위 복원 버튼에 접근할 수도 있다.

11개 장면을 각각 2.6초씩, 총 28.6초 주기로 반복한다.
일시정지·재생, 처음부터, 다음 장면 버튼으로 흐름을 조절할 수 있다.
동작 줄이기를 사용하는 환경에서는 일시정지 상태로 시작하며 재생 버튼으로 시작한다.

기본 자동 시연은 로그인 없이 동작하는 예시 화면이며 실제 서비스의 홈 컴포넌트,
그림카드, 아이콘, 디자인 색상을 재사용한다. 문장 출력과 정답은 연출된 예시이고
음성은 재생하지 않는다. 계정·기록 API를 호출하거나 데이터를 저장하지 않는다.
`/?promo=demo`로 시연 화면만 열 수도 있다.

‘실제 앱 조작’ 버튼으로 이전처럼 실제 앱을 열 수 있다.
이 모드에서는 기존 계정과 서버 연결을 사용하며 자동 전환은 하지 않는다.
태블릿 내부 화면은 1194×886이며 브라우저 크기에 맞춰 프레임 전체를 축소한다.
정지 이미지나 영상 파일을 자동 생성하는 페이지는 아니다.

## 파일 구성

| 경로 | 역할 |
| --- | --- |
| `frontend/public/promo-ipad.html` | 촬영 페이지 마크업과 공개 진입 주소 |
| `frontend/public/promo/promo-ipad.css` | 아이패드 프레임·배경·촬영 도구 스타일 |
| `frontend/public/promo/promo-ipad.js` | 프레임 크기 조절·재생 명령·촬영 도구 동작 |
| `frontend/src/promo/promo-demo.jsx` | 시연 장면의 React 화면 |
| `frontend/src/promo/promo-demo.css` | 시연 장면 내부 스타일 |
| `frontend/src/promo/promo-timeline.js` | 장면 순서·자막·반복 주기 |
| `scripts/check-promo-layout.mjs` | Chrome 레이아웃 회귀 검사 |

촬영 페이지의 CSS·JavaScript는 원래 인라인 내용에서 들여쓰기만 정리해 분리했다.
공개 주소 `/promo-ipad.html`과 기존 동작은 유지한다.

## 레이아웃 수정과 회귀 검사

프레임의 `transform: scale()`은 CSS Grid가 차지하는 원래 크기를 줄이지 않아,
작은 창에서는 프레임이 오른쪽 바깥으로 밀려 보이지 않았다. 큰 창에서는
화면 중앙에 놓인 프레임과 하단 설정 도구가 겹쳤다. 절대 위치로 중앙을 잡고,
실제 도구 높이를 제외한 영역에 맞춰 축소하도록 수정했다.

시연 화면에는 공통 `section`의 테두리·여백과 홈 그림 컨테이너 크기도
적용되고 있었다. 시연 전용 스타일을 공통 스타일 뒤에 로드하고 해당 속성을
명시했다. 카드 높이를 조정하고 헤더·자막 높이를 확보해 문장 완성 장면의
둘째 카드 줄이 자막을 덮지 않도록 했다. 시연 문서에만 스크롤바 여백을 제거했다.

`node scripts/check-promo-layout.mjs`로 로컬 Chrome에서 재현·검증한다.
Chrome 경로가 다르면 `PROMO_CHROME_PATH` 환경 변수로 지정한다.
설치·빌드 없이 실제 소스 CSS와 시연 장면의 대표 DOM을 로컬 HTTP로 제공한다.
검사 파일은 계정이나 서버에 접속하지 않고, 90초 실행 기한을 사용한다.
결과 JSON·스크린샷·Chrome 임시 프로필은 `.local-validation/promo-layout/`에 생성된다.

- 수정 전: 320×640, 768×1024, 1024×768, 1440×900, 1920×1080의
  네 장면 검사 20건 실패. 프레임 이탈·설정 도구 겹침 및 카드·자막 겹침 재현.
- 수정 후: 동일한 장면 20건과 촬영 모드·Esc 복원 5건 모두 통과.
  Chrome 스크린샷으로 작은 화면의 프레임 표시와 주요 장면의 배치 확인.
- `node --check scripts/check-promo-layout.mjs`, `git diff --check`: 통과.
- 대표 DOM 검사는 React 실행·자동 재생 전체 통합 검사를 대체하지 않는다.
  기존 JSX 파서 실패와 실제 앱 전체 시연 미실행 상태는 위 기록과 같다.
- 빌드: 요청하지 않아 미실행.

## 파일 정리 검증

- 추출한 CSS·JavaScript가 기존 인라인 내용과 들여쓰기를 제외하고 동일함: 통과.
- JavaScript 두 파일의 `node --check`, `git diff --check`: 통과.
- 파일 분리 후 기존 Chrome 레이아웃·촬영 제어 회귀 검사 25건: 통과.
- 사용 중인 Chrome 프로세스가 없음을 확인하고 이번 작업에서 생성한 임시 프로필
  6개와 오래된 실패 스크린샷 12개를 삭제했다. 최신 스크린샷 8개와 결과 JSON은 보존했다.
- React 자동 재생 전체 통합 검사와 빌드: 미실행. 기존 JSX 파서 환경 오류는 미해결.
