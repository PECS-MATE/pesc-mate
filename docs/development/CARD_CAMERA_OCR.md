# 실물 카드 촬영과 OCR 등록

## 사용자 흐름

- 보호자: 아이 관리 → 개인 카드 관리 → 개인 카드 등록.
- 운영자: 공용 콘텐츠 운영 → 공용 카드 등록 → 사진 카드.
- `카드 촬영` 또는 `사진 선택` → 미리보기 → `사진 글자 읽기` → 이름 확인·수정
  → `이 이름 사용` → 뜻·분류 확인 → 저장.
- 촬영·OCR만으로 저장하지 않는다. 보호자의 등록은 선택 아동의 개인 카드로,
  운영자 등록은 명시적으로 모든 사용자에게 공개하는 공용 카드로 저장한다.
- 인식 결과를 적용할 때 비어 있는 뜻만 이름으로 채운다. 기존 뜻은 덮어쓰지 않는다.
- RFID가 없어도 디지털 카드로 사용할 수 있다. 칩 연결은 별도 작업이다.

## 촬영 및 저장 범위

- 카드 한 장과 그 아래 이름이 크게 보이도록 촬영한다.
- HTML 파일 입력의 `capture="environment"`를 사용한다. 모바일 OS·브라우저에 따라
  후면 카메라 또는 파일 선택 UI가 열리며 PC에서는 보통 파일 선택창을 사용한다.
  이 기능은 브라우저 실시간 카메라 스트리밍이나 자동 셔터가 아니다.
- 촬영 입력은 브라우저가 읽을 수 있는 20MB 이하 사진을 받아 JPEG로 변환한다.
  최대 3200만 화소, 긴 변 2048px 이하, 짧은 변 128px 이상, 결과 5MB 이하로 제한한다.
  지원되지 않는 형식은 오류를 표시하며 JPG·PNG 촬영/선택을 안내한다.
- 촬영 원본 대신 변환한 등록용 JPEG가 서버의 원본 보관 대상이 된다.
  기기 사진 보관함의 원본을 변경하거나 삭제하지 않는다.
- `사진 선택` 파일은 기존처럼 원본 바이트를 유지하고 JPG·PNG·WebP/5MB 제한을 적용한다.
- 파일명을 카드명으로 추정하지 않는다. 촬영 사진은 미리보기로 확인한다.
- OCR 실패·글자 없음이면 직접 이름을 입력해 저장할 수 있다.
- 자동 분류, 여러 카드 분리, 배경 제거, 원근 보정, 글자/그림 영역 자동 분리는 포함하지 않는다.
  이번 버전은 촬영한 카드 전체를 이미지로 등록한다. 인식률은 조명·기울기·글자 크기에 영향을 받는다.

## OCR 및 권한

- 기존 `POST /api/cards/ocr`: `image`, `user_id` multipart.
  연결 아동의 카드 관리 권한과 보호자 동의를 기존대로 확인한다.
- 신규 `POST /api/admin/cards/ocr`: `image` multipart.
  `content_manage` 권한을 확인하며 아동 ID나 아동 동의 상태를 사용하지 않는다.
- 둘 다 기존 서버 로컬 Tesseract `kor+eng`을 재사용한다. 외부 OCR API를 호출하지 않는다.
  결과는 `suggested_label`, `candidates`이며 `Cache-Control: no-store`를 적용한다.
- 이미지 형식·크기 검증, 1회 동시 실행 제한, 20초 타임아웃과 임시 파일 정리를 유지한다.
  OCR은 사진·카드를 DB에 저장하지 않는다. 실제 저장은 확인 후 별도 등록 API로 수행한다.
- 촬영 처리 중 저장을 차단하며 사진 교체·화면 종료·대상 변경 후 늦은 OCR 결과를 버린다.
- 백엔드 Dockerfile에는 Tesseract와 한국어·영어 언어팩이 이미 포함돼 있다.
  도구 없음 오류가 나오면 `docker compose up -d --build backend`로 백엔드를 갱신한다.

## 검증 기록 — 2026-11-04

- 로컬 프로덕션 빌드, Python 구문 검사와 FastAPI 앱 import, 공백 검사 통과.
  기존 500kB 초과 번들 경고는 남아 있다.
- Chrome 모의 API 검사 통과: 촬영 입력의 PNG를 JPEG 2048×1536으로 변환,
  파일명 자동 입력 없음, 관리자 OCR 이름 확인·빈 뜻 채우기·공용 저장 요청,
  보호자 대상 ID 전달·개인 저장 콜백의 이미지 전달, 390px 가로 넘침 없음.
- 한국어 TSV OCR 줄 조합, 실행 도구 없음(503), 시간 초과(504)를 모의 실행기로 확인했다.
  관리자 OCR API 정상(200)/no-store와 일반 사용자·보호자·무권한 담당자 차단(403)을
  TestClient에서 확인했다. 실제 계정·DB를 사용하거나 변경하지 않았다.
- 첫 브라우저 검사 시 검사 도구의 동적 문자열 안 정규식 이스케이프 오류가 있었다.
  두 차례 실패 후 검사 도구를 수정하고 전체 흐름을 재실행해 통과했다.
- 개발 서버에는 기존 public 음성 manifest import 경고가 출력됐다.
  이번 촬영/OCR 기능의 빌드는 통과했으며 해당 음성 경로는 변경하지 않았다.
- 실제 Tesseract 한국어 사진 인식률, 실제 모바일 카메라/HEIC/회전,
  실제 MongoDB 저장·아동 화면 재조회·TTS·RFID는 미실행이다.
  로컬 PATH에서 Tesseract를 찾지 못했고 Docker 실행 검증은 수행하지 않았다.
- 영구 자동 테스트 파일을 추가하지 않았다. 모의 검사 통과는 실제 인식률 보장이 아니다.
