# 작은 화면 웹앱 레이아웃

> 후속 변경: 메뉴의 두 열 상단 배치는 [왼쪽 패널과 아이콘 위치 정리](SIDEBAR_TOGGLE_PLACEMENT.md)로 대체했다.

## 변경

- 1000px 이하로 앱에 진입하면 메뉴는 기본 접힘이다. 기존 메뉴 버튼으로
  언제든 펼친다. 화면 크기를 바꿀 때 사용자가 정한 접힘 상태를 강제로 바꾸지 않는다.
- 1000px 이하에서 메뉴는 상단 두 열이며 모든 계정에 동일한 배치 원칙을
  적용한다. 메뉴 자체 가로 스크롤을 없애고 긴 제목은 줄바꿈한다.
- 프로필·로그아웃·톱니바퀴는 겹치지 않도록 별도 열과 유연한 이름 영역을 쓴다.
- 상단 제목·연결 메뉴는 폭에 맞춰 줄바꿈하고 여백을 줄인다.
  연결 상세는 작은 화면 높이를 넘으면 내부 스크롤한다.
- 문장판은 상단 고정과 48dvh 높이 제한을 유지한다. 도구는 44px,
  선택 카드 폭은 120px·그림은 88px로 줄이고 카드 줄만 가로 스크롤한다.
- 빠른 표현·복구 표현은 가능한 열 수로 자동 배치하고 긴 문구는 줄바꿈한다.
- 카드 목록은 화면 폭과 사용자 카드 크기 설정을 함께 반영한다.
- 보호자 테마의 기존 반응형 스타일과 우선순위 충돌을 정리했다.
  구현은 `responsiveUx.css`에서 기존 테마 뒤에 로드한다.

## 확인 결과

- 최종 프런트엔드 빌드와 변경분 공백 검사 통과.
  기존 500kB 초과 청크 경고는 남아 있다.
- 분리 실행한 실제 Chrome에서 아동 말하기 화면을 320·390·640·768·1000·
  1280px로 확인했다. 메뉴 열림/닫힘 모두 페이지 가로 넘침이 없었다.
  1000px 최초 확인에서 문장판 로드가 끝나지 않아 다시 기다려 확인했다.
- 390×700px 화면에 12장 구조를 임시 DOM으로 주입하여 레이아웃만 확인했다.
  페이지 가로 넘침 없이 카드 줄 내부가 스크롤되고, 페이지를 내리면 문장판의
  상단 좌표는 0px·높이는 250px였다. 실제 12장 선택·저장 검수는 아니다.
- 최종 보호자 화면은 320·390·768·1000px에서 메뉴 열림/닫힘과 두 열 grid,
  가로 넘침 없음을 확인했다. 다른 보호자 하위 화면 전수 검수는 미실행이다.
- 390px 빈 문장판·임시 12장 스크롤 화면을 캡처해 확인했다. 캡처는 커밋하지 않는다.
- 검수 로그인은 로그아웃했고 분리 실행한 브라우저만 종료했다.
  카드·설정·동의·프로필·연습 데이터의 저장은 수행하지 않았다.
- 실기기·터치·소프트 키보드·실제 브라우저 확대·전체 역할/하위 화면·USB·TTS
  및 접근성 상태 전수 검수는 미실행이다. 현장 승인으로 간주하지 않는다.
- 사용자가 수정한 제작 체크리스트와 추가 카드 PNG는 변경하거나 커밋하지 않는다.
