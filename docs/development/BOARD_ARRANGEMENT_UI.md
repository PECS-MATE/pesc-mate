# 카드판 배치 편집 UI

## 변경

- 빠른 표현·다시 말하기·기본 카드판 중 하나만 골라 편집한다. 카드 선택 목록과 순서 목록의
  중복을 없애고 아동 화면과 같은 그림 렌더러·어휘·저장 순서를 사용하는 시각 목록으로 합쳤다.
  관리 화면은 배치만 편집하며 카드를 눌러도 음성 재생이나 의사소통 기록을 만들지 않는다.
- 드래그로 이동하거나 카드를 선택한 뒤 앞으로/뒤로 도구를 누른다.
  터치는 선택 후 이동 버튼, 키보드는 선택·도구 또는 Alt+방향키를 사용한다.
  그림/목록 보기 전환과 카드 검색·추가는 같은 초안에 적용된다.
- 변경은 명시적 저장 시 기존 API로 전송한다. 선택 아동과 expected_revision을 유지하며,
  다른 편집 모드로 바꿔도 각 초안을 유지한다. 미저장 상태의 보호자 화면 이동은 확인한다.
- 빠른 표현 8개·복구 표현 4개·기본 슬롯 30개 제한과 필수 복구 표현을 유지한다.
  잠긴 슬롯을 이동하거나 앞선 카드 삭제로 잠금 위치를 밀어내는 변경은 드래그에서도 거부한다.
- 추가 설정·추천·변경 이력은 접는다. 추가/추천 설정은 처음 열 때만 구성하고,
  다시 접어도 설정 내부의 초안은 버리지 않는다. 상황·추천에서 쓰는 슬롯 편집기도 공유한다.
- 예전 이중 패널·순서 목록의 미사용 코드와 CSS를 정리했다. 권한과 서버 데이터 구조는 바꾸지 않았다.

## 검증

- 프런트엔드 빌드 및 `git diff --check` 통과. 기존 큰 JS 청크 경고 유지.
- 격리 Chrome/합성 카드에서 단일 카드판, 터치용 선택/이동, 목록 보기, Alt+방향키,
  드래그, 모드별 초안 유지, 명시적 저장, 잠금 이동/선행 제거 거부, 잠기지 않은 카드 이동,
  필수 복구 표현 제거 금지, 빠른 표현 최대 8개, 추가 설정 접힘/초안 보존을 확인했다.
- 1440·768·320px 가로 넘침 없음. 실제 App에 모의 API를 붙여 메뉴 진입,
  아동 ID·버전·순서 저장 본문, 미저장 이동 취소, 저장 후 홈 이동을 확인했다.
  실제 사용자 계정·DB 데이터는 쓰거나 변경하지 않았다.
- 첫 독립 검수는 Vite의 다른 React 인스턴스를 가져와 훅 오류가 발생했다.
  앱과 같은 모듈 버전으로 수정한 뒤, 선택 직후 상태 갱신을 기다리지 않은 검사도 보완해 통과했다.
- 실제 iPad 터치·터치 드래그·스크린리더·실제 DB 왕복·실사용자 이해도 검수는 미실행이다.
  터치 드래그 자체를 보장하지 않으며 터치에서는 이동 버튼을 대안으로 제공한다.
