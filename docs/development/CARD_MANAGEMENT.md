# 카드 등록과 카드판 관리

> 통합일: 2026-11-04 · 현재 사용 안내와 과거 구현 기록을 구분합니다.

보호자의 아이 관리 → 개인 카드 관리에서 사진·실물 카드를 등록합니다. 관리자 공용 콘텐츠 운영에서는 글자·사진 공용 카드를 즉시 등록할 수 있습니다. 실물 카드 여러 장은 한 번 촬영한 뒤 영역 검출 → 분리·원근 보정 → OCR 이름 확인 → 선택 저장으로 가져옵니다. RFID 없이도 디지털 카드로 사용할 수 있습니다. A4 편집과 공유, 카드 배치·상황별 보드 및 개인 사진 교체도 이 문서에서 찾습니다.

과거 날짜의 검사 통과는 현재 버전 전체의 검수나 운영 배포 승인이 아닙니다. 상세 기록에는 이전 화면·제거된 기능 설명도 있으므로 현재 사용 경로는 위 안내를 우선하고, 남은 실제 기기·권한·음성 검수는 TODO와 각 절의 미실행 기록을 확인하세요.

## 카드 이름만으로 등록 (2026-11-07)

카드의 별도 ‘뜻’ 입력은 제거했습니다. 관리자 글자/사진 등록, 보호자 개별 등록·수정,
여러 실물 카드 OCR 검토, A4 편집기의 아이 계정 등록은 이름·분류·이미지를 기준으로 합니다.
OCR 이름을 직접 고쳐도 숨은 뜻 필드를 따로 고칠 필요가 없습니다.

등록 API의 `meaning`은 선택 항목이며 생략·빈 문자열이면 이름을 내부 호환 값으로 사용합니다.
수정 시 생략하면 기존의 별도 설명을 보존하고, 이전 값이 단순히 이전 이름이었던 경우 새 이름을 따릅니다.
기존 카드·문장 생성용 설명·A4 저장 파일의 메타데이터를 일괄 삭제하거나 DB 마이그레이션하지 않습니다.
이하 과거 상세 기록의 뜻 입력 안내는 당시 화면이며 현재는 이 절을 우선합니다.

검증: 서버 이름 기본값·기존 설명 보존·이름 변경·선택형 스키마 점검 통과.
개인/관리자 multipart 등록과 PATCH에서 뜻을 생략해도 서비스까지 도달하는 HTTP 경계 검사 통과
(서비스 호출은 모의 처리하여 실제 저장 없음). A4 등록 검사에서 뜻 생략 허용·이름/분류 필수 유지 확인.
실제 DB 저장·문장 생성 품질·브라우저 전체 동선 검수는 미실행입니다.
프론트 빌드·diff 공백 검사 통과. 기존 큰 번들 경고는 유지합니다.

## 선택형 그림 생성과 배경 제거 (2026-11-06)

관리자 사진 카드 등록·보호자 새 카드 등록·실물 카드 OCR 결과별 편집에서
‘그림 생성 · 배경 제거’를 펼칩니다. OCR 인식 이름을 확인하고 사용 가능 여부를 조회한 뒤
명시적으로 실행합니다. 결과는 미리보기에서 확인하고 적용해야 하며 자동 등록하지 않습니다.
적용 전에는 기존 사진이 유지되고 공용 공개·그림/뜻 확인은 다시 해야 합니다.

사용자 선택에 따라 기본 생성 경로를 [Hugging Face Inference Providers](https://huggingface.co/docs/inference-providers/tasks/text-to-image)로 변경했습니다.
모델 가중치를 PC나 Docker로 내려받지 않고 원격 GPU에서 생성합니다.
기본 모델은 `black-forest-labs/FLUX.1-schnell`, 추론 제공업체는 `fal-ai`입니다.
2026-11-06 공개 모델 메타데이터에서 해당 조합의 text-to-image 지원 상태가 live임을 확인했습니다.
이는 사용자 토큰의 이용 권한·결제 상태나 실제 생성 품질 확인을 대신하지 않습니다.
[Gemini](https://ai.google.dev/gemini-api/docs/image-generation)는 명시적으로 선택하는 대체 경로로 유지하고,
[rembg 로컬 배경 제거](https://github.com/danielgatis/rembg)는 별개 선택 기능입니다.
마스코트 없는 흰 배경·한 가지 의미·글자 없는 이미지 지시문을 사용합니다.
생성 품질·상징 이해도는 보장되지 않으므로 보호자가 반드시 확인합니다.
외부 이미지 생성과 배경 제거는 별개 선택 기능이며 OCR·일반 등록은 설정 없이 유지됩니다.

### 설정과 비용 경계

| 서버 설정 | 용도 |
| --- | --- |
| `IMAGE_GENERATION_PROVIDER` | 기본 huggingface. 선택적으로 gemini. 자동 대체 없음 |
| `HF_TOKEN` | Inference Providers 호출 권한이 있는 서버 전용 허깅페이스 토큰 |
| `HF_IMAGE_MODEL` | 기본 black-forest-labs/FLUX.1-schnell. 사용 가능한 모델 ID 지정 |
| `HF_IMAGE_PROVIDER` | 기본 fal-ai. fal-ai/hf-inference/together 중 모델을 지원하는 제공업체 지정 |
| `GEMINI_API_KEY` | 서버 전용 Gemini 키. 프론트 환경변수·Git에 저장하지 않음 |
| `GEMINI_IMAGE_MODEL` | 운영자가 현재 사용 가능한 이미지 모델 지정. 기본값 없음 |
| `INSTALL_IMAGE_TOOLS=true` | Docker 빌드 시 선택형 `requirements-image-tools.txt` 설치 |
| `REMBG_MODEL_PATH` | 서버 내부에 사전 배치한 `u2netp.onnx` 절대 경로 |

허깅페이스 호출은 카드 이름과 공통 그림 지시문을 Hugging Face 및 선택한 추론 제공업체에 보냅니다.
사진·사용자 ID·아동 기록은 보내지 않습니다. Gemini를 선택한 경우에만 Google로 전송합니다.
화면에서 표시된 서비스와 모델을 확인하며, 확인 이후 설정이 바뀌면 409로 다시 확인하도록 합니다.
이름에 개인정보를 넣지 마세요. 사용자가 매번 외부 전송·비용을 확인해야 합니다.
자동 생성·자동 재시도·유료 호출 일괄 실행은 없습니다. 시간당 계정당 20회 및 프로세스당 1건의
보호 장치는 재시작/다중 프로세스에 걸친 과금 한도가 아닙니다. 공급자 결제·사용 한도도 별도 설정하세요.
네트워크 시간 초과 후에도 공급자가 이미 과금했을 수 있습니다.

### 허깅페이스 설정 순서

1. [토큰 설정](https://huggingface.co/settings/tokens)에서 Inference Providers 호출 권한의 토큰을 발급합니다. 토큰은 채팅에 붙여넣지 않습니다.
2. [결제·크레딧과 사용량](https://huggingface.co/docs/inference-providers/pricing)을 확인합니다. Hub의 모델 다운로드가 무료여도 원격 API까지 무료인 것은 아닙니다.
3. 루트 `.env.example`을 참고해 `.env`에 `HF_TOKEN`을 저장합니다. 기존 `.env`가 있으면 덮어쓰지 말고 필요한 항목만 추가합니다.
4. `docker compose up -d --build backend` 실행. API 클라이언트만 설치하며 PyTorch·생성 모델 가중치는 설치하지 않습니다.
5. 카드 등록에서 이름 입력 → 그림 생성 · 배경 제거 → 사용 가능 여부 확인 → 외부 전송/비용 확인 → 이름으로 그림 생성 → 결과 확인 후 적용합니다.

설정됨 표시는 토큰·모델 문자열·클라이언트 설치 상태일 뿐 공급자 실연결 검사가 아닙니다.
토큰 권한/인증, 크레딧, 요청 한도, 지원하지 않는 모델·제공업체를 구분해 안내합니다.
원격 처리는 별도 프로세스로 전체 80초에 제한하고, 앱의 자동 재시도·다른 제공업체 자동 전환은 하지 않습니다.
생성 의미·한국어 이름 이해·일관된 그림체는 실제 검수해야 하며 AAC용 전문 모델이라고 보장하지 않습니다.

배경 제거는 서버 CPU에서 처리합니다. 선택 패키지와 모델이 없으면 503으로 안내하고
모델을 자동 다운로드하지 않습니다. 라이브러리 라이선스와 모델 가중치 이용 조건은 별도 확인하세요.
Docker에서 모델 폴더를 읽기 전용으로 마운트하고 `REMBG_MODEL_PATH`를 컨테이너 경로로 지정해야 합니다.
예: Compose override의 backend `volumes`에 `./models/card-background:/models/card-background:ro`를
추가하고 모델을 직접 배치한 뒤 경로를 `/models/card-background/u2netp.onnx`로 설정합니다.
환경 설정 후 `docker compose up -d --build backend`로 다시 만듭니다.
모델 파일·API 키는 커밋하지 않습니다.

### API와 검증 경계

- `GET /card-image-tools/status`, `POST /card-image-tools/generate`, `POST /card-image-tools/remove-background`
- 공용은 `content_manage`, 개인은 보호자/담당자의 연결 카드 권한과 동의를 확인합니다. 처리 후에도 재확인합니다.
- 결과는 임시 data URL이며 저장소에 자동 보관하지 않습니다. 기존 등록 API의 이미지 검사·공개 승인을 유지합니다.
- 공급자 오류 본문·키는 응답에 전달하지 않습니다. 응답 크기·업로드 크기·추론 시간을 제한합니다.
- 생성 요청 JSON에는 `expected_backend`와 `expected_model`도 필요합니다. status에서 받은 값을 확인 정보로 넘깁니다.
- 실제 Hugging Face/Gemini 유료 호출·모델 설치/다운로드·rembg 실추론·iPad 촬영 통합 검수는 미실행입니다.
- 검증: 프론트 빌드(큰 번들 경고 유지)·백엔드 라우터 import 통과. 설정 미비 차단·외부 전송 확인·모의 공급자 응답·이미지 유효성·보호자 권한·동시 실행 제한 점검 통과. 실제 API와 브라우저 통합은 미검증입니다.
- 허깅페이스 전환 검증(2026-11-06): API 클라이언트 huggingface-hub 1.33.0 설치·import 확인. 설정/잘못된 모델 URL/자동 공급자 차단, 외부 전송 확인, 설정 변경 409, 모의 워커 이미지 변환, 인증·크레딧·한도·모델 오류, 전체 시간 초과 안내 점검 통과. 추론 함수는 모의 처리하여 유료 호출은 0회입니다.
- 프론트 빌드·Compose config·diff 공백 검사 통과. 최초 Compose 검사는 sandbox의 Docker 설정 접근 경고가 있었고 읽기 권한으로 재검사 통과했습니다. 실제 Docker 이미지 재빌드·브라우저 전체 동선·실제 공급자 생성은 미실행입니다.

### 관리자 공용 카드 등록

<a id="admin-card-registration--사용-방법"></a>
#### 사용 방법

운영 권한이 있는 계정으로 로그인 → 공용 콘텐츠 운영 → 공용 카드 등록.

여러 실물 카드는 같은 화면의 `실물 카드 한 번에 가져오기`를 사용한다.
[사진 한 장에서 여러 카드 분리·일괄 확인](CARD_MANAGEMENT.md#multi-card-scan)을 지원한다.

- 글자 카드: 카드명·뜻·분류를 입력한다. 흰 배경에 글자만 배치한 미리보기를 제공한다.
- 사진 카드: 같은 정보를 입력하고 JPG·PNG·WebP 사진을 선택한다.
  사진의 공용 사용 권한을 확인해야 한다. 파일명으로 카드명을 자동 입력하지 않는다.
  `카드 촬영`으로 기기 카메라를 열거나 `사진 선택`으로 기존 사진을 가져올 수 있다.
  `사진 글자 읽기` → 인식한 이름 확인·수정 → `이 이름 사용` → 분류 확인 → 저장한다.
  OCR 이름 적용 시 뜻이 비어 있으면 같은 값으로 채우며 사용자가 수정할 수 있다.
- 저장하면 승인된 공용 카드로 등록된다. 특정 아동 선택·RFID 연결은 필요하지 않다.
- 저장 후 분류는 유지하고 나머지 입력을 비워 다음 카드를 등록할 수 있다.
- 다른 기기에서 이미 열어 둔 카드 목록은 새로고침 또는 재로그인이 필요하다.
- KAAC 등 외부 플랫폼에서 어떤 단어를 글자로 표시하는지는 자동 판정하지 않는다.
  글자·사진 사용 여부는 등록자가 결정하며 외부 이미지를 자동 수집하지 않는다.

<a id="admin-card-registration--저장-및-권한"></a>
#### 저장 및 권한

`POST /api/admin/cards`는 multipart의 `label`, `meaning`, `category`, `image`를 받는다.
글자 카드는 브라우저 Canvas로 만든 1024×1024 PNG를 전송한다. AI 이미지 생성이나
별도 이미지 업로드는 필요하지 않으며 기존 이미지 정규화·인쇄·오프라인 경로를 재사용한다.
글자 원문은 카드명·뜻으로도 보존한다. 별도의 글자 이미지 편집 기능은 포함하지 않는다.

- API와 서비스에서 `content_manage` 권한을 확인한다.
- 운영자 본인 소유의 공용 카드만 직접 승인 상태로 생성한다.
- 일반 사용자의 기존 공개 승인 요청·개인 카드 동의 절차는 변경하지 않는다.
- 공용 등록에는 아동 개인정보 동의를 요구하지 않는다. 이미지 쓰기 잠금·용량 한도·
  삭제 경합 검사는 유지한다. 이 경로에 연결 아동 ID를 받아 대신 저장하지 않는다.
- 별도 비밀번호 재입력 없이 현재 인증 세션의 운영 권한으로 등록한다.
  기존 승인·반려·비활성 등의 재인증 정책은 그대로 유지한다.
- 이미지 검사, 활성 분류 검사, 카드명 중복 검사, 표현 검토를 재사용한다.
- `published_directly`, 운영자 ID·승인 시각과 `shared_published` 감사 이력을 기록한다.
- 공개된 카드는 기존 승인 관리에서 비활성 처리할 수 있다.
- 사진에는 공용 사용이 가능한 이미지만 등록한다. 가족·아동 개인 사진은 개인 카드로 관리한다.

<a id="admin-card-registration--검증-기록--2026-11-04"></a>
#### 검증 기록 — 2026-11-04

<a id="card-camera-ocr--실물-카드-촬영과-ocr-등록"></a>
### 실물 카드 촬영과 OCR 등록

여러 장을 한 번에 촬영해 분리하는 후속 기능은
[여러 실물 카드 가져오기](CARD_MANAGEMENT.md#multi-card-scan)를 따른다. 아래는 개별 등록 흐름이다.

<a id="card-camera-ocr--사용자-흐름"></a>
#### 사용자 흐름

- 보호자: 아이 관리 → 개인 카드 관리 → 개인 카드 등록.
- 운영자: 공용 콘텐츠 운영 → 공용 카드 등록 → 사진 카드.
- `카드 촬영` 또는 `사진 선택` → 미리보기 → `사진 글자 읽기` → 이름 확인·수정
  → `이 이름 사용` → 뜻·분류 확인 → 저장.
- 촬영·OCR만으로 저장하지 않는다. 보호자의 등록은 선택 아동의 개인 카드로,
  운영자 등록은 명시적으로 모든 사용자에게 공개하는 공용 카드로 저장한다.
- 인식 결과를 적용할 때 비어 있는 뜻만 이름으로 채운다. 기존 뜻은 덮어쓰지 않는다.
- RFID가 없어도 디지털 카드로 사용할 수 있다. 칩 연결은 별도 작업이다.

<a id="card-camera-ocr--촬영-및-저장-범위"></a>
#### 촬영 및 저장 범위

- 카드 한 장과 그 아래 이름이 크게 보이도록 촬영한다.
- HTML 파일 입력의 `capture="environment"`를 사용한다. 모바일 OS·브라우저에 따라
  후면 카메라 또는 파일 선택 UI가 열리며 PC에서는 보통 파일 선택창을 사용한다.
  이 기능은 브라우저 실시간 카메라 스트리밍이나 자동 셔터가 아니다.
- 촬영 입력은 브라우저가 읽을 수 있는 20MB 이하 사진을 받아 JPEG로 변환한다.
  최대 3200만 화소, 긴 변 2048px 이하, 짧은 변 128px 이상, 결과 5MB 이하로 제한한다.
  지원되지 않는 형식은 오류를 표시하며 JPG·PNG 촬영/선택을 안내한다.
- 촬영 원본 대신 변환한 등록용 JPEG가 서버의 원본 보관 대상이 된다.
  기기 사진 보관함의 원본을 변경하거나 삭제하지 않는다.
- `사진 선택` 파일은 기존처럼 원본 바이트를 유지하고 JPG·PNG·WebP/5MB 제한을 적용한다.
- 파일명을 카드명으로 추정하지 않는다. 촬영 사진은 미리보기로 확인한다.
- OCR 실패·글자 없음이면 직접 이름을 입력해 저장할 수 있다.
- 개별 등록 창에는 자동 분류, 여러 카드 분리, 배경 제거, 원근 보정, 글자/그림 영역 자동 분리를 제공하지 않는다.
  이번 버전은 촬영한 카드 전체를 이미지로 등록한다. 인식률은 조명·기울기·글자 크기에 영향을 받는다.

<a id="card-camera-ocr--ocr-및-권한"></a>
#### OCR 및 권한

- 기존 `POST /api/cards/ocr`: `image`, `user_id` multipart.
  연결 아동의 카드 관리 권한과 보호자 동의를 기존대로 확인한다.
- 신규 `POST /api/admin/cards/ocr`: `image` multipart.
  `content_manage` 권한을 확인하며 아동 ID나 아동 동의 상태를 사용하지 않는다.
- 둘 다 기존 서버 로컬 Tesseract `kor+eng`을 재사용한다. 외부 OCR API를 호출하지 않는다.
  결과는 `suggested_label`, `candidates`이며 `Cache-Control: no-store`를 적용한다.
- 이미지 형식·크기 검증, 1회 동시 실행 제한, 20초 타임아웃과 임시 파일 정리를 유지한다.
  OCR은 사진·카드를 DB에 저장하지 않는다. 실제 저장은 확인 후 별도 등록 API로 수행한다.
- 촬영 처리 중 저장을 차단하며 사진 교체·화면 종료·대상 변경 후 늦은 OCR 결과를 버린다.
- 백엔드 Dockerfile에는 Tesseract와 한국어·영어 언어팩이 이미 포함돼 있다.
  도구 없음 오류가 나오면 `docker compose up -d --build backend`로 백엔드를 갱신한다.

<a id="card-camera-ocr--검증-기록--2026-11-04"></a>
#### 검증 기록 — 2026-11-04

- 로컬 프로덕션 빌드, Python 구문 검사와 FastAPI 앱 import, 공백 검사 통과.
  기존 500kB 초과 번들 경고는 남아 있다.
- Chrome 모의 API 검사 통과: 촬영 입력의 PNG를 JPEG 2048×1536으로 변환,
  파일명 자동 입력 없음, 관리자 OCR 이름 확인·빈 뜻 채우기·공용 저장 요청,
  보호자 대상 ID 전달·개인 저장 콜백의 이미지 전달, 390px 가로 넘침 없음.
- 한국어 TSV OCR 줄 조합, 실행 도구 없음(503), 시간 초과(504)를 모의 실행기로 확인했다.
  관리자 OCR API 정상(200)/no-store와 일반 사용자·보호자·무권한 담당자 차단(403)을
  TestClient에서 확인했다. 실제 계정·DB를 사용하거나 변경하지 않았다.
- 첫 브라우저 검사 시 검사 도구의 동적 문자열 안 정규식 이스케이프 오류가 있었다.
  두 차례 실패 후 검사 도구를 수정하고 전체 흐름을 재실행해 통과했다.
- 개발 서버에는 기존 public 음성 manifest import 경고가 출력됐다.
  이번 촬영/OCR 기능의 빌드는 통과했으며 해당 음성 경로는 변경하지 않았다.
- 실제 Tesseract 한국어 사진 인식률, 실제 모바일 카메라/HEIC/회전,
  실제 MongoDB 저장·아동 화면 재조회·TTS·RFID는 미실행이다.
  로컬 PATH에서 Tesseract를 찾지 못했고 Docker 실행 검증은 수행하지 않았다.
- 영구 자동 테스트 파일을 추가하지 않았다. 모의 검사 통과는 실제 인식률 보장이 아니다.

<a id="multi-card-scan--한-번-촬영한-여러-실물-카드-가져오기"></a>
### 한 번 촬영한 여러 실물 카드 가져오기

<a id="multi-card-scan--사용-방법"></a>
#### 사용 방법

- 보호자·담당자: 아이 관리 → 개인 카드 관리 → 실물 카드 한 번에 가져오기.
- 운영자: 공용 콘텐츠 운영 → 실물 카드 한 번에 가져오기.
- 카드들을 겹치지 않게 간격을 두고 펼쳐 한 번 촬영하거나 사진을 선택한다.
  흰 카드와 대비되는 바탕에서 카드 전체와 이름이 보이도록 촬영한다.
- 카드 영역 찾기 → 영역 확인·수정 → 분리하고 이름 읽기 → 그림·이름·뜻·분류 확인
  → 등록할 카드 선택 → 확인 체크 → 선택 카드 저장.
- 자동 영역은 추정이다. 못 찾은 카드는 영역 추가, 잘못 찾은 영역은 삭제하고,
  네 꼭짓점을 끌거나 좌표 입력으로 수정한다. 모서리는 왼쪽 위부터 시계 방향이다.
- 한 장도 같은 방식으로 처리한다. 경계를 찾지 못하면 영역을 직접 지정한다.
- 기본 범위는 한 사진당 최대 20장이다. 20개보다 많이 검출되면 잘림 안내를 표시한다.
  작거나 흐린 글자는 여러 장으로 나눠 더 크게 촬영하는 편이 낫다.
- 한 장씩 OCR 요청을 보내며 이름 인식은 자동 저장이 아닌 제안이다.
  OCR 도구가 없거나 실패해도 분리된 그림은 유지하고 이름·뜻을 직접 입력할 수 있다.
- 새 이미지 생성, 카드 안 그림만의 누끼, 배경의 의미 제거는 하지 않는다.
  기존 카드의 그림과 인쇄된 이름을 포함한 카드 전체를 유지한다.

<a id="multi-card-scan--저장과-오류-처리"></a>
#### 저장과 오류 처리

- 보호자는 선택한 아동의 개인 카드로 저장한다. 운영자는 공용 공개 권한을 확인한 후
  모두에게 공개한다. 일반 보호자의 사진을 공용으로 자동 이전하지 않는다.
- 공통 분류와 개별 분류를 지정할 수 있다. 이름·뜻·분류를 검토해야 저장할 수 있다.
- 기본 카드와 현재 등록 목록·선택 목록의 중복 이름을 표시한다.
  최종 중복·형식·권한·동의·이미지 검사는 기존 등록 API에서도 다시 수행한다.
- 기존 카드 등록 API를 한 장씩 호출한다. 전체 트랜잭션은 아니며 결과를 카드별로 표시한다.
- 성공한 카드는 다시 전송하지 않는다. 명확한 검증 실패만 수정 후 다시 저장할 수 있다.
- 통신·서버 오류로 저장 여부가 불분명하면 해당 카드를 잠그고 등록 목록 확인을 안내한다.
  등록 목록 갱신이 같은 카드의 저장 완료를 자동 확정하거나 재전송하지는 않는다.
- 영역 찾기·OCR은 중단할 수 있고 늦은 응답은 무시한다. 저장 중에는 중단 버튼을 숨긴다.
  화면을 떠나 이미 전송된 저장까지 취소할 수 있다고 가정하지 않는다.
- 저장 전 사진 교체나 영역 재편집은 확인 창을 거친다. 이미 저장된 카드를 삭제하지 않는다.
- 카드판 위치·기존 카드·RFID 연결은 자동 변경하지 않는다. 아이는 목록 새로고침 후
  새 카드를 사용할 수 있으며 RFID 연결은 별도 작업이다.

<a id="multi-card-scan--구현과-api"></a>
#### 구현과 API

`POST /api/cards/scan` multipart:

- `image`: 기존 업로드 규칙의 JPG·PNG·WebP, 5MiB 이하, 각 변 128~4096px.
- `scope`: `private`(기본) 또는 `shared`.
- `user_id`: 개인 카드 대상 아동. 보호자·담당자의 `cards_manage`와 보호자 동의를 확인한다.
- 공용은 `content_manage`를 확인하며 아동 ID나 아동 동의를 사용하지 않는다.
- `regions` 없음: `{regions: [{corners: [[x,y], ...4개]}], width, height, truncated}` 반환.
- `regions` 있음: 위 영역 배열을 JSON 문자열로 전달. `{cards: [{image: 'data:image/jpeg;base64,...'}]}` 반환.
- 좌표는 0~1 범위이며 최대 20개다. 볼록성·순서·최소 크기·너비높이비를 검사한다.
  잘못된 영역은 422, 도구 없음은 503, 다른 분리 요청 처리 중이면 429다.
- OpenCV의 윤곽선·사각형 근사로 후보를 찾고 중복 경계·큰 바깥 프레임 후보를 줄인다.
  원근 변환으로 카드 영역을 펴서 자른다. 검출은 글자·상징 의미를 이해하는 AI가 아니다.
- 정상화된 사진은 긴 변 2048px 이하, 분리 JPEG는 긴 변 1024px 이하·짧은 변 128px 이상이다.
  작은 영역을 확대하더라도 원본에 없는 글자 세부 정보가 복구되는 것은 아니다.
- OCR은 기존 로컬 한국어 Tesseract API를 카드별로 재사용한다. 외부 API 키가 필요 없다.
- 스캔 API는 사진·이미지·OCR·카드를 DB에 저장하지 않고 `Cache-Control: no-store`를 반환한다.
  브라우저 메모리의 사진·분리본은 해당 화면을 벗어나면 유지되지 않는다.
- 저장할 때만 분리 JPEG를 기존 카드 이미지 보관 정책으로 저장한다. 촬영한 전체 사진을
  서버에 원본으로 별도 보관하지 않는다. 원근 보정 이전으로의 서버 복원 기능은 없다.
- Apple 피사체 분리 API나 새 이미지 생성 API는 사용하지 않는다.

새 OpenCV 의존성을 추가했으므로 Docker에서는 백엔드를 다시 빌드한다.

```powershell
docker compose up -d --build backend
```

구현 참고: [OpenCV 원근 변환](https://docs.opencv.org/4.13.0/da/d54/group__imgproc__transform.html).

### 개인 카드 사진 교체

2026-10-23 B1-01 개발 단위. 연결 아동의 `cards_manage` 권한을 가진 보호자·담당자가
개인 카드 관리에서 카드별 **사진 교체**를 선택한다. 아동의 직접 수정·공유 카드·기본 카드
수정은 허용하지 않는다. 잠긴 핵심 카드의 교체는 409로 거절한다.
[핵심 잠금](../policies/CORE_CARD_LOCK_POLICY.md)의 설정 화면과 API를 후속 단위에서
연결했으며 기존 데이터에 자동 잠금을 지정하지 않는다.

<a id="private-card-photo-replacement--변경-범위와-보관"></a>
#### 변경 범위와 보관

카드 ID·카드명·뜻·분류·소유자·공개 범위·승인 상태·생성 시각을 유지한다. 원본·화면용
WebP·썸네일·안전성 결과만 교체하고 사진 버전을 증가시킨다. 보드 슬롯·빠른/복구 표현·
음성 설정·사용 기록은 수정하지 않는다. 새 썸네일 주소와 ETag로 이전 사진을 갱신한다.
지원 화면에서 이전 목록의 Blob URL도 해제한다. 다른 기기의 화면 강제 갱신은 아니다.

현재 DB 문서의 이전 사진은 덮어쓰며 사진 변경 이력을 별도 보관하지 않는다. 새 원본은
로컬 MongoDB에 실제 바이트 그대로 보관한다. 원본 촬영 정보는 API·안전성 전송·JSON
내보내기에 노출하지 않지만 DB·별도 백업에는 남을 수 있다. 기존 백업은
[로컬 이미지 저장 정책](IMAGE_STORAGE.md#local-image-storage)의 30일 보존·명시적 정리 대상이다.
교체가 백업 삭제를 대신하지 않는다. 개인정보 삭제의 백업 무효화 규칙은 유지한다.

<a id="private-card-photo-replacement--api와-충돌"></a>
#### API와 충돌

`PUT /api/cards/submissions/{id}/image` — 인증 multipart:

- `user_id`: 연결된 아동 ID(필수)
- `expected_revision`: 조회한 `image_revision`(필수, 0 이상)
- `image`: JPG·PNG·WebP 원본(필수, 기존 5MiB/해상도 제한)
- `image_edits`: 선택 JSON. 신규 등록과 같은 엄격한 보정 규격

응답은 기존 카드 등록 응답과 `image_revision`이다. 구버전 카드의 사진 버전은 0으로 읽는다.
현재 교체 화면은 보정을 지정하지 않으며 이전 사진의 자르기·회전 설정은 제거한다.
새 사진의 형식·동의·전체/선택 보정 프레임 안전성·원본/파생 저장량을 재검사한다.
같은 전역 이미지 쓰기 잠금 안에서 삭제 경쟁·연결 권한·핵심 잠금·사진 버전을 다시 확인하고
버전 조건부 갱신한다. 성공 감사에는 담당자와 이전/이후 버전만 남기며 사진 바이트나 원래
파일명은 넣지 않는다.

403 권한·공유 카드, 404 대상 없음, 409 버전/잠금/삭제 경쟁, 413 용량, 422 잘못된
이미지·차단, 503 DB 오류를 구분한다. DB 쓰기 후 감사 실패처럼 결과가 불명확할 수 있으므로
409·권한·네트워크·서버 오류 뒤에는 최신 목록을 확인해야 한다. 자동 재전송하지 않는다.
명확한 형식 거절 뒤에는 파일을 다시 선택할 수 있다. 사진 저장 성공 후 목록 갱신 실패도
업로드 재시도 대상으로 바꾸지 않는다. 세션·아동 전환 뒤 늦은 응답은 폐기한다.

아동 계정에 상황을 직접 만든다. 집·학교·치료실·외출·식사·병원을 이름으로 제안하되 실제
보드를 자동 생성하지 않는다. 초기 한도는 상황 6개와 기본 카드판 1개다. 실제 AAC 사용자에게
맞는 선택지 수·전환 방식 승인은 미실행이며 필요하면 현장 검수 후 한도를 조정한다.

<a id="situation-boards--지원자-관리"></a>
#### 지원자 관리

`board_manage` 권한으로 **빠른 표현·카드판 → 상황별 카드판**에서 관리한다.

- 생성: 저장된 기본 카드판의 슬롯을 미리 보고 새 이름과 복사 위치 확인 후 생성한다.
- 복사: 같은 아동의 기존 상황 ID를 골라 위치만 복사한다. 다른 아동·기관 계정 간 사진
  이전 기능은 아니다. 다른 기기에서는 해당 아동의 최신 구성을 조회해 같은 보드를 읽는다.
- 편집: 선택한 상황의 이름·슬롯만 변경한다. 기본 카드판과 다른 상황은 바꾸지 않는다.
- 삭제: 해당 상황 구성만 명시 확인 후 삭제한다. 카드·원본·음성·의사소통/학습 기록을
  삭제하지 않으며 기본 카드판 삭제는 허용하지 않는다.

상황 이름에 사람 이름·진단 등 개인정보를 넣지 않도록 안내한다. 중복 이름·빈 이름·제어
문자·최대 수 초과·사용 불가 카드·중복 슬롯을 거절한다. 각 보드는 1~30장이다.
[핵심 잠금](../policies/CORE_CARD_LOCK_POLICY.md)은 모든 상황에서 기본 카드판의 같은
슬롯 번호를 보호한다. 다른 위치의 상황이 있으면 새 잠금을 거절한다. 앱이 기존 상황을
강제로 정렬하지 않으며 먼저 해당 상황을 맞추거나 잠금 선택을 조정해야 한다.

<a id="situation-boards--아동의-전환과-오프라인"></a>
#### 아동의 전환과 오프라인

**그림으로 말하기 → 상황 카드판 바꾸기**에서 저장된 보드를 선택한다. 선택만으로 바꾸지
않고 위치 미리보기·확인 후 적용한다. 현재 상황을 표시하고 담아 둔 문장 카드·음성·빠른
표현·복구 표현·학습 범위는 유지한다. 검색·분류·페이지는 초기화해 새 보드의 시작 위치를
보여 준다. 의사소통의 **기록 상황**은 별도 선택이며 보드 이름으로 상황/의도를 추정하거나
자동 기록하지 않는다. 위치 변경 안내는 말하기를 막는 모달이 아니다.

전환은 현재 화면의 선택이며 서버 기본 슬롯·revision을 수정하지 않는다. 새 로그인이나
새로고침에서는 기본 카드판으로 시작한다. 이미 보고 있는 상황을 서버에서 수정/삭제하면
현재 화면의 선택 스냅샷을 자동 교체하지 않고, 최신 구성을 읽은 시점에 안내한 뒤 직접
재선택하도록 한다. 계정 변경·로그아웃·동의 철회·삭제 상태 확인 시 선택 스냅샷을 비운다.

기존 사용자별 IndexedDB 스냅샷의 `board_layout`에 저장된 상황을 같이 보관한다. 유효한
AAC 계정의 캐시가 있어야 오프라인 전환·새로고침 후 재선택할 수 있다. 신규 상황을 만들거나
지원자가 오프라인에서 편집하는 기능은 없다. 새 서버 변경은 재연결 조회 전에는 알 수 없고
다른 기기의 캐시를 원격으로 강제 삭제하지 않는다. 로그아웃·개인정보 삭제는 기존 계정별
캐시 삭제 경로를 따른다. 기본 발화의 기기 TTS 지원 한계는 기존 정책과 같다.

<a id="situation-boards--api저장과-권한"></a>
#### API·저장과 권한

`GET /api/board/layout`에 `situations: [{id,name,slots}]`, `situation_names`,
`max_situations`를 추가한다. 구버전 보드는 상황이 빈 목록이다.

`PUT /api/board/layout/situations?user_id=...`의 JSON:

| 작업 | 필수 필드(공통 expected_revision 포함) |
| --- | --- |
| create | operation, name — 저장된 기본 슬롯 복사 |
| copy | operation, name, source_id — 같은 아동의 상황 복사 |
| update | operation, situation_id, name, card_ids |
| delete | operation, situation_id |

불필요한 필드·외부 소유자 지정·기본 보드 삭제·클라이언트의 신규 ID 지정을 거절한다.
현재 연결 권한을 재검사하고 이미지/삭제 공유 잠금 안에서 최신 카드판과 삭제 상태를 읽는다.
기본·잠금·상황이 같은 revision을 사용한다. 같은 CAS 스냅샷에서 원본 복사와 잠금 검사를
마친 뒤 조건부 저장하고 `situation_create/copy/update/delete` 감사를 기록한다.
403 권한, 404 없는 원본/대상, 409 충돌·잠금·중복 이름, 422 형식·한도 오류를 구분한다.
응답 유실·서버 오류 뒤에는 최신 조회 없이 자동 재전송하지 않는다. 아동·세션·버전이
바뀌면 늦은 응답을 폐기한다. 현재 화면의 감사 목록은 다음 카드판 조회 때 갱신된다.

새 컬렉션 없이 `board_layouts.situations`에 같은 소유자의 카드 ID·위치를 저장한다.
이미지 바이트를 복사하지 않는다. 개인정보 삭제는 기존 보드 문서/감사 삭제와 함께 제거하고
기존 BSON 백업에도 같은 문서로 포함된다. 백업 보존/파기는 별도 정책이다.

## 보호자용 활동별 카드판 정리 추천

<a id="board-organization-suggestions--보호자용-활동별-카드판-정리-추천"></a>
### 보호자용 활동별 카드판 정리 추천

> 작업일: 2026-11-01
> 추천은 초안이며 보호자가 저장하기 전에는 아무 카드판도 변경하지 않는다.

<a id="board-organization-suggestions--사용-흐름"></a>
#### 사용 흐름

보호자 로그인 → 연결 아동 선택 → 마이페이지의 사용자·운영 설정 →
빠른 표현·카드판 → **자주 쓰는 카드로 카드판 추천**.

1. 사용 기록으로 카드판 추천 받기를 누른다.
2. 제안된 식사·간식 / 이동·외출 / 놀이 / 자주 쓰는 표현 중 후보를 고른다.
3. 이름·카드·슬롯 순서를 확인하고 필요하면 수정한다.
4. 확인란을 체크한 뒤 새 상황별 카드판으로 저장한다.
5. 저장된 상황 목록에서 확인한다. 기본 카드판과 기존 상황은 덮어쓰지 않는다.

공용 카테고리를 새로 만들거나 카드 자체의 분류를 바꾸는 기능은 아니다.
아동별 상황 카드판을 제안해 같은 카드를 활동별로 묶는 첫 구현이다.
아동 화면의 카드판 선택 방식·기존 빠른 표현·RFID·사진·발화 동작은 유지한다.
한 카드가 여러 활동 후보에 들어갈 수 있으며 사용 횟수만으로 자동 이동하지 않는다.

<a id="board-organization-suggestions--권한과-개인정보"></a>
#### 권한과 개인정보

- 보호자 역할(`caregiver`)만 추천을 조회한다. 아동·관리자·담당자 역할에는 제공하지 않는다.
- 연결된 해당 아동의 `records_read`와 `board_manage` 권한이 모두 필요하다.
- 기록 이용 동의가 없거나 삭제 진행·실패·완료 상태면 사용 기록을 조회하지 않는다.
- 기존 추천 설정의 끄기·숨긴 카드·승인 모드의 승인 카드 범위를 따른다.
- 결과를 만들고 나서 연결 권한·기록 동의·추천 설정 버전을 다시 확인한다.
- 이름·발화 원문·사진·모델 입력을 수집하지 않고 해당 아동의 카드 ID와 최소 근거만 읽는다.
- GET 결과는 `Cache-Control: no-store`이며 추천 조회 자체는 새 추천 기록을 DB에 저장하지 않는다.
- 계정·아동·카드판 버전·비활성 상태가 바뀌면 화면의 추천과 초안을 비운다.
  늦은 응답은 토큰과 화면 요청 범위를 확인해 무시한다.

<a id="board-organization-suggestions--추천-기준"></a>
#### 추천 기준

- 최근 30일의 성공한 `speech_result`, 또는 성공 상태가 있는 기존
  `immediate_speech`·`selection_speech` 이벤트를 최대 500개 읽는다.
- 실패·취소·단순 카드 선택·문장 생성만 된 기록·학습 시도 테이블은 추천 근거로 쓰지 않는다.
  단어 미리 듣기 등도 성공 발화 이벤트로 기록됐다면 포함될 수 있으며 실제 의도를 판단하지 않는다.
- 같은 `selection_id`의 반복 재생은 한 건으로 센다. 선택 ID가 없으면 이벤트 ID 기준으로 센다.
- 그룹별 최소 3건의 발화와 각각 2건 이상 등장한 서로 다른 카드 2종이 필요하다.
- 빈도 높은 카드 최대 12종을 먼저 후보로 고르고 실제 슬롯은 기존 상대 순서를 유지한다.
- 식사·간식: 식사로 표시했거나 먹다/마시다가 포함된 성공 발화.
- 이동·외출: 외출로 표시했거나 가다가 포함된 성공 발화.
- 놀이: 놀다가 포함된 성공 발화.
- 자주 쓰는 표현: 전체 표본에서 반복된 카드.
- 실제로 식사·외출·놀이를 했다는 추론은 하지 않는다. 후보명과 함께 근거를 표시한다.
- 같은 카드 순서의 상황판이 이미 있거나 앞 후보와 구성이 같으면 중복 제안을 생략한다.
- 표본 상한에 도달하면 화면에 표본 사용을 표시한다. 충분한 근거가 없으면 후보를 만들지 않는다.
- 핵심 잠금 카드가 있으면 마지막 잠금 위치까지의 기존 앞부분을 함께 유지한다.
  이때 포함된 카드는 반복 사용 후보와 구분해 표시한다. 잠금·추천 정책·30슬롯 한도를
  동시에 지킬 수 없으면 무리하게 재배치하지 않고 후보를 생략한다.

이는 설명 가능한 규칙 기반 추천이다. Ollama나 외부 AI를 호출하지 않으며
문장 생성 모델에 새 작업이나 대기열을 추가하지 않는다. 빈도는 선호·필요·언어 능력의 판정이 아니다.

<a id="board-organization-suggestions--api와-저장-경계"></a>
#### API와 저장 경계

```text
GET /api/board/layout/organization-suggestions?user_id=<연결된 아동 ID>
```

응답은 아동 ID·카드판 버전·추천 후보·카드별 근거 횟수·표본 안내를 포함한다.
자동 생성·자동 적용·공용 카테고리 수정 API는 추가하지 않는다.

저장은 기존 `PUT /api/board/layout/situations`의 `operation: create`를 사용하며
선택적인 `card_ids`를 허용하도록 확장했다. 생략하면 기존처럼 기본판 복사로 동작한다.
추천 후보를 눌러도 저장 요청은 보내지 않는다.

- 이름·카드·순서를 수정하면 확인 체크가 해제된다.
- 서버는 현재 사용 가능한 카드·중복 카드·이름·최대 6개 상황·30슬롯을 검사한다.
- 기존 `expected_revision` 충돌 검사, 핵심 잠금 위치 검사, 삭제 경쟁 잠금과 변경 감사 기록을 유지한다.
- 저장 충돌·불확실한 오류 후에는 최신 카드판 확인과 새 추천을 요구한다.
- 상황 만들기는 기록 조회 권한이 없어도 기존처럼 수동 관리 권한으로 사용할 수 있다.
  이는 개인 사용 기록 추천을 볼 권한을 추가로 부여하지 않는다.
- 자동 테스트·검증 파일·새 데이터 컬렉션·마이그레이션·이미지 변경은 추가하지 않는다.

<a id="board-organization-suggestions--검증-상태와-남은-확인"></a>
#### 검증 상태와 남은 확인

Python 3개 파일의 AST 구문과 JSX 2개·CSS 1개의 정적 구문 검사를 통과했다.
권한 분기·조회 전용 경로·슬롯 저장 경계를 소스로 확인했으며,
문서 링크·코드 블록과 `git diff --check`도 확인했다.
실제 DB·사용자 계정의 추천 생성·저장이나 자동 테스트·빌드·브라우저·실기기 검증은
사용자 요청에 따라 미실행이다. 구문 검사와 커밋을 권한·추천 품질 검증 완료로 취급하지 않는다.

수동 확인 항목:

<a id="caregiver-card-print-editor--보호자-a4-카드-편집기"></a>
### 보호자 A4 카드 편집기

<a id="caregiver-card-print-editor--사용-경로"></a>
#### 사용 경로

보호자 → 개인 카드 관리 → 아이 선택 → **A4 그림카드 만들기·인쇄**.
기존 `cards_manage` 연결 권한과 계정별 진입 조건을 유지한다.
OCR·다중 카드 자동 분리·RFID 순차 매핑은 이번 범위가 아니다.

<a id="caregiver-card-print-editor--편집-흐름"></a>
#### 편집 흐름

1. 새 사진·카메라 촬영 또는 등록된 개인 카드를 보관함에 추가한다.
   새 사진의 파일명을 이름·뜻으로 자동 입력하지 않는다. 보관함에는 이미지만 표시하고
   칸에 넣은 뒤 오른쪽에서 인쇄 이름을 입력한다. 등록된 개인 카드의 기존 이름은 유지한다.
2. 기본 A4 칸에 카드를 배치한다. 방향·크기·행열·여백 등 출력 설정은 프린트를 누른 뒤 조정한다.
3. 용지의 칸을 선택하고 보관함 카드를 누르거나 끌어 넣는다.
   보관함은 편집 박스 상단의 한 줄 이미지 목록이며 좌우 스크롤한다.
   사용 안내는 제목 옆 정보 아이콘을 눌렀을 때만 표시한다.
4. 칸 사이 드래그는 두 칸의 내용을 교환한다. 터치·키보드에서는 칸 선택 후
   보관함 카드 선택과 칸 비우기를 사용할 수 있다. 같은 카드를 여러 칸에 넣을 수 있다.
5. 오른쪽 설정에서 칸별 인쇄 이름·8~24pt 글자·그림 맞춤·1~2배 확대를 바꾼다.
   전체 보이기는 비율을 유지한다. 꽉 채우기와 확대는 일부 그림을 자를 수 있다.
6. 편집본을 다운로드하거나 프린트 버튼으로 설정 창을 연다.

<a id="caregiver-card-print-editor--용지와-배치-규칙"></a>
##### 용지와 배치 규칙

- 실제 A4 210×297mm 또는 297×210mm, 여백 5~20mm, 간격 0~10mm.
- 직접 구성은 최대 8열·10행이며 칸이 15mm 미만이거나 인쇄 영역을 벗어나면 거부한다.
  기본 양식은 정사각형이고 직접 구성은 용지의 가용 영역을 등분한 직사각형이다.
- 기본 4cm 세로 양식은 4열×6행 24칸, 최대 5쪽이다. 빈칸은 그대로 유지한다.
- 양식 변경 시 배치된 항목이 끝에서 잘리지 않도록 필요하면 쪽 수를 늘린다.
  5쪽을 넘기는 변경은 거부한다. 쪽 삭제는 마지막 쪽만 가능하며 내용이 있으면 확인한다.
- 빈칸 자동 채우기는 보관함 순서로 현재 빈칸만 채운다. 기존 칸을 덮어쓰지 않는다.
- 편집 화면의 배치·칸 속성은 최대 20단계 실행 취소/다시 실행을 지원한다.
  프린트 창의 용지 설정은 출력용 복사본에서만 변경하며 배치 이력에 넣지 않는다.
  보관함 이름/등록 상태 변경은 배치 이력 대상이 아니다.
  보관함 원본 제거와 편집본 불러오기는 배치 이력을 초기화한다.
- 30~100% 미리보기 배율은 편집 화면에만 적용하며 실제 인쇄 크기는 바꾸지 않는다.
  작은 화면에서는 보관함·용지·속성을 세로로 배치하고 용지 안에서 스크롤한다.

<a id="caregiver-card-print-editor--편집본-저장불러오기와-개인정보"></a>
#### 편집본 저장·불러오기와 개인정보

- **편집본 다운로드**는 `pecsmate-a4.json` 파일이다. 용지 설정·칸 배치·
  보관함 이미지 원본과 이름을 포함한다. PDF와 달리 다시 수정할 수 있다.
- 서버/DB/브라우저 영구 저장소에는 편집본을 자동 저장하지 않는다.
  화면을 떠나기 전에 다운로드해야 하며 개인 사진이 포함된 파일은 안전하게 보관한다.
- 최대 30MB, 보관함 60개 제한이다. 새 사진은 한 번에 20장, 장당 5MiB 이하의
  JPG·PNG·WebP를 허용한다. 촬영 파일도 같은 검사를 거친다.
- 불러오기는 형식·버전·선택 아이 ID·이미지 자료형·카드 식별값·배치/수치 범위를 검사한다.
  다른 아이의 파일·범위를 벗어난 배치·중복 식별값은 거부한다.
- 불러오기로 기존 편집을 교체하기 전 확인하며 실패 시 현재 편집을 유지한다.
  아이 계정 등록 체크는 항상 해제한다. 서버에 저장됐던 항목은 현재 등록 목록에 대조하고,
  확인되지 않으면 저장 여부 확인 필요로 표시해 자동 재등록을 막는다.
- 임시 이미지 URL은 원본 제거·편집본 교체·화면 이탈 때 회수한다.
  업로드/편집본 처리가 진행 중일 때는 배치와 인쇄 등 충돌하는 조작을 잠근다.

<a id="caregiver-card-print-editor--아이-계정-등록과-인쇄의-분리"></a>
#### 아이 계정 등록과 인쇄의 분리

- **보관함 카드 정보·아이 계정 등록**을 펼쳐 보관함 이름·뜻·분류를 수정한다.
- 전체 등록 체크를 켜고 카드별 등록 여부를 선택한 뒤 별도 저장 버튼을 눌러야 서버에 전송한다.
  인쇄만 하거나 편집본을 다운로드/불러오는 것은 아이 카드 등록이 아니다.
- 기존 제출/초안 활성화 API, 권한·동의·중복·용량·안전성 검사를 재사용한다.
  기존 카드 원본을 인쇄 편집으로 수정하거나 비활성/반려 카드를 재활성화하지 않는다.
- 이미 저장된 카드·불확실한 저장 결과는 자동 재전송하지 않는다. 부분 저장 결과를 표시한다.
- 칸의 이름·그림 확대·맞춤은 출력 전용이다. 아이 계정에는 보관함의 원래 사진과 등록 정보를 저장한다.
- 칸 비우기·보관함 제거는 서버 카드 삭제가 아니다. 카드 등록 후 아이 화면에서 다시 불러온다.
  고정 카드판이나 RFID 연결은 자동 변경하지 않는다.

<a id="caregiver-card-print-editor--인쇄"></a>
#### 인쇄

- **프린트 → 프린트 설정 → 프린트 → 브라우저 인쇄창** 순서다. 첫 버튼은 인쇄를 실행하지 않는다.
- 설정 창은 왼쪽 미리보기와 오른쪽 방향·4/5/6cm 크기·가로/세로 카드 수·이름 표시·단면/양면 선택으로 구성한다.
  여백·간격은 접힌 추가 항목에서 조정한다. 편집 화면에 같은 인쇄 설정을 반복하지 않는다.
  작은 화면에서는 세로로 쌓고 미리보기 내부를 스크롤한다.
- 설정 변경은 이번 출력용 복사본에만 적용한다. 취소·Escape로 닫아도 원본 배치와 편집본은 바뀌지 않는다.
  포커스는 설정 창 안에 두고 배경을 inert 처리하며 닫을 때 기존 포커스와 스크롤 상태를 복구한다.
- 양면은 각 용지의 앞면 그림 페이지 다음에 뒷면 이름 페이지를 생성한다.
  뒷면은 열 순서를 좌우 반전하고 용지 오른쪽에 정렬해 기본 정사각 양식의 남는 폭도 보정한다.
  이름 숨기기는 앞면에 적용하며 뒷면에는 카드 이름이 표시된다.
- 앱은 프린터 양면 옵션을 자동 설정하지 않는다. 브라우저 인쇄창에서 양면 인쇄 및
  세로는 긴 쪽/가로는 짧은 쪽 넘김을 직접 선택해야 한다. 프린터별 지원·종이 급지·정렬 검수는 남아 있다.
- 동일 출처 iframe에 버튼·설정 없는 출력용 용지만 렌더링한다. 사용자 문구는 React 텍스트로 처리한다.
- 그림 디코딩과 글꼴 준비 후 인쇄 창을 연다. 페이지 규칙에 A4 방향과 0 여백을 설정하고
  용지 안쪽 여백은 편집 설정으로 적용한다. 빈칸의 편집용 점선·선택 윤곽은 출력하지 않는다.
- 브라우저에서 A4, 설정한 방향, 배율 100%, 여백 없음, 머리글/바닥글 끄기를 확인한다.
  실제 프린터 크기·여백 지원과 PDF 페이지 수는 별도 확인이 필요하다.

  실제 다운로드 위치·실제 인쇄창/PDF/프린터 실측 검수는 미실행이다.
- 실제 보호자 로그인·아이 등록 API·권한 회수·모바일 촬영/터치·전체 접근성·
  네트워크 오류·모든 비정상 파일 회귀 검수는 미실행이다. 배포 승인으로 간주하지 않는다.

<a id="caregiver-card-print-editor--프린트-설정-창-추가-검증"></a>
##### 프린트 설정 창 추가 검증

  첫 프린트 클릭 시 인쇄 호출 없음, 설정 창/배경 inert, Escape 취소 및 배경 복구를 확인했다.
- 방향을 세로로 바꾸고 가로 카드 수 3·이름 숨김·양면을 선택했다.

  세로 용지 규칙을 확인했다. 프린트 확정 시 대체 인쇄 함수 1회 호출을 확인했다.
- 설정 후에도 원래 편집 화면의 가로 A4 배치가 유지됐다. 390px 화면에서 문서 전체 가로 넘침 없음.
- 일회성 Node 검사로 두 쪽 뒷면의 열 반전·빈칸 보존·재반전 복원을 확인했다.
- 실제 인쇄창/PDF·프린터 양면·앞뒷면 정렬·자동 급지와 전체 보조공학 검수는 미실행이다.

<a id="caregiver-card-print-editor--파일명-자동-입력-제거"></a>
##### 파일명 자동 입력 제거

- A4 새 사진/촬영만 이름·뜻을 빈 값으로 시작한다. 일반 카드 일괄 등록의 파일명 규칙은 변경하지 않는다.
- 보관함에서 이름과 ‘이름 없음’ 표시를 제거하고 이미지와 접근성 이름만 제공한다.
- 이름을 입력하지 않은 칸은 앞면에 빈 이름 영역을 만들지 않는다. 오른쪽 인쇄 이름은 칸별이며,
  아이 계정 등록에 필요한 보관함 이름·뜻·분류는 기존 등록 영역에서 별도로 입력한다.
- 프런트엔드 빌드·공백 검사 통과. 기존 청크 크기 경고는 유지된다.
- 격리 Chrome에 임의 파일명의 합성 PNG를 넣어 보관함 이미지 전용 표시·접근성 이름·
  칸 이름 초기 빈 값·빈 이름 영역 없음·오른쪽에서 수동 입력 반영을 확인했다.
  실제 계정·DB는 사용하지 않았다. 실제 인쇄·아이 등록 API 검수는 미실행이다.

<a id="caregiver-card-print-editor--인쇄-설정-통합과-가져오기-도구-간소화"></a>
##### 인쇄 설정 통합과 가져오기 도구 간소화

- 사진 추가·촬영·등록 카드 가져오기·편집본 열기·다운로드를 44px 아이콘 버튼으로 제공한다.
  공통 UiIcon 선 아이콘을 사용하고 각 버튼에 접근성 이름과 title을 붙인다.
- 파일 입력은 숨기고 직접 클릭한 아이콘으로만 연다. 등록 카드 선택 목록은 아이콘을 누를 때만 펼친다.
  펼치면 선택 목록으로 포커스를 옮기며 Escape로 닫고 원래 버튼으로 복귀한다.
  기존 진행 중 잠금·권한/오프라인 차단·파일 검사는 유지한다.
- 편집 화면의 용지 설정은 제거하고 배치 실행 취소/다시 실행만 아이콘으로 유지한다.
  인쇄 크기·여백·간격은 프린트 창으로 옮긴다. 칸별 이름·그림 편집은 오른쪽에 유지한다.
- 프런트엔드 빌드·변경분 공백 검사 통과. 기존 청크 크기 경고 유지.
- 격리 Chrome/합성 사진으로 아이콘 5개·이름·이미지 전용 보관함·설정 중복 제거·
  등록 카드 펼침/포커스/Escape 복귀·다운로드 동작·5cm 3×5 배치·15mm 여백 반영·
  취소 후 원본 10mm 여백 유지·390px 전체 가로 넘침 없음을 확인했다.
- 실제 파일 선택창·촬영·서버 카드 조회/등록·인쇄창/PDF·프린터와 전체 접근성 검수는 미실행이다.

<a id="caregiver-card-print-editor--상단-가로-보관함과-통합-도구-줄"></a>
##### 상단 가로 보관함과 통합 도구 줄

- 실행 취소/다시 실행을 사진·카드·편집본 아이콘과 같은 도구 줄로 합쳤다.
  도구는 줄바꿈하지 않으며 작은 화면에서는 도구 줄 안에서 좌우 스크롤한다.
- 보관함은 편집 박스 전체 너비의 상단에 한 줄로 표시한다. 썸네일은 일정 크기로 유지하고
  보관함 안에서 좌우 스크롤하며 아래에는 용지와 선택한 칸의 속성을 배치한다.
- 정보 아이콘은 클릭·터치·키보드로 안내를 토글한다. aria-expanded/controls/describedby를
  제공하며 Escape로 닫고 정보 버튼으로 포커스를 돌린다. hover만으로 안내를 제공하지 않는다.
- 배치·드래그·이력·빈칸 채우기와 기존 등록/인쇄 기능은 유지한다.
- 프런트엔드 빌드와 변경분 공백 검사 통과. 기존 청크 크기 경고는 유지된다.
- 격리 Chrome에서 합성 PNG 16장으로 도구 7개 한 줄·보관함 한 줄/가로 넘침·
  보관함이 용지 위에 위치함·초기 안내 숨김·클릭 열기/Escape 닫기·포커스 복귀·
  실행 취소/다시 실행을 확인했다. 390px/320px에서도 두 줄이 각각 한 줄을 유지하고,
  보관함 좌우 스크롤이 가능하며 문서 전체 가로 넘침은 없었다.
- 최초 검수 스크립트의 중첩 문자열 구문 오류를 수정하고 재실행한 결과다.
  실제 계정·DB·장치는 사용하지 않았으며 영구 테스트 파일은 추가하지 않았다.
- 실제 터치 제스처·스크린리더·사진 촬영·아이 등록 API·PDF/프린터 검수는 미실행이다.

<a id="caregiver-card-print-editor--사진-글자-인식으로-이름-제안"></a>
##### 사진 글자 인식으로 이름 제안

- 보호자/지원자의 새 카드 등록창에서 사진을 선택하면 `사진 글자 읽기`를 사용할 수 있다.
  A4 편집기에서는 직접 추가한 사진을 칸에 배치한 뒤 같은 기능을 사용한다.
  기존 등록 카드나 아동 화면에는 별도 OCR 도구를 추가하지 않는다.
- 사진은 현재 백엔드로 전송하여 한국어·영어 글자를 읽는다. 외부 OCR 서비스는
  사용하지 않으며 처리용 임시 파일만 만들고 제거한다. 동의·연결 권한은 서버에서 확인한다.
- 인식한 이름을 수정하고 `이 이름 사용`을 눌러야 적용한다. 기존 입력을 자동 덮어쓰지 않는다.
  A4에서는 선택한 칸의 인쇄 이름만 바뀌며 원본 보관함 이름·카드 뜻·아이 계정 등록은
  변경하지 않는다. 사진/대상 사용자 변경·닫기 이후 도착한 결과는 적용하지 않는다.
- 한 장의 사진 속 글자 인식만 지원한다. 여러 카드 자동 분리·일괄 등록·RFID 자동 매핑은
  포함하지 않는다. 사진 속 글자가 없으면 이름을 직접 입력한다.
- 한국어·영어 언어팩을 포함한 Docker 백엔드 빌드와 프런트엔드 빌드 통과.
  기존 500kB 초과 JS 청크 경고는 남아 있다.
- 일회성 컨테이너에서 합성 이미지의 `사과`, `APPLE` 단독 인식 성공.
  첫 혼합 언어 이미지의 `Apple`은 `40016`으로 오인식하여 정확 일치 검사가 실패했다.
  모든 글꼴·촬영 조건의 정확도를 보장하지 않으므로 결과 확인 절차를 유지한다.
- 빈 사진·잘못된 MIME/내용/초과 용량, 도구 없음·타임아웃·엔진 실패·동시 요청과
  일반 계정·연결 권한·동의 거부 경로를 직접 호출/모의 검사했다. 실제 DB는 사용하지 않았다.
- 격리 Chrome의 모의 응답으로 자동 적용 없음·명시적 이름 적용·대상 변경 후 늦은
  응답 무시를 확인했다. 첫 검사는 종료된 Chrome 디버깅 포트로 실패했으며 재실행 후 통과했다.
- 실제 보호자 계정의 업로드 API 왕복, 실제 카드 촬영 사진, iPad 터치·음성 재생,
  전체 접근성·프린터 검수는 미실행이다. 영구 테스트 도구는 추가하지 않았다.
- 실행 중인 컨테이너는 검증 과정에서 재생성하지 않았다. 도구 적용 시 기존 실행에 쓴
  Compose 파일을 그대로 사용하여 백엔드를 다시 올린다. 기본 개발 구성은
  `docker compose up -d --build backend`, 태블릿 구성은
  `docker compose -f compose.yaml -f compose.tablet.yaml up -d --build backend`다.

<a id="a4-card-sharing--보호자-a4-카드판-공유"></a>
### 보호자 A4 카드판 공유

<a id="a4-card-sharing--사용-흐름"></a>
#### 사용 흐름

- 보호자 홈의 `함께 만드는 그림 카드판`: 둘러보기·내 보관함·새 카드판 만들기를 제공한다.
  아이 연결 전에도 이용할 수 있고 기존 아이 관리 기능은 유지한다.
- A4 편집기의 `편집본 저장·공유` 아이콘에서 모든 쪽의 미리보기와 제목·주제·설명을 확인한다.
  프린트 설정 창의 같은 아이콘은 현재 미리보기의 방향·행열·이름 표시·양면 구성을 그대로 사용한다.
  기본은 비공개 새 편집본 저장이다. 아이 계정 사용 체크박스와 전체 공유는 별개다.
- 공개에는 공유 승인 요청, 이미지 권리 확인, 개인정보 확인을 명시적으로 선택해야 한다.
  다른 보호자의 복사·수정·재공유·인쇄와 이미 만든 사본의 회수 불가를 안내한다.
- 기존 콘텐츠 운영 담당자의 카드 승인 화면 상단에서 공유 요청·신고를 검토한다.
  승인 전에는 작성자와 운영 담당자만 볼 수 있다. 자기 승인은 금지하며 반려·중단·신고 처리에는 사유가 필요하다.
- 다른 보호자는 상세 A4 미리보기를 보고 독립 비공개 사본을 복사해 편집·인쇄한다.
  아이의 디지털 카드로 자동 등록하지 않으며 원본을 수정하지 않는다.
- 편집 중인 변경은 새 편집본으로 저장해야 서버에 남는다. 덮어쓰기·자동 저장·댓글·채팅은 MVP에서 제외한다.
- 본인 공유는 중단할 수 있고 비공개/반려/중단 편집본은 삭제할 수 있다. 공개·대기 자료는 먼저 중단한다.
  삭제는 되돌릴 수 없으며 다른 보호자의 사본은 남는다.

<a id="a4-card-sharing--데이터와-경계"></a>
#### 데이터와 경계

- 실제 배치된 카드·보이는 인쇄 문구·용지·칸 설정만 저장한다. 배치하지 않은 사진, 원본 보관함 이름,
  숨긴 문구, 아이 ID, 개인 카드 내부 ID, 뜻·분류·원본 파일명은 전송하지 않는다.
  단 양면 인쇄의 뒷면에 표시되는 이름은 보이는 문구이므로 포함한다.
  서버 스키마도 추가 필드를 거부한다.
- JPG/PNG/WebP의 서명·크기·해상도·디코딩을 검사하고 최대 768px WebP 사본으로 정규화한다.
  EXIF 등을 제거하지만 사진 픽셀 안의 얼굴·이름·민감성은 자동 보증하지 않는다. 보호자 확인과 수동 승인이 필요하다.
  기존 개인 카드 원본 보관 정책은 바꾸지 않는다.
- 상세는 기존 브라우저 A4 렌더러로 모든 쪽을 보여 준다. 목록은 첫 쪽의 작은 참고 썸네일이며
  글꼴·줄바꿈은 실제 인쇄와 다를 수 있다. 인쇄 설정은 기존 프린트 창에서 한다.
- 로그인한 보호자 또는 기존 콘텐츠 운영 권한 담당자 전용이다. 아동·일반 지원 담당자·비로그인은 이용할 수 없다.
  공개 작성자의 실명·계정 ID·아이 연결 정보는 목록/상세에 제공하지 않는다.
- 계정당 활성 편집본 100개, 요청 12MiB, 처리 후 프로젝트 8MiB, 카드 원본 60개·A4 최대 5쪽이다.
  양면은 최대 10면이며 기존 이미지 사용자/전체 저장 한도에도 포함한다.
  저장·복사는 요청 UUID로 중복 생성을 막고 상태 변경은 버전을 확인한다.
- 보관함 삭제 시 사진·제목·설명·출처를 제거하고 최소 요청 식별/중복 방지 표식만 남긴다.
  전체 이용 데이터 삭제 시 이 표식도 삭제한다. 지연된 동일 저장 요청으로 사진이 되살아나지 않는다.
- 개인정보 내보내기에 본인 카드판 메타데이터·신고를, 전체 이용 데이터 삭제에 본인 카드판·신고를 포함한다.
  이미지 저장 잠금·삭제 경합 검사에 참여한다. 다른 보호자의 독립 사본, 이미 시작한 복사·다운로드,
  이미 열린 화면·파일은 회수할 수 없다.
- 공개 목록은 최신순·제목 검색·주제 필터·12개 페이지다. 신고는 계정/카드판별 한 번 접수한다.
- 소프트웨어가 적법한 공개·재이용 권한을 대신 확인하지 않는다. 공개 운영 전 이용 정책·이미지 권리·
  개인정보 처리 절차는 별도 검토가 필요하다.

<a id="a4-card-sharing--api"></a>
#### API

| 메서드 | 경로 | 범위 |
|---|---|---|
| GET | `/api/a4/projects?scope=discover/mine/review&topic=&q=&offset=0` | 공개/본인/운영 검토 목록 |
| POST | `/api/a4/projects` | 비공개 저장 또는 명시적 승인 요청 |
| GET | `/api/a4/projects/{id}` | 권한 확인 후 편집 가능한 사본 |
| POST | `/api/a4/projects/{id}/copy` | 승인 자료를 본인 보관함에 독립 복사 |
| POST | `/api/a4/projects/{id}/withdraw` | 본인 공유 중단 |
| POST | `/api/a4/projects/{id}/review` | 운영 승인·반려·중단·신고 검토 완료 |
| POST | `/api/a4/projects/{id}/report` | 다른 보호자의 공개 자료 신고 |
| DELETE | `/api/a4/projects/{id}` | 본인 비공개/반려/중단 자료 삭제 |

응답은 `no-store`이며 상세의 사본 이미지는 인증 JSON에 포함한다. 별도 공개 이미지 URL은 만들지 않는다.
내부 컬렉션은 `a4_projects`, `a4_reports`다. 기존 카드 승인·아동 연결 권한은 변경하지 않는다.

<a id="a4-card-sharing--검증-기록"></a>
#### 검증 기록

<a id="a4-card-sharing--검색과-페이지-이동-단순화"></a>
##### 검색과 페이지 이동 단순화

- 상위 화면 제목과 겹치는 ‘의사소통판’ 제목·소개를 없애고 검색을 목록 맨 위로 옮겼다.
  검색 입력란의 안내는 placeholder로, 주제는 선택 상자만 표시하고 실행 버튼은 돋보기로 바꿨다.
  보이지 않는 접근성 이름은 입력·선택·아이콘 버튼에 유지한다.
- 페이지 이동은 테두리 없는 좌우 화살표와 최대 다섯 개 숫자로 표시한다.
  현재 페이지는 밑줄과 접근성 속성으로 구분하며 전체 개수는 목록과 같은 권한·검색 조건으로 센다.
  검색·주제·보관함 변경 시 첫 페이지로 돌아간다. 선택된 목록 버튼의 글자 대비도 복구했다.
- 검증: 프런트엔드 빌드·백엔드 문법·`git diff --check` 통과. 모의 DB로 공개/개인 범위와
  주제·검색어 조건이 전체 개수에도 유지됨을 확인했다. 격리 Chrome/모의 API에서
  숫자 이동·끝 화살표 비활성·돋보기 검색 후 첫 페이지·1440/768/320px 가로 넘침 없음,
  박스 없는 버튼·기존 상세/복사/편집/공유 흐름을 확인했다.
  기존 큰 JS 청크 경고 유지. 실제 DB 전체 왕복·iPad·스크린리더 검수는 미실행이다.

<a id="a4-card-sharing--보호자-홈과-아이-관리-분리"></a>
##### 보호자 홈과 아이 관리 분리

- 사이드바 후속 수정: 상위 두 메뉴의 너비와 행 높이를 통일하고 시작 위치를 고정했다.
  사이드바 전체 대신 상세 메뉴만 스크롤하며 프로필·로그아웃은 하단에 유지한다.
  보호자 이름과 설정 아이콘은 한 줄로 배치하고 긴 이름은 말줄임 처리한다.
  데스크톱 너비는 256px로 조정하고 작은 화면은 기존 서랍 너비를 유지한다.
- 고정 배치 검증: 빌드와 `git diff --check` 통과. 격리 Chrome/모의 전체 권한 계정으로
  1440×700·390×700·320×568에서 홈/관리 전환 전후 상위 메뉴·프로필 좌표 동일,
  이름 줄바꿈 없음, 사이드바 전체 넘침 없음, 상세 스크롤 시 상위 메뉴 유지 확인.
  기존 큰 JS 청크 경고 유지. 실제 iPad 터치·스크린리더 검수는 미실행이다.

- 후속 UX 수정: 아이 관리로 들어가면 주 메뉴 아래 여섯 상세 항목을 권한 범위에 맞게
  펼친다. 상세 화면에서도 유지하여 관리 첫 화면으로 돌아가지 않고 바로 이동할 수 있다.
  선택한 항목은 현재 페이지로 표시하며, 홈에서는 하위 목록을 숨긴다.
  작은 화면에서는 아이 관리 클릭 직후 메뉴를 닫지 않아 상세 항목을 바로 고를 수 있다.
- 후속 검증: 프런트엔드 빌드와 `git diff --check` 통과. 격리 Chrome/모의 API로
  단일 권한 및 전체 여섯 항목, 상세 직접 이동·선택 표시·홈 복귀,
  390px에서 펼침 후 메뉴 유지 확인. 전체 권한 첫 검사는 연습 제안의 모의 403이
  권한 회수 처리를 유발해 실패했고, 권한 오류가 아닌 모의 503으로 수정 후 재검사 통과했다.
  실제 iPad·스크린리더·실계정 왕복은 미실행이다.

- 보호자 홈에는 공유 갤러리와 카드판 만들기·보관함만 표시한다. 아이 선택·연결 안내,
  개인 카드·연습·기록·음성·카드판·기기 관리는 별도 ‘아이 관리’ 화면에 모았다.
- 보호자 주 메뉴는 홈과 아이 관리로 단순화한다. 담당자 메뉴는 변경하지 않으며,
  관리 기능의 기존 아이별 권한 확인과 저장하지 않은 설정의 이동 확인을 유지한다.
- 프런트엔드 빌드와 `git diff --check` 통과. 기존 큰 JS 청크 경고 유지.
- 격리 Chrome/모의 API로 홈에는 공유만 표시, 관리 화면 이동, 권한별 메뉴,

  첫 검사는 합성 계정의 프로필 누락으로 초기 프로필 화면에 머물러 실패했으며,

##### 미리보기 중심 갤러리 정리

- 가운데 제목과 짧은 소개, 큰 미리보기, 제목·주제·쪽수·카드 수·등록일 순서로 정리했다.
  작성자 이름이나 계정 식별값은 공개하지 않는다. 등록일은 서버가 제공한 날짜를 표시한다.
- 데스크톱 3열, 태블릿 2열, 작은 화면 1열로 배치한다. 미리보기 영역은 4:3으로 통일하되
  세로형 A4와 카드 이미지 자체는 자르거나 늘리지 않는다. 보관함·검토 상태는 별도 표시한다.
- 격리 Chrome/모의 API로 1440·768·320px 열 수, 긴 제목의 동일 높이,
  가로 넘침 없음, 이미지 비율 보존, 등록일 표시와 상세 → 복사 → 편집 → 공유 흐름을 확인했다.
  첫 비율 검사는 이미지 고유 크기로 영역이 늘어나 실패했으며, 이미지 배치 수정 후 재검사 통과했다.
- 프런트엔드 빌드와 `git diff --check` 통과. 기존 큰 JS 청크 경고는 유지된다.
  실제 iPad 터치·스크린리더·프린터와 실제 계정 전체 왕복은 이번 UI 작업에서 미실행이다.
