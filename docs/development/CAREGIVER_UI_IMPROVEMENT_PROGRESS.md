# 보호자 UI 개선 진행 기록

기준: `docs/planning/CAREGIVER_UI_IMPROVEMENT_PLAN.md`. 과거 PDF 구현 기록은 유지한다.
코드 구현·브라우저 확인·실제 보호자/기기 검수를 구분한다.

## 1단계 — 공통 가독성과 표면

- 실제 로컬 앱을 분리된 임시 Chrome 프로필로 열고 기존 보호자 계정으로 확인했다.
  변경 전 홈·카드·설정을 1440/1024/768/390px에서 임시 캡처했다.
  기본 권한의 브라우저 경로 조회는 제한됐지만 승인된 로컬 실행으로 확인했다.
- 본문·입력 16px, 보조 14px, 제목 24~28px와 영역 제목 20px을 출발점으로 적용했다.
  작은 프로필 설명·권한 안내·필터 글자를 키웠다.
- 민트색 바깥 홈 패널과 반복 그림자·큰 모서리를 줄이고 선·여백으로 구분한다.
  모바일 작업 카드를 목록형으로 바꾸고 보호자 전용 범위를 유지했다.
- 검증: 변경 전 3개 화면·4개 폭 캡처에서 페이지 가로 넘침 없음.
  변경 후 홈 1440/390px에서 설명 14px·버튼 글자 16px와 넘침 없음을 확인했다.
  JSX 6개·CSS 정적 구문과 공백 검사를 통과했다. 전체 빌드는 4단계에서 수행한다.
- 실제 보호자 과업·실물 USB·음성 검증은 미실행이며 전체 완료로 표시하지 않는다.

## 2단계 — 홈과 아이 선택

- 보호자 전용 홈을 분리해 아이 선택 → 현재 관리 대상/연결 상태 → 주요 작업
  3개 → 연습 제안 → 보조 관리 목록으로 정리했다. 권한별로 항목을 필터링한다.
- 지원 메모 안내 카드는 제거하고 기록 보기 설명에 포함했다. 홈에 없는 통계를
  임의로 0이나 점수로 표시하지 않는다. 추천의 동의·기록 없음·오류 상태는 유지한다.
- 연결 없음에는 아이 계정의 프로필/보호자 설정에서 연결하는 실제 절차와
  보호자 아이디를 안내한다. 새 연결 API나 권한 자동 부여는 추가하지 않는다.
- 실제 계정 홈을 1440/1024/768/390px에서 캡처했고 주요 작업 3개·보조 3개,
  페이지 가로 넘침 없음을 확인했다. JSX 7개·CSS 구문과 공백 검사 통과.
- 실제 복수 아이·무권한·연결 없는 계정 검수와 실기기·보호자 과업은 미실행이다.
  해당 분기의 코드와 기존 권한 조건을 대조했으며 실제 검수 완료로 간주하지 않는다.

## 3단계 — 카드와 연습 관리

- 개인 카드 검색·분류, 로딩/검색 결과 없음/카드 없음 구분을 제공한다.
  등록·일괄 등록 성공 안내에 대상 아이와 카드명을 표시하고 등록 항목 보기와
  카드판 관리 이동을 제공한다. 카드판 위치는 자동 변경하지 않는다.
- 카드 등록 응답은 계정·토큰·아이 대상이 그대로일 때만 화면에 적용한다.
  아이 변경 시 검색과 등록 안내를 초기화한다.
- 보호자 메뉴를 연습 관리로 바꾸고 제안에 활동·카드·문제 수·짧은 근거와
  검토 동작을 먼저 표시한다. 표본·출처는 상세로 옮기고 개인화 상태는 남긴다.
- 준비한 연습과 의견은 실제 완료를 뜻하지 않음을 명시한다. 과거 의견의
  내부 후보 ID 대신 활동명·날짜 또는 중립적인 ‘이전에 준비한 연습’을 표시한다.
  기존 API만 사용하며 과거 후보명을 얻기 위한 API 확장은 추가하지 않았다.
- 실제 계정에서 제안 3개와 출처 기본 접힘·검토 열기, 카드 검색 UI,
  카드 화면 1440/390px 캡처와 가로 넘침 없음을 확인했다.
  JSX·CSS 정적 구문과 공백 검사를 통과했다.
- 실제 카드 생성·수정·인쇄와 연습 준비·의견 저장은 실제 데이터를 바꾸므로
  이번 화면 확인에서는 수행하지 않았다. 부분 실패·복수 아이 전환도 미검수다.
