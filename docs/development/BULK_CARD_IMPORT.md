# B1-01 개인 카드 사진 일괄 등록

2026-10-23 첫 개발 단위. 보호자·담당자가 `cards_manage` 권한을 가진 연결 아동의
**개인 카드 관리 → 사진 일괄 등록**에서 사용한다. 공용 카드 일괄 승인 기능은 아니다.

## 등록 흐름

1. JPG·PNG·WebP 사진을 최대 20장 선택한다. 파일당 비어 있지 않은 5MiB 이하만 허용한다.
2. 확장자를 제외한 파일명에서 밑줄을 공백으로 바꿔 카드명과 뜻을 제안한다.
   예: `검증_연필.png` → `검증 연필`. 서버의 이름 규격에 맞지 않으면 저장 전에 수정한다.
3. 공통 카테고리를 미등록 항목에 적용하거나 카드별로 이름·뜻·카테고리를 수정한다.
4. 필요하면 사진별 중앙 정사각형 자르기·오른쪽 90도 회전·밝기 조절을 선택한다.
   기본값은 보정 없음이며 초기화로 원래 보정 설정으로 돌아간다.
5. 미리보기와 중복 후보를 확인하고 등록 가능한 항목을 저장한다.
6. 항목별 저장 완료·등록 실패·저장 여부 확인 필요·권한 확인 필요를 구분한다.

중복 후보는 같은 선택 안과 현재 아동의 등록 카드 이름을 NFKC 정규화·공백 제거로 비교한다.
반려된 카드 이름은 제외한다. 이미지 유사도 검사나 다른 아동의 개인 카드 조회는 하지 않는다.
공용 기본 카드명과 동시 등록 중복 등은 기존 서버의 최종 검사가 판단한다.

클라이언트 파일 형식·용량 검사는 사전 안내일 뿐이다. 해상도 128~4096px·실제 MIME·
시그니처·안전성·동의·권한·중복·저장 한도는 서버에서 다시 검사한다.
클라이언트는 이미지를 가공하지 않고 선택한 원본과 선택 보정 설정을 기존 multipart API로 전송하며
[로컬 원본·파생 이미지 정책](LOCAL_IMAGE_STORAGE.md)을 그대로 적용한다.

## 선택형 사진 보정

사진별 설정은 `crop: none|square`, `rotation: 0|90|180|270`, `brightness: 50~150`이다.
밝기는 정수 백분율이며 화면 조절 단위는 5%, 기본은 100%다. 중앙 자동 자르기는 짧은 변을
기준으로 중앙 정사각형을 만드는 규칙이다. 카드 경계·얼굴·텍스트를 인식하는 AI 자동 검출,
원근 보정·임의 영역 선택·의도 추정 기능은 아니다. 글자나 그림이 잘릴 수 있어 기본은 끔이다.

미리보기는 원본 blob에 CSS 자르기·회전·밝기를 표시한다. 최종 저장은 서버가 처리하므로
인코딩·색상·가장자리의 완전한 픽셀 일치까지 보장하지 않는다. 초기화는 보정만 되돌리고
이름·뜻·분류·선택한 파일을 지우지 않는다. 저장 완료·저장 여부 확인 필요 항목은 보정도 잠근다.

서버는 최대 256자의 JSON 객체만 받으며 추가 필드·임의 회전·실수·문자열·불리언 수치를
거절한다. 원본 검증과 EXIF 방향 적용 → 시계 방향 회전 → 중앙 자르기 → 최대 1280px 축소 →
밝기 보정 → 메타데이터 제거 WebP → 최대 256px 썸네일 순서다. 투명도는 보존한다.
밝기 계산 버퍼는 축소한 화면용 크기로 제한한다. 실제 원본 바이트·MIME·크기·SHA-256은
바꾸지 않는다. 보정 설정과 `card-image-edit-v1` 버전은 해당 신규 카드 문서의 `image_edits`에
보관하며 DB/백업 삭제는 기존 카드 문서와 함께 처리한다. 별도 이미지 이력을 쌓지 않는다.

잘라낼 부분의 유해성을 숨기고 원본을 보관하지 못하도록, 보정 전 전체 프레임의 정규화 WebP를
먼저 검사하고 보정 WebP도 검사한다. 어느 쪽이든 차단이면 문서·원본·감사를 생성하지 않는다.
전체 프레임의 수동 검토 상태를 보정 프레임의 통과만으로 상향하지 않는다. 외부 안전성
공급자 미설정·실패의 기존 개인/공용 카드 정책은 유지한다. 선택 보정은 검사 호출을 추가하므로
응답이 느려질 수 있으며, 저장 여부가 불명확한 경우 기존의 재전송 차단 정책을 따른다.

## 요청·실패와 중단

- 새로운 batch API 없이 기존 `POST /api/cards/submissions`를 한 장씩 호출한다.
  `user_id`는 선택한 아동, `visibility=private`, `submission_mode=submit`으로 고정한다.
- 서버가 확인한 저장 완료 항목은 잠그고 재전송하지 않는다. 목록 표시 오류도 성공을 실패로 바꾸지 않는다.
- 400·409·413·422·429처럼 명확한 거절은 등록 실패로 남겨 수정 후 다시 전송할 수 있다.
- 통신 단절·타임아웃·서버 5xx는 이미 저장한 뒤 응답만 실패했을 가능성이 있다.
  저장 여부 확인 필요로 분리하고 해당 항목을 재전송하지 않는다. 등록 목록을 확인한 뒤
  필요하면 파일을 새로 선택한다. 이 기능 자체가 모든 요청의 멱등성을 보장하는 것은 아니다.
- 401·403은 권한 확인 필요로 표시하고 뒤 항목 전송을 중단한다.
- 중단 요청은 이미 전송 중인 한 건의 결과까지 확인하고 다음 항목부터 멈춘다.
  성공한 항목을 되돌리거나 한 묶음 전체를 원자적으로 저장하는 기능은 아니다.

## 경계·보존과 기본 의사소통

아동·계정 전환과 화면 이탈은 남은 전송을 중단하고 미리보기 URL을 해제한다.
기존 세션의 늦은 응답은 새 대상 목록에 반영하지 않는다. 이미 서버로 전송한 한 건까지
취소되거나 서버에서 저장한 사진이 삭제된다는 의미는 아니다.
개인 카드 목록 조회도 요청 순서·세션·대상·현재 권한을 확인해 이전 응답을 폐기한다.

선택한 원본 파일과 편집값은 React 메모리에만 보관하며 IndexedDB·localStorage·로그에
저장하지 않는다. 오프라인에서는 전송하지 않으며 자동 재연결 업로드도 하지 않는다.
화면을 떠나면 미등록 선택은 사라진다. 이미 저장된 카드의 삭제는 기존 개인정보 정책을 따른다.

고정 보드·빠른 표현·문구·음성·추천 순서는 변경하지 않는다. 가져오기 순서를 고정 슬롯에
자동 배치하지 않으며 카드판은 기존 권한 있는 편집 화면에서 별도로 설정한다.

불명확한 결과 제외·중단·계정/아동 전환·미리보기 해제·오프라인 차단을 확인한다.

MongoDB에서 1개 통과. 사진 두 장 중 두 번째 요청을 합성 422로 거절한 뒤 그 항목만 재시도해
개인 카드 두 개가 저장되고 고정 슬롯·revision이 유지되는지 확인했다. 임시 스택은 정리했다.

### 선택형 사진 보정 개발 체크포인트

2026-10-23: Linux 백엔드 377개·격리 MongoDB 이미지 API 16개 통과. 원본의 실제 바이트와
SHA-256 보존, 전체/보정 WebP의 검사 순서·차단 시 무저장, EXIF 방향·알파·중앙 자르기·
시계 방향 회전·밝기 경계와 잘못된 JSON/추가 필드의 사전 거절을 검증했다.

Node 96개는 통과했고 새 보정 컴포넌트 검사 3개도 통과했다. 독립 실행한 프런트엔드
`npm run build`도 통과했다. 다만 React 전체 실행은
5초 시간 초과가 반복되어 최종 통과가 아니다. 읽기 전용 소스 연결, 작업 수 1개 실행,
소스 복사 이미지에서도 발생했으며 마지막 전체 실행은 135개 중 131개 통과·4개 시간 초과였다.
테스트 삭제·기대값 완화·제한 시간 증가로 통과 처리하지 않았다.

Chromium에서는 기존 일괄 등록/실패 재시도 시나리오 1개가 통과했고 보정 업로드도 201을
반환했다. 이후 테스트가 response request에서 multipart 본문을 읽지 못했고 trace 작성 중
`ENOMEM`도 발생했다. 본문은 전송 시점 route에서 관찰하도록 수정했다. 수정 후 이미지
크기·밝기 픽셀 검사까지 브라우저 재검증은 아직 하지 않았다. 보고서는
`.local-validation/card-image-edits-2026-10-23/browser/report/`에 있다. 임시 스택은 정리했다.

진단 시 Windows 가용 물리 메모리는 376,432KiB(약 368MiB)였다. 이는 메모리 부족의
근거이지만 모든 시간 초과의 원인을 확정한 것은 아니다. 다른 앱/컨테이너를 임의 종료하지
않았으며 메모리를 확보한 환경에서 프런트엔드·수정된 E2E 재검증이 남아 있다.
이 보정 항목은 구현 체크포인트이며 TODO를 완료 처리하지 않는다. 전체 검증도 미실행이다.
