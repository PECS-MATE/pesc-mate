# 운영 알림

운영 권한 담당자에게만 공용 카드 검수 대기와 반복 실패를 안내한다.
`GET /api/admin/alerts`는 `content_manage` 권한이 필요하며, 비로그인 401,
AAC 사용자·보호자·일반 담당자는 403이다. 응답은 `Cache-Control: no-store`다.

## 초기 파일럿 기준

다음 값은 서비스 품질 보장 수치나 장애 확정 기준이 아니라 점검을 시작하는 기본값이다.
운영 결과에 따른 조정은 별도 검토하며, 응답 `thresholds`에 현재 기준을 반환한다.

| 알림 | 기준 | 범위 |
|---|---|---|
| `review_pending` | 공개 승인 대기 1건 이상 | `visibility=shared`, `status=pending`만 포함 |
| 같은 대기 알림의 경고 등급 | 가장 오래된 대기가 24시간 이상 | 서버 UTC 기준, 경계 포함 |
| `api_repeated_failure` | 서버 오류+성공 헤더 이후 전송 오류 3회 이상 | 현재 프로세스의 최근 최대 15개 1분 버킷 |
| `tts_repeated_failure` | 최종 재생 실패 보고 3건 이상 | 최근 1시간에 요청한 저장 이력 |
| `offline_sync_repeated_failure` | 서비스 처리 중 실패한 동기화 요청 3회 이상 | 현재 프로세스의 최근 최대 15개 1분 버킷 |

검수 대기는 기본 `info`, 오래된 대기와 반복 실패·조회 불가는 `warning`이다.
대기 건수는 전체 공용 대기 수이고, 오래된 카드 수를 뜻하지 않는다. 날짜가 없는
이전 기록은 대기 수에 포함하되 24시간 경과를 추정하지 않는다.
개인 카드·공용 초안·승인·반려·비활성은 대기 수에 포함하지 않는다.

API의 401·403·404 등 클라이언트 오류는 API 반복 실패 알림에서 제외한다.
TTS 취소·결과 미수신은 실패로 취급하지 않으며, 기기 엔진 실패 후 기본 WAV가
끝까지 재생됐다면 최종 성공이다. 동기화 알림은 실패한 **요청 수** 기준이지
실패 항목·재시도·중복 수 기준이 아니다. 잘못된 학습 값처럼 서비스에서 422로
거절한 동기화도 점검 대상에 포함한다.

## 응답과 장애 격리

`generated_at`, `status`, `thresholds`, `sources`, `alerts`를 반환한다.
`sources`는 `review_queue`, `api`, `tts`, `offline_sync`이며 각각 `status=ok` 또는
`unavailable`이다. 성공한 출처만 해당 합계와 집계 범위를 포함한다. 출처 하나를
확인하지 못하면 응답은 200·`status=partial`로 반환하고 해당 출처의 `_unavailable`
경고를 추가하며, 확인된 다른 알림은 유지한다. 전체 요청 오류는 기존 공통 API
오류 응답을 따른다. 조회 불가를 0건이나 정상으로 바꾸지 않는다.

알림은 고정 `code`, `severity`, `title`, `message`, `count`, `action`을 가진다.
같은 원인은 코드 하나로만 표시하며 누적 알림 문서를 만들지 않는다. 조회 시점에
임계값 아래로 내려가거나 검수가 끝나면 다음 갱신에서 사라진다. 확인·읽음·
강제 해제·숨기기·소리·이메일·외부 푸시 발송 기능은 없다.

검수는 MongoDB에서 합계와 최초 시각만 집계하고 `shared_review_queue` 인덱스와
`maxTimeMS=2000`을 적용한다. 이미지·카드 원문·사용자별 목록은 가져오지 않는다.
TTS는 기존 시간 인덱스와 제한 시간 집계를 재사용한다. 새 개인정보 컬렉션,
별도 음성·이미지 저장, 사용자별 알림 추적은 추가하지 않는다. 지표 응답에는
사용자·요청·카드 ID, 이름, 카드명, 발화·문제 원문, 이미지 URL, 임의 오류 코드를
넣지 않는다. 예외 원문을 알림 문구로 반환하지 않는다.

## 화면 갱신

- 운영 권한 계정의 화면 상단에 `운영 알림`을 표시한다. 일반 사용자 화면에서는 조회하지 않는다.
- 처음 표시할 때, 검수 목록 변경 후, 수동 새로고침, 숨긴 탭으로부터 복귀 시 조회한다.
- 탭이 표시 중이면 60초 간격으로 조회한다. 같은 갱신 주기의 진행 중 요청은 겹치지 않는다.
- 이전 갱신이나 로그아웃·계정 변경 후 늦은 응답은 화면을 덮어쓰지 않는다. 언마운트 시 타이머와 이벤트 감시를 해제한다.
- 조회 실패 시 마지막 결과를 유지하되 이전 결과임을 명시하고 재확인을 안내한다. 최초 실패는 빈 정상 상태로 표시하지 않는다. 401·403이면 이전 결과도 제거한다.
- 검수 알림에서 `검수 목록 열기`로 기존 승인 화면에 이동한다. 승인·반려 후 대기 수를 다시 조회한다.
- 숫자와 제목은 별도 요소로 두고 좁은 화면에서는 줄바꿈한다. 팝업·소리로 아동의 의사소통을 끊지 않는다.

## 운영 해석

표본이 없다는 것은 장애가 없다는 증거가 아니다. 운영 화면을 닫거나 브라우저가
정지되면 화면 알림도 갱신되지 않는다. 백그라운드 감시 서버와 외부 당직 호출을
대체하지 않는다. API·동기화 지표는 재시작·개발 리로드 시 초기화되고 여러 worker를
합치지 않는다. TTS는 기존 DB 기록에서 재집계하며 개인정보 삭제·보관 기간 정책을 따른다.

서버에 도착하지 않은 통신 실패와 기기 저장 실패는 서버 실패 수에 직접 잡히지 않는다.
필요하면 각 지표 API와 요청 ID 로그, 해당 기기의 남은 기록과 재생 상태를 함께
확인한다. 자동 승인·이력 삭제·전체 재전송 같은 조치를 알림이 실행하지 않는다.
상세 분모는 [API 지표](API_METRICS.md), [TTS 지표](TTS_METRICS.md),
[오프라인 동기화 지표](OFFLINE_SYNC_METRICS.md)를 따른다.

알림의 `info`·`warning`은 장애 등급이나 자동 중단 명령이 아니다. 영향에 따른 등급·
담당자 호출·증거 보존·복구 확인은 [장애 대응 절차](../operations/INCIDENT_RESPONSE.md)를 따른다.
