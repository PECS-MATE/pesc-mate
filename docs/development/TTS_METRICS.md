# TTS 시작 지연과 실패율

`GET /api/admin/tts-metrics?hours=24`는 기존 `tts_events`에서 클라이언트가 보고한
최종 재생 결과와 시작 지연을 집계한다. `content_manage` 운영 권한이 필요하며
비로그인은 401, AAC 사용자·보호자·일반 담당자는 403이다. 응답은 캐시하지 않는다.

## 수집과 조회

클라이언트는 재생을 먼저 시작하고 기존 `POST /api/tts/events`와
`PATCH /api/tts/events/{request_id}`로 이력을 보고한다. 별도의 발화 원문·녹음·음성 파일이나
지표용 사용자별 복제본은 추가 저장하지 않는다.

```http
GET /api/admin/tts-metrics?hours=24
Authorization: Bearer {access_token}
```

- `hours`: 기본 24, 1~168시간. 범위를 벗어나면 422다.
- 기간: 요청 시각 `requested_at`이 조회 시점 이전의 지정 기간에 포함된 건이다. 완료 시각 기준이 아니다.
- 조회: MongoDB에서 시간 조건·고정 분류로 집계한다. `requested_at` 인덱스와 `maxTimeMS=2000`을 적용한다. DB 집계 실패·시간 초과는 503이다.
- 보관: 기존 개인정보 삭제·보존 기간 정책을 그대로 따른다. 삭제된 이력은 다음 조회 집계에서도 빠진다.
- 재시작: 기존 이력에서 다시 계산하므로 API 프로세스를 재시작해도 저장된 기간의 결과를 조회할 수 있다.

## 결과와 분모

| 필드 | 의미 |
|---|---|
| `scope`, `source` | `stored_events`, `client_reported` |
| `requested_from`, `requested_until`, `window_hours` | 요청 시각 기준 조회 구간 |
| `totals.requests` | 해당 기간에 저장된 고유 재생 요청 수 |
| `succeeded`, `failed` | 성공·실패로 완료 보고된 건수 |
| `cancelled` | 사용자 중지·다른 발화로 교체·화면 숨김 등 취소 건수 |
| `requested` | 완료 결과가 보고되지 않은 건수. 현재 재생 중임을 보장하지 않는다. |
| `other` | 이전 데이터에 알 수 없는 상태가 있는 경우의 고정 분류 |
| `resolved` | `succeeded + failed` |
| `success_rate`, `failure_rate` | 각각 성공·실패 수를 `resolved`로 나눈 0~1 비율 |
| `startup_ms.samples` | 유효한 시작 지연값을 보고한 완료 건수 |
| `startup_ms.mean`, `max` | 유효 표본의 평균·최댓값, 단위 ms |
| `startup_ms.p50_upper_bound`, `p95_upper_bound` | 백분위가 포함된 지연 버킷의 상한 |
| `startup_ms.buckets[]` | `le_ms` 이하인 지연 표본의 누적 개수 |
| `by_content_type[]` | 카드·문장·복구·미리 듣기 종류별 동일 집계 |
| `failure_codes[]` | 실패 상태의 허용된 오류 코드별 건수 |

취소·결과 미수신·알 수 없는 상태는 성공률·실패율의 분모에서 제외한다.
성공·실패 보고가 하나도 없으면 두 비율은 null이다. 이를 0% 실패로 해석하지 않는다.

시작값이 있는 성공·실패·취소 완료 건의 0~60000ms 값을 지연 표본으로 사용한다.
0ms도 유효한 표본이며 누락·잘못된 값은 0으로 바꾸지 않는다. 표본이 없으면 평균·
최댓값·백분위 상한은 null이다. 지연 버킷 상한은 100·250·500·1000·2500·5000·
10000·30000·60000ms이고, 마지막 누적 개수는 표본 수와 같다. 백분위는 정확한
원시 지연 시간이 아니라 해당 버킷의 상한이다.

## 중복과 최초 결과 보존

- 시작 요청은 요청 ID·소유자로 원자적으로 생성하며, 재전송하면 실제 저장된 상태를 반환한다. 이미 완료한 건을 `requested`로 되돌리지 않는다.
- 최초 완료만 `requested` 상태에서 원자적으로 전환한다. 재전송·동시 완료 요청은 최초 저장된 상태·시각·지연을 반환한다.
- 같은 ID에 다른 결과를 보내도 최초 결과를 덮어쓰지 않는다. 실제로 다시 재생할 때는 새 UUID를 사용한다.
- 다른 사용자의 요청 ID로 시작하면 409, 완료하려 하면 404다.
- 지표는 요청 ID당 한 문서에서 계산하므로 중복 전송을 별도 재생으로 합산하지 않는다.

## 개인정보와 해석 한계

지표 응답에는 사용자·요청 ID, 이름, 발화 원문, 글자 수, 음성 이름, 이미지 URL을 포함하지 않는다.
DB에서 종류·상태·오류 코드를 정해진 분류로 바꾼 뒤 집계한다. 임의 오류 코드에 텍스트가
입력돼도 지표에는 `other`로만 표시하며, 취소 사유를 실패 코드에 섞지 않는다.

성공은 클라이언트가 최종 재생 완료를 보고했다는 뜻이다. 기기 TTS가 실패해도 기본 WAV로
대체 재생이 끝나면 성공으로 집계한다. 최초 TTS 엔진 자체의 실패율이나 사람이 실제로
소리를 들었는지를 이 값으로 판정하지 않는다.

네트워크 없이 재생해 TTS 이력을 전송하지 못한 경우와 볼륨 0으로 재생 전에 차단한 경우는
이 집계에 포함되지 않는다. 따라서 전체 오프라인 재생 성공률이나 실제 기기 지원 판정은
[기기 TTS 검수표](../validation/DEVICE_TTS_VALIDATION.md)에 따라 별도로 검증한다.
외부 경보와 기기별 분석은 이번 구현에 포함하지 않는다. 집계된 최종 실패의
운영자 화면 안내는 [운영 알림](OPERATIONAL_ALERTS.md)을 따른다.
