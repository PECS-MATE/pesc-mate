# 보호자용 활동별 카드판 정리 추천

> 작업일: 2026-11-01
> 추천은 초안이며 보호자가 저장하기 전에는 아무 카드판도 변경하지 않는다.

## 사용 흐름

보호자 로그인 → 연결 아동 선택 → 마이페이지의 사용자·운영 설정 →
빠른 표현·카드판 → **자주 쓰는 카드로 카드판 추천**.

1. 사용 기록으로 카드판 추천 받기를 누른다.
2. 제안된 식사·간식 / 이동·외출 / 놀이 / 자주 쓰는 표현 중 후보를 고른다.
3. 이름·카드·슬롯 순서를 확인하고 필요하면 수정한다.
4. 확인란을 체크한 뒤 새 상황별 카드판으로 저장한다.
5. 저장된 상황 목록에서 확인한다. 기본 카드판과 기존 상황은 덮어쓰지 않는다.

공용 카테고리를 새로 만들거나 카드 자체의 분류를 바꾸는 기능은 아니다.
아동별 상황 카드판을 제안해 같은 카드를 활동별로 묶는 첫 구현이다.
아동 화면의 카드판 선택 방식·기존 빠른 표현·RFID·사진·발화 동작은 유지한다.
한 카드가 여러 활동 후보에 들어갈 수 있으며 사용 횟수만으로 자동 이동하지 않는다.

## 권한과 개인정보

- 보호자 역할(`caregiver`)만 추천을 조회한다. 아동·관리자·담당자 역할에는 제공하지 않는다.
- 연결된 해당 아동의 `records_read`와 `board_manage` 권한이 모두 필요하다.
- 기록 이용 동의가 없거나 삭제 진행·실패·완료 상태면 사용 기록을 조회하지 않는다.
- 기존 추천 설정의 끄기·숨긴 카드·승인 모드의 승인 카드 범위를 따른다.
- 결과를 만들고 나서 연결 권한·기록 동의·추천 설정 버전을 다시 확인한다.
- 이름·발화 원문·사진·모델 입력을 수집하지 않고 해당 아동의 카드 ID와 최소 근거만 읽는다.
- GET 결과는 `Cache-Control: no-store`이며 추천 조회 자체는 새 추천 기록을 DB에 저장하지 않는다.
- 계정·아동·카드판 버전·비활성 상태가 바뀌면 화면의 추천과 초안을 비운다.
  늦은 응답은 토큰과 화면 요청 범위를 확인해 무시한다.

## 추천 기준

- 최근 30일의 성공한 `speech_result`, 또는 성공 상태가 있는 기존
  `immediate_speech`·`selection_speech` 이벤트를 최대 500개 읽는다.
- 실패·취소·단순 카드 선택·문장 생성만 된 기록·학습 시도 테이블은 추천 근거로 쓰지 않는다.
  단어 미리 듣기 등도 성공 발화 이벤트로 기록됐다면 포함될 수 있으며 실제 의도를 판단하지 않는다.
- 같은 `selection_id`의 반복 재생은 한 건으로 센다. 선택 ID가 없으면 이벤트 ID 기준으로 센다.
- 그룹별 최소 3건의 발화와 각각 2건 이상 등장한 서로 다른 카드 2종이 필요하다.
- 빈도 높은 카드 최대 12종을 먼저 후보로 고르고 실제 슬롯은 기존 상대 순서를 유지한다.
- 식사·간식: 식사로 표시했거나 먹다/마시다가 포함된 성공 발화.
- 이동·외출: 외출로 표시했거나 가다가 포함된 성공 발화.
- 놀이: 놀다가 포함된 성공 발화.
- 자주 쓰는 표현: 전체 표본에서 반복된 카드.
- 실제로 식사·외출·놀이를 했다는 추론은 하지 않는다. 후보명과 함께 근거를 표시한다.
- 같은 카드 순서의 상황판이 이미 있거나 앞 후보와 구성이 같으면 중복 제안을 생략한다.
- 표본 상한에 도달하면 화면에 표본 사용을 표시한다. 충분한 근거가 없으면 후보를 만들지 않는다.
- 핵심 잠금 카드가 있으면 마지막 잠금 위치까지의 기존 앞부분을 함께 유지한다.
  이때 포함된 카드는 반복 사용 후보와 구분해 표시한다. 잠금·추천 정책·30슬롯 한도를
  동시에 지킬 수 없으면 무리하게 재배치하지 않고 후보를 생략한다.

이는 설명 가능한 규칙 기반 추천이다. Ollama나 외부 AI를 호출하지 않으며
문장 생성 모델에 새 작업이나 대기열을 추가하지 않는다. 빈도는 선호·필요·언어 능력의 판정이 아니다.

## API와 저장 경계

```text
GET /api/board/layout/organization-suggestions?user_id=<연결된 아동 ID>
```

응답은 아동 ID·카드판 버전·추천 후보·카드별 근거 횟수·표본 안내를 포함한다.
자동 생성·자동 적용·공용 카테고리 수정 API는 추가하지 않는다.

저장은 기존 `PUT /api/board/layout/situations`의 `operation: create`를 사용하며
선택적인 `card_ids`를 허용하도록 확장했다. 생략하면 기존처럼 기본판 복사로 동작한다.
추천 후보를 눌러도 저장 요청은 보내지 않는다.

- 이름·카드·순서를 수정하면 확인 체크가 해제된다.
- 서버는 현재 사용 가능한 카드·중복 카드·이름·최대 6개 상황·30슬롯을 검사한다.
- 기존 `expected_revision` 충돌 검사, 핵심 잠금 위치 검사, 삭제 경쟁 잠금과 변경 감사 기록을 유지한다.
- 저장 충돌·불확실한 오류 후에는 최신 카드판 확인과 새 추천을 요구한다.
- 상황 만들기는 기록 조회 권한이 없어도 기존처럼 수동 관리 권한으로 사용할 수 있다.
  이는 개인 사용 기록 추천을 볼 권한을 추가로 부여하지 않는다.
- 자동 테스트·검증 파일·새 데이터 컬렉션·마이그레이션·이미지 변경은 추가하지 않는다.

## 검증 상태와 남은 확인

Python 3개 파일의 AST 구문과 JSX 2개·CSS 1개의 정적 구문 검사를 통과했다.
권한 분기·조회 전용 경로·슬롯 저장 경계를 소스로 확인했으며,
문서 링크·코드 블록과 `git diff --check`도 확인했다.
실제 DB·사용자 계정의 추천 생성·저장이나 자동 테스트·빌드·브라우저·실기기 검증은
사용자 요청에 따라 미실행이다. 구문 검사와 커밋을 권한·추천 품질 검증 완료로 취급하지 않는다.

수동 확인 항목:

- [ ] 부모만 볼 수 있고 담당자·아동 및 연결/권한 없는 계정의 API 요청이 거절되는지 확인.
- [ ] 동의 철회·삭제 중·추천 끄기에서는 기록 기반 후보가 반환되지 않는지 확인.
- [ ] 최근 발화의 식사·놀이·이동 묶음과 근거 횟수, 반복 재생 제외를 확인.
- [ ] 기록이 없거나 부족할 때 후보를 억지로 만들지 않는지 확인.
- [ ] 추천·초안 선택만으로 기본판·기존 상황·카테고리가 변경되지 않는지 확인.
- [ ] 카드·이름·순서 변경 시 확인 해제와 핵심 잠금 위치 유지 확인.
- [ ] 보호자가 저장했을 때만 새 상황이 추가되고 기본판·기존 상황이 보존되는지 확인.
- [ ] 최대 상황 수·중복 이름·동시 저장 버전 충돌과 최신 상태 재조회 확인.
- [ ] 아동 전환·로그아웃·권한 변경·오프라인 중 늦은 응답이 표시되지 않는지 확인.
- [ ] 작은 화면·키보드 조작·고대비에서 추천과 초안 편집 화면 확인.
