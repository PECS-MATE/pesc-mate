# PDF 참고 랜딩페이지 개편

## 참고와 적용 범위

- 사용자가 추가한 `uxpilot-export-10-28-26.pdf` 2페이지를 확인했다.
  첫 페이지의 텍스트를 추출하고 실제 렌더링 이미지를 확인해 랜딩 구성을 참고했다.
  둘째 페이지는 로그인 이후 대시보드이며 이번 변경 범위가 아니다.
- 소개 영역 → 핵심 기능 3개 → 태블릿 사용 소개 → 시작하기 패널 → 푸터라는
  흐름을 기존 민트·흰색 토큰으로 재구성했다. 기존 이용 방법·FAQ·로그인/가입은 유지한다.
- PDF의 파란 팔레트와 사진을 복사하거나 새 이미지·영상을 생성하지 않았다.
- PDF를 읽던 최초 출력의 문자 인코딩 실패는 UTF-8 출력으로, 렌더러 접근 실패는
  기존 임시 도구의 읽기 권한을 확인한 뒤 재실행해 해결했다.

## 사용자 요청 반영

- 소개 영상 버튼·영상 플레이어·외부 임베드는 넣지 않는다.
- 카드 태그 사용 장면과 태블릿 사용 화면 자리 두 곳은 이미지 없이 설명만 둔다.
  흰 배경·점선 경계와 어떤 이미지가 들어갈지 설명하는 텍스트로 표시한다.
- 장치·센서·언어모델 모델명은 랜딩에 노출하지 않는다. 실물 카드 태그가
  가능하다는 기능 설명만 사용하고, 화면 터치만으로도 사용할 수 있음을 안내한다.
- 카드 태그 연결과 화면 카드 사용의 브라우저 지원 범위를 구분한다.
  모든 태블릿·모든 브라우저에서 장치 연결이 된다고 표현하지 않는다.
- 영상·후기·카드 상점·고객센터·팀 소개처럼 실제 제공되지 않는 경로를 만들지 않는다.
  PDF의 학습 효과 극대화·오류 없는 조작·발화 향상 보장 등의 문구도 사용하지 않는다.
- 실제 기존 로그인·가입 핸들러와 필드·동의 상태를 유지한다.
  예전 랜딩의 카드 미리보기 전달과 불필요해진 스타일은 정리했다.
- 고정 헤더가 로그인 폼과 앵커 제목을 가리지 않도록 스크롤 여백을 둔다.

## 검증

- 최종 프런트엔드 빌드와 변경분 공백 검사 통과.
  기존 500kB 초과 JS 청크 경고는 남아 있다.
- 실제 분리 Chrome에서 320·390·768·1024·1440px의 페이지 가로 넘침 없음을 확인했다.
  이미지 자리 2곳, 영상/iframe 없음, 랜딩 본문의 모델명 없음, 내부 앵커 대상
  누락 없음을 확인했다. 데스크톱과 모바일 소개 영역 및 태블릿 소개를 캡처·시각 확인했다.
- 로그인 링크는 로그인 폼과 아이디 초점으로, 시작하기는 가입 폼으로 전환됐다.
  가입 동의 체크는 기본 미선택이며 320px 가입 폼도 가로 넘침이 없었다.
  FAQ 열기를 확인했고 실제 인증·가입·데이터 저장 요청은 하지 않았다.
- 분리 브라우저는 종료했다. PDF·카드 이미지·검수 캡처·빌드 결과물 및 사용자가
  수정 중인 제작 체크리스트는 커밋에서 제외한다.
- 실기기·키보드 전수 동선·스크린리더·브라우저 확대·실제 인증 제출·카드 태그·
  TTS·문장 모델·미디어 제작은 미실행이다. 배포나 현장 검수 완료로 간주하지 않는다.
