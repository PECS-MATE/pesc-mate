# 관리자 공용 카드 등록

## 사용 방법

운영 권한이 있는 계정으로 로그인 → 공용 콘텐츠 운영 → 공용 카드 등록.

- 글자 카드: 카드명·뜻·분류를 입력한다. 흰 배경에 글자만 배치한 미리보기를 제공한다.
- 사진 카드: 같은 정보를 입력하고 JPG·PNG·WebP 사진을 선택한다.
  사진의 공용 사용 권한을 확인해야 한다. 파일명으로 카드명을 자동 입력하지 않는다.
  `카드 촬영`으로 기기 카메라를 열거나 `사진 선택`으로 기존 사진을 가져올 수 있다.
  `사진 글자 읽기` → 인식한 이름 확인·수정 → `이 이름 사용` → 분류 확인 → 저장한다.
  OCR 이름 적용 시 뜻이 비어 있으면 같은 값으로 채우며 사용자가 수정할 수 있다.
- 저장하면 승인된 공용 카드로 등록된다. 특정 아동 선택·RFID 연결은 필요하지 않다.
- 저장 후 분류는 유지하고 나머지 입력을 비워 다음 카드를 등록할 수 있다.
- 다른 기기에서 이미 열어 둔 카드 목록은 새로고침 또는 재로그인이 필요하다.
- KAAC 등 외부 플랫폼에서 어떤 단어를 글자로 표시하는지는 자동 판정하지 않는다.
  글자·사진 사용 여부는 등록자가 결정하며 외부 이미지를 자동 수집하지 않는다.

## 저장 및 권한

`POST /api/admin/cards`는 multipart의 `label`, `meaning`, `category`, `image`를 받는다.
글자 카드는 브라우저 Canvas로 만든 1024×1024 PNG를 전송한다. AI 이미지 생성이나
별도 이미지 업로드는 필요하지 않으며 기존 이미지 정규화·인쇄·오프라인 경로를 재사용한다.
글자 원문은 카드명·뜻으로도 보존한다. 별도의 글자 이미지 편집 기능은 포함하지 않는다.

- API와 서비스에서 `content_manage` 권한을 확인한다.
- 운영자 본인 소유의 공용 카드만 직접 승인 상태로 생성한다.
- 일반 사용자의 기존 공개 승인 요청·개인 카드 동의 절차는 변경하지 않는다.
- 공용 등록에는 아동 개인정보 동의를 요구하지 않는다. 이미지 쓰기 잠금·용량 한도·
  삭제 경합 검사는 유지한다. 이 경로에 연결 아동 ID를 받아 대신 저장하지 않는다.
- 별도 비밀번호 재입력 없이 현재 인증 세션의 운영 권한으로 등록한다.
  기존 승인·반려·비활성 등의 재인증 정책은 그대로 유지한다.
- 이미지 검사, 활성 분류 검사, 카드명 중복 검사, 표현 검토를 재사용한다.
- `published_directly`, 운영자 ID·승인 시각과 `shared_published` 감사 이력을 기록한다.
- 공개된 카드는 기존 승인 관리에서 비활성 처리할 수 있다.
- 사진에는 공용 사용이 가능한 이미지만 등록한다. 가족·아동 개인 사진은 개인 카드로 관리한다.

## 검증 기록 — 2026-11-04

- 로컬 `npm run build` 통과. 기존 500kB 초과 번들 경고는 남아 있다.
- 로컬 Python 구문 검사와 FastAPI 앱 import 통과.
- 일회성 메모리 모의 검사 통과: 공용 직접 승인·이미지 정규화·감사 기록,
  일반 제출의 승인 대기·동의 검사 유지, 무권한 거부, 중복 이름 거부.
- TestClient에서 비운영자의 새 API 접근이 HTTP 403으로 거부됨을 확인했다.
- Chrome 모의 API 화면 검사 통과: 글자 미리보기·PNG 전송·저장 후 초기화,
  사진 저장·초기화, 필수 파일·공개 권한 확인, 5MB 초과 거부,
  비활성 분류 제외, 390px 화면의 가로 넘침 없음.
- 초기 브라우저 검사 도구의 React DOM import 경로·default export 처리 오류로
  두 차례 검사가 실패했다. 검사 도구를 수정한 후 위 항목을 다시 실행해 통과했다.
- Docker 빌드·서버 검사는 엔진 HTTP 500 오류로 실행하지 못했다.
  대신 로컬 환경에서 위 검사를 수행했다.
- 실제 MongoDB 저장·아동 계정 재조회·TTS·A4 출력·RFID·실기기 통합 검증은 미실행이다.
  실제 사용자 계정이나 DB 데이터를 생성·변경하지 않았다.
- 사용자 PPT와 기존 카드 이미지 파일은 수정하거나 커밋하지 않는다.

촬영·OCR 후속 개발과 검증은 [실물 카드 촬영 등록](CARD_CAMERA_OCR.md)을 따른다.
