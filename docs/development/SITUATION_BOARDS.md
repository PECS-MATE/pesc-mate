# 상황별 카드판과 같은 아동의 보드 복사

2026-10-24 B1-01 보드 복사/B1-02 구현. 기본 카드판은 그대로 두고 보호자·담당자가 같은
아동 계정에 상황을 직접 만든다. 집·학교·치료실·외출·식사·병원을 이름으로 제안하되 실제
보드를 자동 생성하지 않는다. 초기 한도는 상황 6개와 기본 카드판 1개다. 실제 AAC 사용자에게
맞는 선택지 수·전환 방식 승인은 미실행이며 필요하면 현장 검수 후 한도를 조정한다.

## 지원자 관리

`board_manage` 권한으로 **빠른 표현·카드판 → 상황별 카드판**에서 관리한다.

- 생성: 저장된 기본 카드판의 슬롯을 미리 보고 새 이름과 복사 위치 확인 후 생성한다.
- 복사: 같은 아동의 기존 상황 ID를 골라 위치만 복사한다. 다른 아동·기관 계정 간 사진
  이전 기능은 아니다. 다른 기기에서는 해당 아동의 최신 구성을 조회해 같은 보드를 읽는다.
- 편집: 선택한 상황의 이름·슬롯만 변경한다. 기본 카드판과 다른 상황은 바꾸지 않는다.
- 삭제: 해당 상황 구성만 명시 확인 후 삭제한다. 카드·원본·음성·의사소통/학습 기록을
  삭제하지 않으며 기본 카드판 삭제는 허용하지 않는다.

상황 이름에 사람 이름·진단 등 개인정보를 넣지 않도록 안내한다. 중복 이름·빈 이름·제어
문자·최대 수 초과·사용 불가 카드·중복 슬롯을 거절한다. 각 보드는 1~30장이다.
[핵심 잠금](../policies/CORE_CARD_LOCK_POLICY.md)은 모든 상황에서 기본 카드판의 같은
슬롯 번호를 보호한다. 다른 위치의 상황이 있으면 새 잠금을 거절한다. 앱이 기존 상황을
강제로 정렬하지 않으며 먼저 해당 상황을 맞추거나 잠금 선택을 조정해야 한다.

## 아동의 전환과 오프라인

**그림으로 말하기 → 상황 카드판 바꾸기**에서 저장된 보드를 선택한다. 선택만으로 바꾸지
않고 위치 미리보기·확인 후 적용한다. 현재 상황을 표시하고 담아 둔 문장 카드·음성·빠른
표현·복구 표현·학습 범위는 유지한다. 검색·분류·페이지는 초기화해 새 보드의 시작 위치를
보여 준다. 의사소통의 **기록 상황**은 별도 선택이며 보드 이름으로 상황/의도를 추정하거나
자동 기록하지 않는다. 위치 변경 안내는 말하기를 막는 모달이 아니다.

전환은 현재 화면의 선택이며 서버 기본 슬롯·revision을 수정하지 않는다. 새 로그인이나
새로고침에서는 기본 카드판으로 시작한다. 이미 보고 있는 상황을 서버에서 수정/삭제하면
현재 화면의 선택 스냅샷을 자동 교체하지 않고, 최신 구성을 읽은 시점에 안내한 뒤 직접
재선택하도록 한다. 계정 변경·로그아웃·동의 철회·삭제 상태 확인 시 선택 스냅샷을 비운다.

기존 사용자별 IndexedDB 스냅샷의 `board_layout`에 저장된 상황을 같이 보관한다. 유효한
AAC 계정의 캐시가 있어야 오프라인 전환·새로고침 후 재선택할 수 있다. 신규 상황을 만들거나
지원자가 오프라인에서 편집하는 기능은 없다. 새 서버 변경은 재연결 조회 전에는 알 수 없고
다른 기기의 캐시를 원격으로 강제 삭제하지 않는다. 로그아웃·개인정보 삭제는 기존 계정별
캐시 삭제 경로를 따른다. 기본 발화의 기기 TTS 지원 한계는 기존 정책과 같다.

## API·저장과 권한

`GET /api/board/layout`에 `situations: [{id,name,slots}]`, `situation_names`,
`max_situations`를 추가한다. 구버전 보드는 상황이 빈 목록이다.

`PUT /api/board/layout/situations?user_id=...`의 JSON:

| 작업 | 필수 필드(공통 expected_revision 포함) |
| --- | --- |
| create | operation, name — 저장된 기본 슬롯 복사 |
| copy | operation, name, source_id — 같은 아동의 상황 복사 |
| update | operation, situation_id, name, card_ids |
| delete | operation, situation_id |

불필요한 필드·외부 소유자 지정·기본 보드 삭제·클라이언트의 신규 ID 지정을 거절한다.
현재 연결 권한을 재검사하고 이미지/삭제 공유 잠금 안에서 최신 카드판과 삭제 상태를 읽는다.
기본·잠금·상황이 같은 revision을 사용한다. 같은 CAS 스냅샷에서 원본 복사와 잠금 검사를
마친 뒤 조건부 저장하고 `situation_create/copy/update/delete` 감사를 기록한다.
403 권한, 404 없는 원본/대상, 409 충돌·잠금·중복 이름, 422 형식·한도 오류를 구분한다.
응답 유실·서버 오류 뒤에는 최신 조회 없이 자동 재전송하지 않는다. 아동·세션·버전이
바뀌면 늦은 응답을 폐기한다. 현재 화면의 감사 목록은 다음 카드판 조회 때 갱신된다.

새 컬렉션 없이 `board_layouts.situations`에 같은 소유자의 카드 ID·위치를 저장한다.
이미지 바이트를 복사하지 않는다. 개인정보 삭제는 기존 보드 문서/감사 삭제와 함께 제거하고
기존 BSON 백업에도 같은 문서로 포함된다. 백업 보존/파기는 별도 정책이다.
