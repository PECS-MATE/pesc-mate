# 마이페이지와 통합 설정

2026-10-28 사용자 요청으로 사이드바의 이름·프로필 사진을 설정 진입점으로 사용한다.
프로필 영역에 `마이페이지 · 설정`을 표시하고 클릭·Enter·Space로 설정 창을 연다.

## 사용 흐름

- AAC 사용자: 프로필 설정, 접근 설정, 음성 설정, 보호자 설정을 한 창에서 선택한다.
  보호자 설정에는 기존 동의·보존 기간, 보호자·담당자 연결 권한, 내보내기·삭제와 삭제 결과가 있다.
- 보호자·담당자: 자신의 프로필을 수정하고 `사용자·운영 설정`에서 현재 연결 사용자의 허용된
  카드·카드판·음성·접근·학습·RFID 설정으로 이동한다. 운영 메뉴는 별도 계정 권한에 따른다.
  대상 아동 이름을 표시하며 연결 아동의 개인정보 관리 권한을 새로 부여하지 않는다.
- 프로필이 없는 첫 로그인은 기존 필수 프로필 선택을 유지한다.
- 설정 창을 열어도 현재 화면과 선택 카드는 유지한다. 저장 버튼으로 기존 API에 저장하며,
  개인정보 동의는 명시 저장 전까지 기록 수집에 적용하지 않는다. 설정 분리는 보호자 인증이 아니다.
- 사이드바의 별도 프로필·보호자·접근 설정과 말하기 화면의 음성 설정을 통합했다.
  지원 업무용 주 메뉴는 기존 위치에서도 사용할 수 있다.

## 접근성과 상태

네이티브 `dialog.showModal()`로 배경 조작·초점 이탈을 막는다. 배경 스크롤을 잠그며 닫기·Escape로
종료하면 프로필 버튼에 초점을 복원한다. 좁은 화면에서는 설정 창 안에서 스크롤하고 닫기 헤더를
고정한다. 기존 고대비·동작 줄이기 설정을 적용한다. 오류와 저장 결과는 창 안에 표시한다.

프로필을 저장하는 동안 창을 닫더라도 현재 계정·토큰이 같은 경우에만 계정 상태를 반영한다.
USB 연결·문장 선택 화면을 교체하지 않으며 동의·지원 권한·백엔드 API·DB 형식은 기존 것을 사용한다.

## 검증 상태

`frontend`에서 `npm test`의 Node 110개·React 204개, 총 314개가 통과했다.
네이티브 창의 Tab 경계 보정 뒤 해당 컴포넌트 검사 1개와 빌드를 다시 통과했다.
개발 서버에 새로 생성한 합성 계정만 사용하는 Chromium 검사로 다음 6개 흐름을 확인했다.

- 키보드만 사용하는 로그인·선택·순서 변경·발화·삭제
- 독립 듣기 버튼의 이름·크기·간격과 선택 상태
- 좁은 화면과 글자 두 배 표시의 카드 조작
- 동의 없는 말하기·미저장 동의·저장 후 다음 로그인 유지
- 마이페이지의 네이티브 모달·초점 복귀·프로필/접근/음성 저장과 새로고침 후 복원
- 마이페이지 안의 개인정보 삭제 결과·건수·유지 항목·백업 한계 표시

브라우저 검증은 단일 실행에서 기존 4개, 범위 재검사에서 마이페이지·삭제 2개가 통과했다.
최종 모바일 2열 메뉴·헤더 겹침 보정 뒤 마이페이지 검사 1개와 빌드를 다시 통과했다.
390px 화면에서 메뉴 크기·헤더 아래 배치·가로 넘침 없음과 캡처를 확인했다.
실제 휴대폰·태블릿 사용성 검사와 백엔드 전체·전체 통합 검증은 이번 UI 작업에서 재실행하지 않았다.

### 실패와 재검증 범위

초기 범위 검사에서 JSX 괄호 오류, 새 저장 상태 선택자 불일치와 기존 2개 검사의 5초 시간 초과가
발생했다. 괄호와 저장 표시·모의 저장 응답을 수정하고 설정 창을 열 때만 내용 JSX를 구성하도록 했다.
검사 제한 시간·검사 개수·파일 격리는 완화하지 않았다.

첫 브라우저 4개 병렬 실행은 1개 통과·5개 실패였다. 개발 Vite 컨테이너가 `ENOMEM: read`로
종료됐으며 OOMKilled 표시는 false였다. 기존 MongoDB 볼륨을 유지한 채 개발 프런트엔드·백엔드를
다시 올려 API 정상 상태를 확인하고 브라우저를 `--workers=1`로 실행했다. 메모리 문제의 일반적인
자동 복구나 리소스 설정 개선을 완료한 것은 아니다.

두 번째 실행은 4개 통과·2개 실패였다. Shift+Tab이 창 밖 브라우저 영역으로 빠지는 경우는
Tab 경계를 직접 순환하도록 보정했다. 삭제 검사는 화면 결과 확인 후 fixture의 후행 정리 요청에서
ECONNRESET이 발생했다. 새 계정을 사용하는 범위 재실행에서 마이페이지·삭제 2개가 통과했다.
모바일 캡처에서 발견한 메뉴 세로 줄바꿈과 헤더 겹침은 2열 배치·너비·쌓임 순서로 보정했다.

실패 실행의 일부 합성 계정은 후행 정리 요청의 연결 실패로 사후 정리가 남아 있다.
실패 로그의 세션 토큰을 사용하는 정리 시도는 자동 승인 검토가 명시적 승인이 필요하다는 이유로
거부해 실행하지 않았다. 과거 실패 계정의 정리 완료로 표시하지 않는다. 이후 성공 실행의
검증 계정은 각 실행의 기본 fixture에서 정리했으며 과거 로그 토큰을 재사용하지 않았다.

로컬 결과 파일은 `.local-validation/my-page-frontend-tests.log`, `my-page-build-final.log`,
`my-page-focus-test.log`, `my-page-browser-final.log`, `my-page-browser-recheck.log`,
`my-page-browser-visual.log`에 있으며 검증 로그·화면 캡처는 저장소에 커밋하지 않는다.

이번 작업은 UI 설정 진입점 변경이며 하드웨어·실제 아동 사용성 검수나 전체 배포 승인을 의미하지 않는다.
