# 카드 이미지 제작과 어휘 목록

> 통합일: 2026-11-04 · 현재 사용 안내와 과거 구현 기록을 구분합니다.

현재 공용 기본 카드는 113종입니다. 그림 카드 PNG 87종과 글자 카드 SVG 26종으로 구성하며, 남은 우선 그림 제작 후보는 같이·저것·언제입니다. 그림 카드는 흰 배경·정사각형 1024×1024px·마스코트 없이 사물은 사진형, 동작·상태는 일관된 사람 그림상징을 사용합니다. 그림 안의 글자와 장식 테두리는 넣지 않습니다. 글자 카드는 흰 배경에 문구 자체를 크게 표시하는 별도 유형입니다. 이름의 공백은 파일명에서 밑줄로 바꾸며, 공백을 생략한 파일은 후보가 하나일 때만 보조 연결합니다. 이미지만 추가해 새 카드가 등록됐다고 간주하지 않습니다.

과거 날짜의 검사 통과는 현재 버전 전체의 검수나 운영 배포 승인이 아닙니다. 상세 기록에는 이전 화면·제거된 기능 설명도 있으므로 현재 사용 경로는 위 안내를 우선하고, 남은 실제 기기·권한·음성 검수는 TODO와 각 절의 미실행 기록을 확인하세요.

## 시간 일정과 사회적 표현 글자 카드

2026-11-05: 기존 글자 카드 13종에 아래 13종을 추가했다. 글자 카드는 총 26종이며
전체 기본 카드는 113종이다. 별도 관리자 계정의 DB에 쓰지 않고 공용 기본 어휘로 제공한다.

- [x] 시간과 일정 8종: 지금, 나중에, 오늘, 내일, 어제, 아침, 점심, 저녁
- [x] 사회적 표현 5종: 안녕하세요, 안녕히 가세요, 고마워요, 미안해요, 괜찮아요

흰 배경·진한 글자·1024×1024 SVG 형식을 유지한다. 아침·점심·저녁은 음식명이 아니라
시간대라는 뜻으로 등록한다. 시간 카드는 수식 역할과 `time/date` 의미 그룹을 부여해
기존 말하기의 `시간/일정` 탭에 표시하고, 사회적 표현은 `사회적 표현` 분류 폴더에 표시한다.
두 분류는 기본 시드에 추가하되 기존 분류명·표시 순서·비활성 설정은 덮어쓰지 않는다.
이 작업은 시간 어휘 추가이며 달력·예약 관리나 모든 한국어 시제 활용의 개선은 아니다.

기존 A4 카드 선택 경로도 글자 카드 26종을 제공한다. PNG 보관함 생성과 편집본 저장·공유
변환을 재사용하며 기존 기본 카드·복구 표현·저장된 RFID 연결을 변경하지 않는다.
규칙 엔진 버전은 `ko-particle-v6`다.

### 검증 기록

- 프론트/백엔드 기본 카드 113종의 ID·표시명, 글자 카드 26종의 뜻·분류 일치 검사 통과.
- 새 SVG 13종의 배경·문구·크기, 단독 표현 의미·안전 검사와 문장 조합 4건 검사 통과.
  내일을 어제로 바꾼 문장의 의미 검사가 실패하는 것과 감사·사과의 대체 표현도 확인했다.
- 모의 컬렉션에서 새 분류 시드 반복 및 기존 사용자 설정 보존 검사 통과.
- 별도 Chrome 일회성 검사 39개 통과:
  고유 이미지 매핑 113종, 새 SVG·PNG 생성 13종, 글자 영역 넘침,
  시간/일정 탭 8종과 사회적 표현 폴더 5종, A4 선택·배치·편집본·공유 변환을 확인했다.
- `npm run build`와 `git diff --check` 통과. 기존 500KB 초과 묶음 경고는 남아 있다.
- 실사용 DB·계정, 실제 TTS·RFID·프린터·iPad·오프라인 전체 흐름은 미검수다.
  사용자가 별도로 추가한 PNG 파일은 이번 글자 카드 작업에서 변경·커밋하지 않는다.

## 공용 기본 글자 카드 13종

2026-11-05: 사용자 요청으로 아래 표현을 공용 기본 카드에 포함했다.
특정 관리자 계정의 DB에 대신 등록한 것이 아니라 코드에 포함된 기본 어휘이며,
서버 반영 후 계정에서 카드 목록을 다시 불러오면 사용할 수 있다.

- [x] 확인·정정: 맞아요, 아니에요, 잘못 눌렀어요, 그 뜻이 아니에요
- [x] 대화 조절: 잠깐만요, 다시 말할게요, 제 말을 기다려 주세요, 질문을 잘 모르겠어요
- [x] 요청·자기결정: 바꿔 주세요, 보여 주세요, 천천히 해 주세요, 내가 할래요, 쉬고 싶어요

모두 `요청과 선택` 분류에 있으며, 흰 배경·진한 글자·1024×1024 SVG로 제공한다.
문구는 생략하지 않고 긴 문장은 줄바꿈한다. 이 SVG는 신뢰할 수 있는 내장 리소스이며
사용자 SVG 업로드를 허용하도록 파일 검증 규칙을 바꾸지는 않았다.

`맞아요/아니에요`는 `confirm/deny`라는 새 ID로 등록하고 기존 `yes/no`의
`네/싫어요`와 저장된 RFID 연결을 바꾸지 않는다. 나머지 복구 표현 6종은 기존 복구 ID를
재사용해 같은 ID의 카드가 풀에 중복되지 않게 했다. 기존 복구 표현 설정은 유지한다.
문장 단독 발화와 의미 검사를 지원하며 규칙 엔진 버전은 `ko-particle-v5`다.

보호자의 A4 편집기에서 **등록 카드 가져오기**를 누르면 이 13종도 선택할 수 있다.
기존 관리자 글자 카드 생성 함수를 공용 서비스로 분리해 인쇄 보관함에는 PNG로 넣는다.
따라서 기존 A4 편집본의 PNG 형식과 공유용 WebP 변환을 유지한다.
기본 카드를 인쇄 보관함에 넣는 것은 개인 카드를 서버에 다시 등록하는 작업이 아니다.
RFID UID는 자동 생성·연결하지 않으며 기존 등록 화면에서 사용자가 연결한다.

### 검증 기록

- 프론트/백엔드 기본 카드 100종의 ID·표시명 일치, 글자 SVG 13종의 구조·문구·흰 배경 검사 통과.
- 글자 카드 13종의 단독 문장·의미·안전 검사와 문장 조합 3건 및 기존 복구 ID 호환 검사 통과.
- 별도 Chrome 일회성 검사 37개 통과:
  전체 카드 고유 이미지 매핑, SVG 로딩과 글자 영역 넘침, PNG 생성, 기존 복구 표현 연결,
  A4 카드 선택·중복 선택 방지·13칸 배치·편집본 내보내기 검증·공유 형식 변환을 확인했다.
- 최초 브라우저 검사는 보조 스크립트 초기화 오류, 다음 시도는 꺼진 개발 서버로 실패했다.
  스크립트를 초기화하고 로컬 Vite를 실행한 뒤 위 검사를 다시 수행해 통과했다.
- `npm run build` 통과. 기존 500KB 초과 JavaScript 묶음 경고는 남아 있다.
- 실사용 계정·DB 쓰기, 실제 TTS·RFID·프린터·iPad와 전체 오프라인 흐름은 미검수다.
  사용자 추가 이미지 `고양이.png`, `곰.png`는 이번 요청 범위 밖이므로 변경·커밋하지 않는다.

## 추가 카드 21종 전체 연결

2026-11-04: 기존 66종에 다음 21종을 추가해 PNG 87장과 기본 카드 87종을 1:1로 연결했다.
추가 이미지도 코드와 함께 관리한다. 아래 체크는 파일·메타정보·화면 연결 완료를 뜻하며
실제 사용자 이해도나 임상적 적합성을 검수했다는 뜻은 아니다.

- [x] 생활용품 9종: 물병, 비누, 수건, 숟가락, 접시, 치약, 칫솔, 포크, 휴지
- [x] 놀이 3종: 블럭, 인형, 퍼즐
- [x] 학습 2종: 그림, 종이
- [x] 행동 6종: 걷다, 그리다, 뛰다, 손 씻다, 책을 읽다, 타다
- [x] 질문 1종: 어디

`손 씻다`와 `책을 읽다`는 각각 `손_씻다.png`, `책을_읽다.png`로 연결한다.
`블럭`은 제공된 파일명과 같은 표시명을 유지한다. 새 놀이 분류는 기본 시드에 추가하지만
기존 관리자가 바꾼 분류명·순서·비활성 상태는 덮어쓰지 않는다.
말하기 화면의 분류 폴더는 API 카드·분류 목록을 사용하므로 별도 화면 하드코딩 없이 표시된다.
문장 생성용 품사·문장 역할을 등록하고 어디의 질문형, 걷다·그리다·손 씻다 등의 활용형 의미를
검사한다. 규칙 엔진 버전은 `ko-particle-v4`다. RFID UID는 자동 할당하지 않으며 기존 등록 화면에서 연결한다.

### 검증 기록

- PNG 87장 형식·무결성 및 백엔드/프론트 카드 ID·표시명 일치 검사 통과.
- 파일명 매핑 87개 고유 연결, 누락·중복 연결 0건.
- 새 카드 21종 단독 표현, 문장 조합 8건, 한국어 활용형 5건 검사 통과.
- 모의 컬렉션으로 분류 시드 반복 실행과 기존 설정 보존 검사 통과.
- 별도 브라우저의 말하기 카드 컴포넌트 검사 17개 통과:
  5개 분류의 폴더·대표 그림·새 카드, 전체 87종 노출과 새 이미지 21장 로딩을 확인했다.
- 최초 브라우저 검사 실행은 명령 길이 제한으로 시작되지 않았다.
  전달 데이터를 줄인 후 재실행해 위 17개를 통과했다.
- `npm run build` 통과. 기존 500KB 초과 JavaScript 묶음 경고가 있으며 원본 PNG 용량 최적화는 미실행이다.
- 실제 계정의 DB·분류 상태, 실물 RFID 매핑·음성 출력 및 실제 사용자 검수는 미실행이다.
  서버가 자동 재시작되지 않는 환경에서는 백엔드 재시작 후, 화면에서 카드 목록을 새로 불러와야 한다.

2026-11-05: 아래 8종은 모두 글자 카드로 제공했다. 다음 PNG 파일명은
추후 그림형 대안을 만들 때의 후보이며, 현재 별도 그림 제작이 필수인 항목은 아니다.

| 순서 | 파일명 | 표현 기준 |
| --- | --- | --- |
| 4 | `맞아요.png` | 상대의 확인에 긍정 응답. ‘좋아요’ 감정과 구별 |
| 5 | `아니에요.png` | 내용에 부정 응답. 원치 않는다는 ‘싫어요’와 구별 |

| 7 | `그_뜻이_아니에요.png` | 전달된 의미를 정정. 상대방 자체를 거절하지 않음 |
| 8 | `잠깐만요.png` | 짧은 기다림. 강한 중단 표시와 구별 |

추상 표현의 뜻을 그림 하나로 완벽하게 구분할 수 있다고 가정하지 않는다.
표시 단어·발화와 함께 시범 사용하며 확인한다.
위 순서는 프로젝트 제작 순서이며 아동 교육·중재 순서가 아니다.

<a id="card-image-next-production--기존-계획-이후-확장-후보--4장"></a>
#### 기존 계획 이후 확장 후보 — 4장

`문.png`, `공.png`, `책.png`는 아직 파일이 없는 확장 후보다. `열다.png`는 준비됐다.
위 후보 중 실제 사용할 어휘를 골라 추가한다.
이미지 파일 추가만으로 DB 카드·RFID 연결이 새로 등록되지는 않는다.

## 추가 카드 이미지와 기본 어휘 연결

<a id="card-vocabulary-expansion--추가-카드-이미지와-기본-어휘-연결"></a>
### 추가 카드 이미지와 기본 어휘 연결

<a id="card-vocabulary-expansion--범위--2026-11-04"></a>
#### 범위 — 2026-11-04

현재 PNG 66장과 기본 카드 66종을 연결한다. 기본 어휘 33종에 없었던 단어 33종을
추가했으며 기존 ID·카드판·개인 사진·RFID·기록은 변경하거나 삭제하지 않는다.
이번 요청에 사용하는 새 PNG 26장도 기능 커밋에 포함한다. 이미지 바이트·구도는 수정하지 않는다.
예전에는 이미지 파일만 있고 카드 정의가 없어 말하기에 보이지 않던 10종도 함께 연결한다.

| 추가 분류 | 새 기본 카드 |
| --- | --- |
| 사람 | 아빠, 선생님 |
| 장소 | 학교 |
| 행동 | 씻다, 입다, 벗다, 자다, 보다, 듣다, 꺼내다, 넣다, 닫다, 열다, 앉다, 일어나다, 오다, 주다 |
| 요청과 선택 | 주세요, 원해요, 안 할래요, 끝났어요, 이것, 혼자 |
| 질문 | 누구, 무엇 |
| 몸 상태 | 배고파요, 목말라요, 졸려요, 피곤해요, 더워요, 추워요, 가려워요, 어지러워요 |

기존 `더`, `간식`, `다리`는 ID를 새로 만들지 않고 추가된 이미지만 연결한다.
전체 분류별 카드 수는 사람 8·음식 5·행동 25·장소 3·감정 9·요청과 선택 6·질문 2·몸 상태 8이다.
질문·요청과 선택·몸 상태는 기본 분류로 추가한다. 기존 DB에도 누락된 분류만 추가하고,
같은 이름의 사용자 분류나 기본 분류 ID가 있으면 이름·순서·비활성 상태를 덮어쓰지 않는다.
개인/공용 사용자 카드가 이미 같은 이름으로 존재하더라도 기존 ID를 자동 통합·삭제하지 않는다.

<a id="card-vocabulary-expansion--화면과-이미지-연결"></a>
#### 화면과 이미지 연결

- 그림으로 말하기 → 홈의 분류 폴더 또는 모든 카드에서 접근한다.
- 기존 홈의 좋아요·싫어요·도와주세요와 개인 고정 카드판 위치는 바꾸지 않는다.
- 몸 상태는 의미 그룹도 지정하여 기존 감정 탭에서 볼 수 있다.
  안 할래요·어지러워요는 기존 안전 관련 카드 탐색에도 포함된다.
- 이름의 공백은 기본적으로 `_` 파일명과 연결한다. 정확한 파일명을 우선한다.
  정확한 파일이 없고 공백·밑줄을 제외한 후보가 단 하나인 경우에만 보조 연결한다.
  따라서 `안할래요.png`를 이름 변경 없이 ‘안 할래요’로 사용할 수 있다.
  보조 후보가 여러 개면 임의로 고르지 않는다. 카드별 파일명 하드코딩은 추가하지 않는다.
- 개인/서버 이미지가 있으면 기존처럼 기본 PNG보다 우선한다.
- 문장 역할·뜻·의미 그룹을 추가한다. 혼자는 수식어로 처리하고 주세요·질문 표현을 보완한다.
  규칙 엔진 버전은 `ko-particle-v3`다. 부정·몸 상태의 한국어 활용형 의미 검사도 확장한다.
- 동작 카드 추가만으로 새 학습 활동이나 임의 문장 예문을 만들지 않는다.
- 온라인 상태에서 페이지를 새로고침해 새 목록·분류를 불러온다.
  이미 설치된 오프라인 캐시의 과거 카드 목록이 즉시 갱신된다고 가정하지 않는다.

<a id="card-vocabulary-expansion--검증-기록"></a>
#### 검증 기록

- 실제 PNG 66장의 파일 형식·무결성과 기본 카드 66종의 고유 ID·이름·분류·매핑을 대조했다.
- 신규 33종의 단독 규칙 문장 의미 검사와 ‘저는 혼자 놀고 싶어요’, ‘이것을 주세요’,
  학교 이동·목마름 조합 및 거절 의미가 긍정 문장으로 통과하지 않음을 확인했다.
- 최초의 전체 단독 의미 검사는 기존 ‘나’ 카드가 주어 조사 없는 ‘나’로 출력되는 경우에
  기존 의미 검사가 통과하지 않아 실패했다. 기존 자기 지시 의미 정책은 이번 범위에서 바꾸지 않았다.
  이후 신규 33종과 위 조합으로 범위를 구분해 재검사했고 통과했다.
  기존 카드 전체의 문장 생성 회귀가 통과했다고 표시하지 않는다.
- 분류 시드의 반복 실행·사용자 동일 이름·비활성 상태·기존 순서 보존을 메모리 모의로 확인했다.
  신규 분류 검사도 한 번의 기존 목록 조회로 처리해 카드별 DB 조회를 추가하지 않는다.
- 파일명 공백·밑줄 연결, 공백 생략 보조 연결, 다중 후보 오연결 방지 Node 검사 통과.
- TestClient에서 모의 사용자 카드 저장소로 카드 API가 66종과 새 메타데이터를 반환함을 확인했다.
- Chrome의 말하기 라이브러리에서 모든 카드 66장 표시, 새 분류 폴더 3개,
  몸 상태 8장·요청 6장 이미지 로딩, 안 할래요 이미지, 질문 2장, 390px 배치를 확인했다.
- 첫 브라우저 검사 실행 준비는 이전 턴 도구 변수 부재로 실패했다. 연결 도구를 새로 구성한 뒤 통과했다.
- 로컬 빌드와 공백 검사 통과. 기존 번들 크기 경고는 남아 있다.
- 실행 프로세스 상세 조회는 OS 권한 거부로 확인하지 못했다. 웹·백엔드 건강 확인은 HTTP 200,
  실제 인증 없는 분류 조회는 예상대로 401이었다. 실제 계정 로그인이나 DB 직접 변경은 하지 않았다.
- 실제 아동 계정·태블릿·TTS·RFID·모델 추론·전체 회귀 검수는 미실행이다.
  분류 시드의 실제 DB 반영은 정상 앱의 분류 조회 시 수행되며 이번 검증에서는 DB를 변경하지 않았다.
- 개발 서버는 사용자가 접속할 수 있게 유지한다. 원격 푸시는 하지 않는다.

## PECS MATE 카드 이미지 제작 규격과 생성 프롬프트

<details>
<summary>상세 구현·설정·검증 기록</summary>

<a id="card-image-production-guide--pecs-mate-카드-이미지-제작-규격과-생성-프롬프트"></a>
### PECS MATE 카드 이미지 제작 규격과 생성 프롬프트

> 기준일: 2026-11-01
> 대상: 기본 카드 33종과 복구 표현 8종, 합계 41종
> 용도: Gemini 등에서 그림을 제작한 뒤 웹·실물 카드에 적용하기 위한 작업 지침

현재 파일 현황과 다음 제작 순서는 [다음 카드 제작 목록](CARD_ASSETS.md#card-image-next-production)을 따른다.
파일 준비는 규격·의미 검수나 웹·실물 확인 완료와 구분한다.
이 문서의 개별 프롬프트 표는 제작 기준이며 최신 파일 재고표가 아니다.
2026-11-04 기본 카드·이미지는 66종으로 확장했다. 아래 41종 표는 기존 프롬프트 범위이며
새 단어·분류·공백 생략 파일명의 자동 연결은 [어휘 확장 기록](CARD_ASSETS.md#card-vocabulary-expansion)을 따른다.

이 문서의 픽셀 수·여백·출력 크기는 프로젝트 제작 권장값이다.
임상 표준, PECS 공식 규격, 접근성 인증 또는 실제 아동 사용성 검증 결과가 아니다.
민트색을 사용한다는 이유만으로 의사소통 효과가 좋아진다고 가정하지 않는다.

**카드 이미지에는 마스코트를 사용하지 않는다.** 사물은 실물 사진형, 행동·감정·
신체 부위는 단순한 사람 그림상징을 기본으로 한다. 실제 가족·물건·장소의 사진은
사용 권한과 동의를 확인한 개인화 자료로 사용한다. 웹의 기존 브랜드 마스코트는
제거하지 않는다. 2026-11-01 재제작 준비를 위해 기존 내장 카드 PNG 28개를 제거했으며,
이후 로컬에 `나.png`가 추가되었다. 내용 검수와 납품 규격 확인은 대기이며,
개인 사진·프로필·브랜드 이미지는 삭제 대상이 아니다.

<a id="card-image-production-guide--1-현재까지-수정한-범위와-남은-부분"></a>
#### 1. 현재까지 수정한 범위와 남은 부분

| 구분 | 현재 상태 |
| --- | --- |
| 화면 색상 | 공통 토큰 23개·실제 HEX 22종으로 통합, 민트·크림 적용 |
| 카드 주변 UI | 흰색 카드 표면, 순번별 배경색 제거, 선택 테두리·기존 체크 표시 유지 |
| 접근성 표현 | 주요 토큰 쌍 대비 계산·CSS 구문 확인, 파란 포커스·흑백 고대비 유지 |
| 그림 자체 | 재제작 준비로 기존 내장 PNG 28개 제거. 새 이미지 제작·반영·검수 필요 |
| 기본 기능 | 카드 선택·문장·TTS·RFID·개인화는 기존 구현을 유지. 이번에 재검증하지 않음 |
| AI·현장 검증 | 임의 의미 추가 방지, 전체 상태의 접근성, 오프라인·실기기·사용자 검증 완료를 뜻하지 않음 |

기존에 익숙해진 그림과 위치를 한꺼번에 바꾸지 않는다. 보호자·담당자가 새 그림을
검토한 뒤 교체 범위를 정한다. 기존 그림이 규격·의미 구분을 만족하면 재사용할 수 있다.

<a id="card-image-production-guide--소스-기준-자산-현황"></a>
##### 소스 기준 자산 현황

- 기본 카드 이미지: 로컬 파일 1/33종, 복구 표현 이미지: 0/8종. 규격·의미 검수는 별도다.
- 현재 `나.png`가 추가되어 나머지 40종이 미배치다. 이 파일은 아직 Git 미추적 상태이며
  이번 문서 커밋에는 포함하지 않는다. 최신 제작 체크는 위 체크리스트를 따른다.
- `frontend/src/assets/cards/`의 기존 PNG 28개를 사용자 요청으로 제거했다.
  폴더와 자동 연결 경로는 `.gitkeep`으로 유지한다.
- 제거 전 자산은 2048×2048 PNG 28개, 합계 약 124.2MiB였다. 파일들은
  삭제 이전 Git 이력에서 복구할 수 있으며 원격 저장소 이력을 지우는 작업은 하지 않았다.
- DB의 카드·사진·RFID 매핑·발화 데이터와 마스코트·프로필 이미지는 변경하지 않았다.
- 이미지를 다시 넣기 전에는 기존 이미지 없음 대체 UI를 사용한다. DB 이미지나 브라우저의
  기존 캐시는 이번 파일 삭제로 제거되지 않으므로 일부 환경에 예전 그림이 남을 수 있다.

<a id="card-image-production-guide--2-제작납품-규격"></a>
#### 2. 제작·납품 규격

| 항목 | 기본 제공 카드 기준 |
| --- | --- |
| 파일 형식 | 실제 PNG, 확장자는 소문자 `.png` |
| 웹 납품 크기 | **1024×1024px, 정사각형 1:1** |
| 편집 원본 | 필요 시 2048×2048px 이상 별도 보관. 웹 폴더에는 납품본만 배치 |
| 색상 | sRGB 기준으로 내보내고 실제 브라우저에서 확인 |
| 배경 | **불투명 흰색 `#ffffff`**. 그라데이션·배경 장식 없음 |
| 안전 여백 | 사방 약 10%, 1024px 기준 약 102px 안쪽에 핵심 내용 배치 |
| 피사체 크기 | 전체 폭·높이의 약 65~75%부터 시안 제작. 손끝·동작 화살표도 여백 안에 포함 |
| 선 | 그림상징은 일정한 짙은 외곽선, 1024px 기준 8~12px부터 축소 확인. 실사에는 만화 외곽선을 덧그리지 않음 |
| 표현 방식 | 사물 사진형 / 단순한 2D 사람 그림상징 / 제공된 실제 사진 편집 중 하나. 한 카드에 한 개념 |
| 이미지 속 글자 | 단어·문장·숫자·로고·워터마크 없음. 웹의 단어 표시는 UI가 담당 |
| 테두리·선택 표시 | 그림에 그리지 않음. 카드 테두리·체크·선택 상태는 UI가 담당 |
| 용량 목표 | 장당 1MiB 이하 권장, 복잡한 시안도 2MiB 이하를 목표로 조정 |
| 파일명 | `[표시 카드명].png`, 표시명의 일반 공백은 `_`로 치환 |
| 저장 경로 | `frontend/src/assets/cards/` 바로 아래. 하위 폴더는 현재 자동 검색 대상이 아님 |

1024px·1MiB는 제작 권장값이지 현재 코드가 강제하는 조건은 아니다.
생성 도구가 다른 크기나 형식으로 내보내면 편집 도구에서 실제 크기·형식을 변환한다.
확장자만 PNG로 바꾸지 않는다. PNG 최적화 후 외곽선·피부색·작은 기호가 유지되는지 확인한다.

<a id="card-image-production-guide--웹-ui-팔레트와-그림-색상의-관계"></a>
##### 웹 UI 팔레트와 그림 색상의 관계

- 민트 `#81c7b5`, 진한 민트 `#317766`, 크림 `#fff9f0`은 웹 UI의 역할 색상이다.
- 기본 카드의 **이미지 내부 배경은 크림이나 민트가 아니라 흰색**을 사용한다.
- 사과는 빨간색, 우유는 흰색 등 사물의 식별에 필요한 고유색을 유지한다.
  모든 물체를 민트색으로 칠하지 않는다.
- 인물의 피부색·옷·외곽선은 세트 안에서 일관되게 유지한다. 옷의 작은 민트색 포인트는
  가능하지만 의미 구분을 색상에만 맡기지 않는다.
- 그림의 픽셀 색상을 웹 UI의 HEX 22종으로 제한하는 규격이 아니다.

<a id="card-image-production-guide--api-업로드-규격과-구분"></a>
##### API 업로드 규격과 구분

직접 Git에 넣는 내장 PNG와 보호자 화면에서 업로드하는 사진은 처리 경로가 다르다.

| 경로 | 현재 코드의 처리 |
| --- | --- |
| 내장 자산 | `*.png`를 Vite가 불러옴. 백엔드의 원본 보관·WebP 변환을 거치지 않음 |
| 카드 사진 업로드 | JPEG·PNG·WebP, 비어 있지 않은 5MiB 이하, 각 변 128~4096px, 전체 16,000,000픽셀 이하 |
| 업로드 파생 이미지 | 화면용 긴 변 최대 1280px, 카드 썸네일 긴 변 최대 256px. 비율 유지·확대하지 않음 |
| 업로드 원본 | 기존 정책에 따라 별도 보관. 화면용 정규화본의 메타데이터 제거와 원본 보관을 혼동하지 않음 |
| 일괄 업로드 | 현재 프런트엔드 제한은 한 번에 최대 20개. 파일명 `_`를 공백으로 읽어 카드명 초안 생성 |

<a id="card-image-production-guide--3-반드시-지킬-의미그림체-원칙"></a>
#### 3. 반드시 지킬 의미·그림체 원칙

1. 사물은 그 사물 하나를 크게 보여 준다. 행동은 신체 부위와 최소한의 사물을 먼저 사용하고,
   전신·보조 인물은 의미 전달에 필요한 경우에만 추가한다. 마스코트·동물 캐릭터는 쓰지 않는다.
2. 물/마시다, 밥/먹다, 그만/기다려 주세요/잠깐만요가 서로 구분되어야 한다.
3. `배`는 신체의 배, `다리`는 신체의 다리다. 과일이나 교량을 그리지 않는다.
4. 현재 코드의 `좋아요`는 `happy`이며 뜻은 **좋거나 만족스러운 감정**이다.
   동의 응답으로 새로 정의하거나 `네`·`맞아요`와 임의로 합치지 않는다.
5. 거절을 분노·문제행동으로만 표현하지 않는다. 통증에 피·큰 상처·공포 장면을 넣지 않는다.
6. 알 수 없는 이유·인물·장소를 덧붙이지 않는다. 예를 들어 무서워요에 특정 가해자를 그리지 않는다.
7. 사람 그림이 필요할 때는 같은 그림체·인물 비율·외곽선을 사용한다. 모든 카드에 같은
   인물 전신을 넣을 필요는 없으며 성별이나 특정 외모를 의미의 조건으로 삼지 않는다.
8. 가족·장소·개인 물건의 실제 사진은 동의받은 사용자별 대체 이미지로 관리한다.
   공용 세트에 실제 아동 얼굴·집 주소·기관명·연락처를 넣지 않는다.

<a id="card-image-production-guide--4-gemini용-제작-방식-선택과-프롬프트"></a>
#### 4. Gemini용 제작 방식 선택과 프롬프트

마스코트 파일을 참조로 첨부하지 않는다. 참고 사이트의 그림을 그대로 복제하지 않고
흰 배경·단순한 의미 표현이라는 구성 원칙만 참고한다. 한 요청에서 한 카드만 만든다.

| 방식 | 현재 기본 세트의 적용 대상 | 사용 방법 |
| --- | --- | --- |
| A — 사물 사진형 | 물, 밥, 사과, 우유, 간식 | 실제 사진을 제공하지 않을 때의 사진처럼 보이는 생성 시안 |
| B — 사람 그림상징 | 위 A의 5종을 제외한 기본 28종과 복구 표현 8종 | 부분 신체·동작·표정·관계 중심의 단순한 2D 그림 |
| C — 실제 사진 편집 | 개인 물건, 가족, 실제 장소를 개인화할 때 | 동의·사용 권한이 있는 원본 사진을 첨부해 편집 |

A는 실제 촬영 사진이나 아동의 실제 소유물이라는 뜻이 아니다. 익숙한 실제 물건을
정확히 가리켜야 하면 C를 사용한다. 기본 `엄마`는 B의 일반 사람 그림이며, 실제
엄마를 대신하는 가짜 인물을 생성하지 않는다. 개인화 때만 제공된 실제 사진을 사용한다.
이 분류는 프로젝트의 초기 제작안이며 사용자가 기존에 이해하는 사진·상징이 있으면 우선 검토한다.

<a id="card-image-production-guide--41-a--사물-사진형-공통-프롬프트"></a>
##### 4.1 A — 사물 사진형 공통 프롬프트

아래 프롬프트에 5절의 A 대상 장면 하나를 붙인다. 예시는 `사과.png`다.

```text
AAC 의사소통 도구 PECS MATE의 사물 카드 이미지 한 장을 만들어 주세요.
마스코트·동물 캐릭터·사람·만화 얼굴을 넣지 마세요.

[표현 방식]
- 실제 물체를 촬영한 것처럼 자연스러운 사진형 이미지.
- 완전히 흰색인 불투명 배경에 대상만 분리한 구도.
- 대상의 실제 형태·고유색·비율·재질을 유지합니다.
- 만화 외곽선, 눈·입이 달린 물건, 과장된 3D 장난감 표현은 사용하지 않습니다.
- 단순하고 고른 조명. 장식적인 반사광·진한 그림자·받침대·식탁·배경 소품은 없습니다.

[공통 납품 규격]
- 정사각형 1:1, 최종 목표 1024×1024px PNG 한 장.
- 대상을 중앙의 약 65~75% 크기로 배치하고 사방 약 10% 안전 여백을 확보합니다.
- 글자·숫자·브랜드·로고·워터마크·카드 테두리·UI 버튼은 넣지 않습니다.
- 한 가지 개념만 표현하고 여러 카드를 묶거나 분할 화면을 만들지 않습니다.
- 결과는 흰 배경 이미지이며 투명 체크무늬를 그리지 않습니다.

[이번 카드]
의미: 사과
장면: 꼭지와 작은 잎이 있는 빨간 사과 한 개를 크게 보여 주세요.
다른 과일, 단면 조각, 손, 포장, 주스는 넣지 마세요.
```

<a id="card-image-production-guide--42-b--행동감정신체관계-그림상징-공통-프롬프트"></a>
##### 4.2 B — 행동·감정·신체·관계 그림상징 공통 프롬프트

아래 프롬프트의 마지막 장면을 5절의 B 대상 장면 하나로 교체한다.
같은 그림체로 승인된 사람 그림상징이 있을 때만 스타일 참조로 첨부한다.

```text
AAC 의사소통 도구 PECS MATE의 그림상징 카드 한 장을 만들어 주세요.
마스코트·동물 캐릭터·브랜드 캐릭터는 사용하지 마세요.
사진이나 실사풍 3D가 아니라 단순한 사람·신체 부위·사물의 2D 그림입니다.

[의미 표현]
- 한 카드에는 지정한 의미 한 가지만 표현합니다.
- 신체 부위와 최소한의 사물만으로 동작이 명확하면 얼굴·몸 전체를 추가하지 않습니다.
- 자세·표정·관계가 필요한 경우에만 사람의 상반신·전신 또는 보조 인물을 사용합니다.
- 손·발·관절은 자연스러운 형태로 그리고 필요한 동작 단서를 생략하지 않습니다.
- 정지 그림에서 접촉·방향·자세로 행동을 보여 주며 애니메이션이나 연속 컷은 만들지 않습니다.
- 원인·장소·감정·사물을 임의로 추가하지 않습니다.

[그림체와 납품 규격]
- 완전히 흰색인 불투명 배경, 굵고 일정한 짙은 외곽선, 단순한 자연색 색면.
- 그라데이션·광택·질감·강한 그림자·장식은 없습니다.
- 사람 그림끼리는 외곽선·비율·기본 복장을 일관되게 유지합니다.
- 정사각형 1:1, 최종 목표 1024×1024px PNG 한 장.
- 핵심 그림은 중앙의 약 65~75% 크기, 사방 약 10% 안전 여백.
- 글자·단어·문장·숫자·로고·워터마크·카드 프레임·UI 선택 체크는 없습니다.
- 작은 확인/취소 기호·물음표·방향 화살표는 이번 장면에서 요청한 경우에만 사용합니다.
- 다른 사이트의 특정 그림상징을 복제하지 말고 독립적인 그림으로 제작합니다.

[이번 카드]
의미: 마시다
장면: 사람의 입과 턱, 컵을 잡은 손, 투명한 컵만 크게 보여 주세요.
45도 옆 구도로 컵 테두리가 입에 닿고 컵이 기울어진 마시는 순간입니다.
컵을 들고만 있는 장면이 아니며 눈·머리 전체·전신·식탁·배경은 넣지 마세요.
```

<a id="card-image-production-guide--43-c--제공한-실제-사진-편집-프롬프트"></a>
##### 4.3 C — 제공한 실제 사진 편집 프롬프트

AI에게 개인 사진을 전달하기 전 처리 서비스의 전송·보관 조건과 동의 범위를 확인한다.
외부 전송이 적절하지 않으면 로컬 편집 도구로 배경을 정리한다. AI 편집 결과가 원본의
얼굴·물체를 바꾸면 채택하지 않는다. 실제 인물·장소를 새로 만들어 대체하지 않는다.

```text
첨부한 실제 사진을 AAC 의사소통 카드용으로 정리해 주세요.
사진의 인물·물건을 새로 생성하거나 다른 대상으로 바꾸지 마세요.
마스코트·만화화·미화·얼굴 교체·새 소품 추가는 하지 마세요.

[대상]
여기에 남겨야 할 실제 인물·물건·장소를 지정합니다.

[배경 처리: 아래 두 가지 중 하나만 선택]
A. 물건·인물: 대상의 형태와 식별 특징을 유지하며 불필요한 배경만 제거하고 흰색으로 채웁니다.
B. 장소·행동: 장소나 동작을 알아보는 데 필요한 문·변기·손·도구·접촉 관계는 유지합니다.
   나머지 주변 정보만 정리하며 배경 전체를 무조건 제거하지 않습니다.

[납품]
- 정사각형 1:1, 최종 목표 1024×1024px PNG 한 장.
- 대상의 일부가 잘리지 않도록 배치하고 필요한 경우 흰 여백을 추가합니다.
- 얼굴·손·물건의 고유색·형태·비율을 임의로 보정하거나 재구성하지 않습니다.
- 글자·로고·워터마크·카드 테두리를 새로 넣지 않습니다.
```

원본 사진에 있는 개인정보·이름표·주소·상표는 촬영 단계 또는 별도 편집 단계에서 확인한다.
생성 모델의 지시 준수만으로 개인정보 제거가 보장된다고 가정하지 않는다.

<a id="card-image-production-guide--44-개별-장면-적용-예시와-확인"></a>
##### 4.4 개별 장면 적용 예시와 확인

- `물.png`: A + 5절의 물 장면. 사진형 컵과 물만 제작하며 사람을 추가하지 않는다.
- `마시다.png`: B의 예시를 그대로 사용. 입·손·컵의 접촉을 확인한다.
- `먹다.png`: B + 입·음식을 담은 숟가락·숟가락을 잡은 손. 얼굴 전체는 생략한다.
- `싫어요.png`: B + 고개를 살짝 돌리고 한 손바닥으로 거절하는 상반신. 분노로만 표현하지 않는다.
- `도와주세요.png`: B + 서로를 향해 내미는 사람의 두 손. 한 손은 도움을 구하고 다른 손은
  받쳐 주려는 열린 자세. 악수·하이파이브로 읽히는지 확인하고 모호하면 보조 인물을 추가한 시안과 비교한다.

생성 결과의 크기·PNG 형식·배경·손가락·표정·장면을 사람이 확인한다.
실제 아동에게 뜻이 통하는지는 별도의 사용성 확인이 필요하며 이미지 제작만으로 완료 처리하지 않는다.

<a id="card-image-production-guide--45-시안-검토-후-그림체-부분-보정"></a>
##### 4.5 시안 검토 후 그림체 부분 보정

2026-10-31 사용자가 공유한 카드 모음 시안을 기준으로, 전체 재제작보다 **기존 구도와
의미를 유지한 부분 보정**을 우선한다. 아래 평가는 채팅에 첨부된 시안에 대한 제작 판단이며,
저장소 이미지가 교체되었거나 실제 사용자의 의미 이해가 검증되었다는 뜻은 아니다.

| 시안 | 권장 판단 | 조정 기준 |
| --- | --- | --- |
| 사과·밥·물 | 현재 사진형 유지 | 사람 그림과 맞추기 위해 억지로 만화화하지 않음 |
| 나·엄마 | 사람 그림상징의 스타일 기준으로 유지 | 승인한 시안의 외곽선·피부색·단순한 얼굴 표현을 참조 |
| 먹다·마시다 | 동작과 구도 유지, 필요할 때만 세부 보정 | 손 주름·손톱·입술·코 윤곽을 단순화하되 접촉과 방향은 유지 |
| 도와주세요 | 두 손의 구도 유지, 그림체만 필요 시 보정 | 두 손의 관계를 유지하며 악수·하이파이브로 혼동되는지는 별도 확인 |
| 잘못 눌렀어요 | 현재 의미 구조 유지 | 손과 카드·되돌림 화살표가 읽히면 불필요하게 다시 만들지 않음 |

행동 카드의 입·손이 자세히 그려졌다고 해서 실사인 것은 아니다. 첨부 시안의 행동
그림은 설명용 일러스트에 가깝고, 나·엄마보다 세부 묘사가 많아 다른 세트처럼 보일 수 있다.
사진형과 그림상징을 하나의 그림체로 강제 통일하지 말고, **사람 그림상징끼리의 일관성**을 맞춘다.
‘굵고 일정한 선’은 가능한 한 두껍게 그리라는 뜻이 아니다. 승인된 나·엄마 그림을 우선
기준으로 삼고, 2절의 선 굵기 수치는 초기 시안의 출발점으로만 사용한다.

<a id="card-image-production-guide--gemini용-부분-보정-프롬프트"></a>
###### Gemini용 부분 보정 프롬프트

수정할 행동 카드 한 장과 스타일 기준인 나·엄마 시안을 함께 첨부한다.
기준 카드 자체를 바꾸거나 여러 카드를 한 화면에 합성하지 않도록 요청한다.

```text
첨부한 이미지는 다음 역할로 구분합니다.
1. 수정 대상: 이번에 보정할 행동 카드 한 장.
2. 스타일 기준: 승인된 ‘나’와 ‘엄마’ 카드. 이 두 이미지는 수정하지 않습니다.

수정 대상의 의미·구도·동작·신체 부위·사물 배치·색상은 유지하고,
스타일 기준과 어울리는 단순하고 부드러운 2D 그림상징으로 세부 묘사만 정리해 주세요.

[보정할 부분]
- 외곽선 굵기와 피부색, 색면 표현을 기준 카드와 맞춥니다.
- 과도한 손 주름·손톱·입술의 질감과 세밀한 명암은 줄입니다.
- 입·손·도구의 형태는 자연스럽게 유지하고, 귀여움을 위해 신체 비율을 과장하지 않습니다.
- 마스코트·동물·새로운 인물·소품·감정·상황은 추가하지 않습니다.

[반드시 보존할 의미 단서]
- 마시다: 컵이 입에 닿는 접촉, 컵의 기울기, 손으로 컵을 잡은 모습.
- 먹다: 음식이 담긴 숟가락의 방향, 입 가까이 가져가는 동작, 손의 자연스러운 자세.
- 도와주세요: 도움을 구하는 손과 받쳐 주려는 상대 손의 관계.
이번 수정 대상에 해당하는 단서만 적용하고 다른 카드의 요소는 섞지 마세요.

[납품]
- 기존과 같은 흰색 불투명 배경, 정사각형 1:1, 최종 목표 1024×1024px PNG 한 장.
- 사방 약 10% 여백을 유지하고 손끝·도구·입이 잘리지 않게 합니다.
- 글자·워터마크·카드 테두리·체크무늬·비교판·콜라주는 넣지 않습니다.
- 수정 대상 한 장만 출력하고 기준 카드들은 결과에 포함하지 않습니다.
```

<a id="card-image-production-guide--적용-순서"></a>
###### 적용 순서

1. 동작이 명확한 마시다 시안은 우선 유지한다. 세트에서 실제로 이질적인 카드 한 장만 보정한다.
2. 보정 전후를 같은 화면 크기로 비교하고 의미 단서가 약해졌으면 원본을 유지한다.
3. 새 버전의 스타일이 더 잘 맞고 의미도 유지될 때만 다른 행동 카드에 같은 보정을 적용한다.
4. 기존 파일명·카드 ID·고정 위치·RFID 매핑은 유지한다. 생성 시안만으로 자산을 일괄 덮어쓰지 않는다.
5. 최종 선택은 그림체 선호와 의미 이해를 구분해 기록한다. 사용성 확인 전에는 검수 완료로 표시하지 않는다.

<a id="card-image-production-guide--5-현재-연결-대상-41종과-개별-장면"></a>
#### 5. 현재 연결 대상 41종과 개별 장면

`있음`은 파일이 존재한다는 뜻이며 그림 품질 승인이나 새 규격 통과 표시가 아니다.
`신규`는 현재 로컬 파일이 없어 제작 또는 배치가 필요한 항목이다. 기존 자산 제거 후
`나.png`가 추가되어 1종은 `있음`, 40종은 `신규`다. 카드 데이터를 새로 등록해야 한다는 뜻은 아니다.
아래 ID는 기존 ID를 바꾸기 위한 목록이 아니다.

| stomach | `배.png` | 신규 | 배: 정면 신체 도식에서 복부를 손과 윤곽으로 분명히 가리킨다. 과일 배·음식·통증 장면은 없다. |
| hand | `손.png` | 신규 | 손: 자연스럽게 펼친 손 하나를 크게 표현한다. 손가락 수와 관절이 정확하고 정지 표지·시계는 없다. |
| leg | `다리.png` | 신규 | 다리: 단순한 신체 도식에서 다리를 짙은 윤곽과 지시선으로 강조한다. 교량이나 걷는 동작은 없다. |
| here_hurts | `여기가_아파요.png` | 신규 | 여기가 아파요: 아이가 자신의 몸 한 지점을 직접 가리키며 아픈 표정을 짓는다. 일반 아파요와 달리 지시 동작이 명확해야 한다. 특정 부위로 뜻을 고정하지 않도록 검토한다. |
| uncomfortable | `불편해요.png` | 신규 | 불편해요: 아이가 자세를 조심스럽게 바꾸며 불편한 표정을 보인다. 다친 부위·피·특정 원인은 추가하지 않는다. |
| scared | `무서워요.png` | 신규 | 무서워요: 아이가 어깨를 움츠리고 불안한 표정으로 두 손을 가슴 가까이에 둔다. 괴물·가해자·위험 원인은 그리지 않는다. |
| noisy | `시끄러워요.png` | 신규 | 시끄러워요: 아이가 양손으로 귀를 가리고 옆에 단순한 소리 물결선을 둔다. 특정 사람을 비난하는 장면은 없다. |
| snack | `간식.png` | 신규 | 간식: 작은 무상표 접시에 단순한 크래커 몇 개를 담는다. 식사 한 상·상표 포장·사탕 더미는 없다. |

<a id="card-image-production-guide--52-복구-표현-8종"></a>
##### 5.2 복구 표현 8종

복구 표현의 `yes`·`no`는 별도 표현 목록의 ID다. 일반 카드의 `yes`·`no`와
파일명·의미를 혼동해 합치지 않는다. RFID 매핑 대상을 이 표만 보고 새로 만들지 않는다.

| 복구 ID | 파일명 | 현황 | B 프롬프트에 붙일 개별 장면 |
| --- | --- | --- | --- |
| wrong_tap | `잘못_눌렀어요.png` | 신규 | 잘못 눌렀어요: 손가락이 방금 선택한 작은 그림카드와 이를 되돌리는 화살표. 잘못된 선택을 수정하는 장면이며 일반 반복 동작이 아니다. |
| not_that | `그_뜻이_아니에요.png` | 신규 | 그 뜻이 아니에요: 아이가 고개를 젓고 자신의 말풍선 속 단순한 그림에 작은 취소 기호를 표시한다. 상대방 자체를 거절하는 그림은 아니다. |
| hold_on | `잠깐만요.png` | 신규 | 잠깐만요: 아이가 한 손을 가볍게 들고 작은 시계를 곁들인다. 강한 중단보다 짧은 기다림을 표현한다. |
| say_again | `다시_말할게요.png` | 신규 | 다시 말할게요: 아이에게서 나온 말풍선 주위에 반복 화살표 하나. 아이 자신이 다시 말하는 방향이며 상대에게 반복을 요구하는 장면이 아니다. |
| please_wait | `제_말을_기다려_주세요.png` | 신규 | 제 말을 기다려 주세요: 말하려는 아이와 조용히 기다리는 상대 사이에 작은 시계를 배치한다. 대기 줄이나 일반 중단 장면은 없다. |
| dont_understand | `질문을_잘_모르겠어요.png` | 신규 | 질문을 잘 모르겠어요: 상대의 말풍선에 의미 기호인 작은 물음표 하나가 있고, 아이는 이를 바라보며 양손을 가볍게 펼친다. 문장·글자는 없고 아이 자신이 질문하는 장면과 구분한다. |
| yes | `맞아요.png` | 신규 | 맞아요: 아이가 고개를 끄덕이고 확인 대화의 말풍선에 작은 확인 기호를 둔다. 즐거운 감정보다 상대의 확인에 대한 응답을 표현한다. |
| no | `아니에요.png` | 신규 | 아니에요: 아이가 고개를 젓고 응답 말풍선 안에 작은 취소 기호를 둔다. 물건을 밀어내는 싫어요 장면과 구분한다. |

추상 표현은 그림만으로 모든 차이를 전달하기 어렵다. 표시 단어·실제 발화·
보호자와의 시범 사용으로 확인한다. 더 복잡한 그림을 넣어 해결했다고 가정하지 않는다.

<a id="card-image-production-guide--53-기존-기획-문서의-확장-어휘"></a>
##### 5.3 기존 기획 문서의 확장 어휘

`주세요`, `원해요`, `오다`, `기뻐요` 등 기존 단어 목록의 확장 제안은 위 41종과
다른 범위다. PNG만 추가해도 새 카드가 등록되는 것은 아니다. 어휘 의미·ID·발화·
카테고리·필요한 문장 역할을 먼저 정한 뒤 앱의 등록 기능 또는 별도 개발로 연결한다.

<a id="card-image-production-guide--6-파일명교체연결-절차"></a>
#### 6. 파일명·교체·연결 절차

<a id="card-image-production-guide--자동-연결-규칙"></a>
##### 자동 연결 규칙

```text
표시 카드명 앞뒤 공백 제거 → 일반 공백을 _로 변경 → .png 붙이기

사과                 → 사과.png
다른 것              → 다른_것.png
그 뜻이 아니에요     → 그_뜻이_아니에요.png
제 말을 기다려 주세요 → 제_말을_기다려_주세요.png
```

- 일반 공백 한 칸을 사용하고 탭·연속 공백·특수 공백을 넣지 않는다.
- `apple.png`, `물_최종.png`, `물_1024.png`, `사과 (1).png`는 현재 자동 매핑 규칙과 다르다.
- 한 장씩 생성한 납품본만 넣는다. 스프라이트·콘택트시트·원본 PSD는 이 폴더에 넣지 않는다.

<a id="card-image-production-guide--적용-경로-선택"></a>
##### 적용 경로 선택

1. **기본 제공 그림 재제작**: 기존과 같은 파일명으로 정적 자산을 교체하고
   카드 ID·표시 단어·배열·TTS·RFID UID 매핑은 유지한다. 기존 자산은 Git 이력 등으로 보존한다.
2. **아동별 개인화**: 보호자 화면의 기존 카드 사진 교체 기능을 사용한다.
   기본 카드와 같은 이름을 신규 일괄 등록하면 중복 카드명으로 거절될 수 있다.
3. **새 어휘 추가**: 카드 등록 절차를 거친다. 파일만 복사해 신규 카드 생성이 된 것으로 보지 않는다.

현재 `card.image_src`가 있으면 개인/서버 이미지가 내장 PNG보다 우선한다.
기본 그림을 교체했는데 특정 아동에게 이전 사진이 보이면 대체 이미지 설정을 확인한다.
이 문서 작성 작업에서는 사용자 사진·DB·UID 매핑을 삭제하거나 변경하지 않는다.

Vite의 정적 이미지 목록은 빌드 시점에 수집된다. 배포본에는 재빌드가 필요하고,
로컬에서는 개발 서버의 갱신 상태를 확인한다. 파일 복사만으로 이미 배포된 번들이 바뀌지는 않는다.

<a id="card-image-production-guide--7-실물-rfid-카드-출력-시안"></a>
#### 7. 실물 RFID 카드 출력 시안

아래는 첫 실물 시제품 예시이며 태그 크기나 아동의 조작 능력에 맞춰 조정한다.

| 항목 | 출력 시안 예시 |
| --- | --- |
| 완성 카드 | 60×70mm |
| 그림 영역 | 48×48mm, 위쪽 중앙, 흰 배경 |
| 그림과 이름 | 원본 그림에는 글자를 넣지 않고 출력 레이아웃의 별도 하단 영역에 카드명 배치 |
| 인쇄 해상도 | 300dpi 목표. 60×70mm는 약 709×827px, 48mm 그림은 약 567px |
| 이름 크기 | 우선 16~20pt부터 출력 확인. 긴 문구는 줄바꿈하되 글자를 과도하게 줄이지 않음 |
| RFID 태그 | 실제 태그·케이스의 크기를 측정한 뒤 뒷면에 고정. 금속 재료·차폐 재료는 피하고 실제 리더기로 인식 확인 |
| 식별 관리 | 카드 앞면은 의미를 전달하고, 필요하면 뒷면에 관리번호 사용. UID는 관리자 매핑에서 관리 |

재단 여백·라미네이팅·모서리 마감·태그 고정 방식은 사용 환경에 맞게 정한다.
분리 가능한 작은 태그를 아동에게 그대로 제공하지 않으며, 보호자가 실제 제품 안전성을 확인한다.
이미지의 교체와 태그의 UID 변경은 별개다. 같은 카드를 재출력할 때 매핑을 불필요하게 바꾸지 않는다.

<a id="card-image-production-guide--8-제작-순서와-사람이-확인할-사항"></a>
#### 8. 제작 순서와 사람이 확인할 사항

<a id="card-image-production-guide--권장-진행-순서"></a>
##### 권장 진행 순서

1. A의 `물`·`사과`와 B의 `마시다`·`싫어요`·`도와주세요`로 시안을 먼저 비교한다.
2. 현재 파일 준비는 나 1종이며, 나머지는 통증·감각·거절·도움 요청 카드를 우선 제작한다.
3. 기본 33종의 사진형끼리·그림상징끼리 스타일을 맞추고 전체 배경·크기·여백을 통일한다.
   기존에 익숙한 그림은 개별 검토 후 교체한다.
4. 복구 표현 8종은 비슷한 의미끼리 비교한 뒤 재사용·재제작을 결정한다.
5. 웹 화면과 실물 시안을 확인한 뒤 최종 파일을 반영한다. 한 장 생성할 때마다 커밋하지 않는다.

<a id="card-image-production-guide--제작-완료-체크리스트"></a>
##### 제작 완료 체크리스트

- [ ] 실제 PNG·1024×1024px·파일명·용량 목표를 확인했다.
- [ ] 흰 배경이며 글자·워터마크·UI 테두리·무지개색 띠가 없다.
- [ ] 카드 이미지에는 마스코트가 없고 A/B/C의 선택 기준을 확인했다.
- [ ] 생성한 사진형 이미지를 실제 가족·개인 물건을 촬영한 사진으로 오인하게 설명하지 않았다.
- [ ] 배경 제거 과정에서 사물의 특징·손과 도구의 접촉·장소 식별 단서가 사라지지 않았다.
- [ ] 피사체·손가락·동작·여백이 정확하고 한 가지 개념을 나타낸다.
- [ ] 128px 전후의 주 카드와 24·28·38px 빠른 표현에서 식별성을 확인했다.
- [ ] 현재 앱에서 `cover`와 `contain` 표시가 혼재하므로 각각의 실제 표시 위치에서 잘림을 확인했다.
- [ ] 정사각형·10% 여백만으로 가로형 보기의 `cover` 잘림이 모두 해결된다고 가정하지 않았다.
- [ ] 물/마시다, 밥/먹다, 그만/기다려 주세요/잠깐만요, 좋아요/네/맞아요를 비교했다.
- [ ] 실제 아동에게 익숙한 의미인지 보호자·담당자가 확인했다.
- [ ] 카드 추가·삭제·원문 발화·AI 보조 결과 선택·RFID 발화에서 의미가 유지된다.
- [ ] 개인 이미지 우선 적용, 기본 이미지 복원, 오프라인 캐시 표시를 확인했다.
- [ ] 재출력한 실물 카드의 UID→기존 카드→문장→음성 흐름을 확인했다.
- [ ] 이미지 생성 서비스와 참조 이미지의 사용·배포 조건을 확인했다.

체크되지 않은 항목은 완료가 아니다. 이번 문서 작성에서는 이미지를 생성·교체하지 않았고,
자동 테스트·빌드·브라우저·실기기·아동 대상 검증도 실행하지 않았다.

- 성별을 지나치게 강조하지 않는 중립적인 인물 표현
- 카드 이미지 안에는 단어, 문장, 로고, 워터마크를 넣지 않음
- 색만으로 의미를 전달하지 않고 자세·사물·방향으로 의미를 전달
- 축소된 카드에서도 핵심 동작이나 물건을 구분할 수 있도록 제작

<a id="card-photo-word-list--대체-텍스트-적용-기준"></a>
###### 대체 텍스트 적용 기준

- 화면에 보이는 표시 단어와 대체 텍스트를 똑같이 반복하지 않는다.
- 표시 단어는 카드의 의사소통 의미를 전달하고, 대체 텍스트는 그림에 무엇이 보이는지 짧게 설명한다.
- 장식 요소, 배경색, 그림체는 의미 구분에 필요할 때만 대체 텍스트에 포함한다.
- 버튼의 접근 가능한 이름은 `{표시 단어} 카드`로 제공하고, 이미지 대체 텍스트는 위 표의 문구를 사용한다.
- 이미지가 버튼 안에서 장식 역할만 한다면 중복 낭독을 막기 위해 이미지 자체는 빈 대체 텍스트로 처리하고 버튼 이름에 표시 단어를 제공한다.

<a id="card-photo-word-list--4-이미지-제작-규격"></a>
#### 4. 이미지 제작 규격

<a id="card-photo-word-list--공통-규격"></a>
##### 공통 규격

- 상세 규격과 생성 프롬프트는 [현행 제작 가이드](CARD_ASSETS.md#card-image-production-guide)를 따른다.
- 웹 납품본: 정사각형 1024×1024px PNG, 편집용 고해상도 원본은 별도 보관
- 내장 자산은 PNG를 직접 사용하며, API 업로드 이미지만 화면용 WebP와 원본을 별도로 보관
- 피사체: 한 카드에 한 개념, 중앙 배치
- 배경: 기본 제공 상징 그림은 흰색, 사용자별 실제 사진은 시각적으로 단순한 배경
- 여백: 카드 가장자리에서 피사체가 잘리지 않도록 10% 이상
- 문자: 이미지 안에 삽입하지 않음
- 로고·상표: 가능하면 제거
- 촬영 정보: 공용 납품 자산에는 위치·기기 정보 등 불필요한 개인정보를 넣지 않음
- 파일명: 내장 자산은 `[카드명].png`, 카드명의 일반 공백은 `_`로 치환. 영문 ID 파일명으로 자동 연결되지 않음
- 용량: 장당 1MiB 이하 권장. API 업로드의 실제 상한은 5MiB이며 정적 자산 제한과 구분
- 대체 텍스트: 카드 표시 단어와 의미가 일치하도록 작성

#### 9. 권장 카테고리 개편

현재 `사람`, `음식`, `행동`, `장소`, `감정`만으로는 신체와 감각 표현이 섞인다. 다음 구조를 권장한다.

| 순서 | 카테고리 | 포함 예시 |
|---|---|---|
| 1 | 빠른 표현 | 아파요, 싫어요, 도와주세요, 화장실, 그만 |
| 2 | 사람 | 나, 가족, 교사, 담당자, 친구 |
| 3 | 음식·음료 | 물, 밥, 간식, 선호 음식 |
| 4 | 행동·요청 | 가다, 먹다, 주세요, 열다, 바꾸다 |
| 5 | 장소 | 집, 학교, 교실, 치료실, 병원 |
| 6 | 감정 | 기뻐요, 슬퍼요, 화나요, 무서워요 |
| 7 | 몸·건강 | 머리, 배, 아파요, 어지러워요 |
| 8 | 감각·환경 | 시끄러워요, 밝아요, 더워요, 추워요 |
| 9 | 생활용품 | 칫솔, 수건, 옷, 가방 |
| 10 | 놀이 | 공, 블록, 음악, 산책 |
| 11 | 학습 | 책, 연필, 읽다, 쓰다 |
| 12 | 사용자 카드 | 개인 인물·장소·음식·물건 |

복구 표현은 카테고리에 넣더라도 카드 탐색과 별도로 항상 접근 가능한 고정 영역을 유지한다.

#### 12. 카드 등록 체크리스트

- [ ] 카드 ID가 중복되지 않는다.
- [ ] 표시 단어와 의미 설명이 일치한다.
- [ ] 품사와 문장 역할이 지정되어 있다.
- [ ] 같은 발음의 다른 뜻을 이미지와 의미로 구분한다.
- [ ] 이미지가 한 가지 개념을 명확히 보여 준다.
- [ ] 개인 사진의 동의와 공개 범위가 확인되었다.
- [ ] 공용 이미지의 저작권·배포 권한이 확인되었다.
- [ ] 이미지의 EXIF와 불필요한 개인정보가 제거되었다.
- [ ] 카드의 TTS 발음이 실제 기기에서 확인되었다.
- [ ] 오프라인 상태에서 이미지와 핵심 음성이 표시된다.
- [ ] 고정 카드판에 추가할지 라이브러리에만 둘지 결정되었다.
- [ ] 보호자 또는 권한 있는 담당자가 최종 위치를 확인했다.
