# 오프라인 사용 및 한국어 음성 정책

## 구현 범위

- 프로덕션 빌드는 서비스 워커로 앱 셸과 이미 한 번 사용한 정적 자산을 캐시한다. `/api/` 응답은 서비스 워커 캐시에 넣지 않는다.
- 로그인에 성공한 AAC 사용자의 기본·개인 카드, 개인 카드 이미지, 추천, 음성·접근 설정, 최근 학습 설정과 진행 중인 학습 상태는 브라우저의 origin 단위 IndexedDB에 저장한다.
- 서버 연결이 끊기면 인증 토큰을 임의로 지우지 않고 마지막 저장본으로 진입한다. 오프라인 계정 저장본도 서버가 발급한 12시간 세션 만료 시각까지만 사용한다. 기본 긴급·복구 표현은 저장된 WAV, 그 외 즉시 발화와 선택 카드 발화는 기기 TTS로 실행한다. 서버가 필요한 자연 문장 생성은 연결 전까지 비활성화한다.
- 로그아웃과 이용 데이터 삭제 시 계정 저장본과 대기 중 이력을 기기에서도 제거한다. IndexedDB는 디스크 암호화를 자체 제공하지 않으므로 공용 기기에서는 반드시 로그아웃한다.
- 오프라인 발화 이력에는 UUID, 이벤트 유형, 카드 ID와 시각만 저장하며 발화 원문은 저장하지 않는다. 재연결하면 동일 UUID로 재시도하고 서버 확인을 받은 항목만 삭제한다.
- 발화 이력은 발생 시각순으로 최대 100건씩 전송한다. 일부 묶음이나 학습 결과가 실패해도 확인된 항목만 제거하고 나머지는 같은 UUID로 재시도한다. 동시에 들어오는 재연결은 로그인 세션별로 한 번만 실행하며 계정이 바뀌면 이전 대기열 전송을 중단한다. 온라인 상태에서 남은 건수와 `기록 동기화 다시 시도`를 표시한다.
- 전송 직전 기기 대기 항목에 `sync_attempted` 표시를 저장해 새로고침 후에도 재시도 여부를 구분한다. 이 표시는 본문에 넣지 않고 재시도 건수만 헤더로 전달한다. 표시 저장 실패 시 대기 항목을 보내거나 지우지 않는다. 운영자는 [동기화 지표](../development/OFFLINE_SYNC_METRICS.md)에서 서버가 확인한 신규·중복·실패·미처리 건수를 조회한다. 서버에 도착하지 않은 통신·기기 저장 실패는 서버 지표의 실패 수에 포함되지 않는다.
- 진행 중인 학습은 문제 위치와 첫 시도 결과를 문제 선택마다 저장한다. 브라우저를 다시 열면 같은 문제부터 이어 가며, 오프라인에서 완료한 결과는 학습 요청 UUID를 유지한 채 대기열에 저장한다. 재연결 시 기존 학습 API로 전송하고 서버가 저장한 항목만 기기 대기열에서 제거한다.

처음 설치하는 기기에서는 온라인 상태로 한 번 로그인하고 카드와 설정을 모두 불러와야 한다. 브라우저 저장 공간 삭제, 시크릿 모드 종료 또는 사이트 데이터 초기화 후에는 다시 온라인 준비가 필요하다.

## TTS 재생 계층

1. 로그인 직후 기본 빠른 표현 5개·복구 표현 8개의 WAV를 비동기로 기기에 저장한다. 오프라인 또는 한국어 음성이 없으면 해당 WAV를 먼저 사용하며, 온라인 기기 TTS가 실패하거나 시작되지 않을 때도 WAV로 대체한다. 사용자가 추가한 표현은 이 고정 묶음에 포함하지 않는다.
2. 일반 카드와 문장도 같은 기기 TTS를 사용한다. 로컬 여부를 브라우저가 알려 주지 않는 음성은 실제 비행기 모드 시험 전까지 `오프라인 확인 필요`로 표시한다.
3. 고품질 서버 TTS는 선택형 후속 기능으로만 검토하며 핵심 의사소통 경로에 포함하지 않는다. 서버 TTS를 추가하더라도 실패 시 기기 TTS와 화면 텍스트가 항상 남아야 한다.

기본 음성은 공개 고정 문구의 정적 자산이며 IndexedDB `coreSpeech`에 버전별 묶음으로 저장한다. 로그아웃 시에도 유지하고 사이트 데이터 삭제 시 제거한다. 개인 문장이나 녹음 파일은 저장하지 않는다. 원문을 외부 TTS로 전송하지 않으며 TTS 이력에는 원문 없이 콘텐츠 종류, 글자 수, 성공 여부, 오류 코드와 시작 지연을 기록한다. 생성·교체·삭제 기준은 [TTS 정책](TTS_POLICY.md)을 따른다.

## 한국어 음성 지원 판단

웹 앱은 `speechSynthesis.getVoices()`가 현재 기기에서 제공하는 음성만 사용한다. 이 API가 기기의 사용 가능 음성 목록을 반환한다는 점은 [MDN Web Speech API 문서](https://developer.mozilla.org/en-US/docs/Web/API/SpeechSynthesis/getVoices)를 기준으로 한다. 브라우저 이름만으로 오프라인 재생을 보장하지 않고, `ko` 음성과 `localService === true` 표시 및 실제 비행기 모드 재생을 함께 확인한다.

| 환경 | 현장 준비 | 판정 및 대체 |
|---|---|---|
| Windows 10/11 + Edge/Chrome | Windows 음성 설정에서 한국어 음성을 내려받는다. Microsoft는 한국어 Heami와 자연 음성 InJoon·SunHi를 안내하며 내려받은 자연 음성은 기기에서 인터넷 없이 작동한다고 설명한다. | 앱의 미리 듣기를 실행한 뒤 네트워크를 끄고 다시 재생한다. 실패하면 Windows 내레이터 또는 설치된 한국어 음성을 먼저 확인한다. |
| macOS + Safari/Chrome | 시스템 설정 → 손쉬운 사용 → 읽기 및 말하기에서 한국어 시스템 음성을 내려받는다. | 브라우저별 노출 음성이 다를 수 있으므로 두 브라우저에서 각각 비행기 모드 시험을 한다. 실패하면 macOS의 선택 항목 말하기 또는 Live Speech를 사용한다. |
| iPhone/iPad + Safari 홈 화면 | 설정 → 손쉬운 사용 → VoiceOver/콘텐츠 말하기에서 한국어 음성을 선택하고 필요한 고품질 음성을 Wi‑Fi에서 내려받는다. | Safari Web Speech 재생을 비행기 모드에서 확인한다. 실패하면 iOS Live Speech에 같은 문구를 입력하거나 화면의 카드·문장을 상대에게 보여 준다. |
| Android + Chrome | 설정 → 접근성 → 텍스트 음성 변환 출력에서 엔진·한국어를 선택하고 `음성 데이터 설치`를 완료한다. 제조사별 엔진이 다를 수 있다. | Chrome에서 미리 듣기 후 비행기 모드 시험을 한다. 실패하면 기기 TTS 엔진을 Google 또는 제조사 엔진으로 바꾸거나 카드·문장 텍스트를 보여 준다. |

설치 근거와 경로는 [Microsoft 한국어 음성 및 설치 안내](https://support.microsoft.com/ko-kr/accessibility/windows/narrator/appendix-a-supported-languages-and-voices), [Microsoft의 내려받은 자연 음성 오프라인 안내](https://support.microsoft.com/en-us/accessibility/windows/narrator/complete-guide-to-narrator), [Apple macOS 음성 다운로드 안내](https://support.apple.com/en-ph/guide/mac-help/mchlp2290/mac), [Apple iPhone/iPad 음성 다운로드 안내](https://support.apple.com/en-ie/111798), [Android 음성 데이터 설치 안내](https://support.google.com/accessibility/android/answer/6006983)를 따른다.

## 배포 전 비행기 모드 점검

1. 온라인으로 로그인해 `기본 긴급·복구 음성 13개 저장됨`을 확인하고 개인 카드 이미지, 접근 설정과 음성 설정을 연다.
2. 한국어 미리 듣기를 재생한 뒤 브라우저를 완전히 종료하고 비행기 모드를 켠다.
3. 앱을 다시 열어 `도와주세요` 즉시 발화와 `물 → 마시다` 선택 카드 발화를 실행한다.
4. 새로고침 후에도 개인 카드 그림과 설정이 복원되는지 확인한다.
5. 발화 2건을 만든 뒤 네트워크를 연결하고 대기 건수가 0으로 바뀌는지 확인한다.
6. 같은 이벤트 UUID를 다시 보내 서버에 한 건만 남는지 확인한다.
7. 학습 도중 앱을 종료한 뒤 같은 문제에서 재개되는지 확인한다.
8. 오프라인에서 학습을 완료하고 네트워크를 연결한 뒤 학습 대기 건수가 0이 되고 보호자 화면에 한 번만 집계되는지 확인한다.

어느 단계든 실패하면 해당 기기는 현장 기본 기기로 승인하지 않는다. 중요한 의사표현은 화면 텍스트와 그림을 항상 유지하며, OS의 Live Speech/텍스트 음성 변환 기능을 대체 수단으로 준비한다.
