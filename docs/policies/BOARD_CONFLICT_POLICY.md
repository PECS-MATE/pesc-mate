# 카드판 동시 수정 정책

고정 카드 위치와 빠른·복구 표현은 아동이 익숙하게 사용하는 의사소통 구성이다.
보호자·담당자의 나중 저장이 다른 기기의 변경을 조용히 덮어쓰지 않도록 버전으로 충돌을 검사한다.

## 저장 규칙

- 카드판 조회는 `revision`을 반환한다. 저장본이 없거나 기존 문서에 버전이 없으면 0이다.
- 빠른 표현, 복구 표현, 고정 슬롯은 하나의 카드판 버전을 공유한다.
- 모든 저장 요청은 조회한 `expected_revision`을 필수로 보낸다. 누락·음수는 422다.
- 서버 버전과 같을 때만 저장하고 버전을 1 올린다. 기존 문서는 MongoDB 조건부 갱신을 사용한다.
- 첫 저장이 동시에 들어오면 `_id` 고유 제약으로 한 요청만 성공한다. 나머지는 409다.
- 거절된 변경은 구성과 성공 감사 로그를 남기지 않는다. 성공 기록에는 변경 전·후 버전도 저장한다.
- 저장 응답은 해당 요청이 반영한 버전을 반환한다. 이후 다른 요청의 결과를 대신 반환하지 않는다.

## 충돌 화면

409 응답을 받으면 현재 초안을 화면에 유지하고 저장과 추가 편집을 잠근다.
`최신 카드판 불러오기` 버튼 옆에 불러오면 현재 편집 내용이 바뀐다는 안내를 표시한다.
사용자가 불러오기를 선택하면 최신 구성과 감사 이력으로 교체하고 다시 편집할 수 있다.
자동 덮어쓰기·자동 병합은 하지 않는다. 다른 아동으로 전환하거나 로그아웃한 뒤 늦게 도착한
이전 아동의 저장·조회 응답은 새 화면에 적용하지 않는다.

서버 저장 후 응답만 유실된 경우 재시도는 버전 충돌로 처리될 수 있다.
이때 최신 구성을 불러와 실제 저장 결과를 먼저 확인한다. 보호자·담당자 구성 변경은 온라인에서만 지원한다.

## 배포·검증

기존 문서는 삭제하거나 일괄 변경하지 않고 첫 성공 저장 시 버전 1로 전환한다.
`expected_revision`을 보내는 프런트엔드와 필수 필드를 검사하는 백엔드를 같은 배포에 포함한다.
이전 클라이언트의 버전 없는 저장 요청은 422로 차단되므로 새로고침 후 재시도한다.

- 단위 검증: `backend/tests/test_board_layout.py`의 오래된 버전·원자적 갱신 경합·최초 저장 경합·기존 문서 호환
- 브라우저 검증: `frontend/e2e/board-conflicts.spec.js`의 두 브라우저 컨텍스트 저장·409·초안 보존·최신 구성 재조회·재저장·감사 기록

자동 검증은 실제 두 태블릿의 설정 반영·회전·오터치 검수를 대신하지 않는다.
