# 핵심 카드 잠금과 개인 사진 교체

2026-10-23 B1-01 구현. 잠글 내용 자체를 앱이 임의로 결정하지 않는다. 연결 아동의
`board_manage` 권한이 있는 보호자·담당자가 현재 저장된 슬롯에서 카드를 선택하고,
보호 효과를 확인한 뒤 직접 저장한다. 기본 잠금은 비어 있고 기존 카드판은 자동 변경하지
않는다. 실제 사용자에게 필요한 필수 어휘와 잠글 항목의 현장 승인은 별도로 남긴다.

## 보호 범위

- 잠긴 카드는 저장된 슬롯 번호에서 이동하거나 제외할 수 없다. 앞 카드 제거로 위치가
  밀리는 변경과 일괄 가져오기의 슬롯 교체도 같은 서버 검사로 거절한다.
- 개인 카드 사진 교체도 잠금을 확인한다. 공유·기본 카드 사진은 이 교체 API에서 수정할
  수 없다. 승인된 개인 카드의 문구 수정 API도 기존처럼 제공하지 않는다.
- 잠금은 카드 선택·문장 생성·발화·빠른/복구 표현 사용을 막지 않는다. 빠른 표현과 복구
  표현의 별도 구성 정책을 대체하지 않는다. 공용 콘텐츠 운영자의 비활성 정책은 별도다.
- 잠금 해제는 명시적으로 선택 해제 후 확인·저장한다. 카드·사진·사용 기록은 삭제하지
  않는다. 사용 불가 카드의 잠금은 목록에서 해제할 수 있다.

## 저장·경쟁·실패

`GET /api/board/layout`은 `locked_card_ids`를 반환한다. 구버전 문서의 기본값은 `[]`다.
`PUT /api/board/layout/locks?user_id=...`는 JSON `expected_revision`(엄격한 0 이상 정수),
`card_ids`(중복 없이 최대 30개, 전체 해제는 빈 목록)를 받는다. 인증·현재 연결·
`board_manage`를 검사하고 현재 저장된 슬롯에 있는 카드만 잠근다. 미저장 슬롯 편집을
동시에 저장하지 않는다. 화면은 미저장 초안이 새 잠금과 다르면 저장을 차단하고,
**편집 내용을 버리고 저장된 카드판 불러오기**로 명시 복구한다.

잠금 변경은 이미지 쓰기/개인정보 삭제와 같은 전역 잠금을 사용한다. 잠금 획득 후에도
연결·삭제 상태를 재검사한다. 슬롯 변경과 잠금 변경은 같은 카드판 revision의 조건부
갱신으로 충돌을 차단한다. 원래 슬롯과 잠금 비교는 최신 문서를 읽은 같은 저장 경로에서
검사한다. 보드 문서와 개인정보 삭제 범위는 기존 컬렉션을 그대로 사용한다.

성공 감사는 `core_card_locks_changed`, 대상·행위자·이전/이후 ID와 revision을 남긴다.
현재 화면의 최근 감사 목록은 다음 카드판 조회 때 갱신된다. 충돌·통신·서버 오류나
확인된 저장 뒤 목록 반영 실패는 재전송하지 않고 최신 조회를 요구한다. 아동·세션·버전
전환 뒤 늦은 응답은 폐기한다. 보호자 화면의 오프라인 저장은 허용하지 않는다.
