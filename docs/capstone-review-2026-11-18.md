# 캡스톤 발표 전 점검과 promo 개선안

점검일: 2026-11-18 (한국 시간). 자동 검사와 로컬 실행 확인 결과이며,
실제 아동 사용성·치료 효과를 검증한 결과는 아니다.

## 점검 결과

| 범위 | 확인 결과 |
| --- | --- |
| 프런트엔드 | Vitest 24개 파일, 119개 테스트 통과 |
| 백엔드 | 104개 테스트 및 4개 하위 테스트 통과 |
| 실제 MongoDB | 격리된 임시 DB에서 동시성·용량·쓰기 잠금 테스트 5개 통과 |
| 음성 캐시와 발표 동작 | Node 테스트 12개 통과 |
| 음성 파일 생성 도구 | 외부 음성 생성 없는 단위 테스트 3개 통과 |
| 실제 promo 브라우저 | 320×640·768×1024·1024×768·1440×900·1920×1080의 35개 장면 및 전환·촬영·복귀 동작 통과 |
| 실행 상태 | API·MongoDB·Qwen TTS 정상 상태, promo HTTP 200 |
| 프로덕션 빌드 | 성공. 큰 JS 청크와 혼합 정적/동적 import 경고는 남음 |

발견 후 수정한 항목:

- API 명세 기준 파일을 UTF-8로 읽도록 수정했다. Windows 기본 CP949에서 실패하던 검사다.
- 이미지 응답의 CORS 검사를 Origin 있는 요청과 없는 요청으로 분리했다.
  200·304 응답의 Vary와 허용 Origin을 확인한다.
- 현재 카드 응답의 `image_filename` 필드가 명세 기준 파일에 누락되어 있어 반영했다.
  실제 API 동작이나 운영 DB를 바꾼 수정은 아니다.

## promo에 반영한 1차 개선

| 장면 | 메시지와 화면의 역할 |
| --- | --- |
| 1. 서비스 소개 | PECS의 한글 뜻을 상단에, 카드를 상대에게 건네 의사를 전하는 설명을 본문에 배치 |
| 2. 제작 배경 | 말로 의사를 표현하기 어려운 아동, 보호자·담당자를 명시하고 카드 관리 문제 설명 |
| 3. 말하기 시연 | 카드 → Qwen 문장 생성 → 로컬 Qwen TTS 흐름 제시 |
| 4. 맞춤 카드 | 등록·편집·인쇄 화면으로 실제 구현 설명 |
| 5. RFID 연결 | 실제 배선 사진과 태그 → USB → 웹 흐름 설명 |
| 6. 발전 과정 | React·FastAPI·MongoDB·RFID 통합 설명, 학습지 제작은 향후 계획으로 표시 |
| 7. 마무리 | 관람객 체험 유도 |

7개 장면과 75초 전시 반복은 유지한다. 발표자는 수동 장면 전환으로
[3분 이내 대본](presentation-rehearsal.md)에 맞춘다. 자동 화면은 무음 예시이며,
실제 API 호출이나 실제 RFID 수신을 보여 주는 화면으로 소개하지 않는다.

## 다음 개선 우선순위

1. **기술 흐름을 한눈에:** 발전 과정 장면에 웹 → API → 사용자별 카드·UID 조회 →
   문장 생성 → 음성 출력 구조도를 추가하는 안을 검토한다. 이미지 바이트와 카드 메타데이터의
   저장 경로는 [DB 질문 대비](presentation-db-qa.md)의 현재 구현과 일치시킨다.
2. **실물과 화면을 연결:** 발표 때 실제 그림카드 한 장을 먼저 보여 주고, 동일한 카드로
   RFID 시연을 진행한다. 사진만으로 리더기가 작동 중이라고 설명하지 않는다.
3. **보호자 기능을 짧게:** 카드 생성·등록 과정은 한 가지 사례만 보여 준다.
   AI 그림은 제작 규칙을 적용한 시안으로 설명하고 보호자의 확인 후 저장한다.
4. **성과와 계획 구분:** 구현한 기능을 제시하고, 사용성 확인·효과 평가는 후속 과제로 둔다.
   근거 없는 정확도·반응 시간·치료 효과 수치는 넣지 않는다.

## 발표 직전 실기기 확인

- 세 리더 diagnostics가 OK인지 확인하고 태그 제거·재태그·문장 비우기를 직접 시험한다.
  이번 자동 테스트가 현재 배선과 실물 태그의 정상 동작을 보장하지는 않는다.
- 선택한 여자아이/남자아이 음색과 태블릿의 실제 소리·볼륨을 확인한다.
  직전 합성 측정은 CPU에서 약 37~47초였다. 발표용 문장과 음색을 미리 재생해
  캐시를 준비하고, 새 문장이 즉시 합성된다고 설명하지 않는다.
- OpenRouter는 설정 여부와 실제 호출 성공을 구분한다. 이번 점검에서는
  유료 문장·이미지 생성 요청을 추가 실행하지 않았다.
- 현재 Docker 포트는 `127.0.0.1`로 바인딩되어 같은 PC에서 접속할 수 있다.
  태블릿 접속 시에는 `TABLET_BIND_ADDRESS=0.0.0.0` 적용 후 서비스 재생성,
  PC의 실제 IP와 방화벽·동일 네트워크 연결을 별도로 확인한다.
- 큰 화면의 배치 검사가 통과해도 작은 휴대폰에서 발표 글자가 충분히 크다는 뜻은 아니다.
  발표는 가로형 프로젝터/모니터 기준으로 최종 확인한다.
